# 版本化测试计划与质量证据架构

适用：suma 1.0.0，T-QUALITY-115。负责人：质量领域、调度、Runner 与工作台；关联：需求／任务验收、候选独立测试及问题回流。当前实现正式自动化测试计划及逐例证据，不扩展出第二套执行引擎。完整接口及限制以[测试计划合同](../../contracts/test-plans.md)为准，操作见[中文指南](../development/test-plans.md)及[English](../en/test-plans.md)。本设计不是通过验证的证明。

实际检查、环境、结果与剩余范围由[阶段验收报告](../quality/test-plans-verification.md)及[摘要](../quality/test-plans-summary.json)维护。

## 领域所有权与链路

任务领域拥有验收条目和交付责任，质量领域拥有计划／修订、运行绑定、报告投影及受保护问题关系；Go DAG 拥有执行状态、attempt、租约和 fence；Runner 拥有本地命令与实际进程／工作树采集。原人工 Review 继续拥有正式验收决定。每个领域复用现有授权、同库事务、原操作回执和活动记录。

```mermaid
flowchart LR
  T[任务验收条目与关联需求] --> P[计划草稿与发布修订]
  P --> B[任务绑定运行时冻结修订或空绑定]
  C[同运行代码节点与干净提交] --> D[原 Go DAG 固定候选交接]
  B --> D
  D --> R[新独立工作树运行许可测试 CLI]
  R --> X[原始 XML 与真实进程结果]
  X --> E[固定身份报告与逐例派生证据]
  E --> G[当前依据及人工 Review 门禁]
  E --> I[明确确认创建当前失败用例问题]
  I --> Q[原问题池与需求回流]
```

不新增独立 TestExecution 调度器。固定测试节点通过原命令注册和 profile 派发，同一运行的 `candidate_from` 约束测试代码输入。工作流仍可并行测试，但报告与候选关系必须逐一固定，不能只用整图“成功”替代逐例证明。

## 状态、版本与失效

计划聚合与不可变修订分离：一个任务一个计划，多个保存／发布／停用修订。草稿允许尚未完成的步骤和 selector；发布要求完整自动化用例并覆盖当前任务全部验收条目，`covers` 使用任务条目的从 1 开始索引。原需求只作为独立版本依据，不能把需求条目索引混入任务覆盖。

`TestPlanSource` 的任务快照用于追溯，当前性由任务业务依据摘要 `task_basis_sha256` 判断。任务因绑定运行或 Review 自动增版，不单独令计划失效；实际业务依据变化则失效。需求快照按精确版本另行检查。这样既不在执行后因技术性增版产生误失效，也不接受需求已变的旧测试依据。

任务绑定时记录计划修订／摘要／来源；没有已发布计划也记录空绑定。后发修订不能倒签旧运行，停用不删除旧证据或免除旧门禁。当前发布指针、任务当前 run、任务／需求依据或补偿事实不再匹配时，保留旧原件，并将当前可用性标为变化／停用，而不改写历史执行结果。

| 事实 | 持久所有权 | 可变性 |
| --- | --- | --- |
| 计划当前版本和发布指针 | `suma_test_plans` | 当前事务及版本比较更新 |
| 修订正文与来源摘要 | `suma_test_plan_revisions` | 追加不可变快照 |
| 任务运行的修订或空绑定 | `suma_test_plan_runs` | 按运行冻结 |
| 原报告／派生投影／执行身份 | `suma_test_plan_reports` | 按运行、节点、attempt、fence 唯一记录 |
| 失败用例关联问题 | `suma_test_plan_defects` | `(plan,run,case_key)` 受保护唯一关系 |
| 真实派发及执行结果 | 原 DAG 表与 attempt 结果 | 沿原状态机与回执约束 |

报告接收先沿原 Runner／执行池身份、assignment 和 fence 校验，再在结果事务内保存质量事实。迟到旧 attempt 不能写成当前证明；重试保留旧报告，当前性从节点最新 attempt／fence／Worker 重新计算。未知结果不能因再次投递被无证据改为已知成功。

## 报告来源与能力约束

管理员许可命令必须独立声明 `test_evidence` 和 `test_report`，采用 `command/text-v1`、可写的隔离工作树；工具 profile 固定 `suma-junit-report-v1` 和完整配置摘要，当前 Runner／执行池仍需满足已有派发要求。声明能力或探测成功只说明配置／执行入口，不说明测试已通过。带已发布计划的运行要求所有 test 节点具备此能力，至少一个 test，当前拒绝 map、子流程和外部工作流。

报告路径由 Runner 分配，位于当前 attempt 的源码目录旁；CLI 可使用受控环境变量或管理员 Args 字面占位符。Node／pytest 等成熟工具直接产出 XML，不需要为了路径拼接添加 shell 包装。原参数模板参与 profile 摘要，替换只发生于启动参数副本，远端任务不能注入文件路径。

读取发生在进程树确认完成后。普通单文件、目录身份、硬链接、读取前后状态及大小均受检查；解析使用 Go `encoding/xml` 的有界子集，不解析外部实体。不支持的格式明确失败，不通过宽松解析猜测厂商语义。已配置秘密的有限检测失败时保留本地原件而不把删改内容上传成原件。

真实 Node.js 22.16.0 原件确认了 `testsuites` 下直接放 `testcase`，以及 testcase 重复 failure 消息属性的布局。解析器允许该直接布局并沿用全局计数／去重；冗余 `failure` 属性必须与真实 failure 子元素的显式 message 解码后完全相等，不能单独决定状态。属性孤立、消息冲突、伪造 status 或与 error/skipped 混用时仍拒绝。这是已观察格式的明确扩展，不是放宽所有厂商结果。

真实 ExitCode、协议终态、结果未知、报告错误和逐例结果分别保存：退出码 0 可以同时有 failed/error 报告，非零退出也可以有可读报告。没有报告、skipped、unknown、重复匹配或未映射失败不能转化为 passed。聚合验证必须覆盖每个选中代码 head；存在未覆盖 head 或缺失工作树证明时不具备完整交付依据。

## 原件、投影与当前授权

报告 payload 保留原 XML 与原始 SHA-256，projection 保存无原 XML 的结构化事实；普通列表／执行摘要只返回报告引用和逐例结果。报告原文通过单独的当前项目授权接口按需读取，界面把它当作普通文本。内部当前 attempt 核对仍查询完整私有 `dag_attempts.result` JSON 并仅解工作树字段，故目前是响应与投影隔离，不是完全消除所有数据库 XML 读取。

历史事实、原操作回执和当前资格分开。撤权后不能读取原报告或恢复特权响应；恢复原操作保持当时 ID／版本／结果，并重新投影当前允许动作与依据状态。业务内容、XML、CLI 日志和模型文本保持原语言；受控界面状态和诊断使用中英文目录，不按原件内容猜译。

任务模型上下文只引用 `TaskTestPlanContext{revision,sha256,source_sha256,case_count,title}`。完整用例和原报告留在质量读取接口，不把最多 128 KiB 的用例正文自动注入每次模型调用；需要具体测试内容的使用方通过当前授权读取明确范围。

## 门禁与问题回流

Review 在正式事务内重核当前计划、任务／需求依据、运行、候选测试和逐例事实。passed 是自动化证据结论，人工 Review 是另一项有当前权限的决定。通用 API、Runner 或 Agent 都不能提交一个人工 passed 字段替代报告。

仅当前 failed/error 用例可明确确认创建问题；受保护用例关系保证去重，不能用可编辑 issues.data 冒充来源。任务交付摘要将该关系与原 IssueIntake 合并，原需求回流保留可追溯问题。关闭问题本身不改写失败报告；完整缺陷生命周期及独立手工／应用／发布测试管理仍需继续交付。

## 本阶段验证边界

定向检查针对解析约束、真实 Runner 进程／候选工作树采集、领域状态与权限、API 生成一致性及中英文交互。真实 HTTP／CLI fixture、浏览器体验和各环境结果只由本阶段验收记录给出；文档不预先声明通过。分布式数据库、真实第三方账户、厂商全部 JUnit 格式、跨平台安装、规模指标及生产验收不能由本机定向检查代替。

受信任管理员及 Runner 可以报告测试事实，但原 XML 与 SHA-256 不证明测试脚本质量、被攻陷 Runner 的诚实性、供应链可信或业务验收充分性。完整 Issue／TestCase 管理、手工测试、ApplicationRelease 测试仍属于平台原完整范围，不因本次自动化链路落地而完成。

发布与退役推进私有治理世代，保存草稿不推进；每次绑定运行固定当时世代（包括无发布计划）。无计划旧运行经历发布再退役后仍失效，不能借退役恢复旧验收资格；未来新运行固定退役后的当前策略。
