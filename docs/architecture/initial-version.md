# 1.0.0 初始化架构与开发约定

状态：当前实施基线；负责人：平台集成。关联全部需求1–22与P0–P7。[产品基线](../product/v1-baseline.md)、[完整计划](../delivery/implementation-plan.md)、[专项验证](../quality/initial-version-verification.md)。当前代码按全新安装设计，未完成能力继续明确列入计划。

## 单一当前实现

- Go产品版本由internal/buildinfo/version.go提供，Node工作区、Electron和Helm统一1.0.0；check:version防止漂移。API major、第三方协议、工作流和业务修订、attempt/fence及依赖版本各自独立。
- Service.Initialize及领域Initialize方法建立完整当前schema，删除旧入口别名。调度使用唯一dag_ready、资源accounts/ledger、当前依赖语义与固定运行路由；删除旧kernel分代、旧队列／资源镜像及数据回填。
- 身份从首次安装建立source/family/Grant/slot/issuance完整证明；移除migration_status和旧分类回填。无发行证明直接拒绝，初始化不能为既有会话制造授权。
- 设计采用与检索关系在同一批准事务落库，删除启动扫描历史采用记录的回填；缺失原记录明确失败，不能用新发布版本冒充原依据。
- 原生读取Agent沿用一份明确四工具权限清单，通用MCP／应用工具复用正式合同；合并重复allowlist，不扩大机器权限。
- Web删除不可达语言旧基线流程，保持全生产代码严格中文硬编码检查与成对语言键。知识revision只接收JSON正安全整数；不再将字符串别名强制转换为数值。

## 数据库初始化与正常恢复

suma_schema_baselines按组件记录声明，platform拥有suma_领域、DAG拥有dag_领域；共享声明表不算业务表。未声明且已有任一领域表时，任何DDL之前拒绝，不只检查某一锚点，因此部分旧初始化也不能被默认为当前结构。检测到领域表后再次读取声明，避免并发同版首启误拒。

声明先于幂等DDL，它不是就绪／验收标志；同版中断可继续建立当前结构。已声明版本不符仍拒绝，不自动升级、不清库、不重建业务事实。正常重启继续使用持久运行、原attempt/fence、资源账本、唤醒、原回执与证据，不猜测旧图或私有执行路由。旧安装数据仍留在原位置；使用单独空数据库验证和部署1.0.0。

## 必须保留的安全与功能

当前版本内的幂等、CAS、当前权限、租约、未知结果核对、重试窗口、删除墓碑和索引分代是正确性能力；第三方CLI／MCP／数据库驱动的实际协议处理是接入能力。它们不因移除历史兼容层而取消。正式测试、人工验收、部署和业务进度仍分别建模，不以初始化或源码清理代替验收。

## AI SOP

1. 先核实清理对象的生产调用和唯一替代路径，再确定模块归属；不按legacy名称批量删除安全逻辑。
2. 当前合同优先，移除无调用分支及镜像写入后同步所有消费者、公开Schema和双语键；不新增旧入口包装。
3. 仅运行受影响的授权／事务／调度／恢复检查，静态编译覆盖共享名称改动；默认不启动模型或厂商服务。
4. 当前文档作为入口，专项报告保留实际证据与未完成项；压缩重复阶段流水，不改写旧失败。
5. 阶段提交必要源码、合同、文档和精简证据，正常推送指定dev；缓存、数据、凭据、日志、截图和二进制不进入新提交。
