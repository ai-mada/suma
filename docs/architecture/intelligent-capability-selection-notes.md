# 任务执行工具选择：当前观测与固定派发

- 状态：T-P4-034限定本地已验证；HTTP、CLI、隔离实际界面与主预览保持证据见[阶段验证](../quality/task-dispatch-options-verification.md)。
- 负责人：控制面与执行工具集成。
- 关联合同：[任务工具选项](../../contracts/task-dispatch-options.md)。
- 实现：`internal/platform/task_dispatch_options.go`；既有固定预览与启动流程继续使用 `task_dispatch_build.go`、`task_dispatch.go`。

## 选择依据

`GetTaskDispatchOptions` 根据已保存的任务、指定流程版本和智能体节点，提供当前用户能够读取的工具选项。建议为当前页中按工具标识稳定排序的第一个可用选项。此顺序便于一致地选择与翻页，不代表质量、成本或速度最优。

同一当前权限读取事务内完成以下核验：

1. 重新解析当前凭证、项目权限、任务和受保护的设计及代码基线；任务版本必须与请求一致。
2. 读取指定版本的非托管流程，以及项目实际使用的私有节点或执行池路由。
3. 复用工具目录原有权限和投影，检查工具启用状态、执行节点当前凭证及有效观测。
4. 检查工具对应节点与实际路由是否匹配；复用正式预览的纯流程构建器，检查工具能力、节点、受保护基线、上下文大小、独立测试要求及 DAG 编译结果。

选项的 `reason_code` 只有 `eligible`、`tool_unavailable`、`route_incompatible`、`workflow_incompatible` 四种。界面使用稳定代码和本地化诊断展示原因，不能根据原始诊断文本推导状态。

## 读取结果与执行授权

结果保存观测时间、任务及流程版本、节点、任务上下文和实际执行路由。读取不生成运行或派发计划、不改变流程、不预留预算或执行槽位，也不调用模型或启动工具进程。工具目录的有效观测仍受原有新鲜度规则约束，不保证领取时资源空闲。

该接口的上下文不附加额外知识条目。用户确认完整选择后，必须进入既有正式预览，重新核验最终上下文、工具版本、路由、当前权限及完整工作流。启动继续使用固定计划及既有 CAS、幂等和执行门禁。选项结果不能替代预览或启动授权。

分页默认 50 项、最多 200 项。签名游标同时绑定当前用户、项目、任务标识及版本、流程标识及版本和节点；切换任务或修改工程依据后必须从第一页读取。工具目录继续使用原有当前权限读取逻辑，不能通过分页绕过授权。

## 模型、预算与资源边界

当前可写开发工具配置没有统一、可独立替换且可计价的模型合同，因此响应明确返回 `model_state=fixed_by_tool`、`cost_state=unknown`。已有模型计价能力主要适用于声明模型的只读原生规划、提取和诊断配置，不能直接用于为任意 CLI 开发任务计算成本。

本轮不根据工具名称推测模型，不把声明路由当成执行池授权，也不制造成本评分、模型推荐、健康检查、预算满足或节点空闲状态。后续如需跨模型选择，应先增加版本化模型能力、报价来源及有效期、可观测用量、配额和准确的执行工具映射，再接入正式预览和实际记账。

## 验证范围

针对性自动检查覆盖：读取不产生运行、计划或记账；任务版本冲突；真实目录分页及暂停后的变化；流程和路由不匹配；签名游标拒绝跨任务、流程、版本或节点复用。HTTP、CLI、真实执行链路和界面的验收结果另列阶段证据，不能由核心测试通过推断生产验收完成。
