## 所有权与唯一执行路径

## 封闭计划与信任边界

`IntelligentOperationOutput`只含schema_version、summary、rationale、questions和steps。最多8个步骤只允许 `requirement.create_draft`、`requirement.design.save_draft`、`knowledge.create_draft`，各自携带类型化payload；没有任意HTTP、命令、配置、批准、验收或自由data。依赖要求闭合与拓扑有效，设计目标只能来自选中正式需求或已依赖的前序新需求步骤，同一目标不能重复写入。

模型不指定可信身份、版本、SHA、权限或操作key。服务端读取当前主体／租户／项目、正式来源、目标版本和固定工具；preview展示所需权限、目标、依赖、影响及默认值来源。待补充问题未解决、零步骤或依据已变化时can_apply=false。缺失关键事实须明确补足，不把猜测变成已确认值。

上下文投影只取选定来源允许的标题、description与需求／任务验收条目，不传Record.Data、文档元数据、完整配置、环境或登录文件。有限预检查在提交模型前拒绝明显私钥、常见长API key／Token及URL凭证，不声称具备完整秘密分类；只能选择可发送正文。系统提示词不替代服务端边界。prompt及接收输出各最多32000 UTF-8字节，超限拒绝、不静默截断。模型／用户原文按实际接收事实保留，宿主标签与诊断使用成对zh-CN／en-US目录。

同一原生运行时增加显式purpose=`intelligent_operations`、protocol=`suma-intelligent-operations-v1`专用能力，固定模型与地址，max_steps=1、一次调用、MaxRetries=0、输出上限1–8192Token默认4096，无控制面或工作区工具。成熟provider端口、官方SDK及既有计价／预算边界继续复用，不引入另一套代理运行时。探测成功、配置可用、模型成功和业务提案有效分别记录。

## 同库草稿的真实事务

当前三个动作全部是同一数据库内、无外部副作用的草稿写入。apply在同一个当前授权SQL事务内重核完整来源、提案、预览SHA、`suma-local-drafts-v1`策略与目标版本，并调用现有需求创建、设计保存及知识创建事务helper。前序新需求的真实ID在事务内解析为后序设计目标；任何领域校验、版本CAS或回执写入失败，全部回滚。

业务草稿、不可变修订、领域活动／事件、真实步骤Results、分析版本及原操作回执一起提交。因此本阶段无需partial步骤状态，也不能把失败后猜测出的对象当作采用结果。preview只读，不预留资源。模型调用在事务外，apply不调用模型或外部服务。

预览SHA覆盖分析版本、完整来源／提案、全部现有目标版本及固定策略；确认只对本次已审阅预览有效。编辑后清除预览和确认，采用前再次核验当前权限与依据。固定策略只允许本地草稿，不是持久项目自动批准。发布、正式任务采用、运行、团队治理、扩大权限、生产部署、删除和外发继续服从现有各领域批准边界。

Results固定每步真实资源ID、版本／修订／摘要以及source／proposal／原模型SHA与run_id，和后续目标编辑分开。applied只证明草稿写入，不证明需求批准、开发、测试或人工验收完成。统一计划来源关系不冒充独立knowledge_intelligence分析的model_adoption。

## 恢复与外部效果扩展

分析状态为running／ready／failed／reconciling／applied／dismissed。运行成功、输出非法和结果未知分别保存；不能因解析失败自动重调模型。当前来源变化允许展示原件，但不能采用旧依据。running取消沿已有run commands，dismiss不替代停止或核对。

网络超时保留原主体、项目、method／path、body、预期版本和操作key；当前授权先于原成功回执，恢复同一操作与真实ID后再读当前分析／对象。不能因403／409换key盲目重跑，也不能把历史保存版本作为下一次CAS。用量和费用未知不记零。

未来加入文件、配置连接、提供方、消息或部署时，外部效果不属于这个同库事务。此类计划必须在既有唯一DAG与领域operation下逐步保存已发生事实、未知与核对状态；后续失败不能抹除先前外部效果，也不能承诺全局原子回滚。只有瞬时且幂等失败可有界退避，同类智能修复三轮失败转阻塞，沿现有SOP保留诊断和尝试。这是后续扩展规则，不表示本阶段已支持外部动作。

## 配置领域与成熟框架

统一配置视图仍需管理模板、实例、秘密引用、验证观察和变更计划。`ConfigTemplate`、`ConfigInstance`、`SecretReference`、`ConfigValidationRun`、`ConfigChangeSet`是待实现职责，不是本阶段新增的五套服务或表。工具、模型、执行池、存储等原有领域继续拥有正式配置，共享视图引用其版本、差异及实际结果。

表单与高级JSON／YAML应使用同一服务端合同和校验，优先复用Go类型／生成Schema、现有React／Radix控件、官方模型／工具SDK和当前CLI。来源中的Pydantic、Rich／Typer只是示例，不替换Go／Bubble Tea，不为统一输入再引入运行时。秘密只使用受控引用；模型上下文、预览与日志不得出现明文秘密。

未来配置采用遵循：明确范围 → 提案／补全 → Schema及领域校验 → 差异／影响预览 → 当前权限及必要批准 → 原操作采用 → 实际连接／目标核对 → 保存结果。已保存、连接探测、目标健康与业务可用分别记录；回退是有当前权限的新变更，不把不可逆副作用包装成自动撤销。

## 本阶段验收SOP

1. 固定T-INTENT-114源码、独立新库、实际工具profile／模型地址及预算，确认活动预览、原库和原始数据保持；只用任务自己的忽略目录保存运行材料，不重复未变能力的完整验证。
2. 通过真实HTTP创建一次分析，记录原operation及真实run／attempt／fence；确认一个专用只读模型调用、无工作区／项目工具，真实用量保留。自有协议端点与厂商账号证据分别标注。
3. 提交“新需求 → 该需求设计＋知识草稿”代表性目标，核对实际结构化原件、可编辑proposal、待补充问题、依赖、默认值来源及只读预览。生成和预览阶段不得出现业务草稿。
4. 明确确认同一preview_sha256并采用，通过领域API／数据库核对三类真实草稿、设计关联的新需求ID、不可变修订、Results、来源SHA、活动及回执。发布指针、正式任务、运行和批准事实不能由此凭空出现。
5. 在后序步骤制造领域校验／目标版本冲突，证明前序草稿、修订、分析状态和原回执一起回滚；重复原key同正文恢复原IDs，变更正文的同key冲突。响应丢失先恢复原操作，不重新调用模型。
6. 定向验证浏览器及项目API的当前授权、撤权／错误租户项目、Agent／Runner越界、伪造批准／权限／HTTP字段、来源变化、重复设计目标、非法依赖／来源索引、超限、可识别秘密及问题未解决均被阻止；失败不能伪造ready／applied。
7. 验证当前中英代表性交互、加载／空态／缺工具、修订清除旧预览和确认、失败保留草稿、断线恢复及结果链接；实际浏览器受阻则明确记录未验证，不能用API或目录键数代替。
8. 更新一份精简[报告](../quality/intelligent-operations-verification.md)及[摘要](../quality/intelligent-operations-summary.json)，仅记录实际检查／环境／数量和剩余范围。状态台账保持58项限定实现／34待办／92总计，FND-INTENT-001继续未勾选。

完整需求26仍需逐项证明全场景结构化参数、当前授权及提示词越权拒绝、原操作幂等、外部失败／未知恢复、重要变更预览与批准审计、中英文、真实用量／结果，以及Web／CLI／桌面共用领域API的完整旅程。当前草稿闭环和已有验收追踪均不完成完整测试／应用版本生命周期或生产验收。
