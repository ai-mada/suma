# Claude Code CLI 执行模块

状态：1.0.0 已实现固定前台执行合同；真实供应方与生产验收待完成。负责人：平台执行域。关联需求：多工具统一连接、固定模型、任务派发、代码候选与独立质量门禁。合同见 [claude-cli](../../contracts/claude-cli.md)，安装与配置见[接入指南](../integrations/claude-cli.md)。

## 模块边界

工具目录使用 `claude-code-cli`，与作为 MCP 客户端的 Claude、尚未实现的 SDK 适配器分别记录。桌面和命令行复用同一 Go Runner；发现和登记不创建第二条执行路径。

```mermaid
flowchart LR
  A[管理员固定 CLI 配置] --> B[实际可执行版本和帮助探测]
  B --> C[原工具库存与暂停登记]
  C --> D[当前权限明确启用]
  D --> E[原任务预览及固定配置摘要]
  E --> F[私有或 Pool 正式领取]
  F --> G[独立 Git 工作树与前台进程]
  G --> H[关联会话及模型结果]
  H --> I[真实提交候选]
  I --> J[同一候选独立测试]
  J --> K[原人工验收与问题回流]
```

控制面负责当前组织／项目权限、工具启用权、库存、固定模型、两级预算策略、任务和流程版本。Runner 在创建工作树之前核对原 `claude_execution`；精确模型、参数、环境和可执行摘要进入现有 Profile。配置漂移要求新预览，旧操作不能替换权限或模型。

公开事实 `ClaudeExecutionCapability` 与 `ClaudeExecutionEvidence` 从 Go 类型生成到 TypeScript 和 OpenAPI。浏览器只读取配置和关联结果，不接受可执行路径、认证文件、任意参数或权限回复。CLI 当前原登录留在本机，平台凭据不传给子进程。

## 执行和失败语义

仅审阅过的固定前台 CLI 版本及参数可运行；帮助探测必须确认参数实际存在。`restricted`、`safe-mode`、明确空 MCP 配置和文件目录保护限制定制能力；管理策略仍有优先权，Bash 的操作系统隔离不由文件开关保证。目录保护、有限 Git 操作及管理员宿主信任边界在合同中明确。

JSONL 解码器独立于其他 CLI 协议，保留主会话、请求模型、模型确认、工具调用闭合、权限拒绝和唯一整体结果。EOF、进程退出零、助手成功文本、子工具成功都不能单独完成运行。未知副作用继续原 Journal 核对，不自动重新发起模型工作。

成功开发结果仍须存在从固定基线产生的真实 Git 提交。用户原脏目录保持独立；工作树修改本身不构成候选。后续 command／JUnit 测试固定候选提交，外部智能体不得代替独立测试或人工验收。

## 预算与部署

本阶段采用管理员固定完整模型标识，尚未提供逐任务动态选择模型。CLI 返回的使用量最多为部分观测：未知值不填零，辅助调用不冒充完整账单；组织或项目任一级强制预算都会在预览、启动、领取及资源预留时拒绝该能力。原生模型网关的硬额度保持独立。

浏览器、桌面、私有 Worker 和共享 Pool 复用相同权限与执行合同。本机 Windows 协议夹具验证了真实子进程、独立工作树、同提交 Node 测试及取消；这不代表厂商 CLI、跨平台安装、物理分布式或生产已验。验证范围由[阶段报告](../quality/claude-cli-verification.md)单独记录。
