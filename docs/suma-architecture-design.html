3.4 关键设计边界

  • 控制面 / Runner 分离：控制面拥有业务与执行状态；Runner 仅证明已授权执行事实并保留可重传回执。
  • 事务内零副作用：事务内不执行模型、工具、网络请求或长时任务。
  • 检索库是可重建投影：Lance / 索引投影不能批准业务动作。
  • 事件至少一次：业务效果靠操作回执、版本、幂等与结果核对。
  • 浏览器端不持有：数据库、模型或存储主密钥。

5.4 状态机

Run（执行态）
pending → ready → running → waiting / reconciling → succeeded / failed / skipped / cancelled
这是执行状态集合，不是每次必经顺序；任务业务接受独立，人审不能由运行成功代替。
Run
created → claimed → executing → (completed | failed | stopped)
候选由 Run 产出；独立测试与验收是后续独立事实。
Defect（缺陷）
opened → triaged → assigned → fixing → verifying → (closed | reopened | escalated)
按严重度挂 SLA；重复自动合并；无法修复可回流需求池。
Release
draft → candidate → tested → approved → released → (stable | rolled-back)
集合不可变；回滚生成新指针，不篡改历史。
