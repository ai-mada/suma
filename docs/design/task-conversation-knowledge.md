# 资料选择、历史展开与 AI SOP

T-CONTEXT-145 冻结交互设计；实际界面观察与模型证据另记。[领域合同](../../contracts/task-conversation-knowledge.md)约束输入、权限与来源，本页说明用户如何明确选择和恢复。

## 原讨论内的渐进交互

保持原正文输入与发送动作，“添加资料”默认折叠。展开后才读取当前有权的项目知识，以有界搜索和分页选择已发布项，不自动推荐后直接勾选。选择不会保存消息、发布知识或启动模型。

已选项按准确 ID 单独水合，显示所选修订和当前可用状态。新草稿与原发布分别表达；资料后来退役、变更或不可读时保留原 pin 并提示移除或重新选择，不能自动升级到最新修订。最多 16 项，输入资料正文或手工改标题不能绕过服务端批准快照。

消息仅展示发表时标题、类型与修订。点击原引用才读取准确历史正文，保留原文与摘要层次；不在消息列表预取全部正文。读取失败提供原地重试，不以当前 latest 替代。历史可读的提示不能使用“可用于模型”等资格表述。

assistant 消息使用服务端从真实 backing Reply 派生的同一批引用。回复配置和开发预览展示冻结来源，用户不能在这些展示区悄悄换 pin；需要新依据时回到讨论明确选择并发送。

## 草稿、迟到响应与未知写入

草稿只保存原正文、提及人员 ID 和准确知识 pin，不持久化资料全文或模型凭据。账户、组织、项目或任务切换立即隐藏旧响应并取消旧读取；迟到响应不能覆盖新范围。401／403 或当前项目读取权限失效时清除受保护的展开内容，未发送 pin 可作为失效选择显示。仅发布资格失效不把仍有权读取的准确历史改成不可见。

明确区分“未发送草稿”“正在提交”“结果未知”和“原回执已恢复”。未知写保留原调用者、范围、任务版本、操作 ID 及原 JSON；恢复不追加当前新字段，不重新选择当前发布版本。原操作仍不确定时沿既有写恢复流程核对，不另发一次。

语言、主题、窄屏、键盘选择和展开后焦点沿现有组件；中英文标签成对，用户正文、原引用、修订与摘要保持原样。收起、移除和返回任务详情应保留原未保存保护。

## AI SOP

| 步骤 | 明确动作与核验 | 可记录的事实 |
| --- | --- | --- |
| 准备资料 | 沿原项目知识流程审阅并发布；保留正式来源版本与摘要 | 已批准文本及当前发布资格，不是模型已读取 |
| 发表依据 | 人／用户 API 选择准确 pins 并保存讨论 | 已提交消息、固定引用及原回执，不是已发模型请求 |
| 请求回复 | 选择 1–20 条近期消息、模型、输出参数、Token／费用预算并授权 | 原完整 Source、覆盖范围、知识快照和 SHA |
| 执行核验 | 沿原提交、claim／heartbeat 和发表边界重核当前资格 | 原运行、用量、输出与发表状态分别保留 |
| 审阅转开发 | 审阅真实 protected 回复；编辑目标及验收补充，选择新的工具／模型／预算 | 原预览和知识 refs，不是任务已执行 |
| 明确 Start | 原派发器重核来源与当前资格后绑定运行 | 原 DAG 事实；候选、独立测试、正式 Review 仍逐项完成 |

项目资料是待理解的业务数据。资料中要求更换模型、执行命令、扩权、跳过测试或自行批准的文字不获得执行效力；工具、预算、权限和质量仍由原控制面决定。skill 是批准的文字工作说明，不安装或运行插件。

来源上下文最多 32,000 字节，最终请求最多 64,000 字节，近期引用并集最多 16 项。超限时让用户减少消息范围或调整明确引用，不静默删正文、摘掉依赖或声称已完成摘要。资料正文被固定到 Source 也不等于提供方已经收到或理解；实际请求、用量与结果仍需原证据。

## 必要验证场景

以下是待对照实现和实际证据的验收要求，不是本页声称已经通过的结果：

- 无引用旧消息形状、同原请求回执恢复，以及消息／引用／活动／回执任一步失败的原子回滚。
- 新草稿不影响原发布；退役、重新发布、正式来源变化、摘要损坏与当前撤权阻止新的消费，准确历史不跳 latest。
- 人类原引用超出窗口、仅 assistant 留在窗口时仍有依赖；伪造 backing Reply／受保护关系被拒绝。
- 同 pin 去重、冲突 pin 拒绝、16 项及 32,000／64,000 字节边界；引用进入真实固定请求和原开发 Start 通道。
- 账号／项目／任务切换、迟到读取、展开内容失权清除、未知写原 JSON 恢复，以及中英／明暗／窄屏／键盘与焦点。

通用二进制附件、OCR、真实厂商调用、安装、多机和生产验收不因本阶段的协议或组件检查而记为完成。参考行为及许可证采用方式见[架构来源表](../architecture/task-conversation-knowledge.md#参考来源与采用边界)。
