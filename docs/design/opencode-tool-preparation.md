# OpenCode SDK 准备交互

状态：本阶段限定验证；版本1.0.0；需求T-OPENCODE-PREPARATION-207；负责人：Web与主集成。关联[产品验收](../product/opencode-tool-preparation.md)、[闭合合同](../../contracts/opencode-tool-preparation.md)及[实际验证](../quality/opencode-tool-preparation-verification.md)。

原“添加工具 → OpenCode SDK → 配置”进入同一指南。供应方、固定模型、服务地址和凭据变量名称在前；“机器与新配置文件”默认折叠，容纳目标Shell、新文件、Node、原生OpenCode和审核manifest。没有默认机器路径或模型，不从本机浏览器推断远程机器。

未完整时展示原因提示，复制与继续不可用。有效时展示准确准备命令，可按需审阅九字段JSON。复制只写剪贴板，单独的“使用此配置继续”沿原调用者／选择nonce把三个公开字段交给原远程指南，不携带私有机器配置或授予执行权限。已有配置调整仍由原高级配置和正式换新管理，不用快捷路径自动改写。

生成只包含一个OpenCode命令，检查数组为空；页面明确“无检查”不表示独立测试已通过。命令在目标机器静态核验完整审核资源后只创建新文件；文件准备、实际库存、paused登记、明确启用和任务／质量分别显示。

复制异步操作绑定当前输入修订与组件生命周期；编辑或卸载后，迟到成功／失败不能标记新的草稿。disabled同时保护编辑、复制和继续。中文、英文沿原i18next目录；44px控件与键盘焦点、窄屏单列和深浅主题复用原令牌。代码与命令长行在局部容器换行／滚动，不撑开整页。

当前证据覆盖两个代表宽度和主题、原准确节点／协议／路径交接，以及生产页面生成命令在真实PowerShell／Go CLI中的新文件效果。GUI实际没有使用系统剪贴板；复制按钮由定向组件检查覆盖，不能混称实际系统剪贴板旅程。
