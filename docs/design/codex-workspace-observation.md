# Codex 当前执行工作区读取

状态：T-WORKSPACE-103，1.0.0 当前实现。工作台沿用已批准的执行工作区面板；不增加路由或向导。控制面和 Runner 的协议及授权以[观察合同](../../contracts/workspace-observation.md)和[传输能力合同](../../contracts/workspace-transport-capabilities.md)为准。[English](../en/codex-workspace-observation.md)。

## 用户流程

在开发工作区选择“执行工作区”，刷新并选择当前有权读取的原生或 Codex 执行尝试，然后浏览目录和有界文本。执行记录链接保持原 run、node 和 attempt。当前目标关闭、授权失效、读取到期或 scope 改变时，旧正文不继续展示；本地工作区不会代替远程结果。

面板使用服务端返回的准确 scope 和 `can_write`。Codex 目标只读，不挂载可保存的编辑面板，不发起保存。原生目标也只有 `can_write=true` 才显示编辑入口；仅有账户写权限不代表所选目标可写。工具档案 ID 和可选执行池 ID 直接来自当前目标；缺少执行池时呈现项目执行器，不猜测工具厂商、提供方健康或宿主连接状态。

各次目录／正文读取可以看到不同时间的文件状态。文件摘要对应该次读取的原文件字节；分页正文不是完整文件或全工作区一致快照，也不是测试、任务验收或部署证据。

## 编辑状态边界

编辑入口、异步完整文件校验结束和组件挂载均核对当前 API 身份、准确 scope 和写资格。原生编辑器按 scope 与原观察 ID 固定身份。编辑期间，目标选择和目标刷新同时在控件与动作处理处阻止切换，保留未保存草稿、已提交正文及原操作 ID；用户明确关闭编辑器后才可选择另一个目标。迟到的原生读取不能打开 Codex 编辑器。

原生保存继续使用现有完整 UTF-8 文本基线、CAS 与原操作回执恢复；此变更不改变写合同。原生草稿不会成为 Codex 的编辑基线，原保存也不会重定向到新目标。已提交保存的历史回执仍通过现有“最近保存”入口读取。

## 库存导入

导入器使用当前生成的 `ToolObservation` 和 `ToolExecutionProfile` 字段名单。只有 `available=true`、`adapter=codex`、`protocol=codex-app-server-v1`、`read_only=false` 且带有效封闭公开目录的 Codex 观察，才可声明 `workspace_observation_protocol=workspace-observation-v1`。工具的编码用途和工作台的文件只读权限是独立事实。

Codex 不能声明 `workspace-write-v1` 或原生工作区／模型执行／冲突修复 MCP 能力。普通 CLI、错误协议、不可用观察、缺少或非法目录继续拒绝传输声明。导入只是提供待批准配置，当前资格仍由经过认证的 Runner 库存和服务端授权判定；不据此制造连接健康、提供方身份或成功任务。

## 验证范围

针对性前端检查覆盖 Codex 只读目标、准确 list/read、原生切换后的旧响应、草稿与待确认原保存隔离、库存只读声明／拒绝写入及中英切换。原有编辑器恢复测试继续覆盖原 key／正文、较新草稿和显式核对。证据位于项目忽略目录 `.cache/e2e/codex-workspace-103/ui/`；结果由本阶段集成报告记录。
