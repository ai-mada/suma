T-MULTICA-FOLLOW-154，速码1.0.0。状态：限定交互已通过Windows Electron软件离屏／独立SQLite的代表性真实验证。以[本人关注合同](../../contracts/task-subscriptions.md)为准；完整矩阵与平台验收保持独立。

## 一个明确的关注按钮

在当前任务的讨论入口旁放置一个Lucide Bell按钮，沿用现有字体、间距、边框和主题色，不增加一级导航、关注者目录或配置面板。按钮只管理当前本人：viewer可用，业务写权限不能成为个人偏好的额外门槛。

| 状态 | 中文／English | 行为 |
| --- | --- | --- |
| 读取中／尚未读取成功 | 读取关注状态／Loading follow status | 禁用切换；不将未知画成未关注 |
| 已确认未关注 | 关注任务／Follow task | aria-pressed=false；点击发送明确follow |
| 已确认关注 | 已关注／Following | aria-pressed=true；点击发送明确unfollow |
| 提交中 | 保存中／Saving | 同步阻止再次点击；状态以回执确认 |
| 结果未知 | 待核对原操作／Original operation unconfirmed | 锁住切换，沿原WriteNotice提供核对 |
| 读取失败／冲突 | 就近显示读取失败或版本变化 | 明确重读；不自动重发变更 |

Bell图形为辅助，按钮文字和aria-pressed表达已确认状态；可访问名称包含当前状态与下一步动作。加载、错误与未知状态不能宣布“已关注”或“已取消”。成功后保留按钮焦点，以简短状态提示告知结果；若后续当前读取失败，区分“原操作已确认”和“当前状态读取失败”。

默认不弹确认框。需要解释时用一行“接收此后新讨论，可随时取消／Receive new discussions from now on; unfollow at any time”。不增加频率、通道、团队或全员选项，不在挂载、切换语言、重连或打开讨论时自动关注。

## 原操作、版本与页面切换

复用现有useWriteAction和未确认写入保护。发送前持久化当前caller、user／组织／项目／任务、expected_version、明确action及原body／key，存储失败不外发。一次点击确定一个方向，不从迟到结果重新推断toggle。

结果未知时只允许核对原操作，不能换key、换版本或通过再次点击发送反向动作。刷新、GET返回目标following值、其他窗口更改状态都不能替代原回执。回执确认后另读当前偏好；旧回执不覆盖更高版本的当前状态。

版本冲突显示状态已改变，保留错误原因并提供明确重读；重读只观察，用户再次点击才建立新操作。离开页面沿原保护处理待核对命令，不静默丢弃。用户／组织／项目／任务或API caller变化立即退休旧请求和响应；401／403／404清除受保护偏好和来源，不能用上一身份的结果恢复按钮。

## 现有收件箱中的准确消息

task_followed沿现有列表显示“已关注任务有新讨论／New discussion from a followed task”，使用当前授权读取的任务标题与正式通知时间。列表不复制或预览历史正文，不为关注增加第二个通知中心。

“打开讨论／Open discussion”复用原定位：`panel=workbench-task:<task_id>`、`conversation_message=<message_id>`。直接读取准确消息，按需打开讨论、滚动并聚焦高亮；已在当前窗口中不复制一条，页外消息不靠不断加载全部历史定位。代码编辑器与讨论草稿保留，导航继续原未保存保护。

打开与标为已读是两个明确动作。取消关注后旧通知仍能定位；来源缺失或损坏则显示“来源不可用／Source unavailable”，不显示任务链接或正文。当前失权清除受保护内容。提及同一人的同源消息只显示原精准提及通知，不叠加关注提醒。

中英成对词条，任务标题、姓名与消息原文保持原值。按钮支持Tab、Enter和Space，可见焦点不被裁切；状态提示沿现有可访问状态区域，错误可被屏幕阅读器读取，不以颜色单独区分状态。

## AI SOP与维护

AI可以解释当前偏好、通知来源及恢复步骤；不得从任务负责人、用户历史行为或模型建议推断授权并替人关注。关注偏好只改变本人未来讨论通知，不授予发帖、模型调用、执行、调度或正式Review权。

assistant只有经原执行事实确认并最终保存的回复才成为通知来源；流式片段和工具日志不能发送关注通知。通知也不能证明开发、测试、验收或发布成功。
