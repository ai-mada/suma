# Suma 协作工作台

采用已确认的紧凑协作工作台方向：固定项目侧栏、单层页面导航、页面内子视图、一个右侧记录详情。390px 窄屏使用可关闭导航与全宽详情，表格只在自身区域横向滚动。浅色与深色共享语义变量，键盘焦点可见；全局搜索使用 Ctrl/Cmd+K，模态框使用 Radix 焦点管理。

项目、页面、子视图、记录和运行保存在 URL 查询参数。登录使用同源 HttpOnly 会话；密码和 Runner 令牌不写入浏览器存储。主题是唯一写入 localStorage 的偏好。所有实体读写使用 `/api/v1`，无演示数据与假成功。

需求支持创建、修改、验收标准与人工编辑的拆分草稿。选择草稿后调用原子拆分接口。任务支持列表/看板、负责人、需求关联、依赖、状态和独立评审命令。详情不会用通用状态编辑绕过已验收门禁。成员明确区分人类、Agent 和工具。

质量区提供问题、测试记录和证据记录，问题可调用 intake 命令创建保留来源的需求；运维区提供版本记录和服务端能力声明。手工测试登记不会被当成自动执行证明，任务验收仍要求真实 test 节点成功。文档支持 Markdown 源文保存，知识检索保留来源、版本和定位。

接入令牌绑定当前项目，管理员可选择 Runner、Agent 工具或 API 范围。Runner 与 Agent 的接口范围分别说明，表单默认 Runner；结果使用实际响应的 scope、project_id 与到期时间。令牌值仅保存在当前页面内存中，复制失败有反馈。创建请求保持固定操作标识；网络或 5xx 导致结果未知时停止重复提交，在 sessionStorage 中仅记录非密钥的原操作标识、备注与范围。当前服务端尚无令牌创建回执恢复接口，页面明确要求管理员核实，不把未知结果当作创建失败后自动另建。

能力界面分别展示 configured / available / verified。文件工作空间读取真实文件清单，Monaco 与语言 Worker 均从本地构建产物加载。保存携带文件摘要；冲突时保留草稿并读取最新内容。保存期间继续输入会保留新草稿，只更新服务端已保存内容与摘要，下一次保存基于新摘要。网络未知时恢复原文件内容、摘要与幂等身份，不把当前较新草稿代入旧操作。服务端准备写入日志需要恢复时使用独立提示，保留原操作，禁止普通冲突合并绕过该状态。未保存文件阻止页面切换，刷新/关闭触发浏览器草稿提示。未绑定或缺少接口时明确显示原因，目录绑定仍由服务端权限和允许根控制。版本记录不会被描述为部署成功；外部 Agent/工具可用性以服务端事实为准。

通用实体写入对同一次失败操作复用幂等身份。错误保留表单，版本冲突刷新实体版本供用户核对。请求最长等待 30 秒；成功状态下回执解析失败仍归为结果未知，保留原幂等身份。创建项目、记录、拆分、评审、发布、启动及运行命令在结果未知时冻结原请求内容，并提供同一操作恢复；恢复前阻止页面切换与关闭表单。执行命令与工作流发布由服务端校验，网络未知结果不会被渲染为成功。

任务依赖以实际项目任务名称和状态供选择；URL 保留搜索、筛选、看板/列表状态及记录定位，直达记录不在列表窗口内时单独读取详情。单个项目切换会重置页面实例，搜索结果按项目清空，避免残留上一个项目内容。顶栏需求/任务数量和概览均读取真实 overview 响应，成功写入后刷新；未读取到时不显示假数量。

业务记录列表使用服务端 keyset 分页，每次显式读取 100 条。首屏只读取一页，“加载更多”使用 next_cursor 追加并按 ID 去重，保留响应中的完整 SQL total。项目或实体类型切换重置窗口与游标，旧上下文的在途响应不会覆盖新项目。下一页或刷新失败均保留当前窗口，并允许重试同一读取。列表、看板、状态筛选与搜索明确标注仅覆盖已加载范围；本地筛选命中数不会被当成整个项目的精确统计。不会自动把所有页面读入内存。负责人、需求及依赖选择器保留窗口外的当前关联 ID，占位说明未在已加载范围，并提供显式更多选项。运行列表与工作流历史也只读取每页 100 条摘要，显示已加载数和 SQL 总数；节点在打开运行详情时单独读取。任务评审单独读取当前关联运行，使窗口外的有效依据仍可选择。概览运行计数只使用 counts.runs，不用最新运行摘要长度推导总数。

根与延迟页面各有错误边界。旧标签页缺少延迟资源时会显示可手动恢复页面，保留当前 URL，不自动刷新或重新提交操作。默认构建保留旧摘要资源，具体版本目录、资源追加和回收窗口见 `apps/web/README.md`。错误边界不承诺恢复尚未保存到服务端的内存草稿。

本次源码检查已通过 TypeScript 与 29 项合同测试（记录扩展字段和数组、真实 DAG 边、依赖编辑和环路拒绝、渲染失败的显式恢复、同源 Cookie、未知/截断回执与超时后的原请求恢复、项目范围令牌与丢失回执后停止重复创建、真实审批与补偿入口依据、分页追加/去重/失败保留/项目隔离、窗口外关联保留、保存期间输入及日志恢复、深链初始化、运行摘要与当前关联运行独立读取）。Vite 生产构建包含本地 Monaco 语言 Worker；IDE 与工作流按页面延迟加载。大型编辑器/布局包仍会触发构建体积提示。浏览器交互与生产集成验收由总交付记录单独说明，本文不替代该证据。

## 应用目录与固定代码版本

T-APPLICATION-123 的交互入口位于项目概览中的“应用与依赖 / Applications & dependencies”。沿用现有七个主导航，不再添加应用工作台。正式领域和完整后续范围见[应用协同产品基线](../product/application-delivery.md)。主要实现为 [ProjectApplications](../../apps/web/src/ProjectApplications.tsx)、[只读图表](../../apps/web/src/ProjectApplicationGraph.tsx)及同域中英文目录；本文说明当前交互，实际浏览器与环境验收由对应交付报告记录。

默认显示紧凑目录。选中一个应用后打开唯一详情，常用信息是应用名称、责任团队、上级应用和授权代码范围；原始 ID、配置摘要、检查清单、来源收据及解析事实按需展开。应用、微应用、服务和类库共用此域。目录记录修订、被管理应用的代码版本标签和速码产品的 1.0.0 版本各有独立含义。

典型操作按以下顺序完成：

1. 从项目概览打开应用目录，选择“登记应用 / Register application”。选择当前可用责任团队，明确同项目父子关系及 1–8 个受控仓库相对代码范围。表单中 `.` 表示仓库根，正式请求使用空字符串，不接受绝对路径或向上越界。重叠范围须双方明确共享；共享不会自动扩大权限。
2. 在应用详情选择“登记代码版本 / Register code version”。每个代码范围选择一项真实已合入操作，填写独立版本标签和原因。用户不手工输入提交来代替合入证明。没有仓库目标或有效来源时，界面提供到项目任务的入口，沿现有任务验收与仓库合入流程补齐来源。
3. 选择“检查并预览 / Inspect and preview”，读取固定提交、代码树和受限清单，查看原始观察。需要校正时，在新版本草稿中选择精确目标应用、版本与摘要，并填写原因；原始观察不会被覆盖。约束隐藏、无效、解析器不支持和未验证的兼容性分别保留，候选名称匹配不会自动变为正式依赖。
4. 来源、标签、依赖或原因发生编辑后，旧预览和确认立即失效。只有服务端当前允许登记、人工核对并勾选确认后，才提交登记。`registered_preview_sha256` 绑定原先审阅的预览；登记后的 `snapshot_sha256` 描述含正式身份与时间的不可变版本，两者不互相冒充。
5. 从固定版本查看真实来源任务及运行，再沿原任务详情查看需求、测试与交付链路。登记代码版本不表示构建、独立测试、人工验收或生产部署成功。当前版本 DTO 没有需求快照字段，界面不从可变任务关系推造历史需求依据。

| --- | --- | --- |

| 原始观察／人工校正 | Original observations / Manual corrections | 解析事实与人工确定的版本依赖分开保存 |
| 固定目标为历史登记版本 | Pinned target is a historical registered version | 原依赖仍指向精确旧版，不静默跟随最新版本 |

## 依赖图、影响清单与读取范围

依赖图按需打开，复用 React Flow、ELK 和统一可访问性文案。节点显示各应用当前登记版本，边显示原本固定的目标版本；当前版本、历史版本、缺失版本、缺失应用及窗口外对象分别表达。循环是强连通应用组，不画成虚构的有序路径，也不把应用依赖图误作执行 DAG。

等价节点和关系清单始终可用，图表布局失败时仍可完成定位。变更影响分析绑定当前依赖图摘要，路径从所选应用向反向受影响应用展开，保留直接、传递、深度和真实版本。此处只有只读分析与深链，不创建任务、不派发执行、不批准交付；后续开发继续使用既有任务和唯一 Go 调度器。

此域目录与版本历史每页 20 条，使用服务端 `before` 游标显式翻页，并提供返回首页；不会自动拉取全项目。团队、目标、父应用和版本来源是有界选项快照，达到限制时明确提示不完整；版本选项只读取精确选择所需的 ID、标签、序号与摘要，不为选择器加载完整来源证据。正式版本详情按选中 ID 独立读取，URL 使用 `view=overview&layout=applications&panel=application:<id>&record=<version-id>`。

图表同样展示加载范围。`complete=false` 不等于零依赖；`edge_total_exact=false` 时边总数标为“至少 / At least”，不能把有界观察下界展示为全项目精确统计。未登记版本或未报告事实保持未知，不产生百分比、通过率或推算费用。

## 窄屏、键盘与异常恢复

390px 页面使用全宽详情，隐藏被选详情背后的目录，提供“应用列表 / Application list”返回入口。字段、来源事实和操作按钮按单列排列，长提交与摘要允许换行；窄屏依赖视图默认等价清单，用户可再打开图表。键盘可通过标准按钮、选择器及清单完成全部操作，不要求拖拽；编辑表单沿用 Radix 焦点管理和可见焦点。

定位应用与版本是一次原子导航；离开守卫拒绝时不改变部分 URL 字段。版本冲突保留原草稿，由用户显式读取新依据后再预览或保存。网络未知或响应与原预览不符时保留同一请求内容与操作身份，恢复按钮不会换成当前较新的草稿。成功创建后先移除编辑表单的离开守卫，再定位新应用，避免成功记录被自身草稿守卫拦住。

读取与写入均绑定账户、组织、项目及当前记录。切换上下文会中止旧读取并拒绝迟到结果；401／403 等访问失效清除受保护的应用、图表与影响事实。恢复原登记回执可确认历史版本已登记，同时重新展示今日源码、团队或治理资格已经变化；不得把恢复成功描述为当前交付资格仍有效。界面采用同域中英文目录，用户名称、代码路径、包名、日志及原始理由保留原文；未来语言扩展复用相同类型和目录边界。
