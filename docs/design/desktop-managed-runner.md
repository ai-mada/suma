# 本机连接交互与 AI SOP

T-MULTICA-DESKTOP-153。主目标是让用户选择工具后，以明确动作连接本机，再继续151已有登记及独立启用。参见[产品](../product/desktop-managed-runner.md)与[合同](../../contracts/desktop-managed-runner.md)。

## 信息层级

“本机连接”在选中支持的 adapter 后保持可达，包括已有旧身份但工具未上报的情况。初次需要连接时突出“连接本机”；已有新鲜可用配置时收起为次要区域，避免挤占主要登记流程。连接并登记后保留管理入口，可读取原状态或停止本机节点。

日常页面只显示连接阶段、仓库名称及下一步，不要求用户复制 secret、路径或命令。缺少工作区时读取当前项目绑定，复用 `DesktopWorkspacePicker` 明确选择和确认目录；不增加网页路径输入，不自动初始化 Git。

| 当前事实 | 呈现与操作 |
| --- | --- |
| 读取／连接处理中 | 显示实际阶段，阻止重复命令；不根据等待时间显示成功 |
| prepared／issuance_unknown | “恢复原连接”与“核对原连接”；原记录由本机保存 |
| starting | 等待本次启动后的新鲜报告；自动核对仅使用 status |
| connected | 刷新两类节点并选中准确 worker，继续登记暂停配置 |
| 当前访问被拒绝 | 明确提示恢复权限，隐藏连接启动；后续失败核对不能解锁旧操作 |
| stopped | 仅表示本机节点停止，原任务结果单独核对 |
| stop_unconfirmed | 原执行节点的停止尚未确认，可核对原连接。核对中给出状态反馈，原证据通过后才恢复手动连接入口。任务进度在运行详情查看 |
| 绑定／origin变化或凭据不可恢复 | 保留原记录与原因，不静默新建节点或替换 token |

中英文词条成对维护，沿现有颜色 tokens、可见键盘焦点和状态反馈。390px布局允许文案及操作自然换行；已有远程配置下的折叠入口保留明确展开标识。Windows软件离屏环境已实际检查中文1366、英文390的连接／暂停／启用状态并目视图片；DPAPI及正式 Go Worker链路也已限定通过，见[验证记录](../quality/desktop-managed-runner-verification.md)。首次 GUI 库存小数秒解析失败被保留，修复后沿同节点原操作续验。

## 可维护 AI SOP

1. 先读取当前会话、项目、具体 adapter 和原连接事实；安装检测只用于说明安装，不推断供应方登录、模型或执行资格。
2. 缺目录时引导用户通过原生选择器明确绑定真实 Git root，确认完整 HEAD 和已忽略的 `.cache`；不执行 git init、自动提交或修改忽略规则。
3. 仅在用户明确点击后连接。让本机组件保管凭据与原操作，AI及页面不读取、复制或补造 secret，也不生成替代启动命令。
4. 结果未知先核对原连接；恢复保持同一身份、项目、adapter、origin、绑定和操作。失权、过期、变化或不可恢复时停止后续写入，不换 ID 重试。
5. 真实 connected 后采用原新鲜库存，登记暂停档案，再独立确认启用；派发仍核验当前模型、预算、授权和原 Go DAG。
6. 停止后沿准确 run／node／attempt 核对任务结果及 outbox。强停未确认不标“已停止”，不通过删除 journal、日志或状态目录解除阻塞。

系统目录选择由 fixture 固定返回自有 Git root；生产目录签名和 Go 绑定实际执行，不将其称为真实OS选择器界面验收。24小时原 Grant 到期后的明确续权、原节点处置，以及真实供应方、强制崩溃恢复、macOS／Linux凭据存储、安装包、跨主机和生产流程继续待交付或待验；不得将这些目标写成当前已验能力。
