# Octop Harness 接入交互规范

状态：suma1.0.0／T-OCTOP-117。责任：工作台、设计系统和工具集成。关联：[架构](../architecture/octop-execution.md)、[合同](../../contracts/octop-harness-acp.md)、[验证](../quality/octop-execution-verification.md)。复用现有Field、details、工具页和模型事实卡设计令牌，不另建页面导航或设计系统。

## 用户路径与信息层次

组织与项目设置 → 执行工具 → 接入开发工具 → Octop Harness / ACP。常显固定提供方、模型和API地址；“执行环境与检查（必填）”集中绝对Python、zipapp、同目录manifest和固定检查；“凭据与执行参数”收起环境变量名及有限参数；“探测、注册与派发”收起后续操作说明。

全部必要字段有效后才生成可复制配置。空态保留明确待填说明；无真实密钥输入，不因复制、渲染或切换语言注册工具、探测端点或派发。运行路径只能由本机管理员核验，界面不假称可检查远端文件。复制反馈与当前配置内容绑定；复制失败不清空草稿。

## 固定配置与执行事实

当前工具、任务模型区、已保存计划、工作流节点和执行详情复用紧凑事实卡。常显固定模型、“仅配置确认”和“预算仅观测”；运行卡分别显示协议停止原因、Go进程停止及取消意图。会话、摘要、端点来源和版本放在折叠详情。

当前配置与原计划快照不混用。工具SHA变化时不展示旧节点为当前可用；原操作回执必须匹配原任务／计划、唯一agent生产节点、固定配置及工具摘要，异常时保留待核对操作。恢复、批准和重新派发沿既有流程，不新增自动授权按钮。

## 状态、语言与可访问性

未登记、不可用、缺能力、配置变化、运行中、已结束、已停止和待核对分别呈现；不会由ACP结束推导测试或验收成功。所有产品文字使用可扩展zh-CN／en-US域目录，机器码和用户内容保留原值。语言切换保留本地草稿。

使用原生label／input、select、button和details，支持键盘填写与展开。有限数字字段提供min／max／step，代码预览可聚焦、独立滚动，窄屏保持表单可用且页面不横向溢出。沿现有浅深主题和减少动效策略，无新强制动画。当前实际浏览器证据覆盖默认视口和390宽度，其他端及完整派发旅程仍分别验证。
