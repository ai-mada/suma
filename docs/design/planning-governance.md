# 组织治理与项目计划工作台

本轮更新：2026-10-24，持续实施。范围：浏览器工作台，延续现有紧凑布局、浅深色主题和本地设计令牌。12ui 设计规范已读取；遵循已确认的外部上传禁令，没有调用远程设计或上传项目材料。

## 入口与工作路径

开发协作新增“迭代”“项目计划”。项目计划通过任务时间线、里程碑、计划基线和团队容量四个视图完成实际编辑。设置新增“组织账号”“组织团队”“项目授权”，原成员名册改称“项目资源”。顶部组织入口读取真实组织列表，切换后重新读取会话；当前页面在内存中为各组织保留项目和子页面上下文，越权项目会改选可访问项目。

组织邀请在创建后只显示一次链接和令牌，均只保存在对话框内存。链接使用 `#invite=` 片段；接受页支持手动粘贴、明确确认、邮箱与密码证明，不读取查询参数中的令牌，不记录秘密，也不存入 localStorage。已有账号的密码用于证明身份，已有姓名和密码不会被此流程修改。创建回执重放没有秘密时，明确提示撤销后重新邀请。接受响应未知时，禁止自动重复使用一次性令牌，引导普通登录恢复会话。系统不会发送邮件。

人类项目资源必须绑定真实组织 `user_id`，可选项基于组织账号和项目授权；组织所有者、管理员的继承权限单独说明。缺少授权或尚未加入组织时，提供项目授权和组织邀请入口。Agent、工具使用真实项目资源 ID。团队的人类成员引用组织账号，Agent/工具成员引用其项目资源；团队归属不会产生项目授权。访问授权与团队成员的撤销记录保留版本，重新授予使用原版本。

组织角色修改、显式所有者转交和移除均检查当前版本及真实权限。管理员不能修改所有者或擅自授予所有者；转交动作先为目标账号授予所有者，旧所有者需要另行降级或退出，始终保留最后一名所有者。组织成员移除会撤销该组织的会话、项目授权和人类团队归属。项目授权与组织角色变更后，界面重新读取会话和可访问项目。

| 身份用途 | 实际引用 | 权限含义 |
| --- | --- | --- |
| 组织成员、团队human | 真实组织账号user_id | 团队归属单独存在，不增加项目权限 |
| 人类项目资源 | 项目资源ID绑定真实组织user_id | 绑定账号必须有项目访问；任务owner与容量引用此资源ID |
| 团队Agent/tool | project_id与同项目同种类的真实资源ID | 资源登记不证明模型或外部工具已接入 |
| 项目授权 | project_id与真实组织user_id | 显式授权与组织owner/admin的继承权限分别判断 |

## 计划的事实边界

任务交付完成只统计 `accepted`，不从执行成功或计划完成推断。摘要指标使用服务端项目全量汇总，卡片与时间线明确显示已加载任务范围。任务日期绘制真实起止区间；没有日期的任务保持未排期，不画虚构进度。每条图形均有日期文本、复选框和编辑按钮，键盘可完成相同操作。迭代、里程碑的完成请求由服务端检查全部关联任务验收。

排期表单按任务提交完整字段，并同时携带任务版本 `expected_task_version` 与独立计划版本 `expected_version`；批量操作要求原子成功。未知估算和容量保留 `null`，明确的零工时保留 `0`。每周容量以周一为起点；已排已知估算、未估算任务和未知容量分别显示，人工计划工时不作为机器执行配额。

日期使用有名称的原生表单控件，提交时读取实际显示值，避免日期控件与React合成事件不同步导致日期丢失。版本冲突重读只更新基准版本，保留日期及其他草稿；未知回执恢复保留首次完整请求。

每周已排估算来自已保存任务估算和日期，按“估算工时 × 本周与任务区间重合的日历日数 ÷ 任务区间日历日数”分配。区间包含起止日期，只有一个日期时按该日处理；缺少估算或起止均未知的任务另行提示。分摊包含周末，不读取人员工作制、节假日或请假，也不代表已投入或已消耗的实际工时。未知任务不能按零工时用于证明计划可行。

基线是显式捕获的不可变完整快照。列表读取元数据，选择后读取快照及服务端全量比较；快照和当前任务均支持按游标继续加载。范围新增、范围移除、任务定义、排期和真实验收状态分别比较。当前页未加载的任务不会被误标为已移出范围。

“全量”指当前项目的全部任务与计划，捕获不受前端已加载窗口限制。摘要统计来自服务端项目范围，coverage标明任务窗口；该能力尚未提供跨项目portfolio汇总，也未形成连续进度历史、风险管理和预测分析。

## 代码候选与测试依据

工作流测试节点增加“测试候选来源”，只列当前流程中合法的静态command/agent祖先。候选选项和发布信封使用同一份当前依赖图，移除旧依赖不会被旧depends_on重新带回。选择写入`node.config.candidate_from`，清空会删除该字段；高级JSON仍可编辑，非法来源会保留供修正，并由服务端拒绝发布。

每个测试只选择一个来源。调度器核对来源成功尝试的干净提交与工作树证据，并在本次测试attempt中固定commit、来源节点、来源attempt/fence和证据摘要。Runner需要管理员配置的本地repository和固定基准，候选提交必须已在本地且属于允许基准的历史；缺少条件时明确失败，不自动fetch、拼接多分支或推断跨map/子流程候选。完整的远端Git制品分发与多分支集成仍待实现。

运行节点显示当前测试尝试的candidate_pinned来源与固定提交；工作树证据另列管理员基准、候选来源、来源尝试/租约和摘要。实时输出是当前attempt/worker/fence确认的真实有界快照，不是完成比例。重试与补偿读取服务端运行固定定义的标记，不能从最新可编辑工作流推断。

许可写命令使用逐attempt隔离Git工作树，证据记录真实HEAD、差异/状态摘要及有界变更路径。审阅后的合并预检核对目标HEAD、候选HEAD、测试证据与审阅身份，只形成预检回执；实际合并执行与完整冲突恢复仍待实现。

## 恢复与可访问性

所有新治理、计划写入使用稳定操作标识。网络中断、超时和 5xx 后保留原路径、项目、请求字段和版本，恢复按钮重放同一操作；禁止在结果未知时导航或关闭对话框。409 保留草稿，读取当前版本后由用户再次提交；完成门禁等业务冲突不会被转成成功。无权限、读取失败、空范围和加载状态均明确展示。组织切换与邀请接受使用浏览器会话，访问控制由服务端最终核验。

工作台标签支持左右方向键、Home、End；按钮、选择器、日期、复选框与表单均为原生键盘控件，对话框使用现有 Radix 焦点管理。小屏下卡片、组织列表和比较区纵向排列，宽表可横向滚动，保留文本日期和操作入口。
