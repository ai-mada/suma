# 界面原始值的字面插入

状态：T-P4-013 已确认同类入口的实现、独立复核、完整网页门禁及实际图交互已有验证证据。以[冻结合同](../../contracts/ui-literal-values.md)、[平台显示身份](platform-display.md)和最终证据共同判定，不表示全部翻译入口或完整平台通过。

## 用户可见行为

节点、规则、资源、工具及环境的名称仍是用户原文。它们出现在节点辅助名称、上游选择、候选／构建选项、容量周说明、派发工具选项、固定规则依据及发布环境选项时，名称内的变量、目录键、`$t(...)`、替换元字符、引号或标签均逐字保留。真正属于平台模板的节点ID、类型、命令、日期、修订号、状态及后缀仍显示在正确位置。

Handle继续区分输入／目标与输出／来源，并保留同一节点的原始名称和ID。名称相同的节点仍可通过ID辨认。更换语言只改变用途和连接词，不能改写选项值、选择、原记录、工作流、授权、候选范围或命令正文。

## 封闭的静态显示接口

`i18n/literal.ts`只允许冻结合同中的八个名称模板及两个Handle模板。模块直接导入现有语言实例，调用端直接导入该模块，不经过i18n入口重导出。全局`tr`及i18next配置不变；该接口不能读取`display.tool.*`、原生诊断或任意服务器消息键，更不授予资格或来源身份。

每个键有唯一的必需参数名集合。TypeScript约束键与字符串参数；运行时再次检查批准键、普通对象、完整且无额外的自有数据字段及字符串类型。空归档／待处理后缀合法。日期、数字和状态仍由原调用端格式化；派发工具版本调用`formatNumber`后插入，其记录和请求中的整数版本不改变。

模块通过公开`getResource`读取当前语言的自有静态资源，确认模板是合法字符串、占位符集合完整且没有未知或损坏语法。随后仅扫描模板一次，由替换回调返回对应原始字符串。插入值不会再次经过扫描或翻译，也不会作为替换字符串解释`$&`等符号。React把结果当作普通文本或属性值处理，不使用HTML解析。

这不处理复数或富文本，不替代带完整规范原文证明的工具诊断渲染，不扩展到未经确认的所有字符串入口。标识符受编译器限制而不可达的三个候选、参数顺序负例及九个单参数对照保留为分析边界，不能宣称它们是已修漏洞。

## 失效、恢复与状态连续性

批准资源缺失、类型错误、占位符不兼容，或运行时参数形状错误时，不展示推测的平台说明；回退显示可安全取得的原始标量值。名称和ID不会因资源缺失而消失。Handle保持原有通用端点标签及原始名称／ID的回退形式。未批准的键不会触发任何资源读取。

模块不缓存结果、不发请求、不更新状态、不修改输入。资源恢复后，已存活组件可按当前资源重显；节点辅助名称不再依赖仅以locale为条件的旧结果缓存。相同节点、Handle、表单、选项值、草稿、焦点、选择和viewport保持原有身份，语言切换本身不引起读取或写入。

## 验证边界

原独立16项测试直接调用旧全局`tr`，作为未改变的历史API校准保留其RED，不能用alias或测试替身伪装迁移成功。新的定向门禁复用同八个名称／后续参数场景，在两语言下验证封闭接口的16项正向结果；编译时、运行时、空后缀、顺序、坏资源及恢复另测。

真实Workflow／ReactFlow／Handle、Candidate／Artifact及Capacity组件核对原文、辅助名称、选择值、焦点和草稿；精确AST门禁只约束批准的八个调用键，防止回到直接`t/tr`。它不扫描所有翻译，不证明全库或全部语言内容安全。完整网页测试、构建、独立代码复核与真实服务／浏览器交互分别验收，P0–P7范围继续保留。
