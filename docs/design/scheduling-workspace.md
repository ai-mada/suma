# 项目执行调度工作台

状态：T-P4-005 界面实现与前端消费者验证；真实后端、实际浏览器、运行包与阶段验收由主集成另行记录。日期：2026-10-24。负责人：UI 实现代理。依据：[调度内核合同](../../contracts/scheduling-kernel.md)、[调度内核](../scheduler/engine.md)、[工具工作台](tool-workspace.md)。

## 范围与事实分层

本轮实现当前项目的配置准入额度、持久策略预览与显式确认、真实就绪队列、节点当前条件、持久尝试历史及精确尝试深链。统一类型来自 `packages/contracts/src/index.ts`，不自行虚构资源池或调度 DTO。

资源表示管理员配置的准入上限，不代表 CPU／内存硬限制或实测负载。`execution_slots` 为并发槽位，每次 worker attempt 默认预留 1；累计预算单位为 `admission_units`，默认每次 worker attempt 消耗 1。审批／定时／内部汇合不作为收费尝试。降低上限不终止已有执行，不退还已有累计消耗；预算历史覆盖不完整单独显示。

默认槽位额度 1、策略版本 0／default=true 来自服务端。明确 0 阻止新领取，预算和其他资源的 null 表示不限制；未知字段不补成 0。界面拒绝负数、小数、指数写法及超过安全整数范围的输入。人员周容量继续位于项目计划，机器执行约束与人工计划工时独立。

当前公平范围仅为 `project_run_round_robin / project`。本轮没有跨租户公平、共享池或权重编辑控件，没有虚构硬件容量、队列名次、预计完成时间、Token 费用或完成百分比。

## 信息架构与交互

真实首屏审查后，当前策略采用紧凑摘要呈现并发槽位、累计执行额度、累计已用、版本与读取时间；资源表和调度方式放入默认收起的原生 details。桌面额度编辑前置且两主字段并排，窄屏改为纵向，其他资源约束可键盘展开。已知资源与单位统一使用中文名称，定制资源保留原标识；同一标签用于预览差异、节点请求和预留。实现与验收待办保留在设计／能力文档，不作为产品界面的说明清单。上限变化与累计消耗不退还在工作台保留一条明确提示，不重复堆叠。

| 入口 | 组件 | 用户行为与正式数据 |
|---|---|---|
| 项目设置 → 执行调度 | [SchedulingWorkspace](../../apps/web/src/SchedulingWorkspace.tsx) | 读取策略、准备草稿、生成固定预览、审阅差异和当时影响、单独确认 |
| 开发协作 → 执行记录 → 就绪队列 | [ExecutionWorkspace](../../apps/web/src/ExecutionWorkspace.tsx)、[SchedulingQueue](../../apps/web/src/SchedulingQueue.tsx) | 分页读取正式 ready 记录，按精确运行与节点进入详情 |
| 运行 → 节点详情 | [NodeSchedulingFacts](../../apps/web/src/NodeSchedulingFacts.tsx)、[SchedulingFacts](../../apps/web/src/SchedulingFacts.tsx) | 查看当前多个阻塞、依据版本和请求／预留，再查看独立历史尝试 |
| 原有暂停／恢复／取消确认框 | `RunAdmissionReview` | 审阅运行与流程版本、当前完整快照中的节点数量及命令语义；确认仍受服务端 CAS 约束 |

策略页展示服务端 `allowed_actions`，需要当前人类 write+approve 权限才能预览／确认。只读事实不因客户端角色猜测而解锁写入。草稿所据版本与当前读取版本分别保存；后台／人工重新读取当前策略不会覆盖草稿。需要保留草稿重基时，先显式读取当前版本，再重新生成预览，不能直接替换旧预览的版本提交。

预览固定原策略版本、目标策略、前后差异、摘要、到期时间与观察时影响。默认策略被运行创建或领取持久化后也可能变化；版本不同、过期、无效、已提交或读取失败时，旧预览不再提供确认资格。已提交预览显示实际 `applied_policy_version`，不能再次提交。旧预览及其观察影响不会被当前占用量偷偷改写。

就绪队列显示服务端总数与已加载范围，不从第一页计算全量统计。新读取可能已经过时，实际领取仍再次核验；列表不自动轮询重排，用户通过“重新读取”或“加载更多”推进。API 未提供当前判断时，显示尚未确认，不根据 command 或资源名称推断执行器存在。

节点当前派发条件每 10 秒及运行依据变化时重新读取。早于当前运行版本、不同运行／节点或读取失败的诊断不会作为当前阻塞显示。能力尚未指定时保留 unknown，多个阻塞同时展示。已运行／终结节点可以显示“不等待派发”，但不意味着历史失败或未知效果已经消除。

历史尝试从持久表分页读取，选定尝试后以精确接口读取完整结果，不能用最近 SSE 事件拼造历史。即使尝试不在第一页，也可以刷新直达。`exit_code=0`、`stopped=true`、`outcome_unknown=true`分别呈现；停止不被自动解释为外部副作用已消除。工具证据、工作区证据、测试和业务验收继续分层。

尝试始终显示服务端 `result_source`。`not_loaded` 仅代表列表元数据，需要精确读取；`unreported` 保持结果待核对。只有 `runner_result` 将已保存的结果标为进程退出码／实际停止回执。`manual_reconciliation` 显示人工核对 outcome 与 reason，没有机器 Result 时不补造 exit0；`child_workflow` 显示真实 child_run_id 和持久状态；`managed_observation` 标为提供方观察核对，其合成状态码不能称进程退出码。历史数据未提供来源时明确显示“未报告来源”，不猜测 Runner 来源。

运行版本或当前节点的 attempt／fence／state 变化时，尝试列表及已选精确记录重新读取，包括 attempt 编号不变而终态更新的情况。更新保留选择、已加载较早记录和焦点，迟到响应不能覆盖新结果；读取中／失败时明确标记暂留上次已读内容。另提供“重新读取尝试历史／所选尝试”，避免错过通知后只能刷新整个页面。历史列表不做周期轮询重排。

## 路由、恢复与键盘

```text
?project=p&view=settings&sub=scheduling
?project=p&view=settings&sub=scheduling&record=preview-id
?project=p&view=development&sub=runs&layout=queue
?project=p&view=development&sub=runs&run=r&node=n&attempt=2
```

`attempt` 只接受规范的正安全整数；节点或项目切换清理失效尝试，组织切换不可访问项目时也清理。URL 刷新和浏览器返回通过现有 App 路由消费。队列／尝试链接保留真实 href 和修饰键原生行为，普通主键点击进入受控路由及既有离页保护。当前项目、精确运行与节点始终保留。

策略非秘密原请求在发送前保存到当前标签页的 sessionStorage，按组织、用户、项目的三元组隔离。仅允许两个策略 POST 路径及白名单字段。超时、连接中断、5xx 或回执无法解析时，恢复固定路径、完整输入、原 expected_version 和同一操作标识；不得让后台新版本或编辑后的字段替换原请求。之后的 403 不能证明原未知操作没有生效。记录损坏或存储不可用时阻止新写入。可显式保留标识暂缓核对，不能把它描述为取消或未执行。

390／768 宽度使用完整纵向卡片、单列资源表单和现有完整节点列表；桌面保留图与检查器。链接使用完整可点击盒和长标识换行，主要动作可换行。历史尝试加载后焦点进入明确标记的详情区域，关闭后回到尝试历史区域。原生按钮／输入／链接和显式标签提供键盘等价操作，没有仅拖拽入口。重新读取不移动草稿或自动重排队列。

本页新创建或恢复取得的新预览 ID，在对应精确 GET 成功后只聚焦审阅区域一次；同 ID 重读不抢焦点。直接刷新已有深链不自动夺取焦点。提交完成以 `role=status`／`aria-live=polite` 宣告实际版本，不自动跳转或将焦点移到状态消息。

确认按钮在自身提交进行中保留原 DOM 和键盘焦点，以 `aria-disabled` 与处理器共同阻止重复提交；收到成功回执后直接变为唯一的“继续调整策略”。继续只返回编辑，不再次 POST；已提交深链也只提供此导航动作。仅显式继续后聚焦首个可编辑额度字段，用户已经移至其他控件时不强行聚焦。额度表单 fieldset 仅在自身范围清除浏览器默认边框、内边距与外边距，不改变其他表单。

`ready` 的产品名称统一为“待派发”，不声称全部准入条件已满足。就绪队列首先呈现中文阻塞标题和真实的请求／上限／已占／可用数；原始 code、source、服务端 message 保留在可键盘展开的“诊断依据”。未知代码保留原始原因；未知执行结果明确要求核对后再处理，执行节点资格未知不描述成没有执行器或已经可执行。

桌面图通过 ReactFlow 正式 `onSelectionChange` 同步非空且仅一个节点的键盘选择，与鼠标共用同一入口；同 ID 通知去重，空／多选通知不清除当前详情。URL 的恢复也更新图中选中状态，节点变化按 App 现有规则清理旧 attempt；连续刷新不重复写入浏览历史。真实 Workflow／App 集成用例保留详情与事件模块，只替代图布局，原生 Enter／Space 与图几何仍由实际浏览器验证。

真实运行页暴露过自动刷新遗留旧面板：调度事实与工具状态相邻组件曾使用相同 sibling key。现在以不同命名空间绑定完整 project／run／node；不关闭自动刷新，不直接删除未知 DOM。独立集成消费者保留真实 WorkflowView、NodeSchedulingFacts、SSE 读取与定时快照，只替代 ReactFlow／ELK 布局，连续多轮模拟10秒诊断／15秒运行刷新及切节点时，调度事实和尝试历史均应各一份，旧依据被新读取替换。实际浏览器长期停留验证仍由主集成记录。

## 队列与尝试读取恢复

首次读成功后才显示空态或计数。保留结果的后台读取有独立状态提示。暂时的续页失败保留已加载记录，原读取按钮切换为重试并请求原游标。正常状态下，手动重新读取从首页开始。读取期间按钮保留原位置和焦点。

项目、账号或组织切换立即退出旧读取范围。服务端拒绝时，队列撤下记录、计数和继续分页，尝试列表一并关闭当前证据区。恢复授权后从首页重读，原深链仍可读取准确尝试。 [阶段验证](../quality/scheduling-read-recovery-verification.md)

## 队列分诊

队列卡片先显示节点、当前条件和可处理的阻塞，原请求、容量依据和版本可按需展开。每项保留一个准确的运行与节点入口。项目准入额度或累计预算明确阻塞时，提供当前项目的执行调度入口。调整策略继续按原预览、权限与确认步骤完成。

状态筛选只统计已加载记录。全项目队列总数仍由服务端返回。筛选无匹配时可切回全部或继续加载。从运行详情返回同一队列历史条目时恢复原筛选，并重新读取当前授权数据。网络失败、重新读取或当前依据不匹配时，旧诊断不会作为当前条件显示。已通过本次检查仍需实际领取核验执行节点和工具。

参考 Multica 工作列表在当前视图快速过滤并保留原工作入口的交互。速码用 Go 调度器的实时准入事实标记阻塞，并在队列与运行详情复用共享池当前授权投影。 [调度合同](../../contracts/scheduling-kernel.md#项目准入与公开合同)

正式固定工具已暂停、撤销、变化或启用审批权失效时，队列显示具体阻塞和「检查工具配置」。打开后定位当前项目的准确工具体检，可返回原执行节点。缺失档案、读取未确认或固定依据无效时保留执行入口。工具原因与项目额度、共享池约束可以同时存在，工具授权有效也仍需核对领取条件。

## 按执行路径和运行定位

执行路径和准确运行 ID 交给服务端筛选，因此共享池节点即使在未加载的后续页也能直接找到。路径切换立即查询；运行 ID 可以填写后应用，也可以从当前卡片限定到其运行。一个清除操作恢复项目全部路径与运行。

列表计数以当前服务端条件为范围，阻塞、待核对和本次检查通过仍按已加载范围显示。路径表达原运行的固定安排，原授权失效或池暂停继续显示对应阻塞。筛选随队列链接保存，打开运行节点后返回可恢复原范围。无效链接明确要求修正或清除，保留原查看权限和准确导航。

参考 Multica 事项视图从当前运行定位原执行的交互。速码将该定位接到既有调度查询和原准入诊断。 [查询合同](../../contracts/scheduling-kernel.md#按执行路径和运行定位待派发队列)

## 真实用量

`UsageFacts` 接受 complete／partial／unreported；已报告 0 保留为 0，缺失计数字段显示“未报告”。partial 只能称“部分已报告小计”；步骤事件 complete 不代表整轮 complete。最终 ToolEvidence 存在时，绝不从早期步骤事件回填其缺失用量；历史证据没有完整度时明确显示“用量完整度未报告”。没有收费估算或由 Token 推导的完成比例。

## 接口与验证边界

使用冻结接口：策略 GET；策略预览 POST／精确 GET；预览 commit POST；队列 GET；节点 scheduling GET；attempts 分页 GET 和精确 attempt GET。路径、字段、授权和幂等规则以共享合同和 Go DTO 为准。

前端测试覆盖安全额度、0／null、保留未知回执、撤权、默认版本、旧预览失效、只读权限、草稿保护、多个阻塞、历史结果、范围隔离、App 队列点击／返回、精确尝试与焦点、用量完整度。DOM 测试采用合成 HTTP；App 路由接线用例中的 Workflow 明确使用替身，不能据此宣称 ReactFlow 布局或真实后端执行已验收。结构测试没有伪造浏览器几何。真实四宽度、主题、中心鼠标命中、后端额度争抢及条件变化后的领取，需要主集成在最终构建独立验证。
