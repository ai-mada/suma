# Generic CLI preparation and guide handoff

Version 1.0.0 · T-LOCAL-TOOL-PREPARATION-220. See the [domain contract](../../contracts/local-tool-preparation.md) and [Chinese product guide](../product/local-tool-preparation.md). All 31 requirements and P0–P7 remain active.

## Two primary fields

The original guide chooses the exact tool. The card exposes only the target Shell and a new output JSON path. Copying the command and adopting its path are separate explicit actions; adoption does not require clipboard success or prove that a file was generated. The preview follows current inputs. Manual JSON remains in a default-collapsed advanced example, while the five specialized protocols and internal templates keep their original meaning.

The four generic targets are Codex CLI (`codex-jsonl`), CodeBuddy Code (`codebuddy-cli`), Claude Code CLI (`claude-code-cli`) and DeepSeek Harness/dsh (`dsh-multica`). SDK, ACP and App Server setup retains its explicit inputs rather than guessing models, credentials or package paths.

The card uses existing fields, buttons and focus styling with a local 44px control height. Narrow layouts stack in order; commands and long paths wrap. Incomplete, copying, failed and copied-only states remain distinct. Copying must not be presented as a generated file or a working connection.

## Layers and precise adoption

| Layer | Responsibility |
| --- | --- |
| Original Go preparer | Fixed-PATH discovery, bounded passive native version/help probes and original CommandSpecs. It uses anchored directories and `O_EXCL` to create a new file, rejecting overwrite and linked destinations. |
| Pure model | Select exactly four non-special protocols from the original catalog, validate the closed three-key draft and reuse existing path validation and Shell literals for the original CLI mode. |
| Preparation card | Two fields and explicit copy/adopt actions. Bind caller, user, organization, tool and monotonic field revision. Make no API call or command execution. |
| Original guide | Strictly read `{shell, commands, localTool}`, verify the current protocol and source, then use the original nonce-based handoff. |

The ordinary guide adopts only its existing Shell, commands and localTool fields. It does not change identity, project, Worker or execution parameters. The shared guide does not show ordinary project identity commands. It exposes the current output reference for explicit copying, without filling a Pool form automatically, uploading local files or reading remote files.

## Lifecycle and existing authority

Input A→B→A, tool or account switches, API caller changes and disable/re-enable invalidate old clipboard completions. An asynchronous completion updates only a still-current revision and never adopts a path automatically. This local form creates no installation, connection or execution authority.

The parent guide continues to check source owner, epoch, navigationNonce and selectionNonce. If default Codex has no explicit navigation selection, a new explicit adoption establishes a fresh current selection generation. It does not make an old request without a valid source replayable. Permissions, versions, complete fresh inventory, matches, paused registration, separate enablement and task quality gates stay in the original system.

## AI SOP and verification

Confirm the exact protocol and original operations first, then generate through the shared model rather than appending arbitrary flags or guessing private paths. Explicit execution on the target machine performs real passive probe processes and creates a new file; the browser card does neither. Keep Shell quoting, native probes, file creation, reference adoption, inventory registration and model tasks as separate evidence.

Reuse unaffected checks and verify only changed model, card and guide boundaries. Source or component checks do not establish real vendor behavior, cross-platform installation or complete platform acceptance. Actual target-command, file and representative-interface results belong in separate stage evidence.
