原工具详情增加一张紧凑体检卡。首次选择正式档案或准确来源变化后自动读取；默认展示优先原因与一个下一步，四项事实可展开。显式“重新检查”只读，不增加接入向导。

## 卡片事实与状态

| 固定事实 | 展示规则 |
| --- | --- |
| 配置授权 `authorization` | 原档案状态及当前启用人权限 |
| 节点身份 `worker` | 原私有／Pool 身份资格；身份有效不写成在线 |
| 库存时效 `inventory` | 准确上报与原时限；未上报、过期、未来时间明确阻断 |
| 完整配置 `profile` | 新鲜库存下核对原 command、完整 Profile 和 Observation |

状态只用 `pass`／`blocked`／`not_checked`。库存旧时完整配置显示“未检查”，不能沿用旧 Observation 的通过状态；未启用档案仍展示独立节点、库存事实。

原 `Available`／`Reason` 继续表达当前可用性，不新增健康分或 ready。卡片按原判断顺序显示首个阻断；展开后保留四项准确原因，不能仅靠颜色区分状态。

读取中使用原忙状态；失败给准确原因与重读；响应不完整或来源不符不展示动作。所有前提通过时只说明当前已知条件，不推定模型登录、预算、运行或验收成功。

## 下一步只接原入口

| 领域动作 | 用户看到的行为 |
| --- | --- |
| `review_profile` | 打开原启用确认，沿准确版本 CAS；非撤销已启用档案可明确重新审阅 |
| `open_worker` | 定位该档案准确节点的原管理入口 |
| `register_profile` | 打开原快捷配置，明确后续登记流程 |
| `refresh` | 只读重新检查 |
| `none` | 不显示额外动作 |

暂停或启用人权限失效用 review；撤销或完整配置变化用 register；节点、凭据、池和库存问题用 worker；未知事实用 refresh。按钮只调用父级已提供且绑定当前准确来源的动作。

没有准确管理入口时仅显示原因与重读，不伪造“修复”或“连接本机”。体检不自动探测、启用、续期、登记、派发或调用 SDK；原明确确认与写入流程保持。

## 过期、身份与原 pending

报告的数据库 `checked_at` 与 `expires_at` 分别展示观察时间和期限；期限至多 60 秒且不超过新鲜库存原期限。客户端从请求起点以单调计时扣除网络耗时，过期后隐藏可操作建议并提供重读。

TTL 是显示期限，不是授权租约。即使卡片仍新鲜，后续写入也必须重新经过原当前权限、明确确认、CAS 和操作回执。

API caller、账号、组织、项目、工具 ID／版本任一改变，就丢弃迟到响应。返回版本与原详情不同，提示先刷新原详情；旧报告不解锁动作，不恢复旧身份选择。

原 pending 写入优先展示原操作核对入口。体检不能清除日志、换稳定 key、替换原请求或覆盖未知回执；恢复后再读当前事实。

## 中英文与命令行

中英文都使用原状态、按钮、焦点和详情组件；窄屏依次排原因、动作、时间、可展开事实。按钮和展开控件保持键盘可达、可见焦点和原触控尺寸，长配置留在详情。

`suma --project PROJECT tools doctor --id PROFILE_ID` 复用原登录／当前视图／client，核对 scope、完整 Tool、四项及期限，只输出同一 GET 的事实，不运行建议。CLI 只读失败不会产生“写入结果未知”，也不改变原 pending。
