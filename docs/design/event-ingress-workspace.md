# 事件入口与交付工作台

状态：T-P4-003 界面实现、组件回归与本机局部浏览器验收完成；完整视觉与可访问性矩阵待验收。负责人：工作台代理与主集成。需求：P4 外部事件接入；合同：[签名入口](../../contracts/automation-ingress.md)；实现：`apps/web/src/AutomationIngress.tsx`、`ingress-model.ts`、`ingress.css`；证据：[本机验收](../quality/ingress-verification.md)。

## 信息层级

入口位于“开发 → 自动化 → 规则详情”，与固定流程和规则策略一起查看。来源入口可以附着原人工或cron规则，但不改变原触发方式。入口列表、当前入口详情、来源过滤和交付记录组成一个连续工作区。入口选择使用现有URL `panel=ingress:<id>`；刷新和前进后退恢复同一入口，服务端仍逐次授权并检查所属规则。

用户首先确认固定流程和规则修订，再选择受限事件来源。创建只保存暂停元数据；设置秘密和确认启用分别完成，避免“保存来源配置”被误认作已连通远端。GitHub仓库数字ID和名称同时必填；空ref表示所有分支和标签，空结论过滤表示不限，不显示成未配置故障。

## 关键用户流

1. 新建入口 → 选择协议、事件和过滤范围 → 创建暂停入口。
2. 尚无密钥时显示“设置签名密钥”，已有密钥时显示“轮换签名密钥” → 安全生成新密钥或输入调用者提供值 → 保存并保持暂停 → 保存到外部发送端 → 关闭并清除当次原文。
3. 核对并启用 → 展示当前入口与规则版本/修订 → 确认启用。规则仍暂停、修订已变或密钥尚未配置时明确阻止。
4. 外部事件到达 → 独立交付记录查看匹配结果 → 打开受限上下文与正文摘要 → 已创建触发时查看关联触发；实际run_id存在才提供运行链接。
5. 修改来源、暂停、轮换或撤销 → 明确说明哪些排队触发会受阻、已开始的运行需另行管理。旧交付与修订保持只读。

## 写入与秘密状态

普通操作与密钥轮换都保留稳定operation和CAS依据。元数据恢复存储按组织、用户、项目、规则隔离；禁止秘密键名或原文进入存储。秘密只保留在当次表单及恢复对象私有内存。关闭后不提供“再次显示旧秘密”；界面只保留非秘密指纹与代数。

| 状态 | 用户可做的事 | 界面依据 |
|---|---|---|
| 正在提交 | 等待；禁止双击和切换范围造成误发 | 原操作标识与版本固定 |
| 网络未知 | 恢复同一原请求；或保留标识稍后核对 | 不生成新operation，不将超时描述为未生效 |
| 刷新后秘密丢失 | 读取最新指纹；匹配则确认原配置；无法确认则显式结束恢复并新轮换 | 不能重发没有原文的轮换请求 |
| CAS冲突 | 保留来源草稿，读取当前入口和规则再核对 | 不静默覆盖当前配置 |
| 只读或审批权限不足 | 可查看已授权范围，管理按钮禁用 | 当前角色与服务端最终授权 |
| 详情读失败 | 保留上次范围并标明陈旧，阻止据此写入 | 不能用旧数据伪装已刷新 |

## 交付与运行表达

accepted显示“已创建触发”，ignored显示“已忽略”，blocked显示“门禁阻止”；它们描述接收时事实。已知原因提供中文说明，未知原因保留折叠原文；过滤不匹配不会猜测具体字段。重复次数单独展示，不能把回执重放画成新增运行。运行的queued/running/succeeded等从正式关联查询读取；外部conclusion只作来源字段。原始正文与秘密不显示，未通过签名的请求不进入交付表，避免假装该表是完整安全审计。

加载更多后保留历史窗口并停止自动回到最新；用户明确刷新才回到首批。详情可查看受限上下文、签名代数、入口修订、固定规则修订、正文摘要及关联运行。请求迟到不能覆盖已经切换的入口或项目。

## 响应式、键盘与验证范围

入口与交付使用可换行字段网格和有界标识文本；窄屏按单列排列，表单保留全部动作。弹窗沿用Radix焦点管理、Escape和返回触发按钮；写入不确定时先保留原操作，不能凭关闭弹窗丢弃恢复依据。深浅主题共用既有设计令牌和明确文本状态。
