# 云任务工作区交互

T-WORKBUDDY-CLOUD-152；本页与[实际领域合同](../../contracts/workbuddy-cloud-execution.md)配合，不另建权威计划。控制面、父容器和原运行节点详情已接入，已完成定向代码与交互检查；浏览器完成范围由阶段质量报告单独记录。

## 原任务内完成工作

入口已挂入原运行节点详情，保留项目、任务、运行与节点上下文。页面使用该运行的准确`workflow_id／workflow_version`及选中节点识别云协议；定义必须声明`external_workflow`、`plugin=workbuddy-cloud`和`workflow=workbuddy-cloud/v1`。不根据节点名字、最新工作流修订或不存在的NodeRun.config推断接入。原定义不可用、存在未发布草稿或运行读取被拒绝时，不挂载云工作区；已打开的子工作区收到身份或主来源拒绝时移除受保护详情，保留重新读取入口。

先显示当前需要的下一步，再逐层展开固定正文、摘要和授权依据。页面不以“已配置”表示可用，也不因保存委派自动派发。

1. 准确读取原节点及服务端允许的动作。项目成员立即看到共享进度，账号操作按需读取本人匹配连接。
2. 查看固定请求，选择明确期限，确认一次范围后保存委派。
3. 已存在的执行事实按持久prepared、待核对或准确task_id呈现；WorkBuddy专用公开Runner领取及Execute组合继续接线，保存委派不会启动它们。
4. 需要了解供应方近况时明确核对原任务；显示最后观察时间及原状态。
5. 撤销委派阻止后续资格，提示已发生的远端作用仍须核对。

连接必须匹配冻结节点的connection与grant。若要换连接，返回计划调整来源；不能在授权表单中把另一账号替换到旧节点。没有符合资格的连接时显示不可用说明，连接管理仍由现有工具页面承担，不生成评分或健康勾选。

## 返回原任务交付

沿用 Multica 将运行与原任务互相定位的交互思路。WorkBuddy 进度下方呈现一行任务关系与版本，紧跟“打开任务交付”。关联已变化时，关系文字说明当前任务已改绑或解绑，用户仍可打开发起这次运行的原任务。该链接打开现有“交付与质量”面板，浏览器返回回到原项目、运行和节点。读不到当前来源时先使用已有的“读取当前记录”。

团队成员可以查看获准的任务定位。账号及会话继续服从个人授权。任务当前绑定、云运行进度、测试结果和人工验收各自显示，打开面板不会创建执行或触发供应方查询。

交付任务改绑后，当前验证运行的「WorkBuddy 交接来源」保留固定云尝试。卡片按仓库来源或本机候选说明交接方式，原始尝试使用同一运行详情深链。普通查看沿项目读取权限。原账号、会话和供应方操作继续分别检查资格。

## 更新记录与查询供应方

正常状态保留次级“读取当前记录”按钮，读取平台已经保存的准确节点、委派、提交和本人连接。该操作不查询供应方、不刷新授权、不创建云任务。未知、冲突、已确认或待核对状态复用各自的读取入口，不重复堆叠按钮。

团队成员优先看到平台阶段、供应方原状态和最后观察时间，使用原入口重读记录。共享视角无需显示私人账号、委派表单、会话归档或回合入口。缺少可见的委派及提交时显示“共享记录”。原授权人读取本人连接期间可继续查看已核实的进度，原工作区账号操作在读取完成前保持锁定。当前访问被拒时立即撤下受保护内容。见[限定验证](../quality/workbuddy-cloud-status-verification.md#团队进度读取补充验证)。

工作区接收原运行共享快照的`run.version`变化后重读相同来源，不建立卡片轮询。读取合并在途请求；期间再收到快照变化或明确读取意图，会补读下一份快照。相同运行版本重复呈现不额外读取。草稿和恢复作用域不含此版本提示，更新不会重新挂载工作区或丢失选择。

平台记录更新与“查询原云任务”分别表达。后者是本人明确执行的供应方观察命令，仅查询已经确认的原task_id。运行快照可能先于云提交落库，明确读取入口用于核对随后保存的事实；不能把一次快照提示当作全部云进度已经实时送达。

## 状态与操作

| 状态 | 信息与下一步 |
| --- | --- |
| 正在读取 | 清楚的读取状态，旧scope内容不显示 |
| 首次来源不可用／当前无权 | 首次失败不显示未核实正文；当前无权则移除受保护详情，保留重新读取或返回原对象 |
| 后台来源读取失败 | 保留上次已核实事实和草稿，标示未更新并暂停新写入 |
| 待委派 | 固定正文按需展开、匹配连接、期限和持续可见的确认项 |
| 已委派 | 明确到期时间与一次范围；撤销不显示为停止远端任务 |
| prepared／unknown | 原提交结果待核对，禁止新建或换key重试；保留安全恢复定位 |
| task_known | 准确供应方ID、原状态、最后观察时间、用量未报告；本人可明确核对 |
| 版本冲突 | 保留草稿，重读来源并重新确认；不套用新版本自动重发 |
| 网络未知 | 保存原请求与操作ID；仅用原请求核对，不制造另一个操作 |
| 明确失败 | 说明可恢复原因并保留草稿；不把超时归类为未发生 |

任务状态不染成平台验收成功。真实供应方新状态按原文显示，未知保持中性；金额和用量显示未报告。没有候选、独立测试或正式验收时不补绿色完成事实。

## 交互和可访问性

每个状态只有一个最高优先级操作，平台记录读取保持次级。表单标签持续可见，操作期间阻止重复提交，触摸区域至少44px。连接与期限按容器可用宽度自动排列，桌面窄侧栏与手机均可单列，不缩小字体或截断占位提示。正文采用14–16px、长内容可展开；焦点、状态文字及图标共同表达风险。

事实列表采用工作区限定的网格和字号，窄侧栏单列、宽容器可双列，明确使用12px标签、14px内容及1.65行高，避免继承其他侧栏列表的窄列和小字。

中文／英文使用同一语义。运行／节点上下文保留完整DOM文字和title，视觉最多两行；准确路由、作用域和恢复标识始终使用完整ID。其他依据按需展开，动效尊重减少动态偏好。

作用域包含原用户、组织、项目、run和node。切换作用域退休旧响应，不能让迟到的写入回执覆盖新页面。工作流缓存按项目隔离；相同工作流ID／版本也不能借用另一项目定义。当前撤权立即移除受保护内容。来源版本改变保留本scope草稿但撤掉确认；新快照和“读取当前记录”均不能解除未知操作锁。

## 持久恢复

父容器复用现有受控写入恢复机制，在外发前保存稳定操作及准确body。恢复body只含ID、版本、摘要和期限，不缓存请求正文或秘密。存储不可用时阻止写入并解释原因，读取仍可进行。

重新打开页面先读取准确run／node定位已有委派和任务，不依赖上次内存选中项。原操作核对使用原key／body；成功后重读正式对象。刷新页面、读取当前快照、核对原操作与核对供应方任务是不同动作，文案及调用边界分别表达。
