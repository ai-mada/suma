## 单一入口与原工作区

任务交付面板根据服务器正式验收事实显示“提炼交付经验”，不以列表状态判断资格。普通任务详情和依赖图使用同一面板；默认折叠，避免打开任务就增加质量读取。点击只导航到原知识提炼工作区并读取准确来源，不启动模型。

URL使用独立`delivery-knowledge:{taskID}`面板定位，原分析仍使用`knowledge-intelligence:{analysisID}`。刷新、分享与返回保持项目／来源；任务ID不能假作分析ID。原待核写入优先恢复原body／key，新导航不能覆盖它。

## 逐步呈现

| 状态 | 用户可见行为 |
|---|---|
| 正在读取 | 来源区加载，当前来源未确认前不能创建 |
| 当前来源有效 | 标题、版本、测试／候选依据数量及正文预览；细节默认折叠 |
| 没有代码候选 | 明确本次无代码候选，不渲染假的提交或封包 |
| 原依据变化 | 提示重新核对，明确采用当前依据后清除模型使用确认 |
| 来源无权或不合格 | 收起私有详情，显示可恢复提示；不保留旧来源当作可用 |
| 没有提炼工具 | 保持来源可读，说明配置工具后才能创建；不造可用工具 |
| 已有待核操作 | 原请求恢复入口优先，新来源草稿不能替换原提交 |
| 提案／采用／发布 | 三种独立事实，采用显示草稿位置，发布沿原明确门禁 |

主来源固定为导航进入的任务A，追加来源B使用独立选择和读取状态。刷新A不读取B，B读取失败不把A标为漂移；添加B后清空选择不影响A刷新。草稿编辑中的“核对当前来源”也使用专用accepted接口，并保留准确basis SHA。

## 视觉与操作

沿用平台设计令牌、正文尺度和按钮，不增加多页向导、装饰指标或一层配置中心。默认一张来源卡和原有提炼表单；版本／依据／运行／Review与候选细节展开后按需查看。链接可定位真实任务和运行，操作前仍遵守离开保护。

中英文全部采用独立词条。任务标题、ID、摘要和代码提交按原文显示；日期按当前语言格式化。390px下长标题和摘要换行，详情可用键盘展开，反馈区域不抢焦点。当前源刷新、错误、无权限、忙碌和空工具状态都保留明确文字。

## 验证边界

定向组件覆盖正式接受入口、当前／追加来源分离、来源漂移、原请求恢复、当前权限及独立草稿发布。代表浏览器验证使用生产组件、真实授权HTTP及正常Review准备的数据，只读导航／预览／刷新／窄屏返回，不重复模型和已有采用发布业务。受控JUnit准备不代表真实Git或厂商模型；完整App、主题、设备、多机与生产另验。
