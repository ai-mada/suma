# 节点内回答问题

状态：1.0.0当前实现；负责人：Web／主集成；关联需求：T-TOOL-INPUTS-187。合同：[问答](../../contracts/tool-inputs.md)；实现：`apps/web/src/ToolInputPanel.tsx`、`ToolInputCard.tsx`、`tool-input-model.ts`；验证：[限定报告](../quality/tool-inputs-verification.md)。

在现有运行节点内显示独立问题区，与工具操作确认并列，避免增加管理页。服务端返回当前受保护profile能力；未配置且无历史时不显示面板，历史记录可只读查看。配置能力不显示成在线或执行成功。

每个请求直接显示1–3道原问题。原选项采用单选；原问题允许Other时显示其他说明；无选项题直接显示文本框。提交前不自动选择答案。明确“提交回答”与“跳过当前问题”，多题必须准确覆盖。原问题与用户文字不自动翻译，产品标签与诊断提供中文／英文。

状态与行动保持一致：

| 事实 | 展示与操作 |
|---|---|
| 待回答且当前有权 | 可填写、提交或明确跳过 |
| 答案保存 | 展示已保存答案，等待执行器观察 |
| 执行器观察／写开始 | 展示实际投递阶段，不再编辑答案 |
| 完整写出 | 表达“已写出”，不推断代码执行或验收 |
| 原生关闭／回合结束 | 只读；未回答也可正常关闭 |
| 结果未知 | 保留原意图，核对原操作，禁止盲目新答 |
| 过期／撤权／范围变化 | 禁止新写；撤权清理私有内容 |

作用域包含用户、组织、项目、运行、节点与协议；恢复键不包含attempt/fence，原意图内固定旧tuple，避免新尝试掩盖未核对旧提交。未知提交锁住新回答，按原scope读回或重放；旧tuple不因恢复而重新获得新写权限。用户切换账号或项目时，旧异步响应不能覆盖当前页面。

表单使用原组件、清晰标签、可见焦点和顺序键盘操作。窄屏保持单列，长问题／选项／提交摘要可换行；原RPC身份与摘要放入按需展开的详情，不占主要回答空间。错误就近显示，加载与发送阶段禁重复操作；不使用伪进度或自动提交动画。

本地连接设置只增加一个默认关闭的实验性开关，说明用途与当前限制。改变配置仍沿原停止、原意图与重新探测流程；Go／桌面JS使用同一policy4摘要，不接受旧摘要回退，也不修改用户全局Codex设置。
