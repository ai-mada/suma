# 工作流交互

画布基于 ReactFlow，ELK 按真实依赖进行分层布局。边只来自已发布定义的 edges 与节点 depends_on；去重后显示。历史定义无法读取时展示节点和状态，不捏造线性连线。

编排侧栏提供原生“选择节点”下拉和“上游依赖”复选框，可完全通过键盘选择节点、添加或取消依赖。它们直接编辑同一份 edges，和画布拖拽共用校验。自依赖、未知节点和传递环路在编辑时立即拒绝，保留上一次真实图；服务端发布校验仍为最终门禁。依赖条件和删除入口保留。

编排模式允许增加节点、编辑类型/参数/超时/重试/幂等/汇聚规则、连接依赖、删除节点和连线。可直接编辑节点执行条件、分支条件、资源需求与配置 JSON，以及依赖边条件。支持服务端的 command/test/approval/condition/join/agent/script/task/timer/map/noop/subworkflow/external_workflow 类型。subworkflow 配置固定 workflow_id 和大于零的 workflow_version；external_workflow 配置 plugin、workflow、input，并由运行时核实精确插件能力。汇聚规则使用真实合同 all_success、all_done、any_success、quorum。格式错误的 JSON 阻止发布。工作流发布前必须通过服务端校验，已有定义发布下一版本。发布得到版本后才能启动；启动请求携带 workflow_id、固定版本与关联任务原版本。

执行模式基于轮询的真实运行、节点和事件状态。节点详情显示执行者、尝试次数、原因、输出和错误。节点返回 child_run_id 时，可直接打开真实子运行，浏览器返回保留父运行与节点定位。仅 approval 类型且 waiting 状态的节点可批准或拒绝；失败且声明幂等的节点可请求重试；结果未知节点只能在核实后确认未开始、已成功或失败。取消、拒绝和核实需要说明。暂停、恢复和取消调用运行命令接口，携带原版本。

仅终态运行中存在成功执行、attempt 大于零且配置了明确 `config.compensation` 的工作节点时显示补偿入口。补偿使用独立 `compensate` 命令与必填原因，由服务端核实审批权限；不会自动回滚或改写原运行。若服务端返回 compensation_run_id/state，则显示真实补偿状态与独立运行入口。

诊断模式展示事件原始数据与节点执行输出。事件轮询从已读 sequence 之后增量读取，内存保留最近 300 条、面板展示最近 30 条；稳定图拓扑只更新节点状态并保留位置。所有命令由服务端校验权限、版本与状态。工作流历史快照与运行版本一致，读取失败明确提示；可视化布局不改变执行顺序。历史选择器按页读取运行摘要，显示已加载数量和完整总数，通过显式按钮加载更多；当前 URL 运行单独读取完整快照并保留选项。运行时展开的 map 子节点会展示真实状态，仅在服务端提供依赖时显示对应连线。动态子节点的幂等/补偿配置未在运行快照提供时，客户端不开放对应重试与补偿入口。画布支持缩放、平移、自动布局和键盘选择/删除；窄屏把属性区放在画布下方。

已知边界：图编辑保存在本次页面草稿，发布后才持久化；没有调用外部设计上传服务。未启用的运行适配器不会被表述为可执行能力。
