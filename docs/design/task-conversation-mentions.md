# 任务讨论精准提及

状态：T-MENTIONS-140 实现基线。交互依据为[冻结合同](../../contracts/task-conversation-mentions.md)。源码实现、定向检查及实际浏览器验收分别记录，本文不宣称已通过验收。

在开发工作台所选任务的讨论中，正文继续使用纯文本。输入下方独立选择明确人员，支持搜索、翻页和移除，最多选择20人。写下 `@名字` 本身只是正文，不替代人员选择，也不触发广播或模型执行。

可选项来自当前有权的项目人员目录：活跃human资源、真实用户及规范绑定必须一致，接收人当前具有项目读取权。项目viewer可以被提及；不能把任务交接所需的业务写权错误地当作提及接收条件。未加载的其他页不代表没有匹配人员。

已选草稿仅保存资源ID和正文。重新打开后按当前目录解析名称；未返回的选中ID明确显示为不可用，由用户移除或重新选择。不能静默删去不可用人员后发送。历史消息展示服务端发帖时的固定名称，成员后来改名不会重写原讨论。

正文或提及选择均属于未发送内容。用户、组织、项目和任务共同确定草稿范围。结果未知时冻结原正文、接收ID、操作标识、预期任务版本及原调用者，通过原请求恢复。成功确认后才能清空；未核对写入或未发送内容继续阻止静默离开及自动智能体回复。

收件箱的提及通知提供“打开讨论”。链接保留任务ID与准确消息ID，进入开发工作台后直接读取并聚焦原消息；目标可能早于最新20条，不能让用户反复加载历史寻找。当前窗口已有目标时避免重复展示。打开来源不自动标为已读、不发送消息，也不启动开发。

加载、空态、失败、当前失权、来源不可用与未知写入分别呈现。401／403／404清理受保护消息和人员目录，保留该身份的本地草稿和原请求。键盘选择、焦点返回、中英文、390px窄屏及深浅主题均属实际交互验收范围。

参考Multica的结构化提及与个人收件箱语义。当前参考版本的附加许可限制仍适用；本实现独立编写，不复制其界面、编辑器、通知代码或资产。全员／团队广播、偏好降噪、邮件／IM投递与跨项目汇总继续属于后续完整范围。

## AI 协作与异常处理 SOP

1. 读取当前项目、任务版本及会话。将待关注事项写成普通正文；需要人员关注时，通过当前人员目录明确选择，不能猜测名字对应的账号。
2. 发送前保留原账号、项目、任务版本、正文、接收ID及操作标识。网页使用现有写操作保护；CLI使用`discussion post --file`，不能在重试时换操作标识。
3. 接收人失效或版本冲突时，保留草稿，重新读取当前依据并由发送者调整。结果未知时先恢复原操作，不把未知当作未发送。
4. 从个人收件箱打开准确消息，检查原上下文后决定回复；是否已读由本人明确操作。人员提及不会启动模型或执行命令。
5. 需要智能体开发时，使用原明确模型、预算及讨论开发交接流程。提及消息可进入固定上下文，其不可变元数据必须与服务端来源摘要一致；不能通过提及绕过审批、调度、独立测试和验收。
6. 发生当前权限拒绝时停止读取该范围，清除受保护界面；本人的本地草稿和未知原请求保留。来源损坏时显示不可用，不从缓存拼出讨论正文。按阶段报告登记未完成的浏览器／其他数据库验收。
