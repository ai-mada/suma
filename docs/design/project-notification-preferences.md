# 个人收件箱通知设置

T-NOTIFICATION-PREFERENCES-167；速码1.0.0；2026-10-31。负责人：主集成代理／工作台代理。状态：个人项目讨论设置及限定交互已核验；关联[合同](../../contracts/project-notification-preferences.md)与[架构和SOP](../architecture/project-notification-preferences.md)。

收件箱标题旁一个“通知设置”入口，默认收起，界面不增加配置页。展开后仅有“静音关注任务的讨论通知”复选框、保存／重读及当前项目范围说明。说明必须清楚表达这是本人设置，精准提及与交接仍会送达。沿现有React、Lucide与主题令牌，中英文词条成对，不新增组件库。

## 交互状态

| 状态 | 可操作与反馈 |
| --- | --- |
| 初始读取 | 显示正在读取，不把未知布尔值画成默认false；不发写请求 |
| 已知当前值 | 展示正式状态，编辑后显式保存；收件箱筛选／刷新不另取偏好 |
| 保存中 | 防双击，保存原body/key；当前回执与读取中的当前值分开 |
| 结果未知 | 保留原操作并给“核对原请求”，不能靠重新读取解除pending |
| 版本冲突 | 保留明确意图，提示重新读取，不自动套新版本重发 |
| 当前拒绝访问 | 清除偏好和受保护收件箱数据，保留核对所需元数据 |
| 收起 | 控制器仍挂载；未确认操作及核对提示不会被折叠丢弃 |
| 切换身份／项目／API | 同步退休旧事实，丢弃迟到成功与错误，不把原命令改派到新范围 |

独立的write-action领域作用域避免与同页已读／归档命令共用journal。保存成功的原回执不能直接覆盖当前布尔值，必须独立GET；当前设置可能已由另一个窗口更新。用户主动重读不触发命令，也不标记任何通知已读。

原生checkbox、label和button提供键盘等价入口；入口aria-expanded与面板关联，状态／错误用可读文本，不能只有颜色。窄屏单列、按钮可换行；路径、原始key、内部锁或配置身份不进入普通操作文案。成功／失败／冲突／未知及无权限分别反馈，不制造百分比或实时健康结论。

## 代表性验收

使用真实收件箱／偏好组件与真实本地HTTP、SQLite的两个测试身份：默认讨论通知→本人GUI静音→普通讨论不产生关注通知→精准提及仍送达→GUI解除静音→新讨论恢复。旧回执恢复另读后仍应展示较新设置；原关注、任务依据、历史记录和未读状态不被设置操作改写。
