# 批量负责人变更交互与 AI SOP

T-MULTICA-BULK-150，速码1.0.0。状态：合同冻结、实现进行中；负责人：前端交互／任务领域／主集成，见[合同](../../contracts/task-owner-changes.md)。本页说明[产品](../product/task-owner-changes.md)与[事务架构](../architecture/task-owner-changes.md)要求，不是GUI验收证据。

## 入口与明确选择

沿原任务列表checkbox选择已加载的1～16项，保留原专家团队安排入口。不加入全查询隐式全选、状态批改或自动派发。日常入口只展示选择数及“变更负责人”，详细流程在原Modal内展开。

真实入口为[Records(tasks)→TaskRecordsScope](../../apps/web/src/App.tsx)→[TaskViews.selectionActions](../../apps/web/src/TaskViews.tsx)，恢复组件始终挂载；TaskCollection仅作embedded内容且controls=null。零选择仅禁用新预览，不能卸载未确认写或持久化故障入口；恢复对象按用户／组织／项目隔离。

## 目标人员与真实预览

目标来自当前服务端canonical human目录，支持字面搜索、明确分页和加载／错误状态。未加载成员不等于不存在；不以有限本地成员数组断定资格。选择显示人员名称及规范资源身份，目标与其版本由服务端再次核验。

明确请求预览后，逐项显示任务、原负责人、版本以及将变化／负责人不变，汇总实际变化和不变数量。预览加载失败、来源不完整或失权时不能借旧行启用提交。

全不变时解释无需变更并禁用采用。不变条目仍保留在预览，说明其作为后续任务可能因其他选择变化而失效；不能承诺“此任务完全不受影响”。

## 影响确认与一次采用

通用影响说明明确：实际变更项回到进行中并撤销当前已验证交付资格，后续验收可能失效，已完成迭代／里程碑可能重新打开；运行、代码、测试和Review历史保留。不展示没有准确依据的下游数量、影响百分比或固定图快照。

用户明确勾选影响确认后，使用原选择、目标资源版本及preview_sha256采用。摘要不是访问凭证或批准，确认也不代替当前授权和服务端重算。目标、选择或版本变化后重新预览，不静默接纳新依据。

任一项失败整批不变；成功显示全部所选任务的最终版本／状态，不能从初次预览推算结果。负责人不变条目若被依赖规则改变，也要如实表达最终版本。正式Review和后续独立测试继续原入口，不自动执行。

## 错误、冲突和原操作恢复

| 场景 | 必须提供的反馈与动作 |
| --- | --- |
| 无选择／人员为空 | 阻止新预览；原恢复入口仍可见 |
| 目录或预览加载 | 标明读取中，禁止把旧来源当新预览 |
| 读取错误／缺失来源 | 原地读取重试，保留自己的选择，不推断成功 |
| 父401／403／404或范围切换 | 同步遮蔽预览／目标，abort读取并retire旧caller迟到写结果 |
| 409版本／预览冲突 | 保留原选择和目标；明确重新预览，不自动采用新版本 |
| 提交中／结果未知 | 锁住新写，显示原操作和恢复动作，即使当前零选择 |
| 本地持久化故障 | 明确提示保留页面，保持恢复入口，不隐藏为无选择 |
| 原回执成功／刷新失败 | 分开显示，不因刷新失败再发新的采用 |

恢复只提交原账号／项目、JSON、版本、摘要及操作标识。不能从当前列表或新人员目录补造原请求，也不能换标识盲试；相同标识变正文应明确拒绝。

blocked时提供明确的当前资格核对：仅GET task-owner-targets、limit=1并保留原视角，成功才通知父TaskRecordsScope清denial及刷新读取；返回的人员不被采用。它不授予角色，不自动恢复写；仍须用户明确“核对原结果”（Restore），沿原JSON和操作标识核对。

CLI的targets、preview --file、apply --file与界面共用原合同：POST项目只在正文，保留原tasks数组／版本；采用须有准确摘要、ack:true及原idempotency。未知结果沿同文件恢复，不从新目录补造正文。

## 中英、键盘与窄屏

中英文成对，人员姓名、任务标题和原始版本保留准确。使用现有Radix焦点／离开保护、设计令牌和明确按钮文案；checkbox、按钮和主要操作目标按44px交互要求，390px下逐项信息可换行，键盘可选择、预览、确认及恢复。

加载、错误、冲突及未知状态不用颜色单独表达。上述为交互要求，实际中英／390px／键盘结果由质量记录证明，不能由样式或组件安装推断。

## AI SOP 与维护

AI可解释逐项预览和通用影响，但不隐式扩大选择、不凭摘要代授权，也不未经用户明确授权提交。发生未知结果先核对原操作；需要新版本或新目标时，由用户明确重新预览。
