# Doctor维护建议交互

状态：T-TOOL-DOCTOR-199阶段实现；suma1.0.0；关联[PRD](../product/tool-doctor-maintenance.md)、[合同](../../contracts/tool-doctor-maintenance.md)。

诊断首屏分别显示派发状态和简短的“维护建议”，用一个主操作引导到原检查、核对、进度或准确节点配置。移除无差别的重复“重新检查”按钮，原四项检查与技术依据按需展开。无能力或等待不是成功，状态同时使用文本和图标，不靠颜色表达。

| 情况 | 主操作与反馈 |
| --- | --- |
| 无占用、当前有维护能力 | 进入原“检查此节点”确认，使用准确配置版本 |
| pending／claimed | 查看准确原检查进度，不重复创建 |
| unknown | 查看原记录或进入原核对确认，保留原未知事实 |
| recovery requested／proof_stored | 查看原核对；证据已存与正式关闭分别提示 |
| 同节点其他配置占用 | 明确原配置，读取原来源后跳转；加载／失败可重读且保留当前目标 |
| 维护缺失／过期／不支持 | 解释当前限制并进入准确节点配置 |
| 数据变化／权限失效／过期 | 暂停动作，保留明确状态，重新读取当前诊断 |

点击只读定位期间显示加载，失败按原错误入口重试；未知本机写意图不能被定位覆盖。账号／组织／项目／caller切换立即隔离旧响应与焦点目标。中英文使用同一动作和原因闭集，节点原文仍标明来源；窄屏单列，键盘可操作，减少动效规范沿现设计系统。
