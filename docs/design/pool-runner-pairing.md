# Pool配对的三步交互

状态：本阶段限定验证；版本1.0.0；需求T-POOL-RUNNER-PAIRING-208；负责人：Web／主集成。关联[产品需求](../product/pool-runner-pairing.md)与[唯一合同](../../contracts/pool-runner-pairing.md)。

原Pool节点tab以“配对执行机器”为主入口，手工登记为次入口。完整流程在原Modal中完成，不另造管理中心。

| 阶段 | 主信息与动作 |
| --- | --- |
| 准备 | 名称、槽位1、凭据24小时明确展示；创建原待办 |
| 等待与核对 | 无token命令、机器自报名、完整指纹及准确资源／期限；明确确认才可批准 |
| 完成 | 原节点和凭据期限；主操作返回原节点，新增机器为显式次入口 |

安装、登记、机器持续在线、库存、工具启用、项目授权和业务验收保持独立事实。等待机器时直接展示配对命令；机器已提交提案后，首次命令进入默认折叠的“重新查看配对命令”，突出指纹、确认和审批，展开仍保留原Shell／身份路径草稿。有效期显示24小时等人类单位，精确秒数留在原输入和公开证据。未知写入突出“核对原操作”，恢复沿同一body／key；不更换密钥，不显示虚假完成。409明确重读期间使原依据stale，成功后重新确认本提案；写入前存储失败不能留下父Modal假锁。

定位偏好损坏不阻止当前授权历史读取，不对坏ID发请求。独立未知操作始终优先恢复；无待恢复操作时可明确重置本scope公开定位，保留原操作日志与服务器记录。换组织／用户／Pool或caller时，旧读与旧回执不得覆盖当前窗口。

深浅主题与中文／英文沿原令牌和目录；控件44px、完整可见焦点、390px单列。长指纹与地址在自身区域换行，原完整内容可核对；复制命令不包含token。历史列表分页与当前提案在同一处按需展开，避免首页堆叠说明。
