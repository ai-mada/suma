# 交付处的审核责任

T-REVIEW-142冻结交互基线，实际GUI验收另记。入口位于原任务详情的交付门禁，使用紧凑、默认收起的责任区，不建立另一处验收工作台。

收起时显示指定审核人、准确运行、请求状态，以及直接依据或当前资格变化的提示。原证据与Review入口沿现有授权开放；不能把binding_current显示为“可通过”。展开后可在有界目录搜索和选择一名审核人、填写说明，发起明确请求。没有候选人时说明当前条件，不自动邀请、授权或以任务负责人代替。

已选人员不可用时保留选择并显示原因，不能静默丢掉或改选。发起、取消、原请求恢复和读取中分别展示状态；默认不发送、不取消、不标记已读。pending存在时保留准确历史，不能无提示覆盖。取消说明明确只结束这次责任请求，不改变任务或已有正式结论。

历史每次读取一页，total表示完整历史。姓名保留请求时快照，当前审核资格另行展示。closed展示真实Review的实际决定者、接受／退回及原证据；来源不可用时显示无法确认，不能依据任务状态补造决定。原Review按钮和表单保持现有门禁，不在此复制一套。

Inbox通知准确定位`panel=task-review:<request_id>`，在同一任务详情展开对应请求。若来源关系或当前任务不可确认，保留私人通知但隐藏任务／请求链接。取消、完成、已读、归档是独立事实。

账户、组织、项目或任务变化立即隐藏旧响应，取消旧读取并阻隔迟到结果；401／403／404清除受保护内容。未发送草稿与未知写入按原身份、范围、正文、版本和操作保存；恢复明确显示原请求，不把当前新任务版本替换进去。

必要交互验收包括中英、浅／深色、窄屏、键盘目录选择、焦点回到原入口、准确通知跳转、迟到响应、当前撤权及未知写入恢复。后端或类型检查通过不等于这些界面场景已经观察通过。

原Review的所有打开入口先询问现有离开保护。责任请求尚有未发送内容时，保留原草稿并提示先保存或取消，不先打开一个无法关闭的上层模态窗；清理草稿后沿原入口打开和关闭。此保护不改变正式Review的当前权限、测试证据或提交回执。

已选测试计划的保存权来自该计划当前`allowed_actions`，新建权来自正式会话项目角色；来源未加载时等待，不把它误当作没有验收条目。保存同一计划仅原位刷新；新建成功在原来源和身份仍有效时再导航，未知写入继续保留原操作，不能因页面刷新生成另一笔写入。
