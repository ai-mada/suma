# 收件箱交互与AI开发SOP

状态：T-INBOX-138实施中；负责人：协作体验；关联原人员任务、统一权限及Multica收件箱能力。实现由NotificationInbox组件与notification-inbox-model模块负责；数据合同见[正式接口](../../contracts/notification-inbox.md)，事务边界见[架构](../architecture/notification-inbox.md)。

## 界面层级

开发导航中的“收件箱”与“我的工作”相邻。我的工作回答当前负责什么；收件箱回答哪些真实分配事件需要自己查看。一个紧凑列表承载标题、事件、时间和明确操作，复用现有字体、浅深主题、边界和强调色；不为普通分配添加红色告警或大块统计卡。

顶部三项“收件箱／未读／已归档”使用同一时点的正式计数；载入期间不假造0。刷新与更多分别操作当前窗口。未读以文本和字重区分，不仅依赖颜色；行操作具有独立可访问名称，来源打开与已读按钮分开。

窄屏把行操作自然换行，保留标题与主要来源入口；不要求横向拖拽或悬停才能完成操作。详情来源不可用时显示原因，不渲染无法授权的链接。重新分配后的旧事件明确为“原分配已变化”，不能冒充当前负责人状态。

## 操作流程

1. 源任务事务将任务分配给规范人员，真实接收记录随同提交。
2. 当前人员在对应项目打开收件箱，读取当前标题和真实状态。
3. 打开任务仅导航；明确点击“标为已读”才写个人状态。
4. 归档不改任务或已读状态；恢复归档也不隐式标为已读。
5. 刷新／更多使用原过滤范围，旧身份或旧过滤的响应不得回写。

## 关键状态

| 状态 | 交互 |
| --- | --- |
| 无真实分配通知 | 说明只收录正式分配事件，不展示假样例或自动补历史 |
| 载入／暂时失败 | 骨架或清晰忙碌状态；失败保留本范围重试，不扩大查询 |
| 来源不可用 | 隐去当前标题和链接，保留事件时间与个人状态操作 |
| 别处修改通知 | 保留当前意图，显示版本冲突，明确刷新后重新操作 |
| 命令结果未知 | 保留原操作ID与原版本，可明确恢复；不生成新操作重复写入 |
| 正在核对命令 | 阻止导航丢失未核对动作；过滤和刷新不卸载恢复状态 |
| 当前权限拒绝 | 立即清理列表、计数、来源目标和缓存；旧身份拒绝不清理新身份 |
| 非法分享过滤 | 原样报错，不静默按全部通知读取；选择合法过滤后恢复 |

原操作恢复只保存通知ID、动作、预期版本及操作ID，不保存任务正文或标题快照。所有用户可见文字使用中英领域词条；用户任务标题不自动翻译。

## AI开发SOP

1. 先检查任务权威写入口与规范人员绑定，再增加事件接点；不能以页面可见负责人猜账号。
2. 源事件与个人动作分开测试；任何新通知种类须声明接收者来源、去重键、权限及事务边界。
3. DTO从Go合同生成，不在浏览器发明另一份业务状态；BIGINT序号保留字符串。
4. 请求固定账号／组织／项目与代次；读组件可换过滤，未知写入生命周期不能随过滤重置。
5. 定向验证真实原子提交／回滚、当前权限、版本及回执，再做代表性中英桌面／390px实际交互；不反复执行不受影响全套。
6. 记录准确源码、真实结果与待验范围；以限定文件阶段提交并正常推送dev，排除缓存、凭据、数据库和截图。

## 组织内跨项目处理

在开发 → 收件箱，用“当前项目／全部可见项目”切换范围。组织视图的行内标明所属项目，已读、未读、归档、恢复与打开来源仍用相同入口。项目偏好只在当前项目范围内编辑。范围和过滤进入深链；跨项目打开通知时一次切换项目并定位到原任务、消息、审核请求或交接。浏览器返回可重读原收件箱范围，打开来源不会标为已读。

计数与行从同一正式结果读取。旧分页若因权限变化失效，清除原范围并提示重新读取。读取失败或账号变化不显示旧账号的任务标题。个人状态回执只确认操作，再按当前范围重读；未知结果沿原项目和原请求核对。窄屏范围控件、项目标签和操作按原列表自然换行。

行为参考 Multica 固定提交的工作区聚合和行内个人动作。速码沿自己的任务来源、项目授权、事务和原操作恢复独立实现。 [Multica 收件箱](https://github.com/multica-ai/multica/blob/e8b6a97643ccc35efbcf2a4675c8d088a288ed6e/apps/docs/content/docs/inbox.zh.mdx)

## 执行失败的处理入口

收到任务执行失败通知时，行内使用图标和事件文案，当前任务状态另列。按钮「打开原运行」直接进入事件对应的运行，即使任务已经开始了另一轮。组织范围先切换到通知所属项目，再进入准确运行。打开来源不会自动标为已读，也不会重试运行。旧来源无法核对时显示不可用，个人状态操作继续沿原项目权限。

失败问题照常进入质量回流。通知只提供原运行入口，用户在运行详情看证据和已有的诊断操作。采用 Multica 的订阅失败提醒行为，沿用速码的正式失败事实、问题回执和既有收件箱样式。

## 批量处理已选通知

在收件箱启用批量模式后逐条勾选，可在当前已加载的通知中选至多 20 条。组织范围允许同时选取不同可访问项目。操作栏显示已选数量，提供标记已读、未读、归档或恢复，以及清除选择的入口。移动端操作可以换行，键盘按常规 Tab 顺序进入复选框和操作。

一次提交固定动作、选中项及各自原版本。完成后重新读取当前列表与统计。若权限或版本在提交前变化，整批保留原状态，界面提示刷新并重新选择。未知结果沿原请求核对，页面不推测成功条数。该交互参考 Multica 的收件箱批量处理，沿速码已选记录、当前授权和原回执独立实现。
