# 原云观察共享的交互设计

T-WORKBUDDY-HISTORY-SHARE-165；1.0.0；2026-10-31。状态：交互实现与代表最终状态限定验证完成；[证据](../quality/workbuddy-cloud-history-sharing-verification.md)记录11项实际检查及中英代表图。负责人：工作台与主集成。依据[正式共享合同](../../contracts/workbuddy-cloud-history-sharing.md)及[领域架构与SOP](../architecture/workbuddy-cloud-history-sharing.md)。

## 目的与入口

用户需要把私有开发会话中的具体观察交给团队讨论，同时清楚知道分享了哪些内容、分享给哪个任务。入口保留在准确原运行节点的已保存观察附近；正文依然是本人私有资料。完整人工协作、远程操作与知识发布使用各自流程，不混在一次分享里。

操作顺序是“选记录 → 选任务 → 预览 → 明确共享 → 定位讨论”。不默认选中全部记录，不根据供应方task_id、同名任务或最近操作猜目标；只有正式平台绑定可以作为准确预填，用户仍能核对。

## 主要呈现

已终止观察中的受支持非空条目提供选择；上限8项。序号与实际字面文字一起显示，unsupported只保留原安全提示。选择计数真实来自当前选择集合；切换准确load时清除旧选择，不把本地分页当成供应方历史范围。

目标任务沿现项目任务查询与选择组件，展示实际任务标题与版本，保留搜索／分页边界。没有项目写权限时明确说明需当前权限；云账号断开本身不禁止分享当前仍有权的存档。

预览采用一个清晰的正文区域，展示精确合成文字、目标任务、来源终止状态及coverage未核实。范围说明紧邻明确共享按钮：当前有目标任务读取权限的项目成员可读，已发布副本不随原云连接撤销。正文不可在此静默改写、截断或重新生成；需要调整时返回选择。

讨论中的消息作者为发起共享的真人。附带简洁的共享来源、条目数、终止状态和“覆盖未核实”标记；技术定位按需展开。不会把原供应方assistant文本渲染成平台自己的助手回复，也不会给其他读者提供隐含私有会话授权。

## 状态与恢复

| 状态 | 页面行为 |
| --- | --- |
| 无已保存终态观察 | 保留原读取入口；不创建新加载或分享 |
| 选择中 | 真实计数；空白／unsupported不可选，达到上限明确提示 |
| 预览准备 | 保留目标及选择，重复预览请求受当前域序列控制 |
| 预览可共享 | 精确正文、版本、范围及原覆盖边界均可见 |
| 提交中 | 同一原请求占用提交入口，不生成新key或自动重发 |
| 回执不明 | 显示原目标和“核对原共享”；沿原metadata／key恢复 |
| 已确认 | 显示准确原消息位置；进入任务讨论，不改变任务完成状态 |
| 目标或来源变化 | 清除失效预览，重新核对；已存在的原pending不被当作未执行 |
| 失权或当前账号／项目变化 | 清除受保护正文，阻止迟到请求重新写入；原操作按其准确范围保留 |

恢复控制器位于稳定actor／组织／project／run／node边界，独立于私有来源hash、load当前版本及164正文读取分支。原私有来源失效时，新选择与预览不可用，metadata-only原请求核对仍能由服务端按当前目标任务权限决定。离开该范围不自动换目标或换key；恢复入口不要求重读private load来重新获得原消息。

收到消息回执后核对human作者、原目标任务版本、原load／版本／序号、字面正文与安全摘要，沿原project／task消息详情核对准确目标。服务端是原operation／body映射的权威；客户端不能声称重新计算包含租户／owner的preview签名。没有原预览正文时，不伪造“已重新比较原正文”的结果。

## 视觉、响应式与多语言

复用现有React、设计令牌、按钮、表单、焦点和图标。主流程只保留一个明确下一步，来源技术细节渐进展开；等待状态依照真实请求，不制造百分比。

窄屏使用单列、完整可读的正文与可见操作，文字可换行，主要触控目标至少44px。选择、任务输入／选择、预览、返回和明确共享均可键盘完成；确认后焦点保持可预测，错误区域有可访问的反馈。减少动效不影响状态理解。

界面与安全错误当前提供中文、英文，使用域词条和现统一错误呈现；语言切换不改源文字、摘要、当前选择或原操作身份。后续语言通过相同词条合同扩展。选中内容属于用户资料，不能因界面语言切换自动翻译。
