# 简洁工具确认交互

T-CODEX-HUMAN-REQUESTS-174；suma 1.0.0；2026-10-31。负责人：工作台与主集成。关联[合同](../../contracts/codex-human-requests.md)、[架构与SOP](../architecture/codex-human-requests.md)及[限定验证](../quality/codex-human-requests-verification.md)。

## 一个入口，按需展开

在原运行节点内使用同一“工具确认”区，ACP和Codex共享布局，原生选项及执行语义分别保留。不增加管理页面或配置向导。默认只突出当前请求、命令／文件影响、完整性提示和允许动作；准确ID、摘要、协议和尝试信息收在详情中。

| 场景 | 可见行为 |
| --- | --- |
| 当前待确认 | 显示一次允许／拒绝或取消；按原生协议选择，不提供永久授权 |
| 不完整或不支持范围 | 明确提示原因，只保留拒绝／取消 |
| 已提交但响应未知 | 保留原body/key，提供“核对原提交”；普通刷新不能清除它 |
| 已决定 | 显示原用户决定，执行观察继续独立更新 |
| 供应方清理或item终态 | 移除动作；不把清理标记显示为操作成功 |
| 历史attempt | 只读；查看历史不能批准当前attempt |
| 身份或权限改变 | 清理私有内容，停止旧请求；不自动再次提交 |
| 确定冲突 | 仅在来源仍准确且非未知／恢复中时退休原提交；重新读取后再决定 |

后台轮询不触发全区加载，不打断已聚焦按钮；请求代次、Abort与当前来源检查阻止迟到GET覆盖新视图。调用方必须提供当前完整workflow及唯一原节点版本，连接断开时不允许写入。

## 视觉与可访问性

沿用现有设计令牌、14px正文、44px操作控件、2px可见键盘焦点。窄屏采用单栏，命令／差异区域局部滚动，不让整页横向溢出。多个请求按稳定身份分开，同item的多个RPC也各自保留；一次交互不隐藏其它等待请求。

五种事实明确区分：人已决定、Runner已看到、回复开始、回复完整写出、远端清理／实际item结果。状态文案不使用无依据进度或动画模拟开发完成。

中文和英文保存在独立同名领域词条中，共享稳定键和参数。当前只交付zh-CN/en-US；后续语言通过同一目录、占位符和校验合同扩展，不在组件写双语分支或硬编码供应方错误。

## 关键操作旅程

1. 打开当前运行节点的工具确认，核对影响与完整性。
2. 明确选择一次决定；提交期间防止重复操作。
3. 若响应未知，核对原提交，恢复同一回执；不再次执行。
4. 查看Runner观察、远端清理和item结果，必要时进入原运行诊断。
5. 继续代码候选、独立测试及正式验收；历史事实始终可追溯。

代表界面、真实HTTP与受控CLI的验证范围以[专项记录](../quality/codex-human-requests-verification.md)为准，不外推至完整App、所有主题或真实模型。
