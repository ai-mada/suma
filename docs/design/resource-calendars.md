# 工作日历交互

状态：T-CALENDAR-134；负责人：工作台／产品。依据：[领域合同](../../contracts/resource-calendars.md)、[架构](../architecture/resource-calendars.md)。

在项目“开发 → 排期 → 资源容量”按自然周查看资源。每行展示七天的真实配置来源、周可用工时、已分摊估算、未知诊断及日历入口；0与未知采用不同文字，不只依赖颜色。这里只展示计划数据，保留实际工时／执行配额的边界说明。

编辑按需打开，先读取当前日历。周一至周日各一项；空输入表示未知。工作周模板按钮只修改草稿，不保存。日期例外可以添加／移除，明确工时、未知及备注；保存仍是一次完整、版本化操作，不隐藏部分写入。

| 状态 | 交互 |
| --- | --- |
| 未配置 | 七项未知，提示先明确配置；不自动采用模板 |
| 只读 | 展示配置，冻结字段与保存；服务端仍控制当前权限 |
| 编辑中 | 保留日期／备注原文，脏草稿触发离开保护 |
| 保存失败／版本冲突 | 保留草稿及错误；读取当前版本后显式核对 |
| 回执未知 | 保留原PUT、原版本和原操作标识，显式恢复，不创建第二次修改 |
| 项目／资源／身份切换 | 当前请求和结果绑定原范围，取消旧读；旧回执不能写入新范围 |
| 切换语言 | 保留草稿、焦点及原文，不重新请求或翻译资源名 |

复用现有Modal、Field、错误与原操作组件和设计令牌。窄屏编辑字段按可用宽度换行，日历与列表保留文字标识、键盘焦点和减少动效。DOM与样式源码检查不等于真实浏览器绘制；当前视觉证据范围见[报告](../quality/resource-calendars-verification.md)。
