# 服务端任务视图与跨设备使用

阶段：T-VIEWS-138；初始产品1.0.0；范围属于原Multica M07与项目协作目标。本文件描述本阶段设计，实际实现和验证由阶段交付记录确认；不增加平台完成计数。完整计划仍以[实施计划](../delivery/implementation-plan.md)为准。

## 用户目标与边界

用户在开发→任务设置一次筛选与展示方式，明确保存为个人视图或项目共享视图。个人视图供同一账户在其他已登录设备使用；项目共享视图供当前有项目权限的团队成员使用。视图保存搜索、筛选、排序、布局及分组，不保存任务正文、任务快照、凭证、运行结果或批准。

共享的是工作入口，不是项目访问资格。相同视图在不同人员的当前授权下重新查询正式任务；任务、执行、独立测试、验收和部署继续各自拥有事实。加载视图、改变负责人筛选或另存视图都不启动执行。

本阶段实现在线服务端持久化及重新读取，不冒充离线操作日志、CRDT、设备授权、实时推送或全平台同步。已有本机命名视图保留原件，不静默上传、迁移或覆盖；用户可先应用本机视图，再明确保存到服务端。

## 交互与视觉

任务页保留一个正式列表／看板入口。保存区域区分“本机”“个人”“项目共享”，使用文字标注范围；主要按钮为保存当前条件，高级管理在选中已保存视图后出现。当前选中条件与保存版本不同则标明未保存，不能以选中名称暗示已同步。

保存表单只要求名称与范围，显示当前条件摘要。个人视图默认用于个人跨设备工作；项目共享说明当前项目成员可见。另存创建独立视图；更新只作用于选中的准确版本；删除需显示视图名称和影响范围。对没有管理资格的共享视图提供应用与另存，不呈现可成功修改的假入口。

桌面将范围、选择和动作安排在同一紧凑区域；390px下按顺序换行，主要触摸目标至少44px，名称不能挤走动作。加载、错误、冲突和更新事实使用文字及图标，不仅依赖颜色。复用当前紫色品牌、明暗令牌、Modal与Field，不新增装饰性统计或第二套组件系统。

| 状态 | 用户看到的事实与下一步 |
| --- | --- |
| 首次进入／空列表 | 当前范围没有已保存视图，可保存当前条件；任务查询仍可使用 |
| 正在读取 | 显示读取中；身份或项目变化后旧响应失效 |
| 读取失败 | 提供重试，保留可恢复的当前筛选；不把缓存标为当前服务端事实 |
| 保存中 | 固定本次请求内容和操作ID，阻止重复提交不同内容 |
| 保存成功 | 使用正式回执中的ID和版本更新界面，再读取当前列表 |
| 版本冲突 | 保留本地表单；可读取当前版本比较或另存，不静默覆盖他人变更 |
| 回执未知 | 保留原请求，使用同一操作ID重试核对，不能盲目另建一次保存 |
| 视图已删除／失去可见性 | 清除受保护服务端内容，说明需重新选择；不显示“已同步” |
| 当前身份或项目撤权 | 清除服务端视图及其私有输入上下文，停止迟到响应回写 |

## 架构和状态所有权

项目规划领域拥有视图对象、可见范围、版本和删除事实；身份领域提供当前人员与项目资格。保存对象只包含[任务查询合同](../../contracts/task-workspace.md)允许的条件，未知字段拒绝；不存任意URL、SQL、脚本、动作或权限声明。

后端复用现有当前授权事务、版本比较、稳定操作回执和审计机制。授权检查先于回执读取；曾经成功保存不意味着撤权后仍能读取原回执。共享可见性与管理资格分别检查，客户端按钮状态只是引导，服务端才是权威。

前端分开维护服务端读取、当前筛选、编辑草稿和待核对请求。列表分页或刷新不能自动应用某个视图；只有明确选择才将白名单条件交给现有任务工作台。新查询仍经唯一task-workspace与完整分组摘要，不建立第二份任务存储。

删除保留服务端版本化删除事实，避免迟到更新复活对象。列表使用有界读取；跨页不是不可变快照，用户可明确刷新。组件初始化沿当前1.0.0基线声明，不能重置数据库、回填旧schema或自动吞掉不识别数据。

## 实施与验收

后端、界面和生成合同按独立文件归属并行；主集成维护数据库初始化、HTTP入口、生成器、TaskViews接点及统一文档。先验证当前授权、个人隔离、共享读取、CAS竞争、重复操作及删除回放，再验证两独立浏览器上下文的保存和读取。检查界面时使用独立样例库和隔离构建，不覆盖活动预览。

代表性交互覆盖个人保存→另一设备读取、共享保存→另一有权成员应用、无管理资格另存、两个设备冲突、未知回执重试、删除后迟到更新、撤权清除、本机原件保留，以及中英／明暗／390px。通过范围由实际报告记录，不能用单元测试替代真实浏览器或多机验收。

后续继续完成离线许可与冲突中心、实时协作、混合团队、工具接入、收件箱、跨数据库及物理多机验证。本阶段不关闭这些平台目标。
