# 远程执行节点配对交互设计

T-RUNNER-PAIRING-184，suma 1.0.0。[产品说明](../product/runner-pairing.md)、[合同](../../contracts/runner-pairing.md)与[专项验证](../quality/runner-pairing-verification.md)分别记录使用目标、权威边界和实际证据。

## 原窗口内完成配对

入口放在原 Worker 登记窗口内，默认折叠，不新增管理页。当前项目自动固定。展开后说明“创建待办、在目标机器执行、核对摘要、明确批准”四步；用户明确创建十分钟待办，达到八项有效待办上限时展示服务端原因。

用户必须显式选择 PowerShell 或 Bash 后才复制对应命令。命令只带公开控制面、项目和配对定位信息，不带 token，不自动执行或安装工具。页面显示固定控制地址和绝对期限；回环地址明确仅限本机。机器自报名称旁注明其信息性质，审批依据展示完整摘要，不能只凭名称跳过核对。

| 当前事实 | 展示与可用操作 |
| --- | --- |
| waiting | 显示命令和等待机器提示，允许刷新或按原版本拒绝 |
| proposed | 显示名称、完整摘要与服务端期限；只有新鲜当前读取的 `can_approve` 才允许明确批准 |
| approved | 显示准确 Worker 与凭据期限；继续配置前刷新原 Worker 列表，不宣称持续在线 |
| rejected／expired | 展示结束原因；新配对需要独立明确操作 |
| 创建／批准响应未确认 | 原正文／键恢复优先，并向父窗口报告 locked，不能另发新操作 |
| 权限失效、来源改变或读取过期 | 清除不可继续使用的当前内容，保留原操作，显式刷新或核对 |

写 ACK 保持原快照：创建为原 waiting v1，批准／拒绝为该命令的原结果；恢复后另 GET 当前状态，不把旧 ACK 当作新鲜审批资格。页面不使用客户端墙钟计算虚假剩余秒数，只展示绝对到期时间、服务端 state 和当前资格。

## 恢复与准确接续

仅公开 locator 按原 user／organization／project 保存，秘密不进入 sessionStorage 或通用 pending。读取绑定 caller、项目、locator 和请求版本，支持 abort／stale 丢弃；换账户或组织后不能沿旧页面恢复批准。

批准后准确刷新原 Worker，按返回的 Worker ID 继续配置，不猜列表第一项。库存配置复用、暂停登记与独立启用仍走原界面。机器完成 status 当前 Grant 核对后是 prepared；后续由用户明确单次 report 或启动原 Worker。登记、prepared、库存新鲜、持续运行和启用分别表达。

控制地址或准确路径变化、secret 缺失、摘要不符及身份文件损坏，均显示原件核对原因；不引导换 token、改键、清日志或降级明文来继续。配对取消保留本机原 identity，重启同命令恢复原请求。

## 双语与 AI SOP

中文／英文使用同一状态、操作及错误事实；文案通过原目录扩展。主流程只突出命令、摘要核对和明确批准；底层 identity／Grant／receipt 细节仅在帮助中解释，不进入普通操作表单。未来增加语言或系统不新增旁路权限。

AI 不把机器名称当证明，不替管理员批准摘要，不把旧 approved 或本机 prepared 写成在线；先恢复未知操作，再依据当前身份、项目、版本和服务端状态操作。原配置与任务授权仍需分别明确确认。

后端定向与组件证据不能替代真实系统库或多机联调。SDK v0.2.6 的三 OS 适配不等于均已实机验收；Root Windows 系统库／HTTP 证据待专项报告集成。其他平台、物理多机、厂商执行及完整平台范围保持待验。

项目指南的identity上报模式仍带当前公开控制地址与项目作断言，省去手填Worker、state及token。身份文件若指向另一项目或服务，CLI在网络与日志变更前拒绝，不无声采用旧目标。
