# WorkBuddy 授权交互与 AI SOP

T-WORKBUDDY-CONNECTIONS-147，速码1.0.0。依据[产品范围](../product/workbuddy-connections.md)、[领域合同](../../contracts/workbuddy-connections.md)和[模块架构](../architecture/workbuddy-connections.md)说明当前流程；设计不是GUI或供应方验收记录。

## 工具设置中的渐进管理

“WorkBuddy 账号授权”默认收起。展开才加载当前项目中自己的连接。已有连接优先展示账号、授权状态、实际权限和访问到期。连接 ID、记录版本、授权代次和令牌代次放在“技术详情”。云任务的执行资格与进度在对应任务或运行中查看。

首次连接且当前列表为空时，直接呈现权限选择。已有账号时，通过“连接 WorkBuddy 账号”添加，或从原记录进入重新授权。权限按卡片展示用途，初始均未选。用户勾选后点击“打开 WorkBuddy 授权”，沿原 `StartAuthorization` 创建当前授权实例并打开官方确认。

浏览器在本次点击中预留仅显示准备状态的标签页，解除 opener。服务端返回有效的待授权实例且当前视角仍可授权时，标签页通过 noreferrer 链接导航到固定官方页面。预留标签页最多等待 15 秒，超时、写入未确认或视角切换时关闭仍属于本次操作的空白页。若浏览器阻止打开或标签页已关闭，界面聚焦仍有效的官方入口。桌面则沿同会话授权窗口打开本次实例。失败恢复沿用原操作标识，用户明确点击才会再次打开页面。

打开后集中显示等待确认、到期时间及“查询授权结果”。切回原窗口时自动核对原连接。链接过期、返回列表或查询到断开时，原连接仍可查看，即使原记录不在当前分页内。用户可按服务端允许的动作重新授权或替换仍待兑换的链接。授权 URL 仅存于当前组件和发起本次官方导航的页面内存。 [HTML 链接的 noreferrer 规则](https://html.spec.whatwg.org/multipage/links.html#link-type-noreferrer)

查询结果使用原连接ID，避免当前页看不到对象时误判为空。连接列表按稳定ID分页，每页20条；每次是新的当前授权读取，无精确总数或跨页快照承诺。不要按列表位置或到期时间猜测连接身份。

已有连接的卡片按当前状态突出下一步。仍可替换的待授权链接提供“重新生成授权链接”，刷新中或结果未知的连接提供“核对这条连接”，已授权的连接优先显示服务端允许的“刷新授权”。其他可用动作放在“管理账号”。到期标记来自连接的访问到期时间。刷新后的提示按返回的连接状态区分刷新中、结果未知、需要重新授权和当前已授权。

重新授权先展示可沿用的原权限，并单列已从可申请范围移除的权限。点“沿用以上权限并打开 WorkBuddy”即可为原连接申请这些权限并进入官方确认。“勾选后调整”将相同权限填入表单，便于增减。选定权限后才显示本次变更。

## 独立回调与原视角

用户明确选择范围并发起官方授权。速码准备本次实例，打开确认页，随后通过独立回调取得连接状态。回调沿隔离入口处理。

- 原浏览器cookie保持`SameSite=Strict`。首次跨站GET只交付独立bridge，不消费授权码、不兑换令牌或写连接事实。
- bridge以nonce CSP、无第三方资源、no-store和no-referrer隔离；先从地址栏移除查询，再同源读取当前会话及语言。
- `code`和`state`仅在该文档内存闭包中短暂使用，不写入SPA、浏览器存储、通用回执或草稿。普通授权链接含state，也仅临时保留在当前页面内存。
- 随后的同源POST携带当前cookie和原视角身份头；后端核对原浏览器credential、绑定nonce、项目／所有者、范围及期限。仅有同一用户ID不足以替代原会话。
- 成功后只返回固定站内工具面板路径与安全项目／连接ID。失败页提供安全提示与返回入口，不显示供应方原始错误、code或token，不允许任意回跳地址。

回调页可按当前会话语言显示中文或英文；首次加载使用可得语言。代理和运维日志须按凭据路径处理回调查询，避免将敏感参数保留为普通访问日志；不要削弱原cookie或来源校验来绕过回调失败。

## 桌面窄IPC与草稿保护

Renderer仅提交`project_id / authorization_id / user_id / tenant_id`四个ID。主进程核对原主窗口与mainFrame，再通过父Session固定GET读取当前身份、准确授权实例及允许范围；本机client／scope约束只能收紧。Renderer不能指定URL、Cookie、state、code或token。

授权子窗显式使用父Session，隔离渲染且没有preload／Node；其他弹窗拒绝，回调只接受原state与固定站内返回。关闭子窗并聚焦父窗时，不加载父URL、不重建主页面，不把窗口生命周期当授权成功。

仅在原授权仍存在、当前页面有资格且没有表单草稿、未确认写入或打开中操作时，focus才触发原连接GET；并发focus合并，结果必须匹配原connection ID。迟到结果按当前caller及尝试代次隔离，不用另一条同项目连接显示成功，不自动reload丢草稿。原生能力不可用时只分享平台入口，浏览器自行登录，不退化为导出授权链接或凭据。

服务端复用成熟`golang.org/x/oauth2`，凭据留在控制面加密保管，grant／token代次区分。未知兑换／刷新恢复原事实，不重新取得供应方POST许可。

## 状态与恢复交互

| 场景 | 界面行为 |
| --- | --- |
| 加载／空列表／未配置 | 未配置时展示可展开的部署要求和固定回调路径，有历史连接时继续展示原记录。配置及写资格允许时提供授权表单 |
| 读取失败 | 显示原地读取重试，不触发供应方请求 |
| 权限失效或范围切换 | 清除受保护列表、表单与链接；取消读取，隔离迟到响应 |
| 版本冲突 | 保留原操作事实，重新读取并明确处理当前版本，不静默覆盖 |
| 提交中／结果未知 | 锁住并行修改，展示“读取当前状态”和符合资格时的“恢复原操作” |
| 需要重新授权 | 明确重新选择范围；重新授权使旧资格失效，不偷偷更换外部主体 |
| 本地断开 | 显示影响说明，勾选确认后提交；成功只报告本地禁用 |

原操作恢复保留调用者、范围、原版本、操作标识及原JSON。控制面可接收同一安全请求来恢复原回执；供应方兑换／刷新一旦进入已准备发送、未知或失联状态，不再获得第二次POST许可。读取当前连接不替未知操作宣布成功，也不重新申请授权。

“刷新列表”是只读动作，“刷新授权”是一次显式令牌操作。本地断开清除密文并推进授权代次，使迟到响应失去接纳资格；它不调用远端撤销，也不能证明远端任务已停。配置缺失或scope收紧不剥夺当前有权所有者的本地断开入口。

复用原写恢复、离开保护和设计令牌。表单按钮、权限勾选行、链接和详情入口至少44px；主内容14px，辅助文字12px，窄屏换行并重排操作。提供中英、明暗、可见键盘焦点及减少动态效果设置；不得仅用颜色表达未知或失效状态。实际触屏、键盘与布局仍须浏览器留证。

## 操作者配置指南

配置只在控制程序环境中提供，用户表单和普通API不能传入凭据、端点或回调地址。本指南不包含真实凭据。

请先在 WorkBuddy 开放平台登记第三方应用，并将用户访问速码的公开 HTTPS 源加固定回调路径登记到该应用。应用的授权列表应包含速码允许申请的权限。[WorkBuddy 官方 Open API](https://open.workbuddy.cn/docs/openapi)

| 环境项 | 配置要求 |
| --- | --- |
| `SUMA_PUBLIC_URL` | 已验证的服务公开origin；回调固定派生为`/api/v1/workbuddy-oauth/callback`，不从Host或转发头推导 |
| `SUMA_WORKBUDDY_CLIENT_ID` | 操作者登记的供应方应用ID |
| `SUMA_WORKBUDDY_CLIENT_SECRET` | 仅服务端持有的应用secret，不进入浏览器或代码库 |
| `SUMA_WORKBUDDY_SCOPES` | 明确配置`user.task.readable`、`user.task.invokable`的非空子集，空格或逗号分隔；不默认申请全部 |
| `SUMA_WORKBUDDY_MASTER_KEY` | 若显式提供，须为规范标准Base64，解码后恰为32字节；共享数据库必须配置相同的受管密钥 |

CLIENT_ID／SECRET／SCOPES三项全部缺省时功能保持未配置，不创建不必要的密钥文件。部分配置、无效范围或回调不合法会使配置失败，不静默降级。

SQLite本机未显式提供主密钥时，在持久数据目录创建独立的32字节`workbuddy-connections.key`；已有文件须为完整普通文件，不能静默修复或替换。共享数据库不自动生成各机不同的密钥。主密钥与应用secret分别管理，备份和恢复必须保留正确密钥；此路径不代表已经具备KMS或密钥轮换。令牌只在服务端加密保管，公共投影返回白名单安全事实。

容器的 Compose 覆盖配置和 Helm 的 Secret 引用见[容器部署](../deployment/containers.md#workbuddy-账号授权)。

## AI SOP 与验收界限

AI可解释安全状态、scope和恢复路径，但不得未经用户明确授权选择权限、打开授权、刷新或断开。需要新授权时，由用户明确完成官方确认；需要恢复时，只核对原连接与原操作，不从日志、剪贴板或浏览器存储搬运code／state／token。

验收分别覆盖当前所有者／原浏览器绑定、撤权、原操作恢复、未知不重发、刷新争用、断开后的迟到响应、分页／精确ID、桌面窄IPC和focus草稿保护，以及中英／明暗／窄屏／44px／键盘和独立回调。[连接报告](../quality/workbuddy-connections-verification.md)／[摘要](../quality/workbuddy-connections-summary.json)与[窗口证据](../quality/workbuddy-desktop-oauth-verification.md)保留原模块、接线、组件与受影响复验，不能叠加为新通过数；本机原生协议样例与最终精确候选18项实际GUI／HTTP分别验证。候选使用真实production preload／controller，仅一次授权POST，供应方外网由fixture阻断；父URL／原文档保留、失败不冒充connected、英文／390px DOM与只读恢复有证据。此前样例成功回调不外推为本程真实供应方成功授权，视觉图片仍待验。
