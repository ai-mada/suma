# 原执行交互设计

状态：限定实现与验证通过；suma1.0.0；T-CURSOR-INPUTS-190。负责人：工作台代理；关联[PRD](../product/cursor-inputs.md)、[合同](../../contracts/cursor-inputs.md)、[证据](../quality/cursor-inputs-verification.md)。

沿用运行节点中的一个输入面板，不增加导航页面。任务讨论交接、专家团队和普通／Pool执行进入同一原节点；用户始终能识别项目、任务、当前执行及原输入。源详情默认折叠，核心内容与当前动作保持可见。

问题卡使用语义化单选／复选控件，显示原问题与选项标签，提交使用原ID。单选不预选，多选保留明确勾选；整个请求另有跳过与取消。Codex保留其真实文本／Other规则，Cursor不显示供应方没有的控件。

计划卡依次显示名称、概述、完整计划、原工具待办和阶段。长内容可展开和滚动，保留可选择原文；不执行HTML、脚本或将Markdown内链接当作配置。待办状态只描述工具提案，不映射平台业务进度。用户明确接受、拒绝或取消，没有默认接受；拒绝原因仅进入原typed答复。

确认前说明：接受仅答复原工具，可能在隔离HOME写入计划文档；不会批准后续命令或修改正式需求／验收基线。权限请求仍独立展示，计划确认不能变成“全部允许”。

| 状态 | 用户反馈 |
| --- | --- |
| 加载／空态 | 表达读取中或当前无输入，不伪造等待问题 |
| 待回答 | 原内容、明确控件和提交动作；无预选决定 |
| 已保存 | 只表示控制面保存；不提前显示已送达 |
| 执行器观察／写入 | 分别展示真实事实；完整写不是native ACK |
| 执行关闭 | 只读保留原内容与决定；不在新attempt自动再次应用 |
| 未知／冲突／撤权 | 原意图恢复优先，禁止偷偷重建答复；保留原依据 |

恢复缓存仅存准确scope、源元数据及原答复意图，不复制完整问题或计划正文；来源读取上限有界，整个原意图在新attempt下仍按原操作恢复。换项目、账号或组织不混用缓存。

中文与英文使用同一组件和状态映射；390px默认单列，原生键盘焦点、可见焦点环、标签与忙碌状态沿现设计系统。验证选择问答、多选、计划确认及未知恢复代表状态，不重复整套设备矩阵。
