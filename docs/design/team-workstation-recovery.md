# 共享工作台恢复交互设计

版本1.0.0 · T-TEAM-WORKSTATION-RECOVERY-218。依据[合同](../../contracts/team-workstation-recovery.md)，用户步骤见[产品说明](../product/team-workstation-recovery.md)。

## 一条清晰的主路径

项目工具详情保留原操作与Doctor。共享节点卡只在准确来源仍成立时提供“管理共享节点”；进入原拥有方工作台后，用一张渐进恢复卡展示目标、核对状态及下一步。明确准备后复用原弹窗、私有配置表单和连接区，不增加第二套节点控制台或调度器。

恢复卡与新增表单动作采用44px触达目标，中英文、键盘和窄屏布局保持一致。读取中、受限、未完成、到期与原操作未确认分开说明；不使用“已连接／已修复”概括登记、授权、库存和执行等不同事实。公共弹窗原有控件不属于本轮全部44px的声明范围。

## 来源、草稿与资格分离

公开定位pin固定Pool／Runner／Worker、租户／项目、原工具ID／版本／SHA及adapter／protocol，不包含私有路径、命令或凭据。URL仅表达定位意图；进入拥有方和返回项目都重新读取当前权限与准确来源，A→B→A不能恢复旧异步回应。

| 对象 | 保存与采用规则 |
| --- | --- |
| 当前读取 | 准确Runner GET与原readiness核对同一节点、凭据代次和项目授权；不以首页未找到判定不存在。 |
| 本地有效期 | 最多30秒，扣请求耗时并夹身份到期；只控制界面资格，不新增服务端授权租约；不自动轮询。 |
| 私有表单 | 只在原表单内存中填写。同来源到期保留输入，撤掉预览并禁生成／复制／继续；弹窗内明确重读后才能恢复。 |
| 返回定位 | 只有当前can_open_project允许链接。同原项目tuple带回准确pin，其他项目使用原通用接入；原工具变更要求重新选择。 |

保存表单的公开basis只用于保持显示，不代替当前读取结果。真实账户、API、Pool、Runner身份或来源变化继续触发原失效规则；原未确认写入与未知检查优先，不能以准备入口绕过。

## 模块职责

- `ToolWorkspace`／Root导航：构造与核对公开pin；回项目后重读原工具和诊断，再沿原Quick交接。
- `PoolToolRecoveryPanel`：当前拥有方准确读取、短期展示、明确准备时重读；受限时不生成普通项目身份。
- `PoolWorkspace`：保留原写回执与弹窗，区分表单展示basis和当前采用资格。
- 原准备／连接组件：只预选当前已批准授权的公开项目标识，保留原私有配置、Shell引用及连接模式；当前权限决定回项目链接。
- 原Pool控制面：新增准确Runner只读入口复用原管理权限和DTO；无新表、凭据权威或派发器。

## 桌面离开与收尾

原生控制器默认留下，单个待确认意图不重复排队。已捕获的关闭、退出或准确同源主frame导航，取消原卸载后异步确认；明确离开且窗口、document epoch与意图仍一致时，只重放一次。不能在异步返回后操作早已结束的旧事件，也不设置永久绕过。

无法预先取得准确目的的重载等情形使用官方同步确认，在当前事件内决定；其对话框会短暂阻塞主进程。窗口真实`closed`之后才进入原managed Runner、工具与服务的唯一收尾链。留下保留原服务与IPC，离开不伪造停止回执、清除Journal或认定业务完成。

## 实施与AI SOP

维护时先复核原未确认操作，再检查当前来源与权限，随后验证准确读取、同来源保值／到期禁采用、受限拥有方及回项目定位。复用未变化的原执行与授权证据；记录生产组件合成界面、真实桌面事件、注入确认回应及真实目标机器执行的区别。真实远程修复、Worker收尾、跨平台和完整31项／P0–P7仍需对应证据。
