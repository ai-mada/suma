# 开发客户端接入设计

阶段：T-EXPERIENCE-133。范围：既有工具接入向导中的项目 MCP 配置导出。本文描述实现边界，运行验证以本阶段质量报告为准。

用户先选择开发客户端，再按「签发专用令牌 → 合并项目配置 → 在客户端确认工具」完成接入。入口默认折叠；用户打开后才读取既有 `GET /developer-connection?project_id=…`。配置正文另行折叠，复制和下载始终明确触发。剪贴板或下载失败时展示可选中的只读文本框，保留同一份无秘密片段。

客户端选项共八项。Cursor、Claude Code、Codex、OpenCode 的官方项目配置和环境令牌语法已核对，可以导出真实片段。Qoder、Zed、WorkBuddy 和 Harness 只提供具体指南及限制，不伪造环境引用、不生成未经核实的配置。具体来源和字段见[操作指南](../integrations/developer-clients.md)。

复用当前项目 MCP 服务、元数据类型、身份解析和 Codex 格式化；公共 `projectConnectionEndpoint` 统一核对准确项目路径、HTTPS 或显式回环 HTTP、无用户名密码、查询和片段。原始 URL 只能由源地址和准确项目路径构成，不能经路径归一化换成另一地址；显式默认端口保留原值。项目 ID 限制为现有安全标识字符。客户端配置使用 `suma_<project_id>`，避免不同项目导出同名服务器；现有令牌页的默认 Codex 服务名保持不变。

每次读取绑定原项目、当前 API 视图、刷新版本及取消代次。当前用户／组织上下文存在时，元数据必须匹配两者。切换项目、账号或组织立即移除旧配置，迟到响应不能重新展示。复制完成也绑定原配置、语言、客户端和代次；切换后不能显示旧成功反馈。不持久化配置或凭据，不读取令牌签发结果，不发起 MCP 调用或客户端探测。

导出属于客户端使用项目能力的入站方向。Runner 探测、档案登记、单独启用、模型调用和 Go 唯一调度仍沿现有合同，配置导出没有执行资格。界面保持「尚未验证连接」，不把元数据读取、下载或复制记为安装、认证或厂商客户端验收。

组件使用既有主题变量、明确标签、键盘焦点、加载与失败重试、窄屏按钮及可折行代码。中文与英文采用独立成对 `developer-clients` 目录；品牌、地址和标识不随语言改变。
