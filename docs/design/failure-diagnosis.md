# 失败证据、模型分诊与修复草稿交互

状态：T-P4-030 已完成代表性实际采用、中英界面及最终冷回读；版本：1.0.0；日期：2026-10-27。
依据：[合同](../../contracts/failure-diagnosis.md)、[PRD](../product/failure-diagnosis.md)、[架构](../architecture/failure-diagnosis.md)、[限定验证报告](../quality/failure-diagnosis-verification.md)。
沿用现有专业工作台、已批准 12ui 设计、Field／Radix 边界和主题令牌；不调用付费设计、不上传材料、不新增依赖或顶层导航。

## 入口与主路径

同一默认折叠的 `FailureDiagnosisPanel` 嵌入原失败节点、专家计划阻断卡片和原问题详情。
props 固定 `session`、`project`、`source{run_id,node_id,attempt}`，可选 analysisId、onAnalysis、onChanged、refresh。
入口只传定位，服务端负责来源、fence、权限和问题归属；不根据标题、问题 ID 或模型文字猜尝试。

无深链／待恢复请求时折叠零读取。有效 analysisId 只展开读取准确来源的原分析，不自动调用模型或采用。
保持单列短区块，适合运行侧栏和任务详情，不复制知识页面的复杂导航。
宽屏展开分诊时适度加宽 inspector，使修复表单与原件阅读可用；窄屏仍保持单列，不改变其余工作台布局。

主路径为“固定失败事实与发送范围 → 模型／预算／同意 → 真实诊断运行 → 简单修复草稿 → 明确采用／打开已有需求”。
观察、假设、建议、原模型输出和技术摘要按需折叠。模型摘要可直接读，不能将观察标题写成已确认根因。
原失败 run 与诊断 run 使用不同入口；专家卡片保留外层原计划定位，不因创建分析丢掉返回路径。

## 发送范围与空态

证据每行先展示类型及“完整／末段”和选中／总字节，用户在同意调用前即可看到实际发送范围。
文本及完整来源 SHA 默认折叠；末段明确是局部证据，完整原件可回原运行查看。
不在浏览器裁剪或自动添加源材料，也不把大文本省略号冒充完整输入。

| 情况 | 界面行为 |
|---|---|
| 当前结果未知／需要核对 | 展示原 run 核对入口，禁止新诊断 |
| 失败问题尚未投影 | 明确等待并提供刷新，不在 GET 创建问题 |
| 无可执行专属模型 | 显示工具设置和载入更多入口，不给普通规划／提炼模型替代选项 |
| 配置存在 | 显示固定模型与 origin，并说明不代表账号健康 |
| 已有回流需求 | 打开真实记录，不覆盖、不创建第二份需求 |
| 读取 403／账号范围变化 | 隐藏旧事实、终止旧请求，不保留可用的旧采用权限 |

所有新输入、选择和复选控件使用明确可访问名称；使用已有键盘／焦点习惯，窄屏为单列，主要触点 44px。

## 模型调用与进度

目标为普通文本，输出预算为 1–8192 Token，默认 4096；单次调用不提供循环轮次选择。
确认文案明确将页面所示证据范围发送给预置模型，改变目标、来源或配置后重新确认。
真实运行只展示持久状态和准确诊断运行链接，不虚构百分比、进度文案或账号健康。
只读有界刷新在面板关闭、后台页面或终态时停止；网络未知不自动另起调用。

## 简单修复编辑与采用

默认编辑标题、说明、优先级和每行一项验收标准，最多 16 条。只维护一份 repair 草稿事实，模型 proposal 及原件不改写。
观察和假设保留证据引用与模型置信估计，均只读；建议和测试步骤不直接变为执行命令。
正文、标题、模型内容和源码原文不翻译，系统标签与受控宿主理由走成对中英文目录。
机器理由使用服务端独立诊断元数据按当前语言显示；切换语言不必重新 GET，也不猜译恰好等于模板的人工理由。

编辑后的修复需先保存，再填写理由并明确确认采用。采用请求不夹带未保存 repair，也不偷偷修改原模型 proposal。
成功后链接真实需求，并说明其当前状态需打开查看：创建／关联需求不代表已修复、已发布或原任务已验收。
已有需求直接打开，不重复采用；失败诊断仍可检查原件并关闭。

## CAS、原操作与范围隔离

409 保留修复字段、验收条目和理由；明确读取最新版本后更新 CAS，清除采用确认，不自动重置草稿或采纳新来源。
固定 source 已变化时保留分析／原件并阻止采用，只有需要采用的状态显示该阻断提醒，历史已采用／已关闭不误报待办。
HTTP 不确定先恢复原 path／body／key 和原调用身份；command 需先读到同项目、同原失败尝试的准确 analysis，再允许恢复。
同路径刷新保留可读值但禁止过期写，跨范围立刻隔离并 Abort，语言切换保留输入与原 locale 的待恢复请求。

## 必要验证边界

组件聚焦折叠零读取、未知禁分析、专属能力与同意、完整／末段范围、准确运行链接、有界只读刷新、
同 key 恢复、repair-only CAS 保稿、保存后明确采用、已有需求去重及原模型输出保留。
生成合同／类型／中英检查、一次真实本地模型协议与代表性浏览器流程分别记录；不以这些结果宣称厂商、跨机器或生产通过。

## 最终代表性界面证据

实际流程从准确失败证据创建诊断，阅读模型原件后人工修订 repair，再明确采用为需求草稿。
分析 adopted v4 与需求 draft v1 保持独立状态，原件和固定来源摘要不因人工修改而改变；没有将采用写成已修复或已验收。
原问题已有修复需求时可回到当前记录；需求详情按选中项读取类型化采用来源，链接可返回原分诊。

最终独立 `web-release` 冷回读通过分诊深链、需求来源回链、刷新及中英切换，宽屏加宽样式有实际截图。
