# 修复计划修订与执行历史交互

状态：T-P4-033／1.0.0，2026-10-27。定向组件、真实响应结构、类型及隔离warm14项／最终cold代表性交互已验证；主预览warm21项也通过。见[限定验证](../quality/candidate-repair-revisions-verification.md)。完整设备矩阵、厂商／跨机器／生产及完整平台验收继续实施。

依据：[冻结合同](../../contracts/candidate-repair-revisions.md)、[032交互](candidate-conflict-repair.md)、[前端检查与待验收步骤](../quality/candidate-repair-revisions-ui.md)。[English](candidate-repair-revisions.en.md)。

## 同一任务的新预览

入口位于修复子任务的合成详情，沿用现有紧凑单列、Field、图标及 surface／border／muted 令牌。原冲突任务仍保留失败结果；修订使用同一修复任务、原冲突身份和全部有序来源，产生新的计划 ID，不复制任务。

计划摘要显示服务端固定的计划版本、修订序号、流程版本、产出 Agent、原生工具版本和执行路由。历史计划保留原运行及结果，提供准确的当前、上一版和初始计划链接；打开旧链接不会自动跳到当前版本。

“创建者、理由与固定定义”默认折叠。创建者来自安全的服务端投影，不以当前查看者代替。早期定义若标为 observed，明确显示观察时间；不能把它称为原准备时间，缺失作者也不能补写。

## 明确修订与单独启动

“修订修复计划”默认折叠；无待恢复操作时，折叠不读取修订上下文或配置。展开后先读当前修订资格，允许修订时才加载真实流程、原生工具及当前项目执行路由。

表单顺序为流程版本、原生工具、代码产出 Agent、当前路由、理由和确认。配置不自动选第一项；产出节点限于根 Agent，并保留独立候选测试。未启用、不可用、只读或未声明修复协议的工具不可选择。改变流程或工具清除产出节点；改变选择、理由或依据清除确认。

当前项目路由只读，区别于旧计划已经固定的路由。服务端准备新预览并在 Start 时再次核对；客户端不提交任意路由。

| 中文动作 | English | 结果 |
|---|---|---|
| 修订修复计划 | Revise repair plan | 展开修订资格和配置 |
| 准备修订后的预览 | Prepare revised preview | 明确准备新计划，保持同一任务 |
| 找回原修订 | Recover original revision | 核对原请求及操作编号 |
| 任务执行历史 | Task execution history | 展开准确运行与计划关联 |

修订成功只打开返回的新计划 ID，更新 `record=<same task>&panel=composition:<returned plan>`，并清除 Start 确认。它不创建运行、不调用模型。新预览仍须明确勾选后单独启动。

待启动计划可以修订。失败计划仅在服务端认证所有相关尝试都于工作区和主进程进入前失败时允许替代；错误文字、缺少输出或超时均不构成认证。界面展示前序运行、认证尝试数和恢复依据摘要。结果未知继续核对原操作。

“重新核对并延长预览”仍是原定义的有效期刷新，须独立理由；它不替代流程或工具修订。接受后的计划不能修订。

## 草稿与回执恢复

409 保留选择及理由，明确读取最新计划、上下文和配置后重新确认。401／403 立即隐藏受保护的子计划事实和表单。

写前按账号、组织、项目和原计划保存准确 path／body／key。成功 HTTP 状态仍须通过响应结构及任务、来源、父版、所选定义校验，才清除持久请求。错误结构的200与丢失回执均保留原操作；重开或刷新后仍找回同一请求。即使原计划已成为历史版本，有待恢复操作时仍提供找回入口。

账号、组织或项目切换隔离旧草稿和读取；晚到结果由原范围消费。恢复不会选择“最新计划”，也不会启动新运行。

## 执行历史、用量与中英文

“任务执行历史”是合成面板旁的独立折叠区，展开后按运行 ID 分页去重。每行提供准确运行链接及已有的固定计划链接，区分任务当前运行与较早运行。替代预览创建后、单独 Start 前，前序失败运行仍是任务当前运行。

真实绑定显示已记录的任务版本和绑定时间；后来观察到的旧关联显示观察时间，保留 `task_version=null`、`bound_at=null`。读取历史不创建记录，也不从当前任务补写旧时间或版本。

用量界面将 `host_startup_proof` 显示为“已认证的执行启动前失败 / Certified startup failure”。已知零 Token 和未定价费用分别显示；`null` 费用不变成零价，缺失的其他计数也不补零。

系统标签及已知阻断随当前中英文切换；任务文字、用户修订理由、代码、路径及不可变原件保持原文。输入有显式名称，主要控件沿用44px触点，长 ID／摘要换行，窄屏保持单列；实际键盘、窄屏及刷新效果仍按[待验收清单](../quality/candidate-repair-revisions-ui.md)记录。
