# 任务内受控仓库集成交互设计

状态：T-P4-028 中英文界面、集中类型与实际浏览器流程限定本地已验证；版本：1.0.0。
依据：[冻结合同](../../contracts/repository-integration.md)、[PRD](../product/repository-integration.md)、[架构](../architecture/repository-integration.md)。
沿用既有专业工作台、12ui 已批准设计约束、本地组件和设计令牌；无外部材料上传、新依赖或额外顶层导航。

## 入口与布局

原任务详情增加一个默认折叠的“集成已测试候选／Integrate tested candidate”面板。
`RepositoryIntegrationPanel` 接收 `project`、`taskID`、`session`、`refresh`、可选 `planID`、`onPlan` 和 `onRefresh`。
URL 的 `panel=repository-integration:<planid>` 恢复该任务的真实原计划；`onPlan('')` 只清除定位，不发起准备请求。

未给深链且没有原请求待恢复时，折叠状态零请求。合法计划定位或持久待恢复请求可展开读取事实，不自动批准、执行或调用模型。
页面不修改 IDE 的 `/workspace` 绑定，也不把“版本资料”或发布制品页面改成 Git 集成状态。

主体采用单列短区块，按当前阶段显示主要动作：

1. 准备区：候选、目标、固定来源运行和准备按钮。
2. 审阅区：目标名称／分支、事实状态、实际运行链接、两个提交、文件清单和真实 diff。
3. 决策区：理由、当前阶段专用确认勾选和单一主动作；拒绝为次要动作。
4. 核对区：原操作事实与当前阻断理由；未知时只有原请求恢复或经授权的核对，不提供结果下拉框。

目标绑定管理、固定摘要／原件和历史各自折叠，避免技术内容淹没主路径。目标绑定表单留在本面板内，
普通读取者和没有 `can_manage` 的用户不显示可写管理表单。

## 准备与目标管理

候选只来自 `/repository-integrations/options` 返回的当前项目、任务和来源节点；选项显示真实节点与提交短摘要。
固定任务版本、candidate attempt、原运行和 sealed bundle 依据可按需打开。
没有合格候选时说明先完成独立测试及任务验收；不能手填候选 SHA 或选择任意运行来补造证据。

目标选项显示名称和完整 ref；paused／retired 不可用于准备，活动操作或当前阻断原因明确列出。
没有绑定目标时说明批准者可绑定预置目标；没有 provider／alias 时说明先由管理员配置，不能输入任意 URL、路径、命令或秘密。
管理表单只选择预置 provider／alias 并填名称，实际 ref／配置由服务端向提供方读取。
已有目标仅按版本调整名称与状态，不把一次绑定改指向另一个仓库。

“准备真实差异”是一笔明确 POST，固定任务和目标版本并创建异步准备运行。
准备期间显示真实运行入口，不伪造完成百分比；页面不据此宣称目标已更新。
没有准备权限仍保留当前可读来源、历史和原计划入口。

## 差异审阅与明确决策

预览显示预期目标提交和结果提交，说明结果就是已测试候选，当前仅支持快进。
文件清单保留真实路径、旧路径、状态和 binary 标记。diff 为提供方返回的完整有界文本，使用只读、可键盘聚焦的滚动区。
不把 HTML 或文件内容解释为界面，不猜译源码、路径、diff、用户理由或候选原文。
不提供可编辑 diff、任意冲突命令、通用 merge／squash 下拉框或“忽略限制”按钮。

最多 1000 个变更文件、512 KiB diff；不支持完整审阅或不满足快进时显示阻断，批准按钮不可用。
完整内容受限属于明确失败条件，不显示一个被截断但仍可批准的预览。

| 当前事实 | 主动作 | 必须具备的确认 |
|---|---|---|
| ready 且当前 `can_approve` | 批准此差异 | 理由、固定差异可审阅、明确批准勾选 |
| ready 且有浏览器批准权 | 拒绝计划 | 理由，不产生目标写入 |
| approved 且当前 `can_execute` | 执行已批准集成 | 理由、单独的执行确认；批准后不会沿用已勾选状态 |
| 当前 `can_reconcile` | 核对原操作 | 理由、确认检查／必要时阻止原请求继续写入，由证据确定结果 |
| integrated 且完整回执一致 | 显示已确认集成及原运行 | 不提供人工“标记成功” |

所有写动作以当前读取事实和服务端 `can_*` 为准。刷新时旧值可保留阅读，读取进行中或失败时不能据旧值发起治理动作。
批准、执行、核对后的版本或状态变化清除确认勾选；理由保留，避免丢失审阅工作。
期限使用当前语言的本地年月日和时分，不使用只显示日期的默认格式。

## 冲突、未知与凭据隔离

409 保留来源／目标选择、决策理由和目标设置草稿。“读取当前版本并保留草稿”重新读取原计划及当前选项，
不会把旧批准自动套到新 basis；确认勾选清空。若来源或目标已变化，按明确新准备操作建立另一计划。

不确定的 HTTP 响应通过 `useWriteAction` 保存原 path、body、方法及 idempotency key，再发送请求。
同 key 重放只恢复原决定；不能以换 key 创建替代操作。待恢复的 command 先定位原 plan，
成功读取并验证其 project／task 一致后才允许恢复，不能把另一个任务的存储残留直接重放。

外部效果 unknown 时显示待核对提示，保持目标屏障。准备／执行／待核对期间禁用“重新准备计划”，
未得到原操作正向或负向证明前不显示集成完成。当前活跃租约、撤权或提供方不一致由服务端明确拒绝，
界面不会让人选“已生效／未生效”来替代真实证据。

组件按账号、组织、项目和任务键隔离，切换时立即卸载并 Abort 旧读取；旧响应不能渲染到新范围。
读取被 401／403 拒绝时隐藏旧可读事实，要求用有权账号刷新；未知写保留原调用身份及 scoped storage，不改用后来账号解释原操作。

## 事实展示与更新机制

“已集成”要求当前计划及完整 provider observation／Git receipt 一致，包含原 operation、请求摘要、目标、
ref／配置、before／result、bundle／prepared SHA、generation 和 effect grant。
普通 Git HEAD 相等、Runner exit 0、准备完成或批准记录均不单独产生此成功提示。
完整摘要、批准者与理由、原验收快照、实际 Git receipt 在“固定依据、批准与回执”中查看。

只对当前选中计划的活动准备或执行 run 连接已有 run-events SSE；通知经合并队列刷新原计划和本任务历史。
离开、折叠或终态后关闭流，不轮询全部项目。断线时保留持久 GET 和明确刷新入口。
历史默认折叠并按需加载更多；`before` 是服务端返回的 opaque cursor，浏览器原样编码转交，不推导游标内容或权限。

## 中英文、主题与必要验证

自有控件、状态及受控诊断使用独立 `repository-integration` 中英文目录；宿主固定理由通过闭合集合映射，
未知理由保留原件，不用全局字典猜译用户或源码内容。主状态都有文字，颜色仅辅助表达。
使用现有 `--surface`、`--surface-soft`、`--muted`、`--border`、`--accent`、`--green`，窄屏表单收为单列、
主要动作保留 44px 触点，长 SHA／ref 可换行，diff 独立滚动而不撑开整个任务详情。

首轮必要交互覆盖默认折叠、当前权限、账号／项目隔离与在途取消；预置目标绑定到真实差异的分步确认；
409 理由保留、原请求未知恢复；非快进阻断和原操作回执核对。生成类型、集中构建、真实提供方和代表性 CN／EN
浏览器流程分别完成并记录，不因组件检查通过就宣称完整链路或生产已验收。

阶段实现、实际 Git／中英文旅程及未验收边界见[限定验证](../quality/repository-integration-verification.md)。
