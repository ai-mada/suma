# 本机凭据续期交互

T-DESKTOP-CREDENTIAL-178；suma 1.0.0；2026-11-01。状态：源码、定向、真实私有CLI与代表合成组件验证通过，完整桌面与生产待验。负责人：主集成代理；关联[产品流程](../product/desktop-runner-renewal.md)、[架构与 SOP](../architecture/desktop-runner-renewal.md)和[合同](../../contracts/desktop-runner-renewal.md)。以下为当前交互规范，代表界面和实际行为证据由质量报告另行记录。

续期位于原工具连接卡，不新建账号、配置页或任务入口。用户看到原工具、工作区和 Worker，再明确选择“续期凭据”。界面只提交原 scope 与动作；路径、token 和私有 HMAC 请求由主进程处理。

## 两种期限分开显示

| 显示 | 来源与解释 |
| --- | --- |
| 凭据登记有效至 | `credential_expires_at`；Worker 登记／续期期限 |
| 凭据版本 | `credential_version`；不是工具版本或任务 attempt |
| 库存观察有效至 | `expires_at`；工具观察的新鲜度，不证明凭据仍有效 |

使用带时间和时区的本地化日期，保留准确 `time datetime` 值供读取；缺少元数据时显示未提供，不能猜测有效或已过期。凭据到期、库存过期、授权被撤销三种情况分别表达。

## 状态和动作

| 当前事实 | 呈现与下一步 |
| --- | --- |
| 原 Worker 已停止且信息齐全 | 显示“续期凭据”；点击后进入忙状态 |
| 正在续期 | 显示“正在续期”，阻止重复操作、改配和绕过原操作的选择器 |
| `renewal_unknown` | 显示“原续期结果待核对”；同一按钮改为“核对原续期” |
| 本机／服务端未排空 | 显示具体下一步，保留原 pending 正文和 key |
| 续期已确认 | 显示新登记期限和版本，状态为 `prepared`；用户再明确连接 |
| 正在连接／等待库存 | 显示原启动状态；库存确认前不能显示已连接 |
| 原登记未知、停止未确认、解密失败或来源变化 | 保留各自状态和原核对路径，不能伪装为续期成功 |

`renew`、`connect`、`status`、`stop` 是独立动作。界面丢失 `renew` 的响应时，不能用 `status` 或普通 `connect` 冒充续期回执；续期未知也不能改走新登记。Qoder／Codex 等子入口把 busy／unknown 传给父容器，切换选择器不能解除原操作约束。

## 闭合原因提示

| `renewal_reason` | 用户可理解的说明与处理 |
| --- | --- |
| `execution_pending` | 服务端仍有执行或副作用待核对；先处理原执行，再核对原续期 |
| `local_state_pending` | 本机进程、日志或待回执尚未确认安全；正常停止并保留原状态 |
| `credential_changed` | 当前凭据或版本已变化；核对原操作和当前身份，不覆盖旧状态 |
| `access_changed` | 当前权限或原授权不再满足续期条件；恢复合法授权后核对，撤销不能自动复活 |
| `context_changed` | 项目、实例或工作区来源发生变化；回原来源核对 |
| `result_unknown` | 尚未取得确定回执；继续核对同一次续期 |

这些原因与私有 Inspector 的六类原因是两套合同：本机检查失败可归为 `local_state_pending`，不把私有路径、日志或原始错误显示给用户。重启后未保留的细分原因降为 `result_unknown`，不能推断原操作已失败或可以换 key。

中文／英文沿原词条成对维护。窄屏采用单栏且不挤掉原因与主要动作；长 Worker／版本事实可以换行。按钮保留可见键盘焦点和明确忙提示，结果更新不抢焦点。异步结果必须匹配当前账号、组织、项目与工具，来源切换后忽略晚到响应，保留仍属当前来源的草稿。

最终路径为：`prepared → 明确连接 → 新库存确认 → 原档案暂停登记／明确启用`。续期不会产生启用、模型成功或正式验收的证据。空闲续期之外，旧授权到期且仍有未结副作用的专用恢复票据尚待实现；完整 31 项／P0–P7 范围不缩减。
