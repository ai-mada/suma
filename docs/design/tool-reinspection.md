# 工具重新检查交互

状态：限定实现与验证完成；suma 1.0.0；T-TOOL-REINSPECTION-194；负责人：工作台代理。[需求](../product/tool-reinspection.md) · [架构与AI SOP](../architecture/tool-reinspection.md) · [合同](../../contracts/tool-reinspection.md) · [验证](../quality/tool-reinspection-verification.md)。

工具详情保留当前配置、准确执行节点和一个明确下一步。重新检查是一项真实管理请求，状态刷新只是读取；按钮和反馈必须准确区分这两种行为。技术字段默认折叠，用户不必填写请求ID或领取凭据。

| 场景 | 展示与操作 |
|---|---|
| 可发起 | 显示检查目标；由当前有管理权限的用户明确发起，不默认改变启用状态 |
| 创建中或回执未知 | 保留原操作标识，阻止重复创建；恢复同一操作 |
| 等待节点 | 展示已保存请求和准确节点，允许读取原请求；不以旧库存显示完成 |
| 检查中 | 说明原节点正在检查既有配置；不显示虚构进度百分比或模型健康 |
| 检查结束 | 提示本次报告已保存，重新读取原工具诊断；配置不匹配仍可作为真实阻塞显示 |
| 失联或结果未知 | 保留请求与原操作，提供核对入口，不自动重试执行 |
| 失权或切换项目 | 清除受保护旧事实，停止使用旧回调；用户公开草稿按原scope隔离 |

当前工具筛选为空只提示“没有匹配的连接”，清除工具筛选时保留全局任务状态和项目位置。工具接入主按钮保持唯一，空态不把筛选结果推断为从未接入。

从Doctor进入快速连接时，原工具或公开草稿中的worker是显式目标。本机连接状态即使有效，也不能自动替换它。用户明确切换节点后，新目标才可以参与库存读取、配置匹配和登记；迟到回调必须仍绑定原调用方及目标。

中文和英文共享状态与操作逻辑，窄屏按同一顺序展示目标、状态、下一步及折叠详情。使用既有焦点、加载、确认与错误组件，不增加第二管理页、复杂流程画布或无依据的“智能修复成功”提示。
