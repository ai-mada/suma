# 原结果恢复交互

T-DESKTOP-RESULT-RECOVERY-179；suma 1.0.0。依据[冻结合同](../../contracts/desktop-result-recovery.md)，关联[产品流程](../product/desktop-result-recovery.md)和[架构](../architecture/desktop-result-recovery.md)。本页定义当前交互语义；具体实际通过范围以最终集成证据为准。

入口位于原本机工具连接中，服务于“原结果已提交、ACK 丢失、凭据到期”。一个恢复卡显示原结果总数、已核对数、仍待核对数和下一步。凭据生命周期与恢复进度分别表达：恢复完成不等于已续期、已连接、任务成功或可安全派发。

## 阶段与操作

| 阶段 | 显示和允许的操作 |
| --- | --- |
| 待恢复 | 说明恢复只核对已有提交；用户明确开始，先确认原进程关闭 |
| `prepared` | 原计划已私有保存；继续该计划，不另建操作 |
| `checking` | 正在核对或应用原回执；显示忙状态，阻止并行切换、登记或换配置 |
| `unknown` | 原核对结果未知；保留原操作，提供状态核对入口，不自动走连接 |
| `complete` | 该计划本地 ACK 已补齐；继续显示原只读检查和独立续期入口条件 |
| `partial` | 展示已恢复及剩余数量，按缺失、不符或其他未结原因继续处理 |
| `blocked` | 给出授权、来源、活动进程、状态变化等准确原因及下一步；保留原件 |

`manageLocalTool` 的 `recover` 明确开始或继续原恢复；`recovery-status` 只读取原状态，不创建计划。忙或结果未知时，父级切换和新登记受阻，但原状态核对入口保持可达。关闭或折叠界面不能替换原计划、操作标识或已持久化结果。

## 原因与文案

中文“回执核对／补齐本地确认”对应英文“receipt reconciliation／restore local ACK”。“结果未知（unknown）”须保留原含义，不能写成执行失败或成功。缺少原回执应提示继续核查原提交；凭证到期应提示在当前授权下重查原计划；来源或账号变化应回到准确原连接，不提供绕过入口。

核对凭证过期只影响本次 ACK 应用，不等于安装、模型目录或机器凭据发生变化。续期未知先恢复原续期回执；恢复入口不能覆盖或清除其 pending。未解决的 sidecar（旁路日志）、云／工作区／发布副作用及 `unknown` 继续显示为续期阻塞原因。

前端仅接收安全 `recovery` 摘要：操作标识、阶段、非负整数计数和固定原因码。正文、路径、Plan、Proof、密钥及原凭据均不得进入 renderer。所有结果必须属于当前 scope；账号、组织、项目或连接来源变化后，迟到结果不能恢复旧私有视图。

沿原组件与令牌提供中英文、可见焦点和明确忙状态。主要流程不要求手写 JSON。恢复、续期、明确连接、暂停登记和启用分别操作；本片不新增执行入口，也不宣称完整平台目标已完成。
