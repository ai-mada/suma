# 工具维护与核对恢复交互

状态：限定实现与验证完成；T195；suma1.0.0；负责人：工作台代理。[需求](../product/tool-recovery.md) · [合同](../../contracts/tool-recovery.md) · [架构](../architecture/tool-recovery.md) · [验证](../quality/tool-recovery-verification.md)。

沿原工具详情与检查面板展示能力和恢复，不增加第二个工具中心。主要下一步仍唯一；体检各阻塞项可以提供准确的次操作，读取仅导航、不自动写配置。

| 当前事实 | 界面行为 |
|---|---|
| 新鲜支持 | 允许当前有权限用户明确请求新检查，不推断工具或模型健康 |
| 能力过期 | 显示过期；明确刷新原详情，保留原意图，不能打开弹窗续期限 |
| 不支持或未知 | 说明未观察到可用协议；不以adapter、在线身份或一次上报替代 |
| 原结果未知 | 提供一次“核对并释放本次维护占用”，展示准确原节点和作用范围 |
| 等待原停止证明 | 保留原请求；支持查询和稍后核对，不新probe、kill或盲建 |
| 证明已保存 | 显示仍待节点持久接纳，不提前说占用已释放 |
| closed_unknown | 明确“占用已核对关闭，原结果未知”，之后新检查为独立动作 |
| 缺证明或身份不符 | 解释无法核对，打开准确原节点的隔离／配对入口，不自动操作凭据 |

原创建ACK未知与机器执行结果未知分别处理。恢复元数据按actor／组织／项目／工具稳定隔离，原版本、引用和摘要留在原意图内；不能因为当前配置变化就丢失原操作。失权清除受保护旧事实，非在途“稍后核对”可以关闭弹窗并保留原件。

当前能力读起点与成功数据同caller／scope／epoch绑定。明确刷新读取原ToolProfile，保留dialog与恢复记录；没有可靠单调起点时不显示fresh授权。原恢复不被新检查的fresh门反向锁住。
