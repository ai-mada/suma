# 工具准备与恢复交互设计

T-TOOL-PREPARATION-203；suma 1.0.0；负责人：主集成代理。状态：本阶段限定实现与验证完成，见[验证报告](../quality/tool-preparation-recovery-verification.md)。关联[PRD](../product/tool-preparation-recovery.md)、[架构](../architecture/tool-preparation-recovery.md)、[合同](../../contracts/tool-preparation-recovery.md)。

用户继续使用原“连接工具”流程。SDK准备失败时，在当前操作旁显示简短原因和一个适用的下一步；已有原操作尚未核对时优先显示原核对入口。避免叠加第二工具中心或多个重复大卡。

| 观察 | 用户下一步 |
| --- | --- |
| 原生版本不支持 | 打开同一工具的版本与准备指南 |
| 安装依据变化 | 沿原检测及来源核对，确认当前安装 |
| SDK资源缺失或完整性不成立 | 打开准确工具的受信资源准备指南 |
| Node不可用 | 查看目标机器的运行时准备要求 |
| 凭据环境引用不可用 | 定位当前工具的环境变量名称字段，不展示变量值 |
| 原操作未决 | 核对原操作；准备建议不触发第二次执行 |

只展示调用者真正拥有的原动作。原因不是可执行脚本，不把通用`unavailable`自动解释成安装失败，也不自动安装、登录、启用或停止。安装、连接、模型认证和交付状态保持各自含义。

“准备当前节点”打开原指南时保留当前工具协议和目标节点。已批准节点继续使用原不可编辑身份范围；SDK专门配置与普通CLI准备入口分别准确定位。再次明确选择新工具可以切换准备目标，普通重绘、迟到旧请求及作用域切换不能覆盖人工草稿。

中文和英文使用统一原因语义。可见字段有标签，配置动作定位本组件内对应字段，焦点不被迟到响应抢占；长节点标识和路径换行。按钮沿原设计令牌保持至少44px触达，390窄屏单列，1366桌面清楚展示当前步骤与目标。

代表组件验证由主集成代理收口，真实资源检查与合成界面交互分别记录。完整主题／设备矩阵、实际OS IPC和生产验收继续单独推进。
