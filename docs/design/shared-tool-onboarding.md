# 共享工具接入交互设计

版本1.0.0 · T-SHARED-TOOL-ONBOARDING-219。依据[合同](../../contracts/shared-tool-onboarding.md)，操作说明见[产品文档](../product/shared-tool-onboarding.md)。

## 渐进式主路径

原安装检测、连接提示和Quick高级入口继续共用工具准备指南。目标为共享Worker时，指南保留原配置生成与组合区，用一张简洁共享提示替代普通项目身份区；选中的协议、工具、节点与项目继续进入拥有方工作台。没有有效当前来源或回调时，提示重新核对，不降级为普通身份准备。

共享提示与Pool卡使用原响应式布局及44px动作，中英文状态直接说明下一步。原配置输出路径可明确复制，但界面不读取远程文件、不传递私有路径，也不把复制成功标为已执行。用户仍在目标机器核对文件并选择原连接模式。

## 两种准确定位

| 用途 | 来源与返回 |
| --- | --- |
| 新工具接入 | 独立八字段setup pin固定Pool／Runner／Worker、租户／项目及准确adapter ID／adapter／protocol；没有旧profile字段。返回原项目后重新核对目录与共享行，Quick预选工具和节点，不产生replacementSource。 |
| 已有配置恢复 | 原recovery pin保留旧工具ID、版本及SHA，沿原诊断、未知核对和换新流程，不转换成新接入的假档案。 |

两个定位都是当前用途，不是产品版本兼容分支。URL只表达意图，不授予身份、项目或Pool权限；明确换项目时采用原通用项目工具入口，不沿用原来源。

## 模块与当前性

- `ToolSetupGuide`识别共享目标，只从原固定准备目录取得工具；本机配置生成器不变。来源闭包绑定caller、项目、Worker、协议选择及单调代次。
- `ToolWorkspace`与App重新核对当前目录及共享节点，传递公开setup pin。异步读取返回后再次检查来源，原未确认操作优先。
- `PoolToolRecoveryPanel`与`PoolWorkspace`复用准确Runner读取、原readiness及拥有方权限；目标不在列表首页不等于不存在，不读取消费项目私有记录。
- 原准备表单只扩展共同合法目标的识别，继续核对同一已批准Scope。30秒本地保守期限扣请求耗时并受凭据到期约束；到期保草稿、禁采用、明确重读。保存输入不代表保留过期权限。
- 原连接组件仅在当前can_open_project成立时提供项目链接。同一setup Scope保留工具／Worker定位；不同Scope回原通用接入。

真实账户、API、节点、选择或来源变化使旧回调与复制回应失效，A→B→A不能复活旧结果。新档案登记继续完整库存、matches、原操作键与暂停状态；启用、任务派发和质量验收保留各自门禁。

当前Pool拥有方与已批准的准确Grant允许跨租户Scope离线准备；`can_open_project`只控制返回项目链接，不是准备文件的额外门。拥有方仍不读取消费项目数据或获得执行授权。明确401／403／404向父层撤销对应准备上下文并卸载私有表单，只匹配当前pin／代次，不关闭其他弹窗或清除原写回执；到期与临时网络失败继续保草稿、禁操作。

## AI SOP与验证边界

维护先核原未知操作，再检查共享身份分流与当前公开来源，随后验证准确拥有方、Scope预选和回Quick。不要为减少输入而猜远程路径或从安装观察直接生成正式档案。原维护、停止证明、配置writer和执行内核未变时复用其证据。

本阶段不增加后端接口、表、扫描器或调度器。定向组件检查与生产组件合成界面分别记录；它们不证明真实远程修复、厂商模型或完整平台验收。完整31项／P0–P7继续推进。

成功响应若明确报告原授权、节点或凭据失效，沿同一来源失效通知关闭准确只读准备表单；它与仅到期、慢请求、网络未知及项目不可读分别处理。
