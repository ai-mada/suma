## 3. 十一项业务闭环

P0统一跨域依据与操作，P1补齐完整范围；优先级不缩减最终目标。以下新增交互与能力都是设计要求。

### 3.1 P0 多项目组合与应用目录

- 主工作面：项目列表／卡片，团队／负责人／状态筛选；应用目录保留层级、代码范围、登记版本。
- 动作：创建／打开项目、定位里程碑／待处理／应用；组合分组不改变授权。
- 可视化：已验收／范围、里程碑、阻塞、待核对、更新时间；应用图标明版本依赖及加载范围。
- 恢复：局部读取失败标未知；撤权清缓存；缺失依赖保留断点，不补最新版本。
- 验收：分页仍有全量统计；深链正确切项目；无权对象不进入计数、图边、导出、搜索。

### 3.2 P0 项目待处理与个人工作台

- 主工作面：复用review／blocked／overdue／reconciling；个人工作按负责／审核／关注筛选。
- 动作：每行一个下一步，如看失败、审核证据、调排期、核对原执行；其他动作进入详情。
- 可视化：验收、运行、待审、阻塞分开；集合可重叠，不能相加画进度饼图。
- 恢复：显示范围及时间；跨UTC自然日刷新既有逾期游标；普通失败标过时，401／403清私有结果。
- 验收：分页不重复遗漏；返回保留筛选；in_review不等于用户可批准，动作前重核。

### 3.3 P0 想法、问题与讨论收敛为需求

- 主工作面：想法池与正式需求；想法有待澄清、评估、采用、暂缓，保存来源及决策理由。
- 动作：输入或引用问题／讨论；AI形成方案；预览目标项目和新对象后采用为需求草稿。
- 可视化：想法、澄清、决策、需求连续追踪；价值／成本／优先级来自输入或有来源建议。
- 恢复：失效来源保留历史但阻止采用；未知核对原key；重复来源显示原采用关系。
- 验收：原操作只生成一组对象；暂缓不删除；跨项目先证明访问；AI不自动批准或扩权。

### 3.4 P0 产品、UED与系统架构设计

- 主工作面：全页工作区，左章节、中正文、右验收／依据／检查项；窄屏单面板切换。
- 产品：问题、用户、场景、目标、非目标、验收；体验：流程、页面、状态、文案、原型。
- 技术：领域、模块、数据、接口、部署约束、恢复、观测；架构决策记录选择、理由、影响。
- 动作：保存→检查发布→create／update／keep／exclude预览→原子采用；任务表和图共享提案。
- 可视化：字段校验产生章节检查；原型为固定制品；差异包括正文、负责人、依赖、覆盖。
- 恢复：冲突保留正文并比较依据；错误定位章节和任务；编辑发布版形成新草稿。
- 验收：草稿可不完整，发布须合法；任务无环且覆盖完整；采用冲突全回滚；原型不获额外数据权。

### 3.5 P0 稳定验收项与交付追踪

- 主工作面：矩阵行是验收项，列是设计、任务、用例、人审、应用版本、发布。
- 动作：新验收项采用稳定ID及修订；变更预览影响后采用；现有序号事实按原版本读，不猜等价。
- 可视化：未映射、当前、变化、缺失、读取失败分开；进入精确来源；节点数不是用例覆盖率。
- 恢复：新正文不沿用旧资格；无绑定不按标题补；历史标历史，刷新不批准新依据。
- 验收：重排不换绑、变更失效、删除留历史；统计范围完整；无证据不显示通过。

### 3.6 P0 任务、迭代、排期与进度

- 主工作面：表格／时间线／容量共享筛选、选择、草稿；里程碑／基线／风险关联，日期入URL。
- 动作：行内编辑、拖日期、改依赖先成草稿；底栏给调整数、撤销、影响、保存。
- 可视化：日周月刻度、今天线、计划条、基线轮廓、里程碑菱形；选中才突出依赖，条长只代表日期。
- 日历、节假日、请假、计划、实际工时分开；当前正式容量按完整任务区间可用小时分摊，遵守[资源日历合同](../../contracts/resource-calendars.md)，不把计划估算称为实际工时。
- 历史取真实采样，范围变化另标、缺样断线；预测标方法、窗口、覆盖、区间，数据不足不报确定日期。
- 恢复：CAS逐项比较并留草稿；批次失败不留部分排期；未知不换key；切项目先处理草稿。
- 验收：三视图不丢修改；键盘等价；跨周／时区／未知／零值正确；全量非可见行之和；390px可用列表。

### 3.7 P1 人类、Agent、专家团队与工具协作

- 主工作面：团队管理负责成员／职责；开发工作区负责分配／执行／交接；任务分负责人、执行者、审核者。
- 动作：推荐后预览知识、工具、模型、额度、门禁再派发；接手记录正式交接。
- 可视化：人工工时与Agent／工具槽位／额度分开；负载单元格可定位任务，未知标未设置。
- 讨论复用保存消息、请求分析、据此开发；回复不直接执行，计划保存与启动分开。
- 恢复：超配给建议不静默修改；撤权重核新派发；重规划只改未开始，活动运行固定依据。
- 验收：跨项目负载不泄露无权任务；团队不授访问；交接恢复原回执；AI说完成不改变验收。

### 3.8 P1 测试、缺陷与修复回归

- 主工作面：用例库、计划、执行、缺陷、覆盖；详情标任务／应用版本／发布集合依据。
- 动作：稳定用例ID和修订组成套件；自动测试沿DAG；手工保存人员／附件；失败走原回流。
- 可视化：自动、手工、包验证、人审分开；用例标selector、报告、attempt、候选。
- 分诊保存来源、影响、优先级、责任、重复关系、周期；修复、回归、关单沿受保护关系。
- 恢复：缺失／坏报告／未知不是passed；新计划不补签旧运行；重开保存旧证据并开新周期。
- 验收：失败→需求→修复→同候选独立测试→人审→关单可追溯；手工不替代自动；原失败例不悄悄移除。

### 3.9 P1 应用版本、发布集合与运维

- 主工作面：应用×环境矩阵分登记版本、审批、效果、健康；详情给需求范围、源任务、候选、批次。
- 动作：影响→精确集合→逐原计划批准→启动→核对→恢复／回退；未知兼容不当通过。
- 可视化：直接／传递影响、缺项、循环组；泳道展示成员事实，部分成功和未知持续可见。
- 通用容器／包provider、多环境推广、组合回退按独立合同扩展，复用唯一Go DAG与原发布计划。
- 恢复：未知先核对原操作；不重做健康子项；回退是新执行，不是修改页面状态。
- 验收：同提交不冒充应用构建；缺依赖阻止准备；暂停排空、部分失败、丢回执、回退失败分别实测。

### 3.10 P1 知识、记忆、规范与技能更新

- 主工作面：统一文档／记忆／规范／技能／检索；详情给来源、草稿／发布、消费、共享、采用。
- 动作：人工／模型提炼→核对→草稿→发布；共享与项目采用分开，目录更新进入待采用队列。
- 可视化：正文差异、来源变化、受影响未启动任务、索引水位；检索标关键词／语义及修订。
- 可执行技能、插件、MCP、A2A独立管理包／权限／安装／执行；文本发布不装脚本或扩权。
- 恢复：源更新不覆盖副本和旧运行；同步冲突成提案；失效阻止采用；共享不夹带未授权原件。
- 验收：模型原件与人工稿分开；更新可比较／拒绝／采用；索引失效可诊断，不混用旧权限。

### 3.11 P1 Token、成本、配额与核账

- 主工作面：月度／范围内的报告Token、估算费、预留／持有、待核对，下钻项目／任务／模型／工具／attempt。
- 动作：看来源、改报价／额度、处理预算阻塞、核对；报价预览后发布，旧费率与历史账不重算。
- 可视化：币种分图分账；已报告、估算、人工确认、厂商账单标明；缺用量不归零。
- 团队／成员／应用额度、厂商核账、套餐、商业账单待独立交付，不用运营费率账本代支付结算。
- 恢复：未知保留hold；回执不重复收费；政策修改须权限／CAS；人工确认保留来源和原事实。
- 验收：失败仍记真实用量；币种不相加；阻塞定位政策；无报价不显示免费；人工不冒充厂商实测。

## 4. 执行、调度、Harness与多端配置

执行复用唯一Go DAG及Runner／Pool；图、列表、事件轴共享run／node／attempt，分别解释资源／审批等待与效果核对。
调度展示声明依赖、就绪原因、槽位／预算、租约；不按画布位置造顺序，不把心跳当模型健康。
事件页定位规则、来源、去重键、接收／派发／处理；失败可回问题／需求草稿，重试先查幂等和未知副作用。
模型、CLI、Harness、IDE、SDK、MCP、A2A是不同能力面；矩阵分发现、配置、授权、调度、执行、恢复、平台验证。
Harness／Octop、Codex、OpenCode等按真实协议适配，显示能力与阻塞，不凭名字声称完整对等。
IDE保留文件／任务／Git、中央Monaco、讨论、底部终端／执行；看讨论或证据不重挂载编辑器。
讨论计划和终端候选绑定原任务、模型／工具、基线及独立测试；读、写、执行、封存、采用分别受权。
配置遵循目标→建议及来源→差异→授权／预算→应用→实际验证；秘密只引用及一次性录入，不回显。
Web／桌面／CLI共享ID、版本、命令、回执；移动优先待办、观察、审批、问题输入，复杂编辑可接续桌面。
本机／远程显式选，配置标组织／项目／设备范围；安装、发现、注册、启用、验证分开，不合成绿灯。
默认辅助；受控执行／自主维护需项目策略。自动修复默认一次、最多三次，同一失败连续两次停止；未知先核对。
Yjs协作草稿与正式修订／发布分开；结构化命令、授权、账本、审批不用CRDT自动合并。
离线许可目标默认4小时，可收紧，绑定设备、计划、工具、目录、额度、期限；重启不延长，云模型仍在线。
重连重新授权、核候选、独立测试，不直接验收；离线撤权与缓存删除不声称即时生效。协作／离线是设计目标。

## 5. 视觉、数据解释与公共交互

### 视觉令牌与图表编码

| 项目 | 统一规则 |
| --- | --- |
| 字体 | 正文14px、辅助12px、长文16px、标题24px／18px；关键事实不用8–10px |
| 间距 | 4px尺度，常用8／12／16／24／32px；默认舒适，密集表格显式切换 |
| 控件 | 桌面36px、触屏44px；清晰焦点框，图标有可访问名称 |
| 色彩 | 紫色品牌及明暗；灰未开始、蓝紫活动、琥珀等待／风险、红失败、绿确认完成 |
| 未知 | 中性虚线＋待核对，不等同失败、零、空或成功 |
| 图表 | 来源范围、时间、单位、分母、缺失和明细齐全；颜色外有文字／图形 |
| 动效 | 150–200ms，尊重减少动态效果；长期未知不无限转圈 |
| 响应式 | 桌面列表＋详情，窄屏单面；大图可切列表，固定面板不遮动作 |

计划条只表日期；验收比只用accepted及声明范围；运行、用例、健康不合成一百分比。
趋势取真实历史，缺失断线；币种分开；预测标方法区间；推荐显示依据和可编辑选择。
TanStack Table、Tiptap／Yjs／Hocuspocus、ECharts按需采用，复用ReactFlow／ELK、Monaco和令牌；装组件不等于交付。

### 对象详情、返回与草稿

详情统一标题、范围、状态、依据、下一步；概况／讨论／执行／质量／变更按能力开放，不铺空标签。
跨对象保存来源路由、筛选、排序、日期、选择、滚动；返回恢复来源，不一律回首页。
轻详情侧栏，设计／IDE／完整证据全页；深链稳定，前进后退恢复选择。
草稿绑定账户、组织、项目、对象、原版本；切范围不带旧正文，撤权不展示私有缓存。
状态明确未改／草稿／提交／已存／冲突／未知；冲突比较并留稿，未知仅恢复原操作。
刷新不替换未存正文；原回执成功后读当前版本，历史版本不能用于下一次CAS。
首次骨架，后台刷新保留数据及时间；普通失败标过时，401／403清私有事实并给授权路径。
错误给对象、原因、影响、下一步；SHA／attempt／fence折叠，不要求业务用户理解协议。
公共组件负责页头、范围读取、事实、来源、恢复、空态、详情、工具栏；业务命令留领域模块。

## 6. 能力状态、交付与验收

能力分别显示平台／协议、配置、授权、发现、可调度、执行、取消恢复、费用观测、验证环境。
不合成全部就绪；缺能力给配置，缺权给授权说明，未知给核对，未验平台标待验证。
设计、样稿、代码、夹具、厂商、多机、安装／签名、生产分别留证，一个维度不替其他维度。
接口沿snake_case、稳定ID、CAS、幂等key、当前事务授权；投影声明as_of和完整性，客户端不造可信来源。
沿原计划分组：体验／查询→标准／设计／质量／资源→编排／知识／成本→多端／离线／渠道／SSO／分布式。
每阶段记范围、实际命令环境、旅程、剩余验证；仅文档和样稿不改变生产完成状态。

### 共用验收场景

1. 想法→需求→设计→任务→讨论／派发→独立测试→人审→应用版本→发布，均能返回原对象及位置。
2. 需求／任务／技能／工具变更区分当前依据与历史，不复用失效验收或伪造关系。
3. 并发、丢回执、重复点击、切项目、撤权后重放遵守CAS／幂等／当前权限。
4. 全量／部分、未知／零、计划／实际、执行／验收、估算／账单不混淆。
5. 中英、键盘、390px／桌面、明暗验证；长标题、大数据、空态、慢读、错误可操作。
6. 工具、停止核对、厂商、多机、跨库、移动真机、生产分别实测，不沿用样稿证据。

保护用户数据、其他代理改动、活动预览，构建只入忽略目录。设计不引入历史别名、不重置数据、不授权部署或删除用户文件。

## 7. 主规格到可操作场景（T-DESIGN-135）

样稿扩展为十二个工作区，按“交付工作、协作与运行、能力与治理”分组；生产入口仍遵守第2节。全局查找支持 Ctrl/Cmd K、上下键、Enter 与 Escape，既能搜索工作区也能定位示例对象。对象详情保持单一焦点，关闭返回原控件；对象被筛选移出时回到筛选栏。

| 工作区 / 主规格主题 | 可操作路径 | 决策结果与异常路径 |
| --- | --- | --- |
| 组织交付台、需求、计划 | 项目筛选→待处理→想法原文→整理差异→采用草稿→排期比较 | 采用不会发布；整理记录跨页面保留，可逐次撤销；后续正文有编辑先比较再恢复 |
| 团队与分工 | 项目／成员共享筛选→职责表／分类负载→分配向导→差异→保存 | 人类小时、Agent槽位、专家窗口、工具槽位分开；未知容量不画成空闲；活动执行者锁定，分工不授予访问或启动 |
| 模型与 Harness | 供给通道→能力／驻留／硬预算筛选→跨通道比较→固定选择 | 不合格候选保留排除原因；未知能力不可满足硬约束；修改条件使旧绑定失效，不能静默回退 |
| Harness 接续 | 请求停止→原执行核对→可见交接资料→确认→接续草稿 | 未知／运行中阻止下一步；显式停止证据与请求分开；目标执行仍未启动，不转移隐藏会话或秘密 |
| 事件与自动化 | 模板→触发／范围／检查／动作／审批／结果→匹配预览→本地模拟 | 同事件去重；默认一次修复，显式最高三次；相同失败两次停止；未知外部作用仅查询原操作 |
| 质量与发布 | 标准证据／问题／发布依赖切换→修复草稿→回归→审阅→关闭／重开 | 失败不能进入关闭；回归通过仍需明确审阅；重开新修复周期保留旧记录；发布成员分别保留批准、部署和健康 |
| 配置与设备 | 部署拓扑→继承来源→受限字段→差异→采用；离线场景→三方比较→解决提案 | 配额、并发、许可只可收紧；版本变化留稿重验；无权禁止同步；重开比较恢复原选择，本地原件保留 |
| 架构地图 | 协议入口→控制面→唯一DAG→Runner／Harness→供给通道；按节点查看 | 每个节点说明职责、当前事实、目标和失败恢复；MCP／ACP／A2A方向分开，图上的连线不表示已实现集成 |

### 可视化与信息密度

- 模型页以供给通道和约束栏为第一层，候选卡只放资格、原因与明确操作；参数对比与交接步骤在按需浮层中展开。样例档案不用厂商名称或虚构性能分数。
- 团队页以职责表为中心，冲突与交接置于侧栏；窄屏转为任务卡，标签持续可见。负载条展示计划量／已设置容量，不将全部工作种类加总。
- 规则编辑使用六个有标题的步骤，旁边显示匹配事件和决策；事件、审批、尝试和外部结果是四类信息，不用一条绿色进度条混合。
- 发布以依赖批次表达先后约束，配置以来源链表达可收紧范围，离线以设备关系和三方正文表达恢复依据；每图同时有文字和可操作详情。
- 架构主文档增加章节筛选、准确功能计数、键盘领域页签和原生图表放大对话框。移动目录隔离背景并归还焦点，图表复制使用独立SVG引用，避免多个图的标记互相覆盖。

### 样稿与正式实现之间的接入要求

当前样稿的数据、模型资格、规则决策、回归结果、停止证明和授权状态都是显式合成情景，刷新恢复初始数据；演示未接入服务端、供应商、设备或执行器。生产化时按领域接入强类型查询／预览／采用命令，不将 `data-action` 或前端状态直接用作执行API。详情中的当前权限、来源版本、原操作回执与准入结果必须改由已有权威模块提供。

正式实现仍需补齐持续文档协作、稳定验收项合同、持久跨设备草稿、服务端规则决策与审计、实际适配器能力证明、发布提供方及生产验收。英文、屏幕阅读器和真实触屏验收继续单列，不能由中文样稿与本地浏览器检查替代。
