# WorkBuddy 任务派发交互

状态：T-WORKBUDDY-TASK-DISPATCH-168已实现，原业务／局部中英视口限定验证；suma 1.0.0；2026-10-31；负责人：工作台代理／主集成。依据：[执行合同](../../contracts/workbuddy-task-dispatch.md)、[架构与SOP](../architecture/workbuddy-task-dispatch.md)、[实际范围](../quality/workbuddy-task-dispatch-verification.md)。

任务详情保留原本地工具开发入口，新增清楚命名的WorkBuddy入口。默认界面只呈现任务和账号，不要求复制JSON、手填摘要、节点或模型参数。单个本人账号默认选择；多个账号要求明确选择。没有账号时提供原工具授权面板入口，返回后可重新读取账号。

确认前先生成正式预览：显示固定任务／需求版本和待发送开发目标、采用设计、测试计划及所选知识。高级运行身份和摘要可按需展开。模型表达为供应方管理，用量／费用表达为尚未核实，不能借预览提供未实现的模型切换。

预览与派发是两个动作。账号、任务或知识改变时旧预览失效，用户需要重新预览。明确派发后打开原run/node；刷新或分享计划链接只能恢复当前有权查看的原计划。供应方状态与平台执行／验收分开呈现。

| 状态 | 内容和操作 |
|---|---|
| 加载 | 保留当前任务标题，账号区域显示加载，不抖动弹窗高度 |
| 无授权 | 简短说明与连接账号入口，不显示虚假可派发状态 |
| 可预览 | 明确任务及账号，单个主要按钮“预览派发” |
| 可确认 | 固定上下文摘要及“确认派发”，可返回修改 |
| 原操作未确认 | 保留原正文和key，提供核对原操作；不能再次新建 |
| 依据改变 | 说明需要重读和重新预览，不自动套用新版本 |
| 已派发 | 原运行与节点入口，不能重复派发此计划 |
| 失去权限 | 清除受保护内容，保留准确权限提示，不回显旧计划 |

沿用现有Dialog、按钮、焦点管理和设计令牌。中英文功能一致；窄屏单列，主要操作保持可见，正文可换行，摘要和技术身份不撑宽画面。键盘可操作账号、预览、确认、核对和关闭。实际代表状态与截图范围记录到阶段验证报告，不能以设计文档宣称全设备或供应方已验收。

有效期显示本机语言格式的日期与时分，避免30分钟计划被理解为全天有效；机器日期保留在time元素中。原图仅代表滚动后的内容／操作区，最终时分小修按单独定向结果记录，不重复启动业务运行。
