# 同页候选组合与下游基线交互设计

状态：T-P4-031／1.0.0 限定本地已验证；日期：2026-10-27。范围与边界以专项报告为准。
依据：[合同](../../contracts/candidate-composition.md)、[PRD](../product/candidate-composition.md)、[架构与AI SOP](../architecture/candidate-composition.md)。
沿用已认可的详情工作台、Field／Radix和主题令牌，不新增导航、依赖或外部设计上传。

## 一个入口、逐步展开

当前任务详情中的“合成已验收候选”默认折叠；任务是明确集成任务，不将其改成目标分支操作。
无合法计划深链或原请求待恢复时零读取。展开后只获取当前任务／项目的真实选项与按需历史，不创建run。
有效深链可只读恢复原计划，即使前端任务选择已清空也能查看事实。
URL `panel=composition:<真实计划ID>` 恢复同项目／任务的准确计划；`panel=code-baseline` 展开当前任务的基线面板。
没有计划时不使用“new”等假ID触发GET。验收后的集成按钮通过父层受控open展开028原面板，不自动准备或批准。

主体单列短区块，按当前状态显示一组主要动作：

1. 选择固定流程／producer和有序来源；明确准备只读预览。
2. 核对固定版本与来源顺序，明确确认启动一次真实集成运行。
3. 显示实际组合、独立测试、待Review、失败或未知；提供原运行／任务入口。
4. 原Review验收后，链接既有028集成，并单独展开未开始下游任务的基线绑定表单。

技术依据、密封bundle、摘要及历史默认折叠。不新增依赖画布、在线Git冲突编辑器或多套进度页。
预览、运行成功、正式测试通过、任务已验收、目标已集成、下游基线已绑定分别命名。

## 来源、顺序与真实预览

来源只使用服务端合格候选，显示任务原题、版本、短SHA、真实run和当前阻断。
复选选择2–16项，选中列表保留明确顺序，使用有可访问名称的上移／下移按钮，不依赖拖动。
不能手填SHA／路径／分支，不根据任务accepted文本推导候选可用，不偷偷添加外部依赖。
来源的原测试与验收在披露中可追溯，但不显示为本次组合的测试结果。

预览明确显示集成任务、流程／producer、固定来源、宿主基准及到期时刻；仅合法非空日期显示本地年月日时分。
启动需要独立确认，说明将创建一个真实run并由原质量节点测试新候选；读取或预览不会自动启动。
来源／任务／流程变化时保留选择但显示当前阻断，明确新准备，不把旧预览自动重定向。

## 状态与后续动作

状态以服务端投影为准；queued不称已经占机器，executing不称已测，awaiting review不称已验收。
成功或测试通过后提供原Review入口，不能在此新增自动批准或“标记完成”。
冲突仅展示真实文件／来源和原运行；unknown仅提示原运行核对，不提供自选结果或新运行替代。
已验收计划显示准确合成候选与原测试／验收依据，再给出原028目标集成入口。
目标差异审查、批准、执行和回执继续由028组件承担，不扩展其提供方策略。

下游绑定单独表单：服务端合格未开始任务、当前旧基线、新合成候选、理由及明确确认。
替换原待执行基线要再确认，成功说明任务版本已变化、旧预览失效，未开始专家计划需明确revision。
基线绑定不启动下游、不重写已开始运行，也不把来源测试或验收继承给后续开发。
目标任务侧的同一面板先读当前任务与受保护基线，再按需列出真实已验收合成；不默认选择列表第一项或最新项。
已有运行的任务只读来源事实。专家计划未开始项链接此任务面板，并明确提醒更改后需要修订原计划，不会自动继承。
运行详情将管理员锚点、实际开发输入、合成结果及冲突原路径折叠展示；它们不是测试通过或正式验收标记。

## 恢复、范围和中英文

复用useWriteAction和scoped storage持久原path／body／key／身份。未知写只恢复原操作；command恢复先读取同scope原计划。
409保留来源顺序、理由和绑定草稿，明确读取最新后更新CAS并清除确认，不能默默重新预览／绑定。
账号／组织／项目／任务切换立即卸载旧范围并Abort；403隐藏旧事实，读取中或失败不能据缓存权限写。
只对当前展开活动计划读真实状态；终态、折叠或后台停止刷新，不全项目轮询，不浏览器循环派发。

所有新控件显式label／aria-label，键盘可读来源顺序和披露；主触点44px，长SHA／ref换行，窄屏单列。
系统标签／状态／受控诊断成对中英，原任务／代码／冲突路径／理由／不可变证据不猜译。
采用现有surface／surface-soft／border／muted／accent令牌，不让颜色替代状态文字。

## 必要检查

聚焦折叠零读取及scope隔离；有序来源预览与明确启动；成功仍待原Review；409保稿与同key未知恢复；
已验收后才开放既有集成／服务端允许的下游绑定，绑定保持准确版本且不自动启动。
生成类型、中英、最终构建和代表性真实Git／双Runner界面已按专项报告限定范围验证；不扩大为全部设备或生产验收。

## 本地交付证据

有序固定两份已验收候选，Runner以Git原生三方合成精确M；另一执行节点对M独立测试后，测试账号明确Review，再将M显式绑定未开始任务C。C从M开发出新提交，另一节点再独立测试并单独Review。实际同机两Runner、2项新运行、8项正式检查；原来源、管理员锚点与protected baseline全链路可追溯。中英切换、同一来源深链和冷回读保持准确事实；冲突、未知和重试沿用原操作及质量边界。见[专项报告](../quality/candidate-composition-verification.md)。仅本地自有协议夹具验证；未调用厂商或模型，未报告用量不推断为零Token。真实远端、多机、生产验收、完整P0–P7及全部扩展需求继续实施。
