# 原生智能开发工作台：完整交互规格

状态：1.0.0设计与实施要求，2026-10-29；负责人：产品、UED、前端、Runner和智能体领域。关联需求9–12、21、23、25、26及[逐项参考能力](../product/reference-platform-parity.md)。本文定义速码自己的完整工作台，不能以外部工具启动按钮、适配器列表或某个截图作为完成依据。当前已实现与待交付仍以[状态](../delivery/status.md)及各项实际报告为准。

本规格参照官方公开的Multica事项／运行协作、WorkBuddy任务／产物操作和Octop专家／多入口控制台，采用成熟组件及现有设计系统独立实现。来源版本、许可及逐项缺口统一维护在[能力审计](../product/reference-platform-parity.md)，不复制厂商受限源码、品牌、图标或截图作为产品资产。

当前T-WORKBENCH-126实现切片为原IDE任务上下文，准确边界见[读取合同](../../contracts/workspace-task-context.md)，实际结果见[报告](../quality/workspace-task-context-verification.md)及[摘要](../quality/workspace-task-context-summary.json)。下文是完整交互目标，不能把其中持续会话、终端或Office编辑误读为本切片已经提供。

## 用户目标与产品结构

用户应能在同一任务内表达目标、补齐上下文、审阅计划、交给人或智能体、观察真实执行、查看／修改成果、完成独立测试与正式验收，再交接后续任务。日常操作不要求理解MCP、fence、摘要或数据库类型；这些是可展开的审计依据。

项目固定导航仍为“概览、需求、开发、质量、发布运维、资料”。**开发工作台**属于开发内的正式工作面，任务、迭代、运行、流程仍各自保留；不能把办公、专家、终端等所有功能平铺为新一级菜单。组织设置统一管理设备、模型、工具、技能、连接器与权限。

### 同一工作面的五个区域

| 区域 | 默认内容 | 按需内容及边界 |
| --- | --- | --- |
| 顶部上下文 | 项目、工作区／分支、当前任务、连接状态 | 原来源和当前执行依据；切换不静默覆盖草稿或换绑在途运行。 |
| 左侧任务／文件 | 当前任务、最近任务或授权目录 | 同区切换任务／文件／Git；支持收起、搜索、键盘定位。 |
| 中间主区 | 任务对话／可编辑计划；阅读代码时为编辑器 | 所有状态来自持久事实；长工具输出默认折叠，不强迫阅读日志。 |
| 右侧成果区 | 产物或当前文件，可完全收起 | 文件、差异、文档、网页预览等标签；每标签保留自己的位置和草稿。 |
| 底部执行区 | 默认隐藏 | 有能力时打开真实终端、问题、检查或输出；没有PTY时不能放一个假终端。 |

1366／1920宽度下优先保持主区阅读宽度，侧区可拖动和收起；768默认单一主区＋抽屉；390以任务列表、对话／计划、成果三个完整视图切换，不强行塞入三列。关键动作始终可操作，不依赖横向滚动或画布拖拽。

## 任务输入：简单开始，能力逐步展开

输入区默认只有目标、附件入口和明确发送动作；项目及工作区持续可见。模型／专家／技能／连接器用紧凑选择器，参数和预算折叠；没配置时显示可操作的原因与接入入口，不自动替换模型或扩大权限。

| 操作 | 交互要求 | 正式后台依据 |
| --- | --- | --- |
| 写目标 | 多行文本、输入历史、长文本可展开卡片；中英文输入法不误提交 | 原文及版本，不替用户增添验收范围。 |
| 附文件／图片 | 选择、拖入、粘贴；文件卡显示上传／解析／错误，可移除；不自动发送 | 授权原件、摘要、版本、范围及解析状态。 |
| 引用资料／代码 | 能定位文档段落、代码行或媒体时段；预览后加入 | 当前权限及来源版本，入模型前再授权。 |
| 选模式 | 问答、先规划、执行的真实能力分开 | 受控purpose及允许动作；切换不是授权升级。 |
| 选工具和模型 | 只列当前范围可用项，说明缺配置／版本／认证／容量 | 真实库存、固定档案和完整模型Binding。 |
| 选参数和预算 | 主要参数常显，费率／上限折叠；未知价格明确 | Go选项的动态限制、冻结报价和账本。 |
| 选择专家／技能 | 显示来源、版本、作用范围、依赖及不可用原因 | 正式资源版本；不能根据名称加载任意脚本。 |
| 选工作区／分支 | 当前分支醒目；隔离任务显示独立工作树 | 授权目录和准确基线，原操作回执。 |

“发送”应进入原任务的真实接手状态；必要后台准备就在当前面展示阶段和原因，避免无意义过渡页。长期任务会话与一次执行attempt分别建模，不把任务卡的“已完成”直接等同正式验收。

## 五条核心交互

### 1. 想法到正式开发

```mermaid
flowchart LR
  I[目标和固定资料] --> Q[必要澄清]
  Q --> P[可编辑计划与验收]
  P --> R[原正式派发预览]
  R --> A[人明确启动]
  A --> X[Go DAG与隔离执行]
  X --> E[成果和独立测试]
  E --> H[原正式Review]
  H --> N[基线交接／后续任务]
```

澄清问题可逐项回答、跳过并明确记录假设；已经明确的条件不重复问。计划支持改步骤、责任、依赖、工具、预算和验收，改动产生新可审阅依据。采用草稿与启动执行是两个动作；高风险、合并、正式验收和生产保持原人工门禁。

### 2. 当前运行中补充信息

输入区保持可用，但发送选项必须表达真实合同：**当前步骤后接收**、**排入下一轮**、**中断后处理**。只有工具确实支持的选项才出现。队列显示送达、未送达、被拒绝及撤回事实；可以编辑尚未送达的消息，不能改写已进入执行的原消息。

新条件如果改变代码、计划、权限或验收依据，展示影响并生成修订，不把聊天文本直接当派发命令。外部SDK不支持当前轮引导时明确说明，可保留下一轮草稿；不能显示“已应用”假回执。取消意图、进程停止与补偿分别显示。

### 3. 成果阅读与共同编辑

点击真实产物卡在右区打开，当前任务／run／来源继续保留。标题区左侧显示文件名与未保存／保存中／已保存／冲突；右侧最多三个高频操作，其余收进菜单。预览、编辑和源码切换有明确选中态。

代码和文本先复用Monaco及当前CAS；Word、Excel、PPT、PDF、Markdown、HTML、图片／音视频分别接成熟引擎并保留真实格式范围。能下载不表示能编辑，能预览不表示导出保真。Office改动、选区AI修改、撤销重做及多人冲突需要独立验收。

选区加入上下文必须绑定原文件版本和定位；AI修改前复核用户最新手工改动。来源已变时保留草稿并要求重新定位，不覆盖原内容。变更有可访问的高亮／差异与操作来源，不依赖颜色表达。刷新、切文件、关标签、关窗口和换账号都要保留或明确处理未保存草稿。

### 4. 交接给其他人或智能体

交接包展示目标、当前进度摘要、原任务／需求版本、实际产物、代码基线、未完成项、问题、下一步责任和截止日期。接收方只获得其当前权限允许的内容；凭据、私人记忆、浏览器登录态与无关对话不进入共享包。

代码交接复用现有受保护基线与同SHA独立质量事实；通用办公交接另保留原件版本和上下文。接收方明确接受后进入其后续任务，不偷偷重绑已开始任务或把验收自动转授。回执未知恢复原交接操作，不重复创建任务。

### 5. 失败、阻塞与问题回流

失败卡只显示主要原因、影响对象和下一步；原始原因及证据按需展开。权限、库存／设备离线、模型额度、目录冲突、工具报错、独立测试失败、审批等待与效果未知分别表达。已知失败可提供准确新计划，未知效果先核对原操作。

问题提交复用原可信来源、去重与需求回流；建议、草稿、正式缺陷和已验收修复不能混为一项。对同类修复达到配置上限后明确阻塞并保留尝试。运行时间线可打开原失败用例和对应代码差异，不能只弹一个无法下钻的通用错误。

## 真实状态与可视反馈

| 状态 | 常显反馈 | 用户可执行动作 |
| --- | --- | --- |
| 空任务 | 简短示例和上下文选择 | 写目标或添加资料，不先堆配置。 |
| 规划／澄清 | 当前问题、已知约束和预算依据 | 答复、改计划、保留草稿。 |
| 待启动／排队 | 当前计划、执行者、等待原因 | 明确启动、查看等待对象或取消排队。 |
| 执行中 | 当前真实步骤、执行者、耗时、产物 | 支持时补充消息；停止仍显示请求和回执。 |
| 待输入／审批 | 需要决定的具体版本和影响 | 仅显示当前角色允许的动作。 |
| 断线 | 最后已持久事件时间和连接状态 | 恢复连接、查看原操作；不自动再派发。 |
| 冲突 | 原版本、当前版本、保留的本地草稿 | 比较、重新定位、明确保存或放弃。 |
| 未知效果 | 原操作和待核对事实 | 原操作核对；不能直接标成功或重跑。 |
| 开发结束 | 实际文件／代码、尚未完成的独立质量 | 进入独立测试和正式Review，不提前全绿。 |
| 验收完成 | 原Review、范围和基线 | 明确交接、版本／发布预览。 |

模型思考、执行进度、业务验收、测试覆盖及发布健康分别显示。没有可靠分母不显示完成百分比；部分用量和未知成本不补零。状态更新只更新变化区域；用户正在阅读历史时不强制滚到底，提供“有新事件”按钮。日志采用有界／虚拟列表，原事件ID维持折叠、焦点和位置。

## 国际化、可访问性与视觉系统

中文和英文采用成对领域消息键，后续语言只增加语言包和必要格式，不复制页面逻辑。厂商名称、模型／工具标识、原始正文、代码、路径和不可变证据保持原值；日期、数字、时区和费用使用统一格式器。错误有稳定机器码、本地化解释和原原因入口，语言切换不清草稿、不触发外部动作。

所有重要动作有可见文字与快捷键等价方式；图标按钮有名称，菜单、标签、抽屉及弹窗管理焦点。读屏状态提示适度，完整错误与保存反馈可定位。拖拽有按钮／表格替代；高对比与减少动效生效，长任务不持续播放干扰动画。

沿用现有Radix基础组件、统一令牌、Monaco及正式图表组件。颜色只表达有限语义，优先用标题、间距、分组和简短文字建立层级；高频动作突出、次要依据折叠，避免全屏小卡片、彩色状态墙或伪智能评分。深浅主题共用布局，窄屏不得丢功能。

## AI开发与验收SOP

先冻结真实任务／会话、消息送达、上下文、执行和产物合同，再实现一个完整切片。会话负责用户协作，Go控制面负责权限和正式状态，唯一Go DAG负责派发，Runner／工具负责实际执行，原账本／质量／Review分别提供事实。禁止前端、SDK或“聊天智能体”拥有第二个派发权或自行填造宿主进度。

开发优先复用成熟组件和当前正式模块；只为具体真实断点增加深模块，不建立大量同义服务或历史兼容分支。结构化日志记录原对象、操作、版本和错误码，不记录正文、秘密或不必要本机路径。参数、权限和可选功能可视配置，但配置可见不代表已经连接成功。

每个切片选择一次代表性真实旅程，并检查受改动的保存／断线／权限／未知边界；未变SDK和付费模型不重复调用。源码、模拟协议、真实厂商、安装矩阵及生产签收分别留证。界面验收须经过真实页面操作、刷新、中英、390／768／1366／1920、键盘、错误及恢复；单元测试和静态原型均不替代这些结果。

*English: The native workbench keeps task, conversation/plan, files/artifacts and actual execution in one coherent surface. Advanced configuration is disclosed on demand. Message delivery, running processes, independent tests, human acceptance and deployment remain separate authoritative facts. Full expert, knowledge, office, terminal, browser, channel and installation journeys are product requirements; an adapter list is not a substitute. Current implementation and verification remain scoped and must never be inferred from this design specification.*
