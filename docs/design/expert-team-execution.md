# 专家团队的准确执行跟进

阶段：T-TEAM-EXECUTION-141；产品1.0.0。沿用[团队依赖计划](expert-team-orchestration.md)与[领域合同](../../contracts/expert-team-orchestration.md)，本增量描述计划中已绑定运行的执行投影，不新建计划、调度器或权限系统。实际实现与验证状态由原交付状态和本阶段质量记录维护，本设计不是完成证据。

## 从团队任务定位当前问题

用户在原团队计划中选择任务，先看任务及正式交付状态，再看该项准确run的执行情况。依赖未满足、尚未派发、运行中、等待验收各有自己的来源；不能将前置任务未验收显示为Runner故障，也不能把节点成功当作任务已验收。

执行区使用紧凑摘要和节点列表，不把完整DAG默认铺满页面。每行包含节点名称、当前状态、真实等待／异常原因及原运行定位；最多显示24个，服务端依次优先未知状态或reconciling、cancelling、failed、blocked或paused、waiting、running、ready、pending，最后为succeeded／skipped／cancelled，同级按node_id稳定排序。显示已展示数量、该准确运行总节点数及是否截断；未显示部分通过原运行详情查看，不能把局部列表标成完整执行图或据此计算完成率。界面不另造排序结论。

投影取自计划项的可选execution，携带run_id、observed_at、nodes_total、nodes与truncated。节点的reason保持原文，worker_id／ready_at没有记录时为空，不补造执行者或开始时间。节点状态和计划项状态分别显示；waiting_execution计入待处理，只有实际running计入执行，execution_unknown虽计入blocked注意事项，文案仍为中性的“待核对”。这些是运行事实计数，不是正式验收进度。

## 状态与操作

| 事实 | 展示与处理 |
| --- | --- |
| 等待前置 | 指向原依赖；不暗示正在消耗执行槽位 |
| 等待调度／资源 | 使用原节点实际原因；没有原因则明确未提供，不猜测设备离线或预算不足 |
| 执行中 | 展示实际状态与准确attempt；不绘制推测百分比或剩余时间 |
| 已请求取消 | 保留请求事实，继续显示原运行；不提前显示已停止 |
| 已取消／停止 | 只呈现已有终态或停止证据，不扩展为全部外部作用均已撤销 |
| 效果未知 | 中性提示待核对，打开原run／node／attempt；不自动重跑、不把未知视为失败或成功 |
| 节点失败 | 展示真实失败事实，跳转原对象检查；修复、重试和验收仍走既有授权门禁 |
| 当前运行不可读／缺失 | 明确无可用执行投影；不回退到其他运行或历史attempt拼接事实 |

深链仅使用服务端返回且与该计划项绑定的run、node、attempt，不以任务最近一次运行替换。打开详情只是导航，不派发、不授予权限、不自动取消或重试。返回继续查看原计划；已开始任务的来源及运行身份保持固定。

## 阅读层级与恢复

默认展示业务名称和短原因，完整身份与技术依据按需查看。复用现有视觉令牌、成对中英文状态文案、可见焦点及键盘操作。未知／等待状态不只用颜色区分，长名称与标识可换行；窄屏按单列阅读，主要入口仍可触达。

复用当前打开计划的读取生命周期，不为每行另设轮询。刷新中的旧投影不能授予新操作；账号、组织或项目变化即隔离旧上下文。权限拒绝清除受保护内容；网络故障明确最后读取状态，不能将读取失败伪造成所有节点失败。源API仍执行当前项目授权。

历史修订继续表达其固定计划依据，不把最新运行投影写回历史版本。execution动态明细和读取时间不进入持久计划payload，也不单独引起版本变化或无意义CAS冲突；原控制器根据真实业务派生状态发生的变化，仍按原规则更新计划版本。投影不改变激活或正式验收，不会启动模型调用或消费执行额度。

## 验证边界

定向验证准确运行绑定、异常／活动优先及24项截断、真实原因、取消请求与效果未知区分、旧响应隔离、原节点定位。组件测试和本机协议夹具分别记录，不替代实际中英文、窄屏、键盘旅程或真实多机验收。完整专家分配、调度、厂商工具和平台目标仍沿唯一实施计划推进。
