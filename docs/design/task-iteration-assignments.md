# 批量调整任务迭代

在开发协作的[任务列表或看板](task-board-selection.md)选中最多 16 项已加载的任务，选择「调整迭代」。预览使用当前任务视图的正式排期投影。确认区逐项显示原迭代、目标迭代及变更状态，允许移出迭代。没有变化时停在预览。已完成的迭代不能作为目标，移出已完成范围需要先由有权限的人重开排期。

`POST /api/v1/planning/iteration-assignments` 使用当前人类项目写权限。请求只含项目 ID、目标迭代 ID 与版本、明确任务及其任务版本和排期版本，以及稳定操作 ID。目标为空时版本为零。无排期的任务使用排期版本零。服务端在一个事务内检查当前项目、目标和所有任务的版本，沿用正式排期的完成范围约束。只更新变化项的迭代 ID 和排期版本。排期的工时、日期、里程碑以及任务的验收和关联证据继续由各自原有记录表达。

成功以正式回执为准。回执按选择顺序返回每项排期版本和是否变更。版本冲突后刷新任务和迭代，重新审阅差异。响应丢失时核对原操作，保留原请求和原操作 ID。重放先核对当前写权限，再读取原回执。
