# 在任务依赖图中跟进交付

[English](../en/task-delivery-chain.md) · [精确合同](../../contracts/task-delivery-chain.md) · [编辑任务依赖](task-dependencies.md)

当前版本：1.0.0；关联任务：T-DELIVERY-112。在“开发协作 → 任务 → 任务依赖”选择任务，展开右侧“交付与质量”。面板按需读取当前任务，不会因打开或刷新派发工具、执行测试、提交验收或创建问题。

先看任务版本和关联执行依据。依据一致仅表示运行与当前任务输入相符；依据已变时，旧执行仍可查看，但不能证明当前需求已经完成。依据未知或没有关联运行时，页面明确提示，不补造进度。

任务当前绑定的运行若有 **WorkBuddy 代码交付待核对**，展开交付与质量后选择 **打开 WorkBuddy 原始尝试**，可直接查看对应运行、节点和尝试的已有记录。该入口只读取证据。

“运行测试与证据”显示当前关联运行的测试节点状态，成功数量不等于测试用例覆盖率或验收资格。打开测试节点可下钻到相应运行、节点及已存在的尝试；未开始节点没有有效 attempt。子流程的完整测试结论需打开原运行证据查看。

“正式验收”单独显示当前任务是否满足已有正式验收规则。需要决定时打开任务验收，由正常流程重新核对权限、任务／需求版本、前置验收、独立测试和代码证据。明确退回会保留 Review，生成正式来源的问题，并撤销当前及已验收下游的交付资格；不会把测试成功改成失败执行。

“团队计划”及“问题与需求回流”只展示当前任务所关联运行的正式引用，不包含未开始计划或其他历史运行。每类最多展示 20 项；范围提示会显示实际总数。问题来源为执行失败或验收退回，不能靠手工填写问题元数据建立关联。已正式回流的需求可直接打开；尚未回流的问题需进入详情显式采用。

依赖图和交付记录版本不一致时，先比较或刷新图，保留未保存草稿。切换账户、组织、项目或任务不会继承旧任务记录；权限变化后记录隐藏，按当前身份重新读取。

需要批量开发时，在完整依赖图勾选 1～16 个未验收任务，保存依赖修改并处理冲突后进入既有团队派发。选择已发布专家配置、逐任务职责和模型，核对固定版本预览，再明确启动；此处沿用真实前置验收依赖推进。执行、独立测试、正式验收和问题回流仍是不同动作。

本面板仅展示安全元数据，日志、命令和完整证据通过原有授权详情打开。实际验证范围以本阶段交付记录为准，不代表完整平台、分布式容量或生产验收已完成。
