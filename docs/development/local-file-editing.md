# 本地文件编辑与保存

[English](../en/local-file-editing.md) · [字段、事务与恢复合同](../../contracts/workspace-file-context.md)

本说明适用于当前1.0.0本地工作区文本编辑阶段。进入“开发 → IDE”，选择本地工作区，在项目已绑定的目录中打开已有文本文件。桌面可明确选择并绑定项目文件夹；普通浏览器使用服务端允许根目录内的绑定。完整IDE、多工作区、文件创建／删除、终端、LSP和调试仍在实施范围内。

## 先确认文件来自哪里

目录栏显示当前项目工作区。每次打开文件，服务同时确认项目、工作区名称、实际根目录身份和文件内容，编辑器将这些依据与草稿一起保留。出现“草稿来自…”时，指的是草稿最初读取的工作区，可能与当前目录栏不同。目录名、相对路径和内容都相同，也不能说明仍是同一次工作区绑定。

修改后点击“保存”或按Ctrl／Cmd+S。保存同时核对原文件版本与原工作区上下文，不会自动覆盖其他操作的修改。

## 两种冲突分别处理

| 提示 | 含义与操作 |
| --- | --- |
| 文件版本冲突 | 工作区仍相同，但文件已被其他操作修改。草稿保留在编辑器中。选择“保留草稿并更新版本依据”后，手动核对、合并，再明确保存；选择“载入最新内容”会用已读取的当前内容替换编辑器草稿。 |
| 工作区已变化或需要核实 | 原草稿的工作区已变，或原保存已恢复但尚未确认当前工作区。先点“读取当前文件”，查看当前来源和“比较当前内容”。确认要把草稿用于该工作区后，选择“采用当前工作区并保留草稿”，手动合并后再保存；也可选择“载入最新内容”放弃编辑器中的旧草稿。 |

“读取当前文件”只读取；采用新的依据也不会立即写文件。读取失败时草稿保持原样，不能靠相同目录名、刷新元数据或反复保存把旧草稿转成新工作区的内容。

服务确认原操作未受理时会保留拒绝回执；即使原目录后来恢复，迟到的同一请求也不会写入。采用当前工作区后，下一次明确保存使用新的操作标识。

## 保存结果尚未确认

网络中断、无效回执或“需要核对”不代表文件一定没有写入。使用“恢复上次保存”核对原操作；页面保留原请求、原提交内容和原调用上下文，不会把后来编辑的内容混入该次恢复，也不会自动发起新保存。

原成功回执说明那次保存的结果，不能证明当前工作区仍相同。恢复成功后仍需读取当前文件并明确选择新的依据。若提示需要核对，查看原操作、原内容与已提交内容；仅在确认仍是原目录时，按提示通过外部编辑器核对原版／提交版。目录已替换或原操作来自其他会话时，应依据原记录处理，不能向新目录补写来消除提示。

## 草稿保留的期限

未保存草稿与待确认请求仅保留在当前页面会话的有界内存中，按账户、组织和项目隔离；切换身份不会显示或采用另一身份的草稿。回到原上下文时可恢复仍在内存中的内容，但较早的记录可能被清除。文件正文与待确认请求不写入浏览器持久存储，刷新、关闭页面或重启应用后不保证恢复。

页面会拦截部分离开操作并提示未保存内容；这不等于持久备份。需要长期保留的草稿应先由用户自行保存副本。文件保存成功也不等于测试通过、任务验收或部署完成。
