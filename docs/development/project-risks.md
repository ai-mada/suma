# 项目风险操作与 AI 协作 SOP

状态：T-PROJECT-121当前1.0.0实现说明；负责人：项目治理／工作台。需求7、10、12、13。[English](../en/project-risks.md)、[PRD](../product/project-risks.md)、[合同](../../contracts/project-risks.md)、[架构](../architecture/project-risks.md)。实际检查范围以[报告](../quality/project-risks-verification.md)为准。

## 登记和评估

从项目概览的风险摘要进入项目计划“风险”，或从排期模型的风险建议选择登记。建议是原始线索，正式风险需要明确保存。采用同一建议时，平台返回已登记风险，不会用新表单悄悄覆盖既有评估。

填写标题、描述、当前项目的人类负责人、复查日期、策略和处置计划。概率／影响为1–5顺序等级，可以未知；只有两项已评估时才计算相对评分。评分不是实际发生概率或预计损失。关联的任务、需求、问题必须是真实的同项目记录。

## 处置、复核与重开

1. 启动处置，通过关联任务进入原任务详情与工具派发。风险页不直接执行命令或启动模型。
2. 完成处置后提交复核，选择结论并填写剩余风险、理由和证据说明。缓解结论需要关联任务当前正式验收；代码来源还需要现有精确候选与独立测试依据。
3. 有审核权限的人员核对复核快照后明确关闭，或退回继续处置。已变化的评估、负责人资格、关联版本或验收不能用旧快照批准。
4. 接受、避免、转移或不适用是人员风险决策，按各自结论显示；它们不表示代码修复或独立测试通过。
5. 风险重新出现时重开为新周期，旧关闭结论和依据保留。再次关闭需要新的复核。

保存冲突时保留当前草稿，核对最新版本后再决定。网络失败后使用原操作恢复入口，先确认原请求是否已生效，不以新操作重复提交。关闭详情或切换项目不会扩大其他项目访问权限。

## AI 协作边界

AI可以读取已授权上下文、提出风险和处置建议、帮助完善关联任务及计划；原建议、固定来源和人员决定分别保存。模型不能把“已处理建议”当作“风险已缓解”，不能依据绿色日志替代正式任务验收，也不能自动取得关闭权。

智能体沿原任务、模型／工具配置、DAG和Runner执行。当前直接固定候选的代码处置已有门禁，并沿受保护的当前子流程关系有界递归核对。复杂合成、动态映射和外部流程尚需等价证明，证据不足时阻止缓解关闭。不得通过改成其他结论冒充代码验证。

项目概览数量来自完整授权范围，列表只显示已加载页。未评估与逾期分别显示；历史窗口之外有记录时明确给出总量，不把有限列表当作完整生命周期。
