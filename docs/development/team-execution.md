# 查看团队执行与交付进度

[English](../en/team-execution.md) · [工作台合同](../../contracts/team-execution-workbench.md) · [团队编排与恢复](../../contracts/expert-team-orchestration.md)

在当前项目进入“开发协作 → 执行记录 → 团队执行”。无需先勾选任务，即可查看这个项目中你有权读取的专家团队计划。这里沿用已有团队计划及详情，不会因打开页面、刷新或翻页启动任务。

## 先看计划，再看需要处理的事项

每个计划显示团队、当前状态和原任务进度。等待、执行中、待验收、已验收、阻塞和停止分别展示；发现阻塞或待验收时，打开对应计划，查看任务、依赖、实际运行及现有处理入口。

| 看到的事实 | 如何理解 |
| --- | --- |
| 预览／待启动 | 计划和执行依据已准备，不表示任务或模型已经执行。启动仍需在详情中明确确认。 |
| 等待依赖或阻塞 | 按计划显示的原因检查上游验收、来源变化或授权等依据。反复刷新不会跳过门禁。 |
| 执行成功／待验收 | 运行结果已经产生；是否通过正式验收仍取决于固定版本的测试证据与有权人员的决定。 |
| 暂停／停止 | 暂停停止新增派发；停止不等于运行进程已经退出。查看原运行的停止回执或核对入口。 |

详情中的启动、暂停、恢复、停止、修订、测试与验收继续使用各自原有条件。未知命令结果先恢复原操作；不要用创建新计划或重新启动来代替核对。

## 总数与已加载范围

列表每次最多读取10个计划。服务端总数表示最近成功读取时当前范围内的可见计划数；“已加载”表示页面目前已经取得的不同计划数。需要更多时再加载下一页。逐计划进度不等于全部项目或整个组织的汇总，也不代表机器健康、可用槽位或真实多机容量。

读取暂时失败时，已经显示的数据可能是上次快照；按提示重试读取，确认状态后再处理。权限失效或切换账号、组织、项目后，不沿用旧范围的数据和分页。

## 返回与分享

打开计划后，当前视图和计划标识保留在地址中。刷新或分享链接时，系统重新检查当前访问权限再读取该计划。关闭详情返回同一团队执行列表；刷新列表会重新读取，不保证保留所有已加载页面或滚动位置。

当前地址形式为`view=development&sub=runs&layout=team&panel=expert-team:<计划ID>`，项目仍由原`project`参数限定。URL不会授予项目或团队权限，计划不可读时也不会替换成其他计划。

本说明覆盖当前1.0.0团队执行入口。物理多机运行、外部Multica服务互操作、所有CLI厂商能力、完整IDE和生产容量仍需分别实现并验收。
