# 查看需求验收追踪

当前 1.0.0；[English](../en/requirement-traceability.md) · [接口合同](../../contracts/requirement-traceability.md) · [限定验证](../quality/requirement-traceability-verification.md)。

在需求详情展开“验收追踪”。面板读取当前正式需求、已发布设计、实际采用任务及其确切运行，不会创建任务或启动工具。每条验收标准显示映射任务数和当前正式验收的任务数；展开标准查看任务绑定、运行、测试节点和人工验收，再从真实引用进入任务或运行证据。

标准序号只属于当前需求版本。相同文字仍可有两个独立条目；需求版本变化后不会把旧设计的序号套到新内容。设计发布不等于任务采用，执行成功不等于人工验收，测试节点数量不等于用例数量或覆盖率。

| 看到的情况 | 下一步 |
| --- | --- |
| 尚无发布或标准没有映射 | 在“设计与拆解”补齐草稿，按当前权限审阅发布；普通关联任务不会自动成为可信覆盖 |
| 提案尚未采用 | 阅读完整任务变更预览，明确采用后再按原任务入口派发 |
| 发布、需求或任务依据变化 | 对照当前正式内容重新审阅及采用；旧运行保留追溯，不替代新依据验收 |
| 没有关联运行 | 仅表示该任务当前未派发，不表示整个项目从未执行 |
| 测试节点成功但未正式验收 | 查看确切候选和独立测试，再由有权人员使用既有验收操作 |
| 来源不可用、运行未知或读取失败 | 保留真实状态，检查当前来源和权限；显式刷新，不猜测通过或重复创建任务 |

节点与测试的下钻列表各最多 20 项，完整计数单独显示；列表不完整时不能据可见项推断所有结果。当前测试汇总仅限该运行的测试节点，完整用例计划、逐标准自动测试与应用版本／发布追踪仍待实现。

“刷新记录”会先隐藏旧事实。折叠、切换账号／组织／项目／需求会停止旧读取；权限失败后受保护引用隐藏，重新获得权限后显式重试。外层需求版本已变时，点击“刷新需求详情”重读需求后再查看追踪；版本失配与权限失败均不会自动刷新父页面，避免反复读取。不能用旧页面事实执行下一步。

追踪本身是读取。保存设计、发布、采用、派发和人工验收分别沿用当前权限、预期版本与原操作恢复；结果未知时恢复原请求，不能换一个操作标识猜测是否已执行。用户正文及不可变证据保留原语言。
