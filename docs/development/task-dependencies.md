# 编辑任务依赖

[English](../en/task-dependencies.md) · [接口与一致性合同](../../contracts/task-dependencies.md) · [参考实现整合记录](../integrations/referenced-conversation-integration.md)

版本：1.0.0；关联任务：T-INTEGRATION-111。任务依赖描述交付先后与前置验收，不会因编辑关系启动执行。任务执行仍使用已有流程、开发工具、独立测试和验收入口。

## 在同一草稿中查看和调整

进入项目的“开发协作 → 任务”，打开“任务依赖”。列表与依赖视图沿用同一项目；依赖视图地址使用 `view=development&sub=tasks&layout=dependencies`。在关系图或表格中选择任务，添加或移除前置任务。箭头从前置任务指向后续任务；“B 的前置任务为 A”表示 A 的交付先于 B。

图与表格共用同一份草稿。调整先保存在页面内，点击保存才提交实际改变的任务；取消编辑放弃本地修改。任务名称、当前状态和依赖来自真实项目记录，编辑不生成示例任务或虚构进度。

最多读取 1000 个任务的完整图。项目任务超过范围时，页面显示真实总数和限制，提供返回普通任务列表的入口，不编辑不完整图。单次保存最多 100 个变更任务。

## 保存后确认当前结果

保存时每个改动任务携带开始编辑时的版本。服务端会核对当前全图，拒绝循环、自引用、重复关系和跨项目依赖。相同前置集合不算修改，调整顺序也不会生成新版本。

成功提交会提升改动任务版本，将其置为进行中，撤销旧验收资格，并沿现有规则使已验收下游结果失效。已有执行、测试和验收记录仍可追溯。需要重新按照正常流程证明当前版本符合交付要求。

原操作确认后，页面重新读取当前图。若后续有人继续修改，页面提示复核；如果刷新失败，保留草稿和原操作已确认的提示。不要将原回执当作当前状态，也不要为同一不确定操作重新生成请求。

## 多人编辑与异常恢复

版本冲突时保留当前草稿。读取最新图只展示比较，不会覆盖你的修改；明确选择“采用最新版本并保留本地修改”，才会把本地改过的关系应用在最新版本上，其他人的未改项保持最新。也可以选择“使用最新图并放弃草稿”。再次保存前检查依赖影响。

网络中断且结果未知时，原操作进入恢复状态。页面锁定本次字段，使用原账户、项目、完整请求和操作标识查询或重放原操作；成功确认后再刷新图。切换账户、组织或项目不会把该操作转给新的上下文。权限已撤销时需恢复当前权限后处理。

有未保存草稿时，离开页面、切换项目或打开任务详情会提示处理草稿。图操作也有表格入口，窄屏及键盘用户可以使用表格完成同样操作。界面与服务端诊断支持中文、英文，任务标题等业务内容保留原文。

## 与研发闭环的关系

编辑前置关系不修改执行 DAG，不会合并代码、批准旧测试或启动智能修复。分配负责人使用[任务交接](../en/task-handoff.md)；执行与团队进度使用[团队执行](team-execution.md)。正式验收需要当前版本的真实执行和证据；未知副作用先核对原操作，不自动重跑。
