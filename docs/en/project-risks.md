# Project risk workflow

Status: current suma1.0.0, T-PROJECT-121. Owners: project governance and workbench. Requirements7/10/12/13. [中文](../development/project-risks.md), [PRD](../product/project-risks.md), [contract](../../contracts/project-risks.md), [verification](../quality/project-risks-verification.md).

Open Risks in project planning from the overview summary, or explicitly register an existing planning suggestion. Advice and formal risks remain separate. Adopting an already registered source returns the existing risk without applying a different form over its assessment.

Record a description, authorized human owner, review date, strategy, plan and real same-project tasks, requirements or issues. Probability and impact are ordinal1–5 ratings. Unknown ratings remain unknown; their product is a relative score rather than a statistical probability or measured loss.

Start mitigation through the existing task details and dispatch flow. Submit a review with the intended disposition, residual assessment, rationale and evidence statement. Mitigation requires current formal task acceptance; code-bearing tasks additionally retain the existing exact-candidate and independent-test proof. A green run alone is insufficient.

A currently authorized reviewer explicitly closes or returns the risk. Changes to the assessment, owner eligibility, linked versions or acceptance invalidate the submitted basis. Acceptance of exposure, avoidance, transfer and not-applicable decisions are displayed as human risk decisions, not successful code testing. Reopening starts a new cycle while preserving earlier decisions.

On a version conflict, retain the draft and compare current data. After a network failure, recover the original operation before issuing another write. Overview totals cover the full authorized project; loaded pages and bounded history disclose their own coverage. Unassessed and overdue risks remain separate.

AI may propose risks and actions, but it does not gain closure authority or replace task/test acceptance. Current protected child-workflow relations are checked recursively within bounded depth and node limits. Complex composition, mapping and external-workflow origins still require equivalent evidence; unsupported proof blocks mitigation closure. Current local checks do not establish vendor, multi-host or production acceptance.
