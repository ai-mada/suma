# Cursor ACP development

T-CURSOR-ACP-189; suma 1.0.0. The [contract](../../contracts/cursor-acp-execution.md) is authoritative. The original 31 requirements and P0–P7 remain active. See the [verification report](../quality/cursor-acp-execution-verification.md) for the tested scope.

## Connect and develop

Choose Cursor in the existing tool connection panel. Detect the local installation, provide the name of a dedicated credential environment variable on the execution machine, explicitly read the model catalogue, select its exact model ID and confirm the connection. The renderer receives no credential value or arbitrary command arguments. An editor, launcher or unverified file remains a limited observation.

Reading a catalogue may create a vendor session or require authentication. Sending no development Prompt does not prove that the vendor performs no internal work. Authentication failure provides no usable catalogue. A successful connection requires fresh inventory matching the exact configuration; registration and explicit enablement remain separate actions. Without the desktop bridge, use the existing Runner configuration path on the target machine.

Task development, reviewed discussion plans and expert teams reuse the original fixed-profile Preview and explicit Start. Private and Pool workers retain current identity, inventory, route/Grant, lease and original assignment checks. The selected CLI model is shown as fixed by the tool. Its configuration ACK is not proof of the provider's underlying model identity or billing. Organization or project enforce budgets refuse this observe-only runtime.

During execution, the existing human permission flow accepts only the exact allow_once or reject_once choice. Persistent grants, MCP approvals and unsupported blocking extensions are never silently accepted. The original isolated workspace produces a sealed candidate, a different worker tests that exact commit, and a currently authorized person explicitly reviews the result. Tool completion does not certify quality or acceptance.

## Architecture and recovery

The public entry is `cursor-cli`, with `adapter=cursor` and `protocol=acp-stdio-v1`. It reuses ACP Capability/Evidence, the `acp_execution` node and `acp-go-sdk 0.13.5`. Runtime must exactly match Adapter. No new business table, dispatcher or HTTP API is introduced, and Cursor is not a Qoder alias or a native ModelExecution/Codex selection.

Go fixes the package entry and arguments, verifies the entire local dependency closure and binds its configuration digest. Execution uses fresh home, configuration, cache and temporary directories, mapping only the explicitly referenced credential to `CURSOR_API_KEY`. Current checks refuse executable project/ancestor settings, MCP/hooks and fixed enterprise hook sources; user files are not automatically deleted. These controls and the fixed sandbox argument are not a general OS isolation guarantee.

Only exact `configOptions` and the corresponding `session/set_config_option` ACK authorize the configured model before Prompt. Additional Cursor model metadata and activity notifications grant no task, permission or quality authority. Cancellation, RPC completion, process/tree stopping, usage and delivery are separate facts.

Unknown native effects retain the original assignment, operation key and Journal. Recover original HTTP receipts and durable observations; do not replay Prompt, load an old session or substitute the current draft. Account, organization, project and configuration changes retain the existing current-authority and source checks.
