# Discover installed tools on an execution node

Version 1.0.0 · T-REMOTE-TOOL-SCAN-205 · Owner: integration agent. Status: scoped implementation, actual Worker/HTTP/SQLite journey and final bilingual visual review passed.

Existing inventory only contains configured commands. This feature asks an exact ordinary or Pool node to inspect a fixed installed-tool directory even when it has no registered profile or command allowlist. It reuses the original maintenance owner, durable journal, bounded native probes and current platform permissions.

The machine must explicitly allow installed-tool discovery. The declaration belongs to its original continuous maintenance instance; a one-off report does not claim support. A maintenance-only startup mode performs no new business task claims or execution, and preserves unresolved business journals. Pool authorization also requires the machine's local project scope and current grants/routes.

The user checks current support, requests the selected tool or a bounded permitted set, and reads installation, version and preparation facts. An explicit action opens the original guide for the exact adapter and Worker. Installation, launch support, configuration, provider login, model health, registration, enabling and delivery remain separate facts.

Requests accept only nine fixed adapter identifiers, never executable paths or arguments. Probes use isolated user directories and bounded process-tree tracking. Public observations omit paths, internal commands and credentials. Request state and original operation receipts are transactional; lost acknowledgements replay the same nonce/body/key/reference rather than rerunning a probe.

Started work without a full result remains unknown. Only durable original result or stop receipts can reconcile it. Closed-unknown confirms stopped processes while preserving the unknown result; expiry or missing PIDs are insufficient. Browser wait controls do not cancel machine operations, and permission or scope changes clear stale observations.

Selecting a history entry checks that exact record before showing preparation actions. Read again can replace an in-flight detail request. A late response for the previous selection cannot change the current result or restart its polling.
