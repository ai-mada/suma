# Tool preparation diagnostics and handoff

T-TOOL-PREPARATION-203. Suma 1.0.0. Owner: main integration agent. Status: scoped implementation and verification complete; see the [evidence report](../quality/tool-preparation-recovery-verification.md). See the [contract](../../contracts/tool-preparation-recovery.md), [requirements](../product/tool-preparation-recovery.md), [architecture and AI SOP](../architecture/tool-preparation-recovery.md), and [interaction design](../design/tool-preparation-recovery.md).

Preparing the current execution node must retain the selected adapter protocol. Continue through the existing Quick, workspace and local or remote setup guide using the exact approved node, current caller, scope and explicit request nonce. Unknown adapters never fall back to generic Codex or all-tools preparation. Ordinary rerenders and stale requests must not overwrite manual drafts or a newer tool selection on the same node.

Claude SDK and OpenCode SDK preparation failures expose a small trusted reason set: unsupported native version, changed installation evidence, missing or invalid SDK assets, unavailable Node runtime, and an unavailable explicit credential reference. The optional private connection field is accepted only for these SDK adapters in the unavailable phase. No paths, secret values, raw exception messages or stderr are returned. An unavailable environment reference does not establish a provider authentication failure.

Use existing guide, configuration, detection and original-operation reconciliation actions. A credential-reference action targets the name field. An uncertain original operation keeps priority; suggestions do not authorize a second operation, installation, login, activation or model request. Remote commands remain public drafts to execute explicitly on the target machine.

The original Runner additionally supports `--prepare-tools <new.json> --prepare-codex-stdin`, using seven closed private fields and the existing fixed native app-server protocol. It inspects the selected native file and exclusively creates one new commands file without launching a vendor CLI, model or Worker. The Web form hands the exact file, shell and protocol back to the original remote guide. No business API, table or dispatcher is added. Resource checks, synthetic component interactions, provider authentication and delivery acceptance have separate evidence. The complete 31-requirement/P0–P7 platform objective remains active, including physical multihost, database, installer, scale and production acceptance.
