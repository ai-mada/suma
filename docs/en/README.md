## Historical T-P4-012: exact-attempt tool history — locally verified

The new history reader binds each page to the selected project, run, node and attempt, with current authorization checked in the same database transaction. It preserves the original persisted JSON text as `raw_data`, separate from its parsed projection. Saved cursors retain one fixed watermark, including the initial empty window. Each request scans at most 1,000 candidates, limits one serialized event to 2 MiB and the returned event array to 4 MiB. The UI offers 5, 25, 50 or 100 rows (default 50); history pages are separate from the current live 40-row window.

Language changes only redisplay the loaded facts. Unknown inner content remains available as raw evidence; temporary Go/JavaScript Unicode compatibility interpretation cannot create native diagnostic provenance. Disclosure and focus follow the original event, and refresh restores the exact selected attempt. suma is an intelligent development platform for organizations, teams, projects, requirements, design, execution, testing, human acceptance, releases and issue feedback. Business acceptance, execution state, test evidence and deployment are distinct facts.

The current internationalization work introduces Simplified Chinese (`zh-CN`) and US English (`en-US`) with extensible language catalogs. UI language, business time zone and source content are separate concerns. Original user documents, code, tool output and immutable evidence retain their original language. Unsupported legacy diagnostics are explicitly marked rather than silently replaced by an imprecise translation.
