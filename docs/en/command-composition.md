# Safely compose existing command configurations

Version 1.0.0, stage T-COMMAND-COMPOSITION-215. Implementation follows the [frozen contract](../../contracts/command-composition.md); final scoped evidence is recorded in the [quality report](../quality/command-composition-verification.md), not assumed here. Owners: Runner, workspace and integration. [Product and AI SOP](../product/command-composition.md), [interaction](../design/command-composition.md). The full 31 requirements/P0–P7 and 58 limited/34 pending/92 baseline remain active.

Expand composition in the original tool setup guide, choose the target Shell, provide 2–16 existing absolute source filenames and a new output filename in an existing directory. Copy the command and explicitly execute `suma-runner --compose-commands DEST` on that machine. Its bounded UTF-8 stdin contains only `{"files":["absolute-source-1","absolute-source-2"]}`. The browser handles references, not source JSON, uploads or execution.

The local service reuses original ordinary-file, parent-directory, bounded-read and exclusive new-file writing protections. Input is at most 64 KiB, each source at most 2 MiB, cumulative reads are at most 2 MiB, and output is at most 128 commands/2 MiB. It refuses existing destinations and does not create parent directories or modify sources. Source bytes and directory bindings are checked again before writing.

Each source rejects duplicate JSON keys, unknown fields and empty objects. References such as a developer's `native_workspace.checks` may resolve to commands in another source, so the original complete configuration validation runs after composition. Duplicate command IDs always fail: there is no overwrite, deduplication, automatic rename or added capability. Existing protocol constraints remain unchanged; NativeWorkspace policy is not imposed on Codex, Claude or ACP configurations.

The CLI mode rejects every unrelated explicit option before stdin or credential access, including false switches. It starts no process or probe, reads no system credential, uses no environment-secret fallback and contacts no control plane. A success receipt reports only its protocol, source count, command count and final file-byte SHA including LF. Diagnostics contain a fixed reason, a 1-based source index when applicable and a localized safe message; private paths, commands, environment contents and nested errors are not printed. Preserve original files when inputs change or writing is unconfirmed; never automatically overwrite or retry an uncertain result.

The CLI owns mode/input/receipt handling; the Runner owns bounded composition and original file protections; original command validators own final policy; the setup panel owns current-scope path drafts and copied commands. There is no new backend API, table, store, dispatcher or dependency. AI maintenance must retain two-stage structural/reference validation and distinguish preparation, authenticated inventory, explicit enablement, internal checks and independent test evidence.

A composed file is not a connection, inventory observation or dispatch permission. Continue through the existing Runner guide, current node report, profile registration and explicit enablement. Developer-internal checks do not prove a different Worker independently tested the same commit, and do not replace candidate evidence, human acceptance or baseline handoff. Account/project/node/source changes invalidate drafts and late clipboard feedback. Keyboard, 44-pixel controls and responsive Chinese/English states follow the existing design system; real vendor/model execution, multi-host operation and production acceptance remain separate work.

Current integration: the optional explicit path-adoption action reuses the original ordered configurationRequest channel. It changes only the shell and output reference, preserves the selected tool, identity and workspace, and never proves that composition ran. Guided outputs end in .json to match the existing consumer; standalone native composition validates JSON content independent of extension. Actual component generation/PowerShell and the parent-child guide check have separate evidence scopes. Total source reads and final output including LF each remain at most 2 MiB.
