# Tool diagnostics to exact-node connection preparation

Suma1.0.0 · T-TOOL-RECOVERY-NAVIGATION-217. Owner: tool workspace and integrator. The full31 requirements and P0–P7 remain active. See the [contract](../../contracts/tool-recovery-navigation.md) and [stage report](../quality/tool-recovery-navigation-verification.md).

The existing tool actions move ahead of diagnostics and history. A current tool's diagnostic can take users to its exact ordinary project Worker and continue connection preparation using the original guide, pairing and report feedback. Current unknown inspections or pending writes retain their original reconciliation priority. Shared Pool nodes keep their owner-authorized path and never fall back to ordinary project credentials.

The original public draft preserves the exact adapter/protocol, Worker and source profile. Current caller/scope/version/SHA and monotonic ownership reject stale or delayed reads. Only the existing nine supported preparation tuples are eligible; unsupported tools do not silently use another adapter. An exact new report returns to the original Quick dialog for a fresh profile/match decision. Registration, replacement and enabling remain separate explicit operations.

Opening a guide, copying a command and creating a configuration do not run it or establish health. This change adds no automatic login, installation, model call, task dispatch, process stop, API route, storage table or scheduler. Source implementation, synthetic navigation checks and real remote recovery are recorded separately.
