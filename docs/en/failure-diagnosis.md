# Failure diagnosis and repair drafts

Status: T-P4-030, suma 1.0.0, verified within a bounded local scope on 27 October 2026. The full platform remains in progress.

Open diagnosis from an existing failed workflow node, a blocked expert-plan item or its issue. The panel is folded by default. Where only a run is known, explicitly load its current nodes and select the exact failed attempt. Unknown or reconciling execution must use the original run reconciliation path; it cannot start a new diagnosis.

Review the fixed failure evidence and its full or tail selection before consenting to a dedicated read-only diagnosis model. The service binds the actual run, node, attempt, issue and source versions. A single model request has no workspace or execution tools. Model configuration does not establish account health, and cost estimates are not vendor bills.

Read observations and hypotheses as model proposals, then edit only the repair title, description, priority and acceptance criteria. Save the repair and explicitly adopt it into a project requirement draft. Existing issue-intake requirements are opened without overwriting or duplicating them. Adoption does not repair code, retry execution, accept a task, close the issue or merge a candidate. Original model output and fixed evidence remain immutable and available under disclosures.

After a conflict, read the current version, retain the draft and confirm again. An uncertain response restores the original request and operation key. Changed source blocks adoption while preserving the analysis. Source-run and diagnosis-run links remain distinct; typed adoption lineage in the selected requirement opens the original diagnosis. Chinese/English switching translates system diagnostics while preserving model, source and human text.

The recorded journey used real Control, Runner, DAG and accounting on one Windows host with one owned loopback model response. Analysis `fb963b9d6b1a3528087b6ce924f49807` reached adopted version 4 and linked requirement `223291c900a31d06ef3d511b1da149ec`, draft version 1. It recorded 40 tokens and an estimated 57 CNY micros. Human repair edits remained separate from the original output. Control and Runner exited gracefully, the model thread stopped, and source inventories and older business rows were unchanged.

Final `web-release` cold readback verified diagnosis deep links, requirement lineage, Chinese/English and refresh without another model call, Runner or login. The primary preview was updated forward: the original 177 table schemas and full rows remained unchanged, three empty diagnosis tables and one index were added, and existing authority, grants and runs were preserved.

This does not establish real vendor account/model/billing behavior, physical multi-host execution, a complete device/theme matrix, full platform regression or production acceptance.
