报告由隔离的许可命令生成，Runner 分配源码目录旁的新路径，支持安全 argv 字面占位符及环境变量。保存真实退出码、原 XML／摘要、候选代码、Worker、节点、attempt、fence，并有界解析 JUnit。界面只按需读取原件，任务模型上下文仅带紧凑引用。当前工作树证明查询仍解码私有完整 attempt JSON，不声称消除了数据库 XML 读取。

## 定向检查与修复

共 37 个不同的顶层受影响用例通过，分组运行：Go14 项新增（解析器3、Runner3、DAG1、质量领域4、合同生成2、诊断1）及既有派发／交付／工具回归5；Web计划9、工具2、交付7。既有测试内的子场景和修复后复跑不重复计数。没有重复全套、模型或原生构建。

- 覆盖当前权限、不可变发布、原回执、覆盖不全、跳过／缺失／未知／未映射失败、退休和来源变化、固定 attempt／fence、失败用例去重与需求回流。包括“DAG 成功但用例被跳过仍不能验收”以及“空绑定经历发布→退休仍不能验收”。
- 真实 Node22.16.0 的 testsuites 直接 testcase 与冗余 failure 消息布局已明确支持；孤立／矛盾 failure 属性、未知 status、DTD／namespace、重复 selector、矛盾计数、深度／大小越限仍拒绝。退出码 0 而报告 failed/error 时，测试节点失败并保留真实退出码。
- 修复质量结果的 run URL 被流程页优先截获、TaskDelivery 质量链接未遵守 loading／禁止导航，以及任务技术性自动增版误判来源变化。
- Web类型检查及生产构建通过；5170 对中英文键，placeholder／plural／markup检查通过，自有生产源码硬编码检查为0；OpenAPI／TypeScript合同检查通过，526个模型、269条路径，其中新增7条路径／9个操作，原路径未变。生产构建仍有既有 Monaco／ELK 大块提醒，未以关闭提醒作性能结论。

## 界面验收边界

本阶段尝试通过 Computer Use 观察已有 Chrome 窗口；工具因无法可靠确定当前浏览器 URL 而停止。停止后没有输入、登录或绕过策略，也未修改用户正在使用的预览。组件测试、HTTP 与生产构建不能充当真实界面验收；中英文实际页面、响应式、主题和键盘操作仍待该工具可用时验证。
