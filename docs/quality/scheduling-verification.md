## 实际产品界面闭环

使用新批次 Windows 控制面与两个独立 Runner，在隔离本机项目运行固定v1流程。全部策略调整、运行启动、节点下钻和人工批准通过产品界面完成；命令只操作本轮任务标记文件，不调用收费模型。

1. 初始默认策略v0。先审阅并确认槽位0／累计额度3，得到策略v1；两个真实Runner在线时，两个节点仍待派发，attempt为0、累计使用0，未提前执行。
2. 固定预览再确认槽位2，得到策略v2。两种命令能力分别由两个已注册执行身份领取，两个实际子进程互相等待开始标记；独立测试核对进程不同且工作重叠 **1497ms**。
3. 两分支成功后汇合，独立验证成功，再等待人工门禁；此时3次attempt、累计使用3，没有自动通过审批。
4. 人工核对并批准后运行成功。刷新和只读快照仍为 **5节点、3次attempt、22事件、累计使用3、就绪0**；审批节点没有伪造Runner尝试。两个本轮Runner在运行结束后按PID及准确程序路径停止，预览控制面保留。
5. 精确attempt链接打开实际Runner结果与退出码，刷新保留运行／节点／attempt；列表返回与节点切换可用。当前派发条件和历史回执使用不同组件身份，持续实际观察177272ms仍各1份。

本机运行标识为 `a987e720d2d1397aa248547ee74d1648`。该过程证明调度准入、真实并行、回写与人工审批；两个命令是调度夹具，不能据此声明业务功能或全部需求已经验收。原生CLI的五条真实子进程旅程使用loopback模型／控制夹具，与上述实际控制面运行分别记录。
