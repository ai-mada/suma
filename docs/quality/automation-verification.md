# T-P4-002 自动化与事件验收

日期：2026-10-24。状态：本机功能切面验证通过，完整平台继续实施；负责人：主集成代理与自动化、事件、工作台、独立审核代理。环境：Windows amd64、Go1.24.5、Node22.16、pnpm11.25、真实 SQLite；两个浏览器读取同一本机隔离验收项目。

## 实际产品操作

1. 通过自动化工作台创建五段 cron 规则，选择已发布流程 v1，预演未来五次的 Asia/Shanghai 时间与 UTC；保存为草稿，再明确确认启用。
2. 一次人工触发、一分钟边界上的一次真实定时触发，各创建且仅关联一个运行。两个运行都完成独立工作树开发、固定 C 构建、真实字节制品上传与下载后包 HTTP 测试；共四份 build/package-test 证明、两份真实制品。此运行成功不表示任何新任务已获人工验收或已部署。
3. 暂停后修改规则为仅人工触发，形成 r2/v5，仍保持暂停。原有两条触发继续关联 r1、原固定流程和原运行，刷新精确详情不丢失，完整修订历史显示 r1/r2。
4. 真实运行页面读取最终 `run_succeeded`，独立显示事件连接状态，选择构建节点可查看候选、工作树与输出证据。终态事件的原数据库 `null` 元数据不改写，公开读取按合同返回空对象。
5. 工作台在实际 390、768、1366、1920 宽度进行局部走查；页面级无横向溢出，局部标签栏允许横向滚动。深浅主题、修订历史、弹窗 Escape 只关闭弹窗并把焦点返回“编辑策略”。这不是完整 WCAG、千节点图、所有用户旅程或所有浏览器矩阵。

规则 ID、原始名义时刻、触发、节点、持久事件序号、证明和本地字节重新摘要见 [机器可读旅程](evidence/automation-browser-execution.json)。账户凭证、运行数据库和制品原件保留在忽略的隔离验收目录，不提交。

## 检查中修复的真实问题

| 问题 | 复现与修复依据 |
|---|---|
| API 范围凭证可启用仅限人工会话的规则 | 6 个真实接口边界先失败，再收紧所有非空 scope 并通过 |
| 生成补偿流程可被规则引用 | 真实补偿关系证明创建/启用门禁缺失；补同身份检查，既存违规触发持久受阻 |
| 工作流列表升序导致默认旧版却提示“最新” | 使用服务端真实版本排序，注册表过滤受保护模板；普通同名前缀仍可用 |
| cron 列表中的星号被误当作受限字段 | `1,*` 与 `1,*/1` 保留星期限制；先复现错误日期再修复 |
| 合法大事件毒化续传游标 | 约 1.1 MiB 请求已被服务端接受，旧前端限制不足；统一 UTF-8 预算并限制保留窗口，协议错误可核对 |
| 成功终态空元数据违反公开对象合同 | 浏览器停止在终态之前；真实完整 SSE 测试先失败再规范化读取，保留数据库原事实 |
| 轮换时过期写入截止导致 unexpected EOF | 真实 20 秒连接测试复现；空闲/终止宽限与单次慢写截止分别控制，慢读仍须受限 |
| 并行构建负载下旧测试夹具没有发送生产心跳 | 原失败全文[完整保留](evidence/automation-go-contention.jsonl)；两项原测试串行也通过，随后改用真实 Worker.Run，并以2秒租约/2200毫秒真实进程完成[RED→GREEN](evidence/automation-fixture-heartbeat-receipt.json)。正式30秒租约和5秒默认心跳未放宽 |

最终普通 Chrome 在控制面实际重启后仍保留15条事件、所选 build 节点及完全相同的画布变换，持续连接恢复；正常轮换显示“连接正在续传…”。[重启记录](evidence/automation-browser-restart.json)与[视觉范围](evidence/automation-browser-visual.json)保存边界。IAB 曾出现重连提示，持续连接结论依据普通 Chrome 与真实 HTTP/TCP 测试，不泛化为所有浏览器。
