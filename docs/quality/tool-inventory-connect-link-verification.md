# 终端库存到工具接入核对

速码 1.0.0，`T-CLI-INVENTORY-CONNECT-260`。关联需求为 CLI、工具统一管理、分布式执行节点和中英文交互。 [操作](../operations/task-dispatch-options.md#从终端进入快捷接入) · [合同](../../contracts/tool-profile-reuse.md#从终端进入快捷接入)

终端以现有库存接口核对节点和命令，返回带准确项目、配置摘要和观测时间的接入链接。工作台依次核对当前上报、适配器入口和可复用档案。用户仍须明确暂停登记或启用。使用独立 Web 地址部署时，可显式覆盖链接来源。

交互参考 Multica 将终端操作引导到浏览器确认、并区分自托管 API 与应用地址的方式。速码沿现有库存与快捷接入合同实现该路径。 [Multica 固定参考](https://github.com/multica-ai/multica/blob/e8b6a97643ccc35efbcf2a4675c8d088a288ed6e/CLI_AND_DAEMON.md#L941-L950)

## 阶段验证

- Windows、Go 1.26.10。定向 CLI 检查覆盖选项、准确命令、过期、不可用和工作台地址。实际编译的 CLI 通过回环 HTTP 调用真实控制面与隔离 SQLite。4 次调用均仅请求库存，确认共享节点无上报和过期时拒绝、有效时生成准确链接、共享授权撤回后返回 403。各次读取前后核对 8 张业务表的指纹，结果一致。
- 定向前端验证覆盖错项目、过期、配置变化及从工作台进入原快捷接入后的二次核对。Chromium 使用隔离 API 测试数据，在中文 390 像素和英文 1280 像素下检查键盘进入、准确节点与命令预选和无横向溢出。浏览器验证阶段没有提交登记或启用。
- CLI 和浏览器证据保存在本地忽略目录 `.cache/q260/cli-actual/` 与 `.cache/q260/inventory-handoff-ui/`。本阶段验证截至配置审阅，厂商账号、模型调用和跨机器部署沿原验收范围。
