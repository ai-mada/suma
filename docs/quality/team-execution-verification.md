# 团队执行入口与项目进度验证

状态：1.0.0／T-TEAM-110，限定实现与验证通过。完整P0–P7与需求1–25继续实施。[当前合同](../../contracts/team-execution-workbench.md)、[中文指南](../development/team-execution.md)、[English](../en/team-execution.md)、[精简证据](team-execution-summary.json)。

本轮解除团队计划只能从“编排所选任务”历史入口找到的限制。在项目执行记录中增加团队执行视图，复用正式分页计划和原详情，显示每个计划的正式验收进度、非零阶段及需要处理的事项。URL保留视图／计划，账号、组织及项目切换隔离旧读取，明确权限拒绝时隐藏旧内容，瞬时失败保留并标明未确认快照。

使用现有React、i18next、Lucide、分页与原操作恢复，不新增依赖、数据库、调度器或派发接口。列表和详情分别按需加载；项目总数与已加载范围分开，预览不等于执行，执行成功不等于验收。

## 证据范围

实际命令、源码和产物摘要、检查范围与未完成项由同目录精简摘要记录。私有账号、控制面数据、日志及截图位于忽略目录`.cache/e2e/team-110`；不提交Git。沿用当前已验证Control程序和现有Runner，仅对自有Harness协议进行实际工具探测，没有模型调用或工具任务执行。

真实API准备使用独立185表新库，创建两团队、三计划与五任务：可启动预览、带两个真实排队运行的暂停计划、因任务依据变化不可启动的计划。原计划API以`limit=2`实际跨页核对不重不漏；新页面每页10项，分页交互另外使用定向DOM回归，不把两者伪称同一实际页面旅程。准备过程两次输入假设错误已保留，均关闭专属Control，并通过原API回执从同库续建；累计请求数不等于全部成功检查数。

当前源码优先复用已有当前权限与事务投影；原任务、运行、审批及恢复语义不变。本轮没有重新执行模型、开发、测试验收或生产发布全流程，不据排队运行、安装的CLI或工具探测推断机器健康、实际并发执行或物理多机容量。
