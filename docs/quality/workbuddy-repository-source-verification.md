# WorkBuddy 登记仓库来源核对

T-WORKBUDDY-REPOSITORY-SOURCE-242 · 速码 1.0.0 · 2026-11-05。 [接口与交付合同](../../contracts/workbuddy-task-dispatch.md#核对已登记仓库的分支提交) · [架构设计](../suma-architecture-design.html#workbuddy-repository-source-242)

在任务「交付与质量」展开「核对仓库来源」，选择当前项目的可用目标，再读取分支的最新提交。只有一个可用目标时会预选。结果显示分支、完整提交和观察时间，切换目标、原尝试变化或访问被拒绝会隐藏旧结果。正式候选、测试和验收仍沿原交付链路推进。

| 验证 | 结果 |
| --- | --- |
| Windows、Go 1.26.10、SQLite、实际 Git 裸仓库和回环仓库提供方 | 分支在登记后推进，接口返回实际新 HEAD，而非登记时的快照。校验原任务、运行、节点、尝试及目标版本，Git 引用和运行状态保持原值。 |
| 访问与并发保护 | 畸形查询、旧任务或目标版本、其他运行、未知目标及项目查看者请求在调用仓库前拒绝。提供方读取过程中变更原执行代次，响应拒绝返回已读取的提交。再次读取过期尝试时不再调用仓库。 |
| 中英文前端 | 10 项交付面板测试通过，覆盖按需读取、准确选择器、拒绝及过期响应清除。390×844 Chrome 使用隔离合成 HTTP 响应，通过键盘操作、双语、完整 SHA-256 换行和拒绝后清除验证。共 4 次业务 GET，零写入、页面错误或面板横向溢出。 |
| 合同及类型 | Go 合同测试通过，仅纳入生成的本接口、响应 Schema 和 TypeScript 类型。10,370 对中英文词条通过。以已提交版本隔离并行通知改动后，前端全项目类型检查通过。 |

参考 Multica 用 PR 的确切 HEAD 绑定评审的实现，速码复用已有仓库 Provider 和任务授权。 [Multica 固定提交](https://github.com/multica-ai/multica/blob/e8b6a97643ccc35efbcf2a4675c8d088a288ed6e/server/internal/service/task.go#L1241-L1265)

结果只在当前页面展示。本阶段用回环夹具建立 WorkBuddy 等待状态，实际 Git 验证使用本机隔离仓库。真实 WorkBuddy 代码归属、固定基线后的候选导入、同提交独立测试和分布式存储验收仍需后续验证。
