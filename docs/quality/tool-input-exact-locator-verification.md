# 收件箱定位原工具问题

速码 1.0.0，`T-TOOL-INPUT-LOCATOR-265`。关联需求为团队执行等待、重试后的原问题恢复、跨项目协作和中英文交互。 [收件箱合同](../../contracts/notification-inbox.md#智能体请求人工输入) · [交互设计](../design/notification-inbox.md#工具问题的处理入口)

## 设计与范围

收件箱返回经过原来源验证的问题标识及运行、节点、尝试。浏览器只在范围明确时采用深链，从原尝试详情取得准确 fence，再读取该次尝试的工具问题。当前重试无工作者时，仍可读取有授权的原尝试。问题不存在或链接无效时显示提示；正在核对的原答复优先于新定位请求。

面板展开后只标出匹配问题。初次进入可将焦点移到目标，后续轮询不重复抢占焦点。沿用原提交和个人通知动作。行为参考 Multica 的个人通知与原任务上下文分离方式，并保留速码的执行尝试与工具输入授权。 [Multica 固定参考](https://github.com/multica-ai/multica/blob/e8b6a97643ccc35efbcf2a4675c8d088a288ed6e/apps/docs/content/docs/inbox.zh.mdx#L7-L22)

## 阶段验证

- Windows、Go 1.26.10、真实控制面 HTTP 与隔离 SQLite。普通 Runner 和共享池均验证了同一尝试内两条问题的独立定位、历史原问题以及来源失效后隐藏链接。生成接口验证准确的只读定位字段。
- 62 项收件箱、导航和工作流相关检查与 8 项面板定向检查通过，覆盖排队重试期间读取原尝试、映射节点、错范围和缺失问题、原答复恢复优先。TypeScript、双语词条与生成合同检查通过。
- Chromium 使用隔离协议数据在中文 390 像素和英文 1280 像素验证两条问题中只高亮指定的已关闭问题、首次聚焦和键盘跳转。未发出写请求或出现横向溢出。浏览器证据位于本地忽略目录 `.cache/q265/input-panel-browser/`，后端日志为 `.cache/q265/backend.txt`。

本阶段分别验证了真实 HTTP 和隔离界面。未连接外部厂商会话，也未执行跨机器或 OceanBase 验收。
