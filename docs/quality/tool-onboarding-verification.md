## 验证策略

仅验证本次改变的桌面批量扫描、Web 选择与高级登记预检；未变 Go 探测代码直接复用上一阶段已构建控制面，不重复 Go 测试、生成合同或构建服务。组件用受控会话／桥接检查授权、并发、来源和草稿；一次真实 CLI 被动扫描独立记录，组件浏览器验证使用明确合成事实，不借当前用户账号。

## 当前结果

汇总与最终源摘要见[机器摘要](tool-onboarding-summary.json)。27 个不同定向顶层检查通过：桌面 9 个（6 新／3 原受影响），Web 18 个（8 新／10 原受影响）；重跑同一用例不重复计数，筛选未执行的历史用例不算通过。一次完整 Web 类型检查为 0；随后严格模式与行选择焦点修正分别只检查各自两份变动源码，语义诊断为 0，其余冻结输入复用。8,381 对中英词条检查通过，生产硬编码为 0；未重复 Go 测试、Schema 生成或全套历史验证。初次失败与修正记录保留在忽略目录，不覆盖原证据。

只读审阅后，集成另发现并修复两处实际 P2：严格模式 effect 重放使首次扫描永久等待，以及原批量完成后合并等待者的授权读取缺少自身截止时间。分别扩充原 UI 顶层用例和新增一个桌面用例，先红后绿；只重跑精确改变的分支。行选择另补聚焦／滚动到原配置起点，沿原父组件用例核验，结果未知时禁止选择的原规则仍有效。
