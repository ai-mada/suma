# Octop Harness 开发执行阶段验证

产品：suma 1.0.0。阶段：T-OCTOP-117。日期：2026-10-28。维护责任：控制面、Runner、工作台与集成模块负责人。关联设计：[执行架构](../architecture/octop-execution.md)、[执行合同](../../contracts/octop-harness-acp.md)、[操作指南](../integrations/octop.md)。机器可读来源、结果及限定范围见[摘要](octop-execution-summary.json)。

## 本阶段交付

采用公开发布的 Octop Harness 1.0.5、Python ACP SDK 0.12.1、MCP 1.30.0，新增受控 Python runtime。沿用唯一 Go DAG、现有组织／项目／工具授权、原计划版本、六工具工作区、操作日志与代码候选，不引入 Octop 数据库或第二个调度系统。

管理员固定模型、端点、凭据引用、轮次及单次输出参数；节点只携带原配置快照。Preview、Start、Claim、Pool及原子预算入口均核验当前配置，拒绝覆盖、自动重发和强制预算误用。SDK只支持观测用量；本阶段无可核实完整计量时为 `unreported`，不会补成零或完整账单。

工作台提供中英文配置向导、固定模型事实、计划快照与执行事实。参数和本地环境采用折叠披露；取消意图、ACP结束、Go进程停止、测试和人工验收保持不同状态。

## 真实 SDK 纵向

Windows／Python3.13.3，使用隔离依赖环境、真实发布SDK和真实Go工作区MCP；模型为本任务自有的确定性回环 Chat Completions端点，未调用厂商账户。

1. 只读probe确认真实SDK版本、公开API与固定配置；不创建ACP会话或请求模型。
2. Go建立新attempt工作树，Python通过官方ACP SDK建立实际session。模型请求实际携带固定模型和512输出限制，并且只看到六个工作区工具。
3. 四次本地模型协议请求依次读取原文件、通过Go MCP创建文件、执行固定检查、结束回复。Go记录一次文件变化、固定检查及机器封存；原管理员checkout和HEAD不变。
4. 另一执行者导入封存的精确提交，真实运行独立命令并采集JUnit原件。测试代码SHA与开发候选一致；这没有执行人工批准或生产发布。
5. 另一条独立旅程在真实SDK发起模型请求后取消。ACP取消通知与Go树停止分别取得，结果保持停止／未知终态，不变成成功；未创建代码交付物，也未自动再次请求模型。

对应持久收据：`.cache/mcp019-deps/20261028T140821715Z.*`（候选及独立JUnit）、`20261028T141044402Z.*`（真实取消）。这些是忽略目录内本机原始证据，不随Git提交。测试入口：`internal/runner/octop_sdk_test.go`；需显式指定已准备的Python／zipapp环境，普通检查不安装SDK、不下载模型。

## 失败定位与修复

真实联调先发现manifest约束与完整96项依赖清单不一致，修正为保留完整版本清单并核验必需SDK。随后真实SDK在模型调用前因私有backend仅包含`home/state`、而SkillsMiddleware读取`home/agent/_builtin_skills`而失败。保存有界合成账号诊断后，将公开backend根限定为整个私有home；源码仍位于独立兄弟工作树，只能经Go工具访问，没有放宽到主机根或复制厂商技能。

修复后只重跑受影响SDK链路。完成时间使用规范UTC格式；越界工具硬拒绝保留失败标记，不能先修改／检查再以`end_turn`掩盖拒绝；无法确认的子进程关闭不声明停止。凭据引用不能覆盖Python路径、HOME、Octop状态或遥测／离线策略。

合同、平台、DAG、原操作与Runner检查覆盖固定配置漂移、模型覆盖、预算模式、会话关联、重复字段、未知字段、缺失用量、进程停止及入口摘要变化。Python检查覆盖六工具精确Schema、真实tool-call身份、隐藏操作编号和内置工具硬拒绝。Web检查覆盖配置生成、不可用库存导入、派发资格、原计划回执与紧凑事实卡。本阶段记录31个不同顶层检查通过：Go11、Web14、Python6；分阶段源码快照及限定范围见摘要，不把同一用例复跑或表格子项计为新增通过。

实际浏览器已验证中英文配置向导、未完成时禁用复制、填写后生成配置、语言切换保留草稿及复制成功反馈。390宽度下页面无横向溢出，控制台错误／警告为0；默认视口与临时视口已恢复，临时页面及自有服务均关闭。执行事实卡的组件验证不自动扩大为完整用户界面派发旅程。

## 适用边界与剩余事项

- 当前为公开Harness SDK执行核心，不代表已运行完整Octop CLI／GUI、专家市场、IM渠道、办公、记忆或技能同步。
- SDK直连管理员固定的OpenAI兼容provider，当前没有经过速码原生模型网关。单次`max_tokens`和模型轮次已实际透传，金额／总token硬预算、价格及独立供应商身份未验收；`enforce`明确阻止派发。
- 真实开发、测试与取消均为同一Windows主机的隔离执行。Pool资格链路有行为检查；多物理主机、真实商业模型及生产恢复没有由本阶段推断。
- Python依赖锁与只读probe核验版本；zipapp、manifest与解释器摘要由Go固定。这不证明全部第三方文件字节未被管理员替换，也不是操作系统沙箱。须保护部署目录，跨平台SDK安装仍需对应平台验证。
- 官方Harness ACP工具进度有缺少title／跨轮名称片段的限制。本适配器只转发可关联的有限进度，不生成虚构完成事件；真实文件、固定检查与封存事实来自Go宿主。
- 完整P0–P7、需求1–26及92项能力台账继续推进，本阶段不改变58项限定实现／34项待实现，也不声称整个平台完成。
