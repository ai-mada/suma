# 调度可靠性与故障合同

状态：目标及当前测试要求；具体实现见 engine.md。

## 事实与回执

领取、开始、输出、终结、实际停止、人工验收分别记录。Runner 先落盘，再发送；控制面先提交，再ACK。未知结果保留原操作ID。一个阶段的 ACK 不证明后续阶段已经发生。

| 故障窗口 | 必须保留的事实 | 恢复动作 |
|---|---|---|
| 提交前崩溃 | 原请求内容和幂等ID | 相同请求重试 |
| 提交后ACK前崩溃 | 操作回执、节点/尝试和事件 | 返回同一结果，后继不重复启动 |
| Runner执行后回传前断电 | durable inbox/outbox | 重传已有结果；执行未知进入核对 |
| 租约失效但进程仍运行 | fence、原attempt、占用资源 | 拒绝旧写回，确认停止或核对结果后处理 |
| map部分展开 | manifest和条目标识 | 幂等补齐，不能重复创建 |
| 审批与取消竞争 | 固定版本/输入和决定 | CAS只接受有效决定 |
| 补偿失败 | 已发生效果、补偿尝试与失败原因 | 展示部分完成，人工处理 |

## 资源与预算

内存、CPU、GPU和执行槽位按资源池容量预留；模型并发/速率及累计预算使用独立单位。未知副作用保留相关预留，避免重复执行。等待节点不占执行槽位。资源不足只影响相应候选，不应阻塞其他可执行任务。

当前内核实现项目资源上限和持久运行轮转；租户→项目的完整加权公平、分片锁、模型速率与真实账单结算属于后续阶段，验收不能据单元测试推导。

## 节点类型扩展

需要恢复的扩展必须定义输入、输出、幂等条件、截止时间、授权、取消证据、补偿和核对操作。通用外部流程、生产部署、完整补偿图和版本化子流程只有在各自适配器与故障测试完成后启用。不能用 shell 命令包装替代缺失的生命周期语义。
