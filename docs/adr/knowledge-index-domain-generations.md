# ADR：领域索引与受控处理代次

状态：接受并限定实现；suma 1.0.0；T-KNOWLEDGE-PROJECTION-197。依据：[正式合同](../../contracts/knowledge-projection.md)、[需求](../product/knowledge-projection.md)、[架构](../architecture/knowledge-projection.md)。

## 背景

原投影只解析文档Record，来源键不含领域；HTTP成功被当作完成，嵌入配置变化只隐藏旧行。该实现不足以支撑已发布记忆、SPEC与技能的准确复用，也不能证明退役、重启和分代切换后的结果。

## 决定

1. 来源身份包含租户、项目、领域和ID，单调事件顺序与批准内容修订／SHA分开。事件在原业务事务中保存，投影沿既有后台入口执行，准确原字节ACK才形成正式投递事实。
2. Go `internal/indexcontract` 是唯一wire类型来源；生成领域前缀的Web类型及知识包本地TypeScript合同，避免重复手写或扩大包编译根目录。
3. 复用LanceDB原生全文／向量及成熟RRF能力；OceanBase采用同一来源与融合语义。响应说明实际处理方式及候选范围，不把限量召回或事后筛选当完整目录。
4. 原生索引保存每来源持久head与不可变输入，稳定处理配置与物理代次分开。显式操作ID、来源／请求／时间预算控制重建；相同操作重启保持消耗与截止，不把全文放入每次重写的全局manifest。
5. 完整新代生效前，检索明确不可用／待重建／重建中／阻塞。项目界面只读当前权限下的投递事实；跨项目的全服务重建由操作员配置授权，不能用项目权限触发跨租户消耗。
6. 外部返回后重新授权并核对正式发布和原来源，片段由原文重建。定位采用Unicode码点半开区间，选择仍传原准确引用。

## 取舍与后续

来源head与固定输入让恢复和重建可核对，增加本地派生存储管理。当前原生索引目录由一个受控拥有者维护，不能把本地进程锁当作跨物理机器的分布式租约；共享目录多写、OceanBase共享目录状态与集群化索引所有权需独立设计和真实验收。

项目知识子类型目前在有界候选返回后按正式发布过滤，接口明确`provider_candidates`范围。后续可把已批准子类型加入原生预过滤，提高大规模技能召回；当前结果不提供全库total或召回完整性保证。语义效果、真实商业嵌入、双向外部记忆同步及规模目标继续独立测量。

原生混合检索参考[LanceDB官方说明](https://docs.lancedb.com/search/hybrid-search)，具体调用以本项目已安装SDK类型和实际运行证据为准。
