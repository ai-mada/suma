# 架构决定记录

日期：2026-10-23。每次改变记录原因、替代方案、代价及重新评估条件。

| ADR | 决定 | 依据/代价 | 复审条件 |
|---|---|---|---|
| 001 | Go控制面+TS智能体/检索，Web与Electron共享界面 | 清晰区分业务与执行；跨语言合同需要持续检查 | 服务边界导致明显重复或延迟 |
| 002 | 自建持久DAG，Temporal作为外部流程 | 本机SQLite与OceanBase共用语义；恢复工程由本项目承担 | OceanBase原生支持或运行复杂度超过维护能力 |
| 003 | SQLite本机，OceanBase团队主方案，PG可选 | 保持轻量安装和分布式目标；需维护真实方言矩阵 | 事务/检索混合负载实测不符合目标 |
| 004 | SQL事实、原件制品、派生索引分层 | 允许重建与可追溯；索引存在明确延迟 | 业务与索引一致性需求变化 |
| 005 | 初始DB全局调度锁作为正确性基线；T-P4-005由009演进 | 原始阶段证据保留；初始实现尚不能证明目标吞吐 | 见009增量内核和真实数据库竞争验收 |
| 006 | 结果未知先核对，取消需要停止证据 | 避免重复副作用；恢复需要运行证据 | 外部工具提供更强幂等/停止协议 |
| 007 | 本地专业交互设计，不上传项目素材 | 沿用用户已确认的紧凑工作台方向 | 用户明确授权外部设计服务 |
| 008 | 业务验收与技术节点状态分离 | 防止命令退出0冒充需求交付 | 交付门禁策略改变 |
| 009 | 持久边结算、就绪/唤醒索引和脏节点保存；组织→凭证→项目→运行家族→最终事件尾锁 | 热路径只推进受影响前沿，父子生命周期同家族；全局事件游标仍按提交有序。组织授权仍串行，不能宣称分布式无锁或跨租户公平 | OceanBase/PostgreSQL真实事务、故障与目标负载验证；共享池引入时重审锁序 |
| 010 | 项目执行准入先生成固定影响预览，再独立确认；槽位/资源与累计admission_units分开 | 默认worker至少1槽位、1准入单位；0实际阻止、null明确无限；策略/预览CAS、当前人类会话/权限、审计和回执同事务。配置容量不代表实测硬件 | 多项目共享池身份、配额层级及模型网关许可接入 |
| 011 | 用量计数保留presence与步骤覆盖；原始JSON数字先验证精度 | 已报告0与未知分开，partial只称小计；未知模型输出保留整次allowance，不以缺失用量扩大后续请求；不生成假账单 | 真实模型网关、价格版本与服务端请求结算接入 |
| 012 | Runner先持久claim原请求，恢复同dispatch；active恢复重验执行资格 | 避免丢ACK导致重复attempt；closed/reconciling不启动，已Accept后崩溃保守核对。稳定标识不替代当前凭证和权限 | 第三方执行器提供幂等操作/停止回执协议时增加真实适配器 |
