# 架构决定记录

日期：2026-10-23。每次改变记录原因、替代方案、代价及重新评估条件。

| ADR | 决定 | 依据/代价 | 复审条件 |
|---|---|---|---|
| 001 | Go控制面+TS智能体/检索，Web与Electron共享界面 | 清晰区分业务与执行；跨语言合同需要持续检查 | 服务边界导致明显重复或延迟 |
| 002 | 自建持久DAG，Temporal作为外部流程 | 本机SQLite与OceanBase共用语义；恢复工程由本项目承担 | OceanBase原生支持或运行复杂度超过维护能力 |
| 003 | SQLite本机，OceanBase团队主方案，PG可选 | 保持轻量安装和分布式目标；需维护真实方言矩阵 | 事务/检索混合负载实测不符合目标 |
| 004 | SQL事实、原件制品、派生索引分层 | 允许重建与可追溯；索引存在明确延迟 | 业务与索引一致性需求变化 |
| 005 | 当前DB全局调度锁作正确性基线 | 减少竞争错误；尚不能证明目标吞吐 | 容量测试达到锁瓶颈后改为分片锁 |
| 006 | 结果未知先核对，取消需要停止证据 | 避免重复副作用；恢复需要运行证据 | 外部工具提供更强幂等/停止协议 |
| 007 | 本地专业交互设计，不上传项目素材 | 沿用用户已确认的紧凑工作台方向 | 用户明确授权外部设计服务 |
| 008 | 业务验收与技术节点状态分离 | 防止命令退出0冒充需求交付 | 交付门禁策略改变 |
