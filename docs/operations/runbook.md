# 运维与故障恢复手册

状态：当前服务可操作手册与后续生产要求。

| 现象 | 检查 | 操作 |
|---|---|---|
| 无法打开 | 控制面进程、/healthz、浏览器产物 | 检查绑定地址和SUMA_WEB_DIR；保留数据库 |
| 未初始化 | auth/session的setup_required | 本机创建首个所有者；外部绑定使用设置凭证 |
| 无法执行 | Runner凭证、项目、命令许可、节点能力 | 先修复配置，禁止用运行成功状态绕过 |
| 长期排队 | 依赖、资源配额、暂停、审批 | 查看节点reason，调整明确配额或处理审批 |
| 自动化没有派发 | 当前规则修订/启用人授权、名义时刻、错过/重叠策略及触发记录 | 在自动化详情预演并检查中文原因；修改后重新启用，暂停/修改前的受阻触发不会自动复活 |
| 签名事件未创建触发 | 入口及规则当前状态、固定修订、双方启用者授权、过滤和交付判定 | 先查看入口与交付中文原因；无效签名不写交付表。修复配置后投递新事件，旧ignored／blocked不会自动复活 |
| 发送端超时或重试 | 原交付标识、原始正文字节和持久回执 | 使用相同身份及正文恢复原操作；不要更换ID制造另一次触发。Suma重新签名须采用当前数据库允许的时间窗 |
| 入口主密钥缺失或不匹配 | SQLite原始32字节文件或共享环境base64配置、备份对应关系 | 停止写入并恢复同一密钥；不得生成替代密钥假装恢复。数据库与密钥同步备份，先在隔离环境演练 |
| 运行事件重连 | 会话/当前项目授权、连接配额、反向代理流式缓冲 | 20秒连接轮换属正常续传；权限失败先恢复登录，协议需核对时查看持久历史，不能跳过游标伪称已恢复 |
| 结果未知 | 原Runner日志/outbox、attempt/fence、实际进程 | 核对原操作并提供结论，不能直接重复副作用 |
| 取消中 | 实际停止回执 | 等待受控进程退出；无证据保持未知 |
| 搜索滞后 | outbox状态、索引版本、解析/模型错误 | 重试同一来源版本；原件和业务仍可读取 |
| 文件冲突 | 编辑器hash与磁盘内容 | 保留双方内容，比较并采用新基准 |
| 磁盘满 | 数据、日志和制品目录 | 先盘点和保留唯一原件/证据，再清理任务缓存 |

## 自动处置目标

告警→去重事件→诊断→授权Runbook→环境互斥→独立复测→恢复/回退→需求回流。生产自动修复、冷却/熔断和监控集成尚未完成，不以当前规则建议冒充已恢复。

## 指标

待派发时长、活跃/未知attempt、事件ACK滞后、outbox积压、过期租约、资源/预算占用、数据库错误、索引水位、恢复演练时间和用户旅程成功率。业务完成率与技术执行成功率分别统计。
