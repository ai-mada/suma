# 工作区Git与执行限额 AI SOP

状态：1.0.0／T-P4-035，限定本地验证通过。负责人：平台集成。关联：[产品](../product/workspace-git.md)、[架构](../architecture/workspace-git.md)、[合同](../../contracts/workspace-git.md)。

1. 确认当前组织／项目，进入开发→工作空间。管理员只绑定已经授权且位于配置范围的项目目录；不要将生产密钥目录或其他项目对象库作为工作区。
2. 在文件区编辑；切换变更仅查看磁盘状态，不保存草稿。选择文件后核对“工作树／暂存区”、分支、HEAD、观测时间及重命名来源。
3. 需要修改时返回原文件编辑器。删除文件没有编辑入口；合并冲突应在正确文件中处理，不能把冲突差异当成已合并结果。未保存草稿与磁盘观察要分别判断。
4. 使用Monaco原生Ctrl/Cmd+S或保存按钮。未知保存优先恢复原操作，不能换key盲重写；忙或明确冲突时不再发起新保存。
5. 保存后重新读取Git变化，确认准确来源及内容；此观察不能替代正式候选、独立测试和人工验收。正式交付继续进入平台原任务／运行／候选链路。

无Git／无仓库是配置状态；不安全配置或链接仓库布局必须明确解决，不能关闭权限、过滤器或目录边界检查来让页面变绿。过大或超时明确缩小读取范围；不自动循环刷新或重复执行命令。二进制通过原件工具处理，不把缺少文本当空文件。

CLI：`suma --project PROJECT workspace git`，或`workspace diff --path src/file.ts --source index`。它们只调用正式项目读取接口，不在CLI本机任意执行Git。

设置原生节点`max_steps`与`max_output_tokens`时使用支持范围内的正整数。普通步骤默认8／最高16，受管修复默认64／最高128；累计输出默认4096，普通最高32768，修复最高131072。参数真实映射SDK；超过范围会在工作区与MCP启动前失败。不要把这些额度当成已知厂商账单或动态模型选择；未知用量与费用继续明确记录。

本阶段实际联调只使用独立副本、当前测试身份及本阶段专属普通Git仓库。不得重跑历史模型／正式候选测试来代替新编辑交互验证；缓存、数据库、日志、凭据、原始截图及二进制留在忽略目录，Git只提交必要源码、设计及精简证据。
