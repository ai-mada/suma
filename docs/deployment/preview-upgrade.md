# 本地预览升级与恢复

状态：T-P4-017 已实现的运维规程；负责人：平台集成。关联：[任务依据阶段](../quality/task-design-context-verification.md)、[当前凭证架构](../architecture/current-credential-authority.md)。实际执行结果与规程分开记录。

本流程用于将已有本地 SQLite 预览升级到同一交付版本的控制面与网页产物。升级必须先在一致性克隆上演练，再处理实际预览；克隆演练结果不代表实际预览已升级，也不代表生产、其他数据库或厂商执行已验收。

维护模式行为以 [控制面启动入口](../../cmd/suma-control/main.go) 和 [HTTP 入口](../../internal/platform/http.go) 为准；身份迁移遵循[当前凭证权威性合同](../../contracts/current-credential-authority.md)。数据与入口加密主密钥的配套要求见[服务器部署与恢复](server.md)。

## 启动参数与维护边界

控制面实际提供 `--addr`、`--maintenance`、`--language` 参数。`--maintenance` 默认关闭，启动后不能通过页面或接口热切换，变更模式须正常停止并重新启动进程。以下仅示例本机监听；启动前由现有服务配置明确选定目标数据和网页目录。

```powershell
.\suma-control.exe --addr 127.0.0.1:4310 --language zh-CN
.\suma-control.exe --addr 127.0.0.1:4310 --language zh-CN --maintenance
```

数据目录使用 `SUMA_DATA_DIR`，默认 `.suma`；SQLite 连接由 `SUMA_DB_DRIVER` 和 `SUMA_DB_DSN` 决定，默认驱动为 `sqlite`、数据库为数据目录中的 `suma.db`。网页目录使用 `SUMA_WEB_DIR`，默认 `apps/web/dist`。演练与实际切换都要核对实际配置，不能仅凭当前工作目录推断连接目标。秘密沿用现有安全注入方式，不进入命令参数、升级报告或 Git。

维护模式下的行为如下：

| 入口或后台工作 | 行为 |
|---|---|
| POST `/api/v1/auth/login`、`/api/v1/auth/logout` | 保留正常登录、登出和原有身份校验 |
| API 的 GET／HEAD／OPTIONS | 通过维护闸门，继续遵守原路由、当前身份与权限要求；不保证每个路径都支持这些方法 |
| 其余 API 方法 | 冻结，包括需求设计 preview、检索等只读 POST，以及设置、组织切换、凭证发行、业务命令、Runner 回报和入口投递 |
| 调度循环 | 暂停自动化物化／派发及执行引擎 Tick |
| 索引投影循环 | 暂停项目索引处理 |
| 故障投影循环 | 暂停由执行失败事实投影问题／需求的处理 |

通过原有请求来源检查后，被维护闸门拦截的请求返回 HTTP **423**、错误码 **`maintenance_mode`** 和 **`Retry-After: 5`**，本次业务操作尚未执行。该响应不是成功回执，也不是要求客户端自动重放原命令；维护结束后仍须核对当前身份、版本和原操作状态。来源检查等既有规则仍可能先返回相应错误。

`GET /healthz` 会返回 `maintenance` 字段。`maintenance=true` 时即使 `status=ok`、`database=connected`，也只说明进程与数据库连接可用，业务仍被冻结；不能据此宣布已恢复写入。`maintenance=false` 也不能替代登录、项目权限和具体业务验证。

维护模式不是数据库只读模式。启动时仍执行业务和执行结构迁移，登录／登出仍更新身份记录，受保护读取可能更新授权协调计数。对比证据必须区分这些变化与业务写入。维护模式也不会停止已经在外部执行的 Runner 或提供方进程，切换前须先明确处理在途运行。 此开关只约束当前控制进程；多控制面部署还须协调入口与全部写入实例，不能以单个进程maintenance=true作为集群停写证明。

## 升级前留存与停写

1. 确认实际预览使用的控制面、网页产物、数据目录和 SQLite 文件，记录当前版本与摘要。保留旧控制面程序、旧网页完整目录和原有运行配置，保持控制面与网页成对；新产物放独立目录，不覆盖正在服务的静态目录。
2. 明确当前运行、待回报结果、入口投递和自动化状态。先排空或按现有停止协议处理在途工作，再正常停止旧控制面；确认服务已停止且没有其他写入者。不能把维护模式当成已停止外部副作用的证明。
3. 对需要保留的源快照、唯一文件、旧产物和已有验收证据建立清单并计算摘要。数据库备份须配套保存所需的数据文件及原入口加密主密钥，限制访问；报告只记录验证结果和摘要，不记录秘密内容。
4. 备份与交付证据放项目约定目录，不在盘符根目录新建工作目录。升级期间保留全部可恢复产物，清理另按项目的路径核对与证据留存规约执行。

## SQLite 一致性备份

使用 SQLite 一致性备份接口：源连接以 **`mode=ro`** 打开，由 SQLite 读取主库及仍然存在的已提交 WAL，再通过 backup 接口生成独立目标数据库。不要只复制主库文件，也不要使用 **`immutable=1`** 绕过 WAL；即使旧控制面已经停止，已提交内容仍可能只在 WAL 中。

备份前后记录源主库及存在的 WAL 摘要，核对源文件未被此次备份改写。不为方便复制而主动对源库 checkpoint、移除 WAL 或丢弃其旁文件。若源仍有其他写入者，先重新完成停写协调；不能用两次不一致的文件摘要证明同一快照。

在独立目标上检查 SQLite 完整性、表结构、记录数和关键内容，确认备份可正常打开。对数据库外的文件另做一致性留存与核对；SQLite backup 本身不包含网页、工作区文件或入口加密主密钥。保留一份未被新版启动过的升级前备份，演练从其副本开始。

## 克隆演练与精确比对

1. 以备份生成隔离克隆，使用独立数据目录、数据库和监听地址；明确禁止指向实际预览或共享写入目标。配套复制必要文件与原密钥，避免克隆访问实际外部执行通道。
2. 使用新版控制面与同版网页，以维护模式启动克隆，完成结构迁移。启动失败时保留原错误与克隆，处理原因后重新演练，不修改原库掩盖失败。
3. **首次登录前**，以升级前快照为基准盘点全部旧表和旧列。逐表核对旧列集合、行数以及每行每个旧列的原值；新列只按明确的迁移预期单独核对。比较须保留 SQL 类型、NULL、空字符串、原始文本、整数及二进制内容，采用确定排序或含重复计数的行多重集合，不能只比较总行数、抽样或界面摘要。
4. 列出所有新增表／列及其预期内容。旧表旧列内容应精确保留；迁移确需改变旧值时，必须单独列出具体表、列、变换依据及前后差异，不能用“迁移正常”笼统豁免。完整性检查和精确比对均通过，才能进入登录核验。
5. 通过正常网页入口，用既有真实账户重新登录，核对原组织／项目、已有需求／任务／运行及历史原文。验证维护拒写、只读 POST 冻结、健康响应和网页版本匹配。登录／登出及授权协调变化单独登记，不能把登录后的所有表摘要变化写成业务数据受损，也不能宣称整库完全不变。

旧凭证若缺少可信来源、浏览器家族或独立 Grant／发行证据，升级后要求重新登录或重新发行。旧会话／scope 行的保留是审计事实，不意味着旧秘密继续可用。不得直接修改数据库、伪造批准记录或重新设置系统来绕过正常账号登录；真实登录无法完成时，保持维护并处理原因。

凭证发行和组织切换在维护阶段被冻结。需要重新发行的 API／Runner／Agent 凭证，须在正式恢复后由当前有权的浏览器身份明确批准；不能把旧 scope 自动提升成新批准。

## 实际切换与恢复写入

克隆演练完成后，重新确认实际预览仍停写，生成并核验实际切换时点的一致性备份。将实际预览切到已验证的新版控制面与同版网页，先以维护模式启动，重复迁移结果、旧表旧列、正常原账号登录和关键读取核验。不得把克隆结果直接当成实际切换证据。

核验通过后记录明确的放行时点，正常停止维护进程，再使用同一数据和网页配置以正常模式启动。**正常模式启动即进入恢复写入边界**：后台调度与投影可能先于人工点击开始推进，因此不能等到第一条页面写操作才算正式恢复。

恢复后核对 `maintenance=false`、正常原账号会话及代表性业务操作，再按需要明确重新发行独立凭证并恢复执行客户端。只报告实际完成的验证；原账号登录、凭证发行、运行恢复、厂商执行与业务验收分别记录，不能互相替代。

## 回退边界

在维护核验阶段，确认尚未恢复业务写入、后台推进或外部执行副作用时，可回退至成对保留的旧控制面／网页及升级前一致性备份。回退前先留存维护阶段的数据库与核验记录，避免丢失登录／登出等审计变化；恢复在服务停止时进行，不能将新版数据库直接交给未经兼容验证的旧程序。

回退后须使用原账户重新登录，维护阶段发行的会话不能作为旧版本有效会话继续使用；也不能把已失效秘密重新视为当前授权。若旧版本无法满足必要的身份约束，继续保持冻结并前向修复。

**正式恢复写入后，禁止用升级前备份覆盖当前数据库。** 这会丢失新业务写入、回执、执行事实和后台投影，并可能与已发生的外部副作用冲突。此时先重新冻结并保存当前状态，通过前向修复、兼容补丁或明确的数据修复方案恢复；旧备份用于核对和恢复依据，不作为覆盖当前库的快捷回退。

本页是操作规程。具体预览是否已经升级、登录验证是否成功及恢复是否完成，以对应阶段的实际交付证据为准。
