# AI与人员协同开发SOP

状态：持续适用的开发规范；日期：2026-10-24。负责人：主集成及各领域负责人。关联：[工程架构](../architecture/platform-engineering.md)、[产品需求](../product/platform-foundation-prd.md)、[实施计划](implementation-plan.md)、[验收入口](../quality/verification.md)。

## 输入与责任

每项工作固定需求编号、使用者目标、范围、约束、验收条目、版本基线、风险与责任人。读取仓库指令、当前状态、设计合同和既有实现；当前文件、数据库与真实工具状态为事实来源。先复用既有领域能力及成熟工具，不把参考项目名称当作已接入证明。

主集成负责共享合同、集成、当前权限与最终验收；并行代理按明确文件／领域归属工作。共享DTO和状态机先冻结，接口变更以显式修订通知消费者；禁止各自建立平行类型、任务状态和数据库真相。子任务仍受相同预算、审批与证据规则约束。

## 标准开发流程

| 步骤 | 必要产物 | 放行条件 |
|---|---|---|
| 需求澄清 | 可编辑需求、用户旅程、边界及失败状态 | 已有明确指令直接推进；仅对影响实现的缺失信息提问，不重复索要授权 |
| 领域与方案 | 术语、模块所有权、状态机、关键时序、依赖与成熟SDK比较 | 处理事务、权限、幂等、取消、未知效果、恢复、配置和升级，不只设计成功路径 |
| 设计与合同 | 页面／交互状态、Go类型、HTTP／事件Schema、错误码、验收覆盖 | 消费者共用生成合同；高影响调整提供固定预览与显式采用；不在接口层重建业务规则 |
| 失败检查 | 覆盖实际行为的新增回归或可重现故障 | 区分缺模块／编译失败、断言失败、环境缺失，保留真实记录，不伪造RED历史 |
| 实现 | 小型领域模块、成熟库适配、必要注释、结构化诊断 | 输入和权限服务端校验；秘密引用；不执行事务内外部网络或长任务；没有假状态与静默回退 |
| 并行集成 | 共享合同一致、冲突处理、固定代码／工具／模型依据 | 每个代码attempt隔离工作树，核对目标分支；变更后必要测试重新运行 |
| 自动验证 | 领域测试、接口负向测试、类型／生成漂移及适当静态检查 | 覆盖当前源码；记录环境、命令、退出、输入摘要及失败；不反复重跑无关全套 |
| 实际验证 | 浏览器／Runner／供应商实际流程及持久状态核对 | 明确真实与夹具范围，核对刷新／重启、权限、取消及恢复；不能把退出0当业务验收 |
| 审查与交付 | 精简验收、设计更新、剩余待办、本地阶段commit | 检查暂存文件与已验收字节一致；只提交必要源码、测试、配置与文档；无授权不推送 |

## 开发效率与验证预算

2026-10-25 用户要求：减少不必要的验证和token消耗，优先稳定交付功能。每次改动先确定影响范围，按风险选择最少且有意义的检查；不把穷举材料或反复审查当作开发进度。

- 领域实现按互斥文件并行，共享合同由主集成维护；有明确需求直接实现，避免重复讨论已经决定的方案。
- 日常只运行受影响的行为回归、必要类型或合同检查；输入未变时复用既有结果并注明来源。完整测试和生产构建放在阶段集成，只有共享合同、依赖变更或未解失败才提前扩大。
- 权限、事务、迁移、并发、幂等及未知副作用保留关键负向与恢复测试；可逆文案、普通样式、文档状态不新增重复测试。修复后先定向复验，不无条件重跑全部矩阵。
- 浏览器只验证本次改变的关键操作和代表性宽度；完整宽度／主题／旅程矩阵用于发布验收。没有界面变化不重复截图，未变运行包不重复构建。
- 每阶段维护一份精简结果和必要证据索引。审查有实质行为变化的代码，修订只复核发现及影响范围；不为同一结论创建多层重复报告。
- 优先读取当前状态、差异和相关源码段落；历史记录按需加载，工具输出仅保留错误或结论。功能开发优先于无必要的快照、散列清单和说明材料。

## 代码、接口与注释规范

公共类型与接口说明其作用域、单位、空值／未知、版本、错误及副作用。复杂函数说明业务目的、事务边界和不变量；重点解释锁顺序、fence、原操作恢复、审批失效、资源释放和算法代价。注释随代码修订，不用大段自动生成文字掩盖不完整实现。

命名使用统一领域词汇；错误返回稳定码与适合用户的说明。日志记录必要关联字段和分阶段耗时，不记录凭证、密码、完整模型请求、秘密环境或未经授权的资料。配置有Schema、默认与来源说明，支持可视化探测和审阅；插件／技能／SDK只能通过授权端口进入正式业务。

## 执行、失败与恢复

写入携带原请求标识与预期版本。丢ACK重放原操作，不能换ID猜测重复执行；凭证和当前授权先于回执恢复重新核验。瞬时且幂等的失败可按固定上限退避；未知效果先核对。取消请求、实际进程停止、补偿与人工验收分别保存，旧attempt/fence不得回写或释放新资源。

AI建议以可审阅草稿进入需求、计划、代码或诊断，采用动作仍走统一授权。连续同类智能修复三轮失败转为阻塞并保留诊断／尝试，不能继续无限循环或自行放宽审批。插件、MCP和A2A外部产物进入验收前必须重新检查来源、版本、权限及证据。

## 智能输入、配置与验收追踪

需求26的[统一智能操作架构](../architecture/intelligent-operations.md)沿用现有领域、成熟框架／官方SDK和唯一Go派发。T-INTENT-114的[当前合同](../../contracts/intelligent-operations.md)将自然语言转为最多8步需求／设计／知识草稿计划：一次专用只读模型调用、无项目／工作区工具、固定安全正文来源、原件与人工修订分离。问题未解决不能采用，超限和有限预检查可识别的秘密被拒绝；该检查不代表完整秘密分类。不把Record.Data、配置或环境当作模型上下文。服务端读取浏览器或限定项目API的真实身份、当前权限、来源与资源，提示词和模型声明不能授权。

当前本次明确确认的低风险批次固定服务端`suma-local-drafts-v1`策略，预览绑定完整提案／来源／目标版本。三类动作仅涉及同一数据库，现有领域事务helper、草稿／修订、活动／事件、Results、分析CAS与原operation receipt在同一SQL事务中提交；任一步失败整体回滚。这个真实同库原子性不扩展为跨服务／外部效果保证，不新增partial子步骤。预览与采用不再调用模型；修订后必须清除旧预览与确认。

前后端、CLI与桌面沿同一领域合同扩展，不新增平行dispatcher或业务状态真相；当前独立CLI／桌面智能旅程仍待交付。采用使用预期版本、已审阅preview SHA与稳定原操作；超时保留原主体／项目／method／path／body／key，当前授权先于回执，恢复同一批真实ID后读取当前版本。当前确认不建立持久自动批准策略，不发布、不启动开发；团队治理、扩权、生产部署、删除及外发继续走原批准边界。未来外部效果须沿既有DAG和领域operation逐步核对，不能把部分应用或未知效果显示为全部成功。

配置保存、连接探测、目标健康、执行成功、测试与人工验收分别留证；数据库、代码、测试或目标系统的实际状态用于后验核对，缺失用量／费用不记零。采用Results保存真实目标版本／修订和模型／来源链，后续目标编辑不改写原采用事实；统一计划不能伪造其他智能领域的model_adoption。阶段验收按[定向SOP](../architecture/intelligent-operations.md#本阶段验收sop)留一份报告；58项限定实现／34待办／92总计及FND-INTENT-001未勾选保持，未完成目标不删除。

需求验收追踪使用[正式读取合同](../../contracts/requirement-traceability.md)：标准身份限定需求ID／正式版本／1起始序号，映射只来自当前发布和受保护采用。正文相同不合并、需求变更不复用旧序号；旧设计、运行及Review保留原件。测试节点计数不是用例覆盖，局部追踪不完成完整TestPlan／TestCase、应用版本集或发布验收；新增／变化行为以当前源码和代表性真实旅程验证。

## 验证与证据卫生

测试临时目录使用仓库忽略的`.cache/`，环境变量仅对当前进程生效；禁止在盘根散落任务目录。原始日志、截图、重复源快照、数据库、凭证和二进制保留本地约定目录，不进入Git。需要清理时先核对目录归属、源文件唯一性及摘要，保留不可替代证据，不遍历链接目标。

阶段摘要只保留可复现入口、结果数量、最终来源／产物摘要、实际旅程与局限。测试事件数不等同用户旅程数；交叉编译不等同目标系统安装；协议夹具不等同厂商真实认证；配置已保存不等同运行健康。提交格式为`type(scope): desc [T-id]`，完成后检查工作区、提交范围和原始材料排除情况。

## 后续迭代与排查

从请求／操作ID定位活动，再关联需求版本、任务、运行／节点／attempt、dispatch／fence及制品摘要。先核对事实和当前授权，再提出修复；在独立工作区复现，新增有效回归后实施。完成后更新需求、ADR、接口及运行手册，保持同一证据链，不用覆盖历史记录的方式消除原故障。

构建隔离：活动预览可能直接使用 `apps/web/dist`。执行前先核对静态目录；本阶段验证构建应通过 Vite 的 `--outDir` 写入任务忽略目录。已有预览继续使用它已经验收的后端与静态版本；新阶段在对应联调与迁移准备完成后再整体切换。当前目录配置 `emptyOutDir:false` 保留旧资产，但不会阻止 `index.html` 被覆盖，不能以此替代隔离。
