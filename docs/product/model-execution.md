# 原生模型选择与执行预算

状态：T-P4-036／1.0.0，限定本地实现及验证通过。本文记录当前实现范围；实际验证及未验边界以[阶段证据](../quality/model-execution-verification.md)为准。关联[架构](../architecture/model-execution.md)、[AI SOP](../operations/model-execution.md)及[English](../en/model-execution.md)。

## 用户目标与交付范围

开发人员在原任务派发入口为支持该能力的原生 Suma 工具选择准确模型部署、执行限额和可选预算；先审阅固定计划，再明确启动。模型选择、实际请求和 attempt 用量使用同一绑定，避免环境中的模型设置与用户所见计划分离。

当前选项来自已批准工具所绑定执行节点的有效工具库存，以及管理员本地模型允许清单的公开部分。清单仅包含部署 ID／修订／摘要、协议、模型 ID、公开源地址、完整端点配置摘要和声明的上下文窗口；不返回密钥、私有 API 路径或凭据环境变量引用。项目读取权、工具启用者当前权限、工具摘要、节点／路由和库存有效性共同约束使用；尚无独立模型授权目录或跨项目模型市场。

支持范围要求原生工具显式声明 `suma-model-execution-v1`、可写 `attempt-workspace-v1` 与受支持的 Suma JSONL 协议。外部 Codex／Harness／CodeBuddy 等 CLI 保留原工具配置及既有派发能力，未开放这条独立模型选择链路；不能由界面选择推断它们实际使用了该模型。

## 操作及可见事实

1. 选择当前任务、流程版本及原生工具后，读取该工具准确版本的模型选项。读取只观察现有库存，不调用模型。
2. 明确选择部署并填写 `max_steps`、`max_output_tokens`。本派发入口默认 8 步／4096 输出 Token，普通上限分别为 16／32768；其他采样、推理、端点或环境参数不开放。
3. 可选填写本次 attempt 的 Token／费用预算。费用预算必须有匹配币种的准确费率；未知价格显示 `unpriced`，不能填写为零费用或宣称最优模型。
4. 预览冻结部署、参数、预算及匹配费率快照；启动再次核验当前资格。版本／库存／绑定变化保留原计划事实，要求重新准备，不自动换模型或启动。
5. 运行及用量记录保存原绑定和逐次请求证据；独立候选测试、Review 和正式验收继续独立执行。

预算是 attempt 的入场约束。保守输入预留为“声明上下文窗口 × 最大调用步数”，输出预留为累计输出限额；两者合计必须由 Token 预算覆盖。费用以冻结输入／输出两档运营方费率核算，并与现有组织、项目配额在领取事务中共同检查。它不是提供方账单，也不是已经部署的逐 Token 费用网关；异常提供方超界仍须保留事实并核对。

## 费率与未知结果

现有费率按项目／工具修订存储，每个工具在选项读取时只取一份当前费率；只有其部署 ID／修订／摘要、工具摘要、模型与源地址均匹配的选项显示 `priced`。多个允许模型不代表存在完整多模型报价目录。已冻结计划及 attempt 使用原准确费率 ID／版本，不被后续当前费率替换；没有报价时费用保持未知，强制费用政策可阻止执行。

提供方返回模型 ID 必须与选定模型完全相同；缺失身份、别名转写或另一模型不能算成功。已报告用量保留，不因模型错误而消失。缺失／部分用量、身份不符、结果未知或数值越界按既有 `unreported`／`partial`／`reconciling` 流程保留待核对余额；人工确认须有来源、原因和当前授权，不自动重跑模型。

## 当前边界

模型 HTTP 层复用现有受限 fetch 和 OpenAI 兼容协议适配器；工作区连接复用官方 MCP SDK，没有新增官方 OpenAI SDK，也不据本地协议夹具宣称厂商账单或模型质量验收。`developer check` 提供[真实只读 MCP 诊断](../integrations/developer-connection-check.md)，远程 Runner 工作区和完整 IDE 仍按[未实施的出站 broker 设计](../architecture/remote-workspace-broker.md)推进。
