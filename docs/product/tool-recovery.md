# 工具检查的能力与未知恢复 PRD

状态：限定实现与验证完成；suma1.0.0；T195；负责人：主集成代理。[合同](../../contracts/tool-recovery.md) · [架构与AI SOP](../architecture/tool-recovery.md) · [交互](../design/tool-recovery.md) · [验证](../quality/tool-recovery-verification.md)。原31项及P0–P7完整平台范围继续。

## 用户目标

用户需要知道准确执行节点是否实现维护协议，并在检查中断后安全恢复。工具已注册、一次上报、机器身份有效或命令可用，都不能证明当前存在持续消费维护请求的Worker。未知结果也不能靠刷新、超时或删除本机文件改成成功。

本阶段解决两个实际断点：维护能力未上报，界面无法准确引导；原检查已经开始却没有报告时，没有可审计的维护占用释放出口。

| 编号 | 场景 | 验收要求 |
|---|---|---|
| R195-1 | 查看节点能力 | 原认证库存声明协议及持久Journal逻辑owner；支持、过期、不支持、未知分别显示，一次report-tools不冒充持续消费者 |
| R195-2 | 打开或刷新工具详情 | 能力期限来自服务器checked_at，扣除请求时延并用单调时钟递减；打开弹窗、恢复旧ACK或保留旧数据不能续期 |
| R195-3 | 逐项处理体检阻塞 | 原四项检查的次操作到达准确节点／配置，保持当前权限、版本、调用方和期限；页面仍只有一个主要下一步 |
| R195-4 | 原检查已开始且结果未知 | 当前管理员明确发起有期“核对并释放本次维护占用”，绑定原版本、引用和来源，不重新探测或停止进程 |
| R195-5 | 节点拥有完整原停止证据 | 只读原不可变回执，证明probe已返回、全部启动意图已覆盖、原生进程树真实排空且无待发库存，再存证和持久接纳 |
| R195-6 | 释放维护占用 | 控制面与节点回执同一原操作恢复；关闭保留未知码、Started和历史，不变成completed或not_started；新检查仍须独立明确请求 |
| R195-7 | 重启或丢失回执 | 同Journal逻辑owner稳定；仅读原停止证明、原proof及ACK，不重新probe、kill或因PID不存在推断停止 |
| R195-8 | 没有足够停止证据 | 维持未知并解释缺口，提供准确节点的显式隔离／重新配对入口；隔离凭据不宣称外部进程已停止 |

当前替代管理员可以核对原发起人已撤权的记录。旧配置变化保留原来源，不能让已开始的检查被投影成终结；当前节点身份、Pool精确路由／grant以及核对授权者仍逐次验证。已确认无法匹配原身份时，不放宽权限恢复。

## 交付与边界

新检查需要新鲜、支持的维护声明；核对原未知记录可以使用准确的历史协议／逻辑owner，即使声明已经过期，避免必须先新probe才能恢复旧probe的循环。历史支持不代表在线。

Windows可复用现有Job控制器获取完整树停止事实；其他环境未证明的全树状态保持未知。源码、协议夹具、真实父子进程／Worker／Journal旅程、界面和生产验收分别记证。项目知识检索断点另见[后续切片](../delivery/knowledge-discovery-next.md)，不重复已实现的成果提炼、发布与固定上下文。
