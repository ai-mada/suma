# 修复计划修订与任务运行溯源 PRD

状态：T-P4-033／1.0.0，2026-10-27。本文规定的限定本地阶段已完成实际修订、可信启动失败替换、独立测试／明确Review、D基线及最终中英冷回读和主预览warm验证；见[验证报告](../quality/candidate-repair-revisions-verification.md)。完整P0–P7及厂商／多物理机器／生产验收继续实施。
依据：[033合同](../../contracts/candidate-repair-revisions.md)、[032修复PRD](candidate-conflict-repair.md)、[架构](../architecture/candidate-repair-revisions.md)、[操作与AI SOP](../operations/candidate-repair-revisions.md)。

## 用户要完成的工作

用户已经为原准确冲突创建了修复任务，但原选工具暂停、流程不再适用，或执行在工作区和主进程进入前发生可证明的失败。用户需要重新选择当前合格的执行配置，继续处理同一项修复工作，同时保留原计划、原运行及全部失败证据。

一次明确修订创建新的计划ID，保留同一修复任务ID、原不可变冲突身份、管理员锚点及全部有序来源。原计划的版本、定义和已存执行快照不被覆盖。修订只生成待启动预览；用户另行确认Start后，才建立该新计划自己的运行。修订不克隆任务，也不调用模型。

同一修复任务只有一个当前准备计划。并发修订只能产生一个后继，初始计划为第1版，每个版本族最多32项计划。打开旧链接仍展示准确旧计划，并提供明确的当前计划链接，不自动跳转到最新版本。

## 入口与操作选择

在修复子任务展开“修订修复计划／Revise repair plan”，先读取服务端当前资格，再选择流程版本、agent产出节点、已授权原生工具配置，填写修订理由并明确确认。来源、任务和执行路由由服务端固定，表单不能提交替代任务或任意代码来源。

| 当前事实与目的 | 操作 | 结果 |
|---|---|---|
| 当前待启动预览仅已过期，固定输入仍合格 | 重新核对并延长预览 | 同一计划只更新有效期和版本 |
| 当前待启动计划需要重新选择流程或工具 | 明确修订 | 同任务的新计划预览，不创建运行 |
| 原运行已知失败，全部尝试都有可信执行前证明，且没有后继执行、候选、补偿或未知效果 | 核对恢复依据后明确修订 | 保留失败运行，生成同任务的新计划预览 |
| 原定义仍适用，节点幂等且符合既有同运行重试条件 | 原运行的人工重试 | 保留失败尝试，生成新attempt／fence |
| 原写入或执行结果未知 | 核对原操作 | 保持原path／body／key，不另建修订或启动 |

工具配置暂停或原凭据失效不会删除旧失败；新修订必须由当前实际操作者取得当前权限。当前原始来源不再满足验收依据时，不允许通过换工具或换流程消除阻断。

## 执行前失败的明确边界

普通failed状态、没有模型输出、没有工作区证据或错误文字均不足以证明执行未开始。只有可信Runner记录的类型化`startup_failure`，准确绑定原assignment和固定工具，声明在工作区准备及主进程进入前失败，才可能支持本阶段替换。

服务端检查该运行全部已尝试的产出节点结果，而非只看最后一次失败。任何已执行后继、候选或制品、补偿、活跃或未知工作、矛盾用量事实都会阻断替换。工作区准备已进入后发生的失败不属于此证明范围。

失败后修订不会立即改变任务的当前运行。任务仍指向原失败运行，直至用户确认新预览Start；Start再次核对版本和完整恢复依据，在同一事务登记历史并切换到新运行。期间旧计划不能重新领取、读取新代码、启动、重试或继续执行。

## 历史、验收与体验

任务运行历史保留原运行和新运行的准确链接，每个运行永久只属于一项任务。`bound`表示记录了真实绑定；`observed`表示后来观察到已有绑定。缺乏原始证据的绑定版本或时间显示未知，对应字段为null，不使用当前任务版本或观察时刻补造历史。

初始计划在第一次明确修订时可以记录为“观察到的初始定义”；该时刻是观察时刻，不伪称原准备时刻。创建者仅取已记录的真实主体信息，不从当前查看人推断。所有历史记录均不提供新的执行权限。

新运行产出、候选封存、独立正式测试、人工Review、目标集成和下游基线绑定仍是不同事实。新候选必须由独立节点测试准确提交，再经明确Review；原冲突计划或原失败运行不会因为后继成功而变为accepted。

面板默认折叠零读取。系统文案成对中英，用户理由、任务文字、路径、代码和原证据保留原文。409保留草稿并要求重新读取和确认；未知写入保留准确请求。即使收到200，响应结构无效时也保留待核对请求。读取或写入401／403立即隐藏受保护事实并阻止后续写入。

## 验收目标与未完成范围

本阶段目标覆盖待启动修订、可信执行前失败替换、同任务历史、并发单后继、当前权限与来源核对、旧回执恢复、新计划独立Start，以及准确候选的独立测试和人工验收。实际运行、浏览器、跨机器和生产证据分别记录，不以单项定向检查代表全部闭合。

本阶段不把未知执行自动重放，不自动更换工具、调用模型、Review或交付；不追认旧的证据缺失失败为零用量。真实厂商、跨物理机器、分布式数据库与生产验收，以及完整平台剩余能力继续实施。
