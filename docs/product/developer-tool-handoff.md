# 开发工具交接与远端接入

T-DEVELOPER-TOOL-HANDOFF-182，速码 suma 1.0.0。功能将已审阅的任务讨论交给现有开发工具，并帮助另一台机器准备本机工具配置、单次上报库存。两条入口共用原工具档案、派发与质量流程。范围以[合同](../../contracts/developer-tool-handoff.md)和[专项验证](../quality/developer-tool-handoff-verification.md)为准。

## 从讨论进入开发

选择当前任务的一条已完成、来源仍有效的助手回复，审阅开发目标与补充验收条件，再选择流程、开发节点和当前可用工具。系统创建预览；用户核对后另行点击开始，才会创建正式开发运行。补充条件不会改写任务、已发布测试或人工验收合同。

| 普通开发入口 | 沿用的模型依据 |
| --- | --- |
| suma | 明确选择原生模型部署、参数和预算 |
| codex | App Server 明确选择当前目录模型与推理强度；JSONL 入口保留原工具配置 |
| harness | 原结构化工具配置 |
| codebuddy | 原结构化工具配置 |
| 固定 Qoder ACP | 管理员固定模型与配置 |
| Claude | 管理员固定模型与配置 |
| OpenCode SDK | 管理员固定提供方、模型与配置 |
| Octop | 原模型部署、参数和预算 |

这八类入口沿用普通派发的结构化、可写能力判断；具体配置还必须通过当前库存、权限、路由和流程核对。Cursor 等仅检测入口不会因此获得开发权限。固定配置工具无需填写另一套模型选择。Codex App Server 的用量只观察；要求强制预算的策略仍会阻止派发。

原回复的准确消息、版本、摘要和已发布知识引用随预览固定。知识在模型、上下文和 Codex 原生技能固定前，由原解析器按当前授权复核。用户无需重新复制知识内容，也不能通过表单增加任意知识授权。

开始后打开原运行查看真实工具进展。开发进程完成、候选封存、另一执行节点对同一提交的独立测试、正式 Review、人工验收和后续基线交接仍是不同事实。若创建或开始的响应未确认，先恢复原操作；保留原正文与操作键，不通过另选工具或换键重复启动。

## 在另一台机器准备与上报

1. 在目标机器安装并自行配置所需工具；上报前另备已登记的项目执行节点与 `SUMA_RUNNER_TOKEN`。浏览器指南提供 PowerShell／Bash 命令草稿，不展示凭据值，也不自动执行。
2. 选择已有、无目录链接的本机父目录，用 `suma-runner --prepare-tools PATH [--local-tool ID]` 新建非秘密命令配置。文件不能已存在；程序不会创建父目录。当前只有 `codex-jsonl`、`codebuddy-cli`、`dsh-multica`、`claude-code-cli` 四项可能自动生成，仍以实际安装、可启动及返回命令为准。零项可生成时不落文件，并返回未准备结果。
3. 配置可达的控制面地址、准确项目／执行节点、配置文件和原状态目录。可写工具另需真实 Git 检出根、完整固定基线提交与可用工作区。使用 `--report-tools` 完成一次库存上报或原回执恢复后退出；`--allow-exec` 授权原固定程序、协议和工作区探测，未给时如实上报禁用事实。
4. 回到浏览器按原库存匹配配置、暂停登记并明确启用。准备文件、上报、持续连接与启用是独立操作；库存已确认不代表模型已登录或任务可执行。

Codex App Server、Qoder、OpenCode 与 Cursor 的检测结果仍会明确显示需要配置或当前不支持，不能仅凭安装就生成可运行配置。回环地址只适用于同一机器；远端执行节点需要可达的安全控制面地址。

上报响应丢失时保留原状态目录，以同一控制面／项目／执行节点恢复原清单和操作。单次恢复只返回原确认，不再发一份新清单；该模式不领取任务、不发送任务心跳。缺少或不匹配作用域摘要的日志明确拒绝，不自动回填、清空或跨作用域重放。
