# 执行中的智能体问答

状态：1.0.0当前实现；负责人：控制面／Runner／Web；需求：T-TOOL-INPUTS-187。对应原31项中的工具接入、智能开发、执行协作与异常恢复。合同：[运行中问答](../../contracts/tool-inputs.md)；架构：[问答生命周期](../architecture/tool-inputs.md)；验收：[限定验证](../quality/tool-inputs-verification.md)。

用户在本地Codex连接设置明确开启实验性提问后，真实运行可向原任务节点提交1–3个问题。用户留在原节点查看问题、选择原选项或填写文本，明确提交；无需复制终端JSON或创建新任务。未开启时不显示当前可提问能力，已授权历史仍可只读。

主要旅程：本地连接设置 → 明确开启实验性提问 → 原配置探测／工具登记 → 原计划与模型预算 → 启动执行 → 节点问题区 → 明确回答或跳过 → 原执行接收 → 原代码候选、独立测试与人工验收。开启本功能不会扩大命令或文件权限，也不会改变模型、预算、网络或工作区。

可见状态分开表达：等待回答、答案已保存、执行器已观察、开始写出、已写出、原请求已关闭，以及写入结果待核对。非阻塞问题不显示为暂停整个任务；原回合可以未获回答就结束。超时和原生清理均不能自动制造答案。

验收条件：

- 答案准确对应原问题和选项；无预选自动提交，跳过也需明确操作。
- 当前浏览器账号、项目、原执行版本及期限共同决定能否回答；两人竞争只保存一个答案。
- 提交结果不明时保留原内容与操作标识，核对原回执；不能生成新操作重复回答。
- 原生关闭先于回答时禁止新写；已开始写入的迟到事实保留，不改成已取消或已成功。
- 中英文、窄屏、键盘操作和错误恢复共用当前组件与权限语义。

当前范围是原生 `item/tool/requestUserInput` 的非密码题。官方Default模式feature仍在开发中，因此本地默认关闭、界面明确实验性；密码题整请求在持久化前拒绝。命令授权、生产审批、持续旧thread恢复及其他工具的问答协议分别验收，不从本功能推断支持。
