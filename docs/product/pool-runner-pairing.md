# 共享执行机器配对

状态：本阶段限定验证；版本1.0.0；需求T-POOL-RUNNER-PAIRING-208。负责人：主集成／控制面／Runner／Web。关联[唯一合同](../../contracts/pool-runner-pairing.md)、[架构与AI SOP](../architecture/pool-runner-pairing.md)、[交互](../design/pool-runner-pairing.md)。

## 用户问题与目标

组织资源池已支持独立机器身份、项目双边授权、并发槽位与统一派发，但原节点登记需要管理员复制首次返回的明文令牌。跨机器部署容易复制错身份、遗失回执或把“登记成功”误认为节点已经在线。项目Runner配对只适用于单项目，不能借用它扩大资源池权限。

在原资源池节点页增加“配对执行机器”：管理员固定登记名称、槽位和凭据期限，目标机器仅执行不含令牌的命令。机器凭据在其系统凭据库产生并保存，浏览器只看到完整指纹；核对后明确批准，原子登记原Pool身份。后续继续配置每个项目的本地仓库和命令、授权及显式启动，统一调度保持原语义。

## 用户旅程与验收

1. 当前组织Pool管理员打开节点页，选择“配对执行机器”。简短表单显示名称、默认1槽位／24小时，允许显式调整。创建后获得10分钟待办；暂停Pool、其他组织或项目级身份不能创建／批准。
2. 选择目标Shell，复制无秘密的配对命令，在目标机器执行。只准备机器身份；未批准不领取任务、不报告安装或制造在线状态。机器自报名和登记名称分别显示。
3. 浏览器显示完整摘要、准确控制面、原名称与资源／期限。必须重新确认本提案指纹和依据才批准；Pool版本变化、旧CAS和过期明确阻止。拒绝和原节点撤销分别保留。
4. 提交／批准／机器proposal丢失ACK时，恢复同一持久原操作与token，不重新登记、不换密钥。读取失败隐藏当前依据，保留可核对的原写入；409明确重读后可重新审阅，不能永久锁死。
5. 批准后主操作返回准确原节点，新增机器为显式次操作。原身份只是登记事实；启动需独立本地Pool配置与显式控制地址，项目Grant与数据权限没有自动扩大。
6. 轮换、撤销、凭据过期或Pool暂停后，旧批准和本地metadata不能恢复原机器资格。历史可审计，当前资格明确显示。
7. 刷新恢复公开定位；定位损坏可从当前授权历史重新选择或明确重置本地定位，不能删除未知操作日志。系统凭据库不可用、密钥缺失、元数据损坏／链接或配置范围不符均拒绝，不降级明文或环境变量备用。

本需求不替代原手工节点登记，也不重建现有Pool调度／原DAG、质量与任务链。实际系统库、HTTP、代表界面、多机和生产各自验收，完整31项／P0–P7持续推进。
