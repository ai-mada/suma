# 远程节点工具检测 PRD

版本1.0.0；T-REMOTE-TOOL-SCAN-205；负责人：主集成代理；状态：本阶段实现与限定验证通过。关联[合同](../../contracts/remote-tool-installation-scan.md)、[架构与AI SOP](../architecture/remote-tool-installation-scan.md)、[交互](../design/remote-tool-installation-scan.md)。

## 问题和目标

原工具库存只包含节点已经配置的命令。团队在新机器安装了CLI后，浏览器不能据此发现未登记的工具，仍需要人工查找、复制和判断。用户应能在明确机器上发起有限检测，看到安装、版本及准备原因，再进入准确工具／节点的原配置流程。

本阶段沿Multica统一管理人、Agent和执行节点的方向，复用速码原维护通道、固定工具目录和单一调度权威；不建立另一套执行服务。参考来源为[Multica官方项目](https://github.com/multica-ai/multica)，当前本地参考HEAD为5a2cc891ac338eed1919aa11a1eef5957cd82cec；新增上游产品源码复制0。

## 角色与旅程

机器管理员明确允许安装检测并启动原持续Runner；项目工具管理员选择准确节点和当前工具，发起检测或选择该节点许可的固定工具集合。结果列出已安装、待配置、未找到或检测异常；明确选择后原Guide带入准确协议及节点。准备配置、正式库存、暂停登记、启用、模型和任务交付保持原门禁。

| 要求 | 可观察验收 |
| --- | --- |
| 新节点检测 | commands允许清单为空也能发现固定目录中的已安装工具；不以已有ToolProfile为前提。 |
| 机器授权 | 默认不声明能力；明确允许且持续owner当前有效时才可请求；Pool需要机器本地项目范围及双边授权。 |
| 简单启动 | 独立复制仅维护命令，无需仓库／代码基线／commands；明确模式不领取业务任务，已有未确认业务账不得被清除。 |
| 原操作恢复 | 创建和结果回执丢失恢复原正文／key／引用，不增加请求或重复native探测。 |
| 可靠结果 | 严格固定目录及有界隔离探测，结果不含路径、命令或凭据；完整结果需要真实停止回执。 |
| 未知处理 | started无完整结果为unknown；只能由原持久结果或停止回执核对，不能靠过期、PID缺失或点击重新开始掩盖。 |
| 准确配置 | 安装但仍需配置的SDK也有准备入口；不把launch_supported当作平台可派发或模型健康。 |
| 权限和交互 | 当前caller／scope变更清旧呈现，失去项目访问权拒绝读取；机器撤销保有权历史审计，撤掉当前能力与继续资格。中英文、44px控件、窄屏和键盘等价操作。 |

公开结果使用正式适配目录的名称和协议，历史结果注明时间及来源变化。限时停止页面等待不等于取消机器操作。检测不自动安装、修改配置、登录、调用模型、登记或启用。
