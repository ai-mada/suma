# 需求设计与任务采用 PRD

状态：T-P4-016 限定范围本地已验证；完整平台继续实施。日期：2026-10-25。
负责人：平台领域／工作台／主集成；关联需求：需求设计版本化、结构化任务拆解、审阅采用及执行依据。
统一合同：[requirement-design](../../contracts/requirement-design.md)；实际类型：[RequirementDesign](../../internal/platform/requirement_design_types.go)。

## 目标与使用范围

在正式需求详情中完成产品、体验、技术设计和任务拆解，再由有权人员审阅发布、预览变更并采用为正式任务。
正式需求继续保存业务目标和验收条件；设计作为独立版本聚合，不把正文塞入需求扩展字段，也不改动需求版本。
本轮是人工编写和审阅的结构化设计能力；尚未接通的模型不能标成自动设计成功。
项目知识中的通用 SPEC／技能与这里的正式需求设计基线分别管理：前者提供可选上下文，后者约束具体任务的执行与验收。

## 角色与责任

| 角色／当前权限 | 可完成事项 |
|---|---|
| 项目读取者 ProjectRead | 阅读当前设计、修订及采用记录，预览当前发布的完整变更 |
| 项目编辑者 ProjectWrite | 保存完整草稿，填写任务和验收覆盖；API 可以提交草稿 |
| 当前浏览器项目批准者 BrowserProjectApprove | 明确发布／退役，核对预览后采用；不能以历史成功代替当前权限 |
| Runner／Agent | 消费服务端固定的批准设计；不取得发布或采用权限 |

组织切换、撤权、会话失效和资源范围均由现有统一权限重新检查。任务负责人必须是同项目合法、未停用的资源。

## 主旅程

1. 在需求详情打开“设计与拆解”；未保存时显示当前需求和 version0，不伪造设计记录。
2. 填写产品目标、体验约定和技术方案，编辑具有稳定 key 的任务、负责人、依赖、验收及需求覆盖。
3. 保存草稿；缺内容或依赖尚未完成时保留诊断，安全结构、大小和 key 唯一性仍须合法。
4. 审阅发布；三段设计、任务图和需求验收覆盖必须完整。发布固定服务端读取的需求快照。
5. 查看变更预览中的新增、更新、保留、移出，核对当前正式任务及版本后明确采用。
6. 采用后进入真实任务；任务派发携带同一已采用设计。需要更改时继续保存草稿，不漂移旧发布和已开始运行。

保存、发布、采用和启动开发是不同动作，采用不会自动启动工具或执行代码。

## 交互与迭代规则

- 原需求详情只有一个设计入口，产品／体验／技术／任务四段呈现，任务详情按需展开，避免增加平行菜单。
- 草稿编辑期间旧发布继续有效；正式需求变更后须人工核对并以当前需求版本保存，禁止自动换绑来源。
- 发布或退役会使当前已绑定任务及依赖链的验收失效，保留历史运行和证据，不自动取消正在执行的运行。
- 稳定 key 映射到受保护的正式 task_id；新修订复用任务身份，不按标题猜测或每轮重复创建。
- 移出任务明确归档并停用绑定；重新加入相同 key 恢复同一 task_id，重新审阅采用后回到待办。
- 保留项不改任务状态、版本和采用凭证；无变更采用恢复最近事实，不制造新的交付记录。
- 中英文界面文字成对；用户正文和版本快照原样保留，诊断使用稳定代码和定位字段。

## 发布与验收标准

| 场景 | 可核对结果 |
|---|---|
| 首次打开／保存 | 显示真实需求标题和当前版本；保存设计不改需求版本 |
| 不完整草稿 | 可保存并显示具体诊断；发布拒绝，正式任务不变 |
| 正式发布 | 三段正文非空；至少一项需求验收，1–100任务且依赖闭合无环，每项需求验收都有覆盖 |
| 新草稿／新发布 | 草稿不替换旧发布；新发布要求重新采用，旧运行不能批准新设计 |
| 任务迭代 | 同 key 保留身份；独立任务编辑进入预览并受当前版本保护；移出与重新加入可追溯 |
| 重复／部分失败 | 同操作恢复原结果；中途数据库故障使任务、绑定、采用、聚合、审计和回执一起回滚 |
| 当前权限失效 | 即使持有历史成功回执也不能越权读取或执行批准命令 |

正文三段合计最多16,000 UTF-8字节；完整任务提案最多256KiB，单任务标题200、说明4,000，最多20条验收且每条1,000字节。
任务 key 为1–64个 ASCII 字母／数字／下划线／短横线；依赖与覆盖各最多100项；完整执行 goal 仍限制32,000字节，超出明确拒绝，不截断。
修订及采用历史默认每页20条、最多100条；游标固定租户、项目、需求和历史类型。

## 异常恢复与交付边界

明确409时保留编辑正文，重新读取当前需求、设计和完整任务范围，再由人核对；不得用旧回执的历史版本继续下一次更新。
结果未知时保存原调用身份、路径、方法、完整正文和操作 key；使用同请求恢复结果，不自动改 key、换身份或盲目重放新方案。
来源归档或变更阻止新发布、采用和派发；有权人员仍可退役已有设计，避免停用流程被来源状态卡死。
本轮后端两组领域和五组独立集成定向通过，包含真实 HTTP、任务读取、回滚及完整 goal 限额；不等同于生产规模或跨数据库验收。
完整 UED 原型编辑、模型设计提案、旧手动任务显式导入、跨项目设计复用及外部系统适配仍待后续实现。

实际浏览器、数据库升级及源码证据的精确范围见[阶段报告](../quality/requirement-design-verification.md)。
