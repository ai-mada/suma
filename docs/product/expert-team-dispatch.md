状态：T-P4-027 限定本地已验证；版本：1.0.0；负责人：平台集成，领域／Core／工作台代理并行。
关联需求：团队化分布式开发、统一 CLI 与工具管理、专家资源治理、项目进度、固定技能复用。
合同：[expert-team-dispatch](../../contracts/expert-team-dispatch.md)；实现：`internal/platform/expert_team*`、`internal/dag/managed_batch.go`、工作台专家配置及批次对话框。

## 用户需要解决的问题

现有组织团队可以编组人、智能体和工具，单任务也可以派发到经过批准的工具。
但团队名单与执行参数之间没有正式关系：同一专业职责常需反复选择流程、开发节点、工具与知识，
多个独立任务的派发也缺少可核对的共同依据。

项目专家配置把这些选择保存为可审核版本。项目负责人可在当前任务列表中选择任务，
为每项指定职责，检查固定预览后一次派发。各任务仍保留独立运行、测试、验收和问题回流。
职责记录谁承担哪类执行工作；它不创建账号，不授予项目或机器权限，也不替代人工负责人。

## 角色和操作

| 主体 | 操作 | 权限依据 |
|---|---|---|
| 项目读取者／项目 API | 查看当前配置、不可变版本、批次和运行链接 | 当前项目读取权限 |
| 项目写入者／项目 API | 保存草稿、固定预览、明确启动 | 当前项目写权限及逐项资格 |
| 项目批准者 | 发布或退役配置 | 浏览器身份、当前项目批准权限 |
| 组织管理者 | 维护真实团队及成员 | 原组织治理权限，不因项目配置扩大 |
| Runner／资源池 | 领取并执行已提交运行、回写进度与证据 | 原机器凭据、工具、路由、配额及 fencing |

项目 API 可使用现有速码 CLI 的 `api` 命令和同一合同；不另建一套调度器或客户端权限。

## 用户旅程

1. 打开组织团队详情，展开“项目专家配置”。未配置时说明该配置只对当前项目生效。
2. 添加 1–8 项职责。每项选择当前项目已入队的智能体或工具资源，再选择固定流程、开发节点、
   工具版本与已审核知识。姓名、资源、节点和执行机器分别表达，避免混为同一个“Agent”。
3. 保存为草稿，读取阻断原因，核对后明确发布；正式历史版本保留。
4. 在任务列表选择当前已载入的 1–16 项任务，打开“安排团队执行”。未载入的任务不隐式加入。
5. 选择已发布配置，逐任务指定职责，生成固定预览；展示任务、职责、工具、资格、有效期。
   工具和路由摘要折叠显示，用户可下钻固定依据。
6. 明确确认后一次启动。服务器全部成功提交，或全部回滚；每项链接自己的真实运行。
7. 刷新或分享批次链接可恢复当前状态。网络中断先查询原计划／恢复原操作，避免重复付费执行。
8. 运行按原流程测试与人工验收。失败或问题继续进入既有质量与需求回流，不因团队批次而自动通过。

## 确定规则

- 一配置绑定一个现有组织团队和当前项目。角色绑定使用真实成员及当前版本，不复制组织成员。
- 一职责选择一个实际开发工具与固定流程，保留独立候选测试。执行来源必须通过原派发校验。
- 保存新内容形成新草稿；旧未启动批次因依据变化失效。发布需要再次核对；退役终态不可恢复。
- 批次只包含当前可执行的独立任务。未验收前置任务即使也在批次中，仍不能启动下游任务。
- 一个任务对应一个运行。团队批次不是跨任务验收图，也不自动聚合多个代码分支。
- 不改变任务负责人。负责人交接仍通过独立的交接流程及失效处理。
- 批次人数／任务数不代表同时执行数；实际并发由既有公平调度、机器槽位、模型速率和预算决定。
- 运行开始后保持固定定义；后续模板修改不改写执行原件。工具、机器及资源池凭据仍受当前授权约束。

## 交互与中英文

优先复用现有团队详情、任务列表、表单、写入恢复和空态组件。
配置默认折叠；表单只显示职责、资源、流程、节点、工具和知识，原始摘要不占主要操作区域。
批次对话框先预览、后确认；启动后显示每项的实际运行入口，不显示虚构百分比。
切换项目或身份时终止旧请求；409 保留输入并要求读取当前版本，不能自动把旧决定套到新依据。
所有自有控件、状态和诊断使用中英文目录；用户名称、任务文字、模型原文及证据摘要保持原样。

## 本阶段验收

| 场景 | 必须证明 |
|---|---|
| 固定配置 | 草稿、发布、历史、退役及当前权限；成员／工具／知识变化准确阻断 |
| 原子批次 | 第二项失败时第一项工作流、运行、绑定、事件和收据全部回滚 |
| 幂等恢复 | 同操作重复返回原始运行；撤权或内容不同不能恢复成新操作 |
| 质量门禁 | 未验收前置任务、活动任务、单独启动批次子计划均被阻止 |
| 分布式路径 | 原私有及 Pool 路由、独立运行根、真实领取与回写继续有效 |
| 界面 | 最终代表性中英文配置→发布→预览→启动→运行链接→刷新；原账号和主预览数据保留 |

源码、定向检查、实际本地运行、厂商与生产验收分别记录。完整专家之间的结果交接、自动策略、
候选 AI 审阅、目标分支集成、多数据库及规模验收仍按完整平台计划继续实施。
