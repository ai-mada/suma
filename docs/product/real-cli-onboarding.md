# 真实 CLI 检测与暂停接入

状态：T-REAL-CLI-ONBOARDING-226，1.0.0 阶段交付。负责人：主集成代理。关联需求：工具自动接入、分布式执行节点管理、中英文易用性；[执行合同](../../contracts/real-cli-onboarding.md)、[架构与接入](../integrations/real-cli-onboarding.md)、[验收](../quality/real-cli-onboarding-verification.md)。完整平台仍按原 31 项／P0–P7 推进。

## 用户目标

用户选择工具和执行节点后，能确认该节点的实际安装、理解失败原因、进入对应配置指南或明确重检；确认配置和机器写入许可后，沿同一来源完成准备、库存确认与暂停登记。检测、登记和启用分别表达，避免把安装成功误认为可以执行任务。

## 规则与验收

| 情形 | 产品行为与验收依据 |
| --- | --- |
| 已安装的 Codex CLI | 读取真实程序的版本和 `exec --help`，绑定文件摘要；测试程序不能充当厂商证据 |
| 解析阶段无法确认安装 | 显示“尚未确认”，保留诊断，不显示为明确未安装 |
| 已安装但版本、帮助或协议不满足 | 展示固定原因；“查看指南”传递准确工具和节点，不受其他已选工具影响 |
| 可重试的超时或来源变化 | “重新检测”需用户明确点击，复用原本地扫描或准确远程单工具扫描；不自动安装或修改配置 |
| 停止尚未确认 | 保留原记录和私有目录，禁用再次探测，进入原核对流程 |
| 确认配置 | 原准备工厂生成不可变版本；库存 ACK 与准备完成在原事务中关联，未确认时不能保存成功 |
| 登记工具档案 | 新档案为 `paused`、不可派发；另行启用需要其当前权限与来源校验 |
| 安装成功但探测失败 | “已检测到”及“需处理”分别计数；失败不会因已安装而从需处理数量中消失 |
| 回执未知、权限或会话变化 | 原未知写入恢复和权限规则优先，诊断建议不能扩大权限 |

所有公开诊断只含固定 `stage`、`code`、`next_action`。没有诊断不表示健康；存在诊断也不产生任务执行资格。界面不展示机器原始错误、命令、路径或环境值。中文和英文共用同一组件、格式化及交互逻辑，扩展语言沿现有目录机制添加。

## 数据与范围

复用现有安装扫描、准备、generation、库存与工具档案模型；增加可选非空诊断对象和 `scan_incomplete` 原因，不增加业务接口、数据库表、依赖或调度器。现有模型、预算、正式执行和独测验收合同保持各自责任。

本阶段已用真实 Codex 元数据贯通原 HTTP／SQLite／普通维护 Worker 到暂停档案；模型登录、付费调用、真实代码开发和独立测试仍需其专门验证。代表界面使用生产组件和合成观察源，不能替代完整桌面 IPC、真实远程机器或完整应用验收。
