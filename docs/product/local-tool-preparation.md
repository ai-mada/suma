# 通用CLI配置快捷准备

速码1.0.0 · T-LOCAL-TOOL-PREPARATION-220。依据[领域合同](../../contracts/local-tool-preparation.md)，完整31项／P0–P7继续。

原Go `PrepareToolCommands`已经支持发现已安装工具并独占创建配置文件。本功能把这项能力放到工具指南的两字段准备卡中，尤其补齐共享模式隐藏普通身份指南后缺少的通用准备入口，不新增扫描器或文件写入服务。

| 当前工具 | 固定准备标识 |
| --- | --- |
| Codex CLI | `codex-jsonl` |
| CodeBuddy Code | `codebuddy-cli` |
| Claude Code CLI | `claude-code-cli` |
| DeepSeek Harness / dsh | `dsh-multica` |

## 使用步骤

1. 在原工具指南选择准确工具，填写目标机器的PowerShell或Bash，以及全新commands JSON文件的绝对路径。
2. 复制界面生成的原`--prepare-tools FILE --local-tool ID`命令，在目标机器明确执行。原程序会做有界被动版本／帮助探测并新建配置；父目录须已存在，原文件或链接目录不允许覆盖使用。
3. 明确选择“采用此输出路径”。这只采用当前文件引用，不要求先复制，也不证明文件已经生成。普通指南填入原Shell、commands和工具字段；共享指南只展示可复制的本机输出引用，不写Pool表单或传递私有路径到URL／API。
4. 核对目标机器实际文件后继续原配置、身份、上报和登记流程。完整新鲜库存、matches、新档案默认暂停及独立启用保持不变。

手动JSON保留为默认折叠的高级示例。五种专用SDK／ACP／AppServer协议仍使用原显式配置表单，不猜模型、凭据或包目录，也不因产品名称相同而切换协议。

复制、采用路径和被动探测都不等于登录、模型执行、任务开发或工具启用。实际执行准备命令会启动本机探测子进程并写入一个新文件；浏览器卡片本身不探测、执行命令或创建文件。

## AI操作与维护

AI只沿四项固定目录和当前选择生成命令，复用原Shell引用与新文件writer。先处理原未确认操作，再明确采用当前路径。账户、API、工具或字段变化后，旧剪贴板回应和旧采用回调失效；默认工具首次明确采用会取得新的当前选择代次，不恢复旧请求。

源码和定向组件检查不能代替真实目标机器、厂商或完整平台验收；实际命令、文件及代表界面结果由阶段证据分别记录。
