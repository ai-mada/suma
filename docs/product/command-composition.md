# 已有命令配置的安全组合

版本1.0.0；阶段T-COMMAND-COMPOSITION-215。状态：限定功能已实现，实际范围与验收见[质量报告](../quality/command-composition-verification.md)。负责人：Runner／工作台／主集成。关联：[唯一合同](../../contracts/command-composition.md)、[交互设计](../design/command-composition.md)。完整31项／P0–P7、58项限定／34项待办／92项基线继续。

## 用户目标与操作

将已有开发工具配置、检查命令等组合成一个完整允许清单，减少人工复制JSON和误覆盖配置。例如，开发配置的`native_workspace.checks`可以引用另一份文件中的检查命令；必须组合后一起校验，而不是要求用户把两者手工拼到同一文件。

1. 在原工具接入指南中按需展开配置组合，选择目标机器Shell。
2. 填写2–16个已有源文件的绝对路径，以及已有目录下的全新输出文件。这里只填写引用，不上传源配置内容。
3. 复制生成的准确命令，在目标机器明确执行。`suma-runner --compose-commands DEST`从标准输入读取唯一的`files`数组，准备过程离线完成。
4. 取得安全成功回执后，用输出路径继续原Runner指南及当前机器的检测／库存上报、档案登记和明确启用。复制命令和组合成功都不自动完成这些后续操作。

输入示例：

```json
{"files":["D:\\suma-config\\developer.json","D:\\suma-config\\checks.json"]}
```

## 确定语义与错误处理

输入不超过64 KiB，每个源文件不超过2 MiB，累计读取不超过2 MiB；最终不超过128条命令和2 MiB。源文件与父目录沿原普通文件／不含链接路径规则检查，写入前重核原文件字节及父目录依据。目标使用原独占新文件writer，不覆盖、不创建父目录、不修改输入源。

逐源拒绝重复JSON键、未知字段及空对象。跨源允许既有命令引用，但重名一律拒绝，不覆盖、自动重命名或增加能力。完整组合后调用原`DecodeCommands`／`ValidateToolConfiguration`，原NativeWorkspace及各协议约束保持；不向Codex、Claude或ACP强加NativeWorkspace策略。

| 结果 | 操作者下一步 |
|---|---|
| `source_unavailable`／`source_invalid` | 按安全的1起源序号核对目标机器上的路径、权限及原配置格式；不从错误文本执行修复 |
| `duplicate_command`／`configuration_invalid` | 明确调整原配置的命令ID或引用，再组合；平台不自行覆盖或补检查 |
| `inputs_changed`／`cancelled` | 保留源和原目标，重新确认稳定的输入后由操作者决定再次准备 |
| `output_exists` | 使用者核对原文件，不自动覆盖、改名或清除 |
| `output_unconfirmed` | 保留现场并检查原目标，不把未知写入当作失败后盲重试 |

成功回执仅有协议、源数量、命令数量及最终文件字节SHA（含LF）；错误回执使用固定原因、源序号和CLI当前语言说明，不回显路径、命令、环境内容或底层错误。

## 模块职责与AI SOP

CLI入口只做独立模式检查、标准输入和本地语言回执；Runner组合服务复用原有界来源读取、文件稳定检查及新文件writer；原工具合同校验完整合成结果；工作台仅生成本机命令和管理当前来源的路径草稿。无新增后端API、存储权威、数据表、调度器或依赖。

AI维护时先区分结构解码和完整引用校验：逐源保留唯一键及闭形字段检查，合成后再校验跨源引用。所有其他模式或参数（包括显式false开关）在读取stdin／凭据前拒绝。不要访问系统凭据、从环境补取秘密、启动进程或请求控制面来“验证组合”。改动按受影响解析、稳定性、输出与交互做必要验证，分别记录准备、真实库存、启用、开发内部checks和正式独测事实。

组合回执不是库存、登录或派发许可。内部checks属于开发attempt内部受限检查，不等于不同Worker对同一提交的独立测试，也不代替人工验收、代码候选或基线交接。模型／厂商执行、多机器、完整安装矩阵与生产验收仍沿原计划。

当前接线：明确“使用输出路径继续”复用原同一有序configurationRequest通道，只采用Shell与路径，保留已选工具、身份和工作区，不证明已经运行组合。Web新输出以.json结尾以匹配原消费者；独立CLI按JSON内容校验而不限扩展名。代表GUI／实际PowerShell与原父子指南交接检查分别取证。源总读取及最终含LF输出各≤2MiB。
