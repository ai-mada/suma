# 协作计划中的独立测试配置

速码1.0.0 · T-COLLABORATIVE-TEST-BINDINGS-223 · 负责人：平台协作组 · 状态：限定验证通过，范围见验证报告。关联[合同](../../contracts/collaborative-test-bindings.md)、[架构](../architecture/collaborative-test-bindings.md)、[交互](../design/collaborative-test-bindings.md)。

讨论中的开发计划、智能推荐的明确采用、专家团队任务计划，都使用原任务派发器选择独立测试工具。配置保留准确工具版本、摘要、执行节点和命令；开发工具完成、独测报告和人工验收分别记录。

- 讨论：选择发布流程、智能体和开发工具后，按需选择测试工具；预览冻结配置，开始时重验当前资格。
- 推荐：模型仍只输出原五字段建议。用户明确选择测试工具后采用，按真正被采用的开发Worker复核独立性；切换流程需要重新配置。
- 团队：创建默认使用发布定义；未开始项修订可保留原配置、调整或恢复发布定义。上下文变化必须明确重配；已开始项只读。

验收：三个入口传递同一三字段选择并保存原六字段；同Worker即使不同slot也不能冒充独测；读取漂移阻止新动作但不改历史；未知写入以原地址、原操作标识和原请求核对。完整31项／P0–P7继续，厂商实接与规模验收分别记录。


当前工具的连接诊断沿原自动刷新开关进行只读核对：仅选中且可见时，到期后重读，最短15秒；后台暂停，失败或配置变化等待明确重试。详情后台刷新保留同源已结算与在途读取，避免重复请求或打断慢连接；真实pending／disabled／来源变化取消在途请求，挂起时旧操作回调无效。自动检查不执行修复、启用、注册或模型。
