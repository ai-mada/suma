状态：T-P4-029 限定本地已验证；版本：1.0.0；日期：2026-10-27。真实厂商、跨物理主机及生产验收仍未完成。
依据：[冻结合同](../../contracts/expert-team-orchestration.md)；关联：[架构](../architecture/expert-team-orchestration.md)、[交互设计](../design/expert-team-orchestration.md)、[实际验证与边界](../quality/expert-team-orchestration-verification.md)、[精简摘要](../quality/expert-team-orchestration-summary.json)。

## 用户问题

现有团队配置已经固定专业职责、工具、流程和知识，任务列表也能一次派发独立任务。
真实交付还包含先后关系：前一任务开发和测试成功后，需要负责人正式验收，后继任务才具备执行资格。
如果仅展示一组同时启动的 run，用户难以区分“正在运行”“等待人工验收”和“尚未满足前置条件”。

本阶段直接增强既有 `ExpertTeamPlan` 和任务列表入口，不再创建一套交付计划产品或调度器。
独立任务是全部任务均为根节点的情况；有依赖任务按同一固定计划，在明确启动后由服务端自动跟进。
Go DAG 继续是唯一执行派发器，浏览器不循环创建或启动子任务。

## 用户路径

1. 在当前已载入的真实任务中选择 1–16 项，打开原“安排团队执行”对话框。
2. 选择一个已发布专家配置，并为每项选择固定职责。服务端固定任务来源和实际依赖，不隐式扩充范围。
3. 核对按拓扑排列的任务列表、依赖标签、外部前置验收依据、职责和固定执行上下文。
   预览不创建 run、不占用机器槽位、不调用付费模型。
4. 明确确认后启动固定修订。已就绪根任务可原子绑定并进入现有执行队列；等待项由持久推进器继续判断资格。
5. 逐任务查看实际运行、待人工验收和正式验收结果。测试绿色或 run 成功不能自动激活后继。
6. 需要时暂停新派发；恢复时以当前账号及实际凭据重新授权。停止终止未启动工作，已有运行仍需独立停止或核对。
7. 来源变化时，明确修订尚未开始的项，形成新来源修订和图摘要。已开始项的职责、来源和 run 不可替换。
8. 通过原计划 URL、历史修订和原请求恢复继续跟踪，不因刷新、切换语言或断线重复派发。

## 固定规则

| 范围 | 规则 |
|---|---|
| 图范围 | 同项目、任务唯一、无自引用或环；不暗中补选未选择任务 |
| 内部依赖 | 可在预览时未验收；后继须等待此前置在本计划产生的准确 run 获正式验收 |
| 外部依赖 | 预览和实际派发时须保持当前有效正式验收 |
| 固定来源 | 任务正文／负责人、需求、设计、依赖、专家配置、资源、工具、知识、流程与项目路由 |
| 状态变化 | 合法派发和正式评审状态变化不等于正文漂移；来源实质改变则阻止未开始项 |
| 实际派发 | 就绪时重新构建当前有效 task dispatch plan，保留已审阅语义来源，事务内重核并绑定 run |
| 权限 | 准备、启动及管理使用当前项目写权限；配置发布和任务正式验收保留原浏览器门禁 |
| 凭据 | 启动／恢复固定实际发起凭据引用；每次晚派发重新核对当前有效性与原范围 |
| 失败和未知 | 原运行继续既有恢复，不创建新 run 充当自动重试；未知不当成功 |

计划的修订号、来源图摘要、当前业务版本和授权激活代数分别表达，不用一个版本字段替代全部事实。
未派发项仅有固定源码快照，实际 `dispatch_plan_id`／`run_id` 为空，不显示预留标识为真实运行。

## 跟进与管理动作

进度按明确计数显示：总任务、等待依赖、就绪、执行、待人工验收、已验收、阻止、停止。
页面不通过动画或已载入的局部 run 数推断项目完成度；每项保留真实理由、依赖和原运行入口。

暂停只停止新派发，现有运行继续。恢复是一次明确的新授权激活，重新检查未开始项，不静默修正来源。
停止对未开始项为终态，不声称已关闭现有进程。运行取消和未知核对仍在原 run／attempt 中处理。
修订只包含明确指定的未开始项；切换配置版本时必须明确包括全部未开始项，保持已启动集合不变。
历史修订只读，没有当前写动作。

## 边界与验收

本次是业务依赖编排，不自动切换 Git 基线，不把几个独立候选拼成已测试代码。
代码交接、固定候选测试及受控仓库集成仍使用各自既有合同。

必要验证包括图编译、正式验收而非仅运行成功、错误验收 run、来源漂移、当前凭据与权限、
CAS／回滚／幂等、丢失启动响应、多推进器及公平性，以及一次代表性中英文依赖团队界面流程。
现有成熟 Core／Runner／Git 输入不变时复用其证据；不重复调用模型或扩大为全套验收。
必要定向检查与同一 Windows 主机的真实 Control、双 Runner、本地固定 CLI 依赖旅程已通过：计划在来源修订 R2 达到 completed，
两次真实运行、8 项独立正式断言和 2 次界面明确验收。暂停后根任务已验收仍不派发后继；明确修订未开始子任务并恢复后才继续。
来源修订保留已开始根的来源及 run，恢复遇 409 后读取最新版本、保留草稿并重新确认，中英文／刷新／历史得到代表性验证。
主预览 029 前向升级保持原 175 表结构与全部行，新增 2 张空表及 2 个索引；完整事实、失败保留和制品配对见上述质量记录。
这些事实不代表真实厂商模型、跨物理主机或生产验收；完整 P0–P7 继续实施。
