# 跨执行节点的候选代码交接

状态：T-P4-018 已实现，限定本地验证；负责人：平台集成。关联需求：分布式开发、独立测试、共享资源池、可追溯交付、FND-I18N-001。实际结果见[专项验证](../quality/candidate-transfer-verification.md)。合同见[候选传递](../../contracts/candidate-transfer.md)，架构及操作见[领域设计](../architecture/candidate-transfer.md)。

## 问题与用户价值

开发和测试节点有各自的管理员仓库。调度器虽然固定了候选提交，另一节点缺少该 Git 对象时仍无法开始测试。依赖手工复制仓库既难以自动恢复，也容易测试错误版本。

平台使用 Git 原生 bundle 把已完成开发的固定候选交给获授权消费节点。开发者仍选择既有流程中的候选来源，无需填写远程地址或自行同步提交。普通项目 Runner 和共享资源池机器复用相同候选语义，各自保留真实授权身份。

## 业务行为

1. 代码命令或智能体结束后，Runner核对独立工作树、干净提交及管理员基线。有代码变化时生成有界候选包，先持久保存原结果与固定包，再上传和封存。封存不等于源任务、测试或人工验收成功。
2. 下游仍由调度器固定源节点、attempt、fence、提交及证据摘要。候选已在本地时继续核验；缺失时只获取该固定来源的获授权封存包。
3. 消费节点验证原件、manifest、Git前置对象及对象结构，导入对象后创建独立测试工作树。用户分支、HEAD和远程配置保持；不自动合并。
4. 断网和回执丢失恢复同一个包及原操作。代码命令已经结束时不通过再次执行来重试上传。当前租约、撤权或取消阻止新传输时，保留待核对状态。

## 界面与易用性

沿用运行详情的工作树证据，增加紧凑“候选传递”事实区，不新增导航或复杂设置页。来源封存显示固定提交、包摘要、精确字节及来源身份；消费端只有实际导入回执才显示“本次尝试已导入”。没有回执时明确说明未记录导入，本地对象原本已存在是正常情况。

高级原始来源按需展开。切换语言保留同一事实的展开状态和原值，切换传递记录重置披露，避免错贴旧身份。字段不完整或与当前工作树证据不符时明确提示不可验证。界面不提供越过Runner权限的候选包下载按钮，不从包存在推断测试、健康、质量或验收通过。

## 验收条件

| 场景 | 必须观察的行为 |
|---|---|
| 两份只共享基线的独立仓库 | A开发C，B开始前没有C，随后只导入并测试C |
| 普通与资源池身份 | 均可交接；机器身份不能变成人员角色或剥离资源池范围 |
| 上传／封存回执丢失 | 恢复同操作、同包，代码执行次数保持一次 |
| 上传中取消、撤权或过期fence | 不发布新数据，不恢复执行为成功，保留原结果供核对 |
| 错误摘要、head、base或Git对象 | 导入前拒绝，不运行测试命令 |
| 已有对象 | 不重复下载，继续核对固定候选和基线 |
| 源重试或证明改变 | 旧封存和旧回执不能替代当前成功来源 |
| 中文与英文 | 产品文字切换，原始ID、SHA、字节、版本和代码保持 |

## 配置与边界

使用现有管理员仓库、基线、执行目录、命令能力及当前控制面地址。单包上限64MiB，超限明确阻止，不静默截断。管理员需为测试节点准备正确共同基线；本功能不自动连接远程Git服务、管理远程账户或修改仓库权限。

当前候选原件复用控制面文件制品存储。多控制面部署需要可一致访问的持久存储与匹配配置，不能据一次本地跨Runner验证宣布S3、OceanBase集群或容量验收完成。动态多分支聚合、交互式厂商会话、完整合并授权及生产CI仍按总体计划推进。
