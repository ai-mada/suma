# 接着上一轮代码继续开发

状态：1.0.0当前实现；负责人：控制面／Runner／Web；需求：T-DEVELOPMENT-CONTINUATION-186，对应原31项中的2、9、12–15、21–27。合同：[同任务候选续作](../../contracts/task-development-continuation.md)；验证：[限定报告](../quality/task-development-continuation-verification.md)。

用户在同一任务补充想法后，可以选择上一轮已封存代码继续修改，避免重新从管理员基线开始。原计划与运行保留，新目标形成新预览，再明确启动新的独立执行。

主要旅程：原开发运行 → 补充想法 → 保存真人消息并明确请求分析 → 审阅新回复 → 选择准确候选代码 → 新选工具与模型预算 → 新开发预览 → 明确启动 → 独立工作树导入 M → 形成新候选 N → 独立测试 N → 人工验收。测试失败、人工退回的旧候选可以作为明确授权的代码输入，不能作为新一轮已经通过质量或验收的证明。

只允许同任务当前终态运行的准确成功封存来源。来源列表显示节点、提交与运行依据，支持分页和刷新；不自动猜选第一项。任务／来源版本、成员权限或实际证据变化时必须重新核对。已验收任务按新迭代处理。

验收标准：旧文件修改在新工作树可见；新 attempt 不复用旧工作目录或模型费用；即使 M 已存在本地，也必须重新通过当前授权读取；N 的提交、测试与人工验收分别留证；准备预览不执行，Start 重传恢复原运行；中英文同等可操作。

本能力提供代码连续性。Codex当前仍按新 attempt 创建新 thread／turn，不表示旧工具隐藏会话或内存自动迁移。完整持续工具会话、真实厂商与物理多机能力继续分别交付。
