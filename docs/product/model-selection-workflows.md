# 模型选择与固定执行流程

适用版本：**1.0.0**。本文说明当前工作台的操作和能力边界；[English](../en/model-selection-workflows.md)。完整平台范围仍以[实施计划](../delivery/implementation-plan.md)和[当前状态](../delivery/status.md)为准。

## 入口与选择

| 入口 | 当前支持 | 操作结果 |
| --- | --- | --- |
| 普通任务工具执行 | 支持独立模型选择的原生 Suma 工具；`codex-app-server-v1` 工具 | 准备该任务的固定预览，另行确认启动 |
| 专家团队派发及未开始项修订 | 每项分别选择原生或 Codex 执行 | 按任务保存选择；同职责共享选择和单任务覆盖只是填写方式 |
| 冲突修复创建及修订 | 具备受管修复能力的原生 Suma 工具，可配置原生模型 | 创建独立修复任务的预览，或为同一修复任务准备新修订 |

模型选项来自当前项目、准确工具版本及摘要对应的有效库存。读取选项只观察已有目录，不调用模型，也不证明模型服务健康或厂商账户授权。自行配置模型的其他工具保留其明确能力边界；不能从工具名称推断它支持平台模型选择。

普通任务先选流程和工具，再明确选模型。原生执行选择准确部署修订、最大模型调用次数、累计输出 Token 限额及可选预算。Codex 执行选择当前目录支持的模型、推理强度和可选 Token 提醒阈值。一项任务只能使用其中一种绑定，不同时提交两套设置。

专家团队先为各任务指定职责，再按职责选择模型；需要不同配置时勾选单任务覆盖。取消覆盖会重新采用当前职责选择。每项预览保存自己的固定选择，后续职责配置变化不会改写它。原生预算按任务分别预留和结算，不汇总成一个团队共用预算；依赖等待不占执行槽位。

## 固定依据与明确修订

准备预览会固定任务及配置版本、工具、模型选择和相关摘要。原生绑定还保存允许参数、预算及匹配的运营方费率；Codex 绑定保存目录、配置摘要、模型、推理强度及提醒阈值。预览和执行节点中的绑定必须一致。查看预览、切换语言或刷新页面不会启动执行。

确认启动前应审阅固定事实。服务端在准备、启动及领取时检查相应的当前授权、库存和原计划依据；不符合时保留原事实并阻止新派发，不自动换模型、采用新报价或退回环境配置。

普通任务要改模型，应重新准备预览。专家团队只能明确修订尚未开始的任务项，重新选择当前模型；已经开始的定义和原运行保持。冲突修复先从完整冲突证据创建独立任务；修订沿用同一修复任务和固定来源，生成新的预览并保留旧计划及原运行。修复修订仅在服务端允许的未启动状态，或具有完整启动前失败证明时开放。准备、修订、启动、独立测试和人工验收是分别确认的操作。

**Codex 修复仍不支持。** 当前受管修复需要专用原生工作区，Codex 工具在修复创建和修订中明确不可选；不能把这一限制显示成已支持的固定工具配置。

## 原生额度与 Codex 用量提醒

原生执行有平台可执行的调用次数和累计输出限额，领取时执行 Token／费用预算准入与预留，并受组织、项目策略约束。预留依据声明的上下文上限和允许调用次数；它不是精确 Token 预测，也不保证厂商最终账单。费用按固定运营方费率计算；缺少匹配费率显示未定价，不显示免费。用量缺失、部分上报或结果未知时保留已知事实和待核对预留，不擅自记零。

Codex 固定为 **observe-only**：Token 阈值只产生用量提醒，不保证强制停止、硬额度或精确费用。要求强制额度的策略会拒绝该工具，不能自动降为观察模式。CLI 配置确认只证明它接受了配置，不证明提供方实际模型身份、模型质量或厂商计费；未知费用保持未定价。

## 原操作恢复与验证边界

请求超时、连接中断或返回内容无法确认原任务及绑定时，保留原完整请求和操作键，使用恢复入口核对原操作。HTTP 2xx 本身不能清除未知结果：模型、推理强度、提醒阈值、原生参数或工作流绑定不匹配时仍须恢复。不要更换操作键重复创建任务或启动运行；配置变化必须在原操作查明后再明确准备新预览或修订。

本轮界面核验限定为本机隔离夹具中的目录选择、固定预览、未开始项修订和刷新回读；没有点击启动，也没有新增模型请求。它验证这些操作及持久事实的衔接，不构成厂商推理、实际编码、物理多机、正式验收或生产集成验证。此前实际执行证据保留各自的来源和范围，不因本轮界面检查而扩大。
