# 已验收候选合成与下游开发基线 PRD

状态：T-P4-031／1.0.0 限定本地已验证；日期：2026-10-27。范围与边界以专项报告为准。
依据：[冻结合同](../../contracts/candidate-composition.md)、[架构与 AI SOP](../architecture/candidate-composition.md)、[交互设计](../design/candidate-composition.md)。完整 P0–P7 和用户全部扩展范围保持。

## 用户要完成的工作

专家计划能等待准确前置运行正式验收，但业务依赖满足不代表其代码已合并。
用户需要把多个真实已验收候选组合成新的代码结果，对这一精确结果独立测试，再明确决定目标交付及下游开发基线。
本阶段在原任务详情内完成这条路径，不新增顶层页面，也不把浏览器变成派发器。

组合本身是一项明确的集成任务。选定固定流程版本、producer 节点及有序 2–16 个来源，先预览，再明确启动真实运行。
可信 Runner 在私有 attempt 中导入准确授权 bundle，用 Git 原生三方合成生成新候选。
原流程正式测试节点通过 `candidate_from` 测试这一新候选，最终使用原浏览器 Review 正式验收。
运行成功、测试通过、原来源已验收均不等于集成任务已验收。

## 来源、结果与权限

来源从当前项目的服务端合格选项选择，保留原任务验收、run／attempt／fence、独立测试和密封字节依据。
不接受用户手填分支、SHA 或文件文本代替真实候选，不隐式扩选或丢弃来源。
来源顺序、宿主基准、策略、时间、流程及执行路由在明确启动时固定；预览不创建运行。
当前账号／组织／项目、原真实凭据、私有／Pool 路由及 fresh code access 继续复核，模型和浏览器均不能增权。

合成不要求付费模型。冲突是带准确文件与来源的真实失败结果，不能生成夹带冲突标记的“成功候选”，
也不提供 ours／theirs 捷径或自动代替人工修复。未知先核对原运行，不自动另起运行。

## 明确的后续动作

1. 在当前集成任务内固定来源和流程，查看只读预览并明确启动。
2. 打开原真实运行查看组合、独立测试、冲突或未知；技术依据默认折叠。
3. 正式测试完成后进入原任务 Review，对准确运行明确验收。
4. 集成任务验收有效后，可使用既有028受管集成入口审阅完整差异、批准并执行目标CAS；031不扩展提供方职责。
5. 另行选择尚未开始的下游任务，核对旧／新代码基线，填写理由并明确绑定已验收合成结果。

也可从下游任务详情展开受保护基线面板，先明确选择当前已验收合成，再确认绑定；不会自动选“最新结果”。
已经开始的任务只读当前绑定及原来源，不能替换。两种入口复用同一绑定组件、权限与双版本CAS，不另造派发路径。

目标仓库集成与下游基线绑定是分开的治理动作；任何一步都不会自动启动下游。
绑定是受保护领域数据，不能由普通记录字段、流程配置或工作区路径伪造。
绑定使下游任务版本变化，旧预览失效；未开始专家计划项须明确修订才能固定新依据，不改已开始运行或历史计划。

下游实际工作区从合成结果 M 开始，同时保留管理员锚点 B 及完整来源。
它产生自己的候选、独立测试及验收，不继承来源或合成任务的测试／验收状态。

## 恢复与体验边界

面板默认折叠零读取；合法深链和原请求恢复仅打开读取，不自动预览、启动、绑定或审批。
403 隐藏旧权限与事实；跨账号／组织／项目／任务立即隔离并中止旧请求。
409 保留选择、理由和绑定草稿，明确读最新后重新确认；未知响应只恢复原请求及原 key。
当前运行、候选、测试与验收状态均来自服务端，不能用进度条或客户端推导伪造完成。
系统标签成对中英；任务、源码、diff、理由与不可变原件保持原文。

## 验证与剩余范围

必要验收将分别核对分叉来源的真实合成、另一 Runner 对精确结果的正式测试、原 Review、028目标CAS及下游确实取得组合代码。
冲突、来源变化、权限／Pool／fence、未知回执、基线替换和旧预览失效分别验证；实际结果由最终质量记录确认。
实际通过范围、初始失败与定向复验见专项报告；不得把有限证据扩大为完整矩阵验收。真实厂商、跨物理机器、完整设备／数据库／容量矩阵及生产验收继续实施。

## 本地交付证据

有序固定两份已验收候选，Runner以Git原生三方合成精确M；另一执行节点对M独立测试后，测试账号明确Review，再将M显式绑定未开始任务C。C从M开发出新提交，另一节点再独立测试并单独Review。实际同机两Runner、2项新运行、8项正式检查；原来源、管理员锚点与protected baseline全链路可追溯。中英切换、同一来源深链和冷回读保持准确事实；冲突、未知和重试沿用原操作及质量边界。见[专项报告](../quality/candidate-composition-verification.md)。仅本地自有协议夹具验证；未调用厂商或模型，未报告用量不推断为零Token。真实远端、多机、生产验收、完整P0–P7及全部扩展需求继续实施。
