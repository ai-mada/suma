# 工具快速接入

T-TOOLS-151，速码1.0.0。用户先选工具，系统读取已登记执行节点的真实探测结果，自动填入可用配置，减少手写JSON和复制清单。[合同](../../contracts/tool-quick-connect.md)定义权限与恢复边界；本页不作为验收证明。

## 添加工具

1. 在“工具管理 → 执行工具”点击“添加工具”，选择所需的已实现执行入口。
2. 系统确认当前项目节点。只有一个活动节点时自动选择；多个节点时明确选择。随后读取该节点最近上报的工具。
3. 唯一匹配的可用配置自动选中并建议名称；多个配置可选择，名称可修改。版本、只读／工作树写入方式先显示，摘要等技术信息按需展开。
4. 点击“登记配置”后保持暂停。核对节点与权限，再单独点击“启用工具”并确认。派发时平台仍检查当前资格与实际观察。

未上报、过期、没有匹配工具、读取失败与权限无法确认分别提示。重新读取只读取现有上报，不会在远端运行探测。高级接入保留本机配置说明、完整清单导入和原登记表单。

## 尚未连接节点时

界面提供“连接执行节点”，进入既有项目节点登记流程。节点登记和Runner启动仍需原配置与凭据；本阶段没有自动启动本机Runner。已有登记记录本身也不说明节点在线。

桌面端可点击“检测本机安装”，检查Codex、CodeBuddy Code或DeepSeek Harness。结果说明是否找到安装及固定启动方式是否通过探测，必要时展开本机路径与版本。普通浏览器没有这项电脑探测能力，不能借服务器检测推断用户电脑的安装。

安装观察不会连接节点、登记配置或启用派发；探测通过也不说明已登录供应方、模型可用或任务成功。WorkBuddy账号授权是另一项连接，不能用CodeBuddy CLI安装代替。

## 失败与后续体验

读取失败可以重试；写入结果未知时先核对原操作，页面保留恢复入口，避免重复登记或重复启用。换账号、组织、项目或工具后，旧结果不能覆盖当前页面。

下一步完整自动接入应让受控本机组件安全接收一次性节点凭据、加密保存并托管Runner，用户只核对本机节点及授权。当前这些能力尚未实现；不能通过把secret交给网页复制来代替。
