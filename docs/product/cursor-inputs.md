# 原执行提问与计划确认 PRD

状态：限定实现与验证通过；suma1.0.0；T-CURSOR-INPUTS-190。负责人：主集成代理；关联[合同](../../contracts/cursor-inputs.md)、[架构](../architecture/cursor-inputs.md)、[交互](../design/cursor-inputs.md)与[限定证据](../quality/cursor-inputs-verification.md)。原31项／P0–P7完整范围持续。

用户在任务运行节点回答原智能体的问题，或阅读其完整计划后作出明确决定；答复通过当前执行器返回同一原生请求，继续原工作区开发，不复制一段计划手动开新任务。既有Codex提问与Cursor ACP提问／计划共享一个平台入口，保持各自真实协议。

| 用户动作 | 结果与验收要求 |
| --- | --- |
| 打开当前节点 | 只读加载准确attempt／fence的原输入；配置不是在线证明，历史不是新执行 |
| 回答Cursor问题 | 使用原选项ID；单选／多选按原题要求，覆盖全部原题；无预选、自由文本或虚构Other |
| 跳过／取消问答 | 明确作用于整份原请求；不等于批准权限或成功开发 |
| 阅读计划 | 原name／overview／完整Markdown／todos／phases可查看；工具自报待办状态不冒充平台业务进度 |
| 接受／拒绝／取消计划 | 原项目写权限、InputID、版本和稳定操作ID；仅答复该计划，不修改Task、需求、DAG、正式基线或验收 |
| 结果未知 | 恢复原意图与原回执，不选择新节点替代、不重答或重发Prompt；保留原正文及决定依据 |
| 查看送达 | 保存、观察、开始写、完整写和执行关闭分别展示；Cursor没有Codex请求关闭ACK |

计划接受可能使原生工具在本attempt私有HOME保存计划文件，界面在确认前说明。拒绝必须返回正常typed rejected，不能用RPC error触发原工具的本地回退。后续命令仍须原一次权限，候选须独立测试和人工验收。

限额：16题、每题32项，计划128KiB；规范化完整请求总量256KiB，待办／阶段有界。原输入与权限共享32次原生交互上限，等待受原deadline与预算约束。此阶段维持原活进程等待，不声称释放执行槽位或持久旧session恢复。

权限、重复操作、并发回答、撤权、暂停、租约变化和断线恢复沿原控制面。没有真实供应方账号时，受控SDK／HTTP／SQLite与合成GUI分别证明实现，不外推真实模型或生产验收。完成情况以限定证据为准。
