# 当前人员任务分配收件箱

状态：T-INBOX-138限定交付；负责人：协作领域；关联Multica M27、原项目与团队协作、统一权限及多语言。正式合同见[收件箱](../../contracts/notification-inbox.md)，实现位于notification_inbox、NotificationInbox及Suma CLI。实际范围以[验收报告](../quality/notification-inbox-verification.md)为准。

人员需要区分“当前负责哪些任务”与“发生了哪些真实分配事件”。收件箱记录正式分配历史，保持任务详情、团队派发、独立测试和人工验收各自的权威；点击通知不自动接受交付。

| 用户与能力 | 明确边界 |
| --- | --- |
| 当前组织／项目有读取权限的人员 | 读取本人的真实分配、当前标题与未读／归档计数 |
| 项目viewer | 管理本人已读／未读／归档／恢复；不能借此写任务 |
| 组织管理员 | 仍只能通过个人入口查看自己的通知，不具有他人收件箱覆盖参数 |
| Agent／Runner | 不使用人员入口；任务执行和机器事件沿已有独立合同 |

主旅程：正式创建／采用设计／拆解／接受交接→任务分配给规范人员→当前人员打开项目收件箱→按需查看来源、明确已读或归档→刷新恢复真实状态。自分配也是真实事件，缺少账号绑定不猜接收人。

验收要求：源事务回滚不留通知；重复原操作不重复生成；原分配变化保留事件并明确当前差异；来源删除后不恢复历史正文；未知结果保留原命令；旧版本冲突明确重读；当前失权清除私有数据；中英与390px操作保持完整。

范围外但仍在原计划：讨论提及、审批／阻塞／完成多源路由、通知订阅与降噪偏好、跨项目聚合、IM／邮件投递、完整离线／数据库／多机验收。本阶段不关闭原完整收件箱复合待办，也不改变58限定实现／34待交付／92总项。
