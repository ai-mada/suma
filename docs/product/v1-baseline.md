# 1.0.0 产品与设计基线

状态：当前开发版本 1.0.0；完整平台仍在实现与验收中，不是生产就绪声明。依据：用户最新完整需求与“所有设计不考虑历史兼容，直接采用最佳合理方案”。

## 统一决定

新接口、数据模型、模块与交互只按当前 1.0.0 最合理结构设计，不增加旧字段别名、双写、旧版本协议转换或历史适配层来迁就既有实现。需要调整已有实现时直接修正对应领域与同源合同，不保留重复业务中心。架构与 API 的版本化、不可变执行证据和安全恢复仍是正式能力，不等同于兼容包袱。

现存业务数据、版本、原始结果、日志与审计证据继续保留；不把版本升级解释为清库或删除用户文件。必要数据变更明确迁移，未知外部效果先核对。产品 release SemVer、第三方 SDK 版本、执行合同版本、业务修订及数据版本分别管理；不能批量替换协议 v1 或第三方依赖号。

## 最新完整能力扩展

| 需求 | 统一实现边界与近期交付方向 |
| --- | --- |
| 13 自主规划与编排 | 自然语言目标生成可编辑任务／验收／成本／约束与 DAG/pipeline；只由 Go 调度器派发，事件持久后确认，智能诊断与预警保留来源和恢复依据。自动规划与治理策略单独版本化。 |
| 14 Token 计量、成本与配额 | 模型请求／attempt／项目／组织维度保存真实 usage、计价版本与去重账本；未上报不同于零。输入、输出、缓存、推理等按实际厂商口径映射；预算预留、结算、释放与额度竞争原子处理。金额使用明确精度，价格可配置且有生效版本，不硬编码未核实价格。优先补齐本领域。 |
| 15 代码仓库、分支、版本 | 受管仓库、分支权限与固定候选／测试／审批结果，目标提交通过 CAS 变更；未知合并效果核对原操作。不能将候选封存或预检当作目标分支已合并。 |
| 16 统一技能仓库 | 技能正文、元数据、领域、应用场景、检索索引与不可变版本分层；组织／项目／团队／成员／专家组／Agent 权限隔离，使用前重验当前权限。向量结果再次授权。萃取先形成可审阅提案，发布和采用均固定版本，统一下发不导入私人会话秘密。优先补齐本领域。 |
| 17 自有智能 CLI | 单一控制面提供命令／JSON/TUI、本地独立与远端 SaaS 连接、任务派发及状态回写、离线/断线恢复、简易安装；复用成熟 SDK 和正式当前身份。当前 handoffs 命令已实现，不能把它扩大为完整自主开发 CLI 完成。 |
| 18 模型与智能体平台 | 统一模型／供应商／账号／权限／路由／成本控制，按官方 SDK/API、MCP/A2A 或平台正式异步合同接入 OpenAI、百炼、Coze、Dify、Pi 等；逐项记录发现、版本、调用、进度、取消、恢复与真实验证范围。未经实际接入不能标记可用。 |

全部能力纳入既有 P0–P7，不缩减项目、需求、设计、团队、质量、运维、同步、安装、国际化和 SaaS 范围。当前各项实现／未实现见[交付状态](../delivery/status.md)，本轮团队交接见[验证](../quality/task-handoff-verification.md)。

## 体验与开发纪律

默认页面简洁，常见操作直接可见，低频依据按需展开；中文／英文同源目录，新增语言可扩展。成熟工具包优先，按领域并发且共享合同由主集成者冻结。只验证新增行为、权限、事务、一致性和代表性交互，复用未变证据，不重复模型、全套或设备矩阵。阶段完成只提交必要源码、配置、文档与精简事实。
