# 多项目执行配置准备

版本1.0.0；状态：T209限定实现与验证通过，结果见[报告](../quality/pool-config-preparation-verification.md)。负责人：Runtime／工作台。关联：[实施合同](../../contracts/pool-config-preparation.md)、[原机器配对](pool-runner-pairing.md)。

## 用户目标

共享机器完成配对后，运营者能够在一个简短表单中给多个项目配置工作目录，并引用目标机器已有的工具允许列表；无需手工拼接整段JSON。已有配置调整时生成新文件，旧文件和运行记录保留。消费项目的业务资料与秘密不经过Pool管理页面。

## 交付范围

1. Pool节点行进入准确节点的“准备项目配置”，显示固定Pool／节点和槽位上限。
2. 选择目标Shell、新配置文件，逐行从已加载的批准项目中选择，或手工填写租户／项目，再填写工作目录。允许增加、删除行；默认1槽位。引用已有命令文件可选，空值仅准备工作目录。项目选择只使用Pool管理者当前可见的公开授权元数据，不加载消费项目资料。
3. 仓库、固定提交、独立工作树及模型／外部仓库配置文件放入行内高级选项。仓库与完整提交成对填写，不自动猜当前分支。
4. 显示字段或范围错误，并自动展开、定位可修正的字段；只有有效输入才能生成并复制命令。复制不会执行命令。目标机器检查现有目录、文件、整体配置和容量上限后创建新文件；再执行同一命令明确拒绝覆盖。
5. 后续启动继续使用原配对身份、PoolSession和Grant核验；工具发现、登记和启用保持原明确操作。

## 验收标准

表单在中文／英文和窄屏完整操作；复制内容准确传输含空格、引号和非ASCII路径。删除行后焦点可继续操作。切换账户、组织、Pool或节点不会带入旧草稿。输入超限、重复项目、无效槽位、非绝对路径、仓库基线不成对时停止生成。机器拒绝损坏或链接的来源、超限私有文件、既有目标及混合CLI模式；失败不改原件，不输出私有内容。

配置准备、静态检查、机器连接、实际工具库存、当前派发资格和业务验收是六个独立事实。该流程不自动创建Grant，不自动发现或运行开发工具，不代表原31项／P0–P7平台完成。
