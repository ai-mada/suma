# 批量变更任务负责人

T-MULTICA-BULK-150，速码初始产品1.0.0。状态：合同冻结、实现进行中；负责人：任务领域／前端交互／主集成，按[合同](../../contracts/task-owner-changes.md)分工。本页定义本片产品行为，不作为测试、GUI或交付验收证据。

当前任务列表已有最多16项的明确选择、普通任务更新、分配通知及依赖失效能力。本片将它们连接为一次受保护的批量负责人变更，不扩大原专家团队安排、执行或正式Review权限。

## 明确选择、预览和采用

1. 在当前项目列表选择1～16项已加载任务，不把筛选结果全部隐式选中。
2. 从服务端当前人员目录选择一个真实账号绑定、仍有项目访问的规范人员资源。人员目录按字面搜索和明确分页读取，不从有限本地成员列表推测资格。
3. 请求真实预览，逐项检查标题、原负责人、当前版本及“负责人将变化／负责人不变”，并查看实际变化和不变数量。
4. 阅读通用影响说明并明确确认，再一次采用同一批任务、目标人员版本和预览依据。预览摘要不是访问凭证，也不是采用批准。
5. 查看原操作回执及全部所选任务的最终版本／状态；刷新失败与原操作已保存分别显示。

目录需要当前调用者的项目写资格；有项目访问的viewer可以是负责人，但该选择不赋予新权限。预览仅供当前有权用户读取，不保存业务回执、活动或通知，也不启动工具。

## 负责人不变与依赖影响

| 情况 | 行为 |
| --- | --- |
| 实际负责人变化 | 沿普通任务更新规则改为进行中、撤销当前已验证交付资格并投影分配通知 |
| 负责人已经是目标人员 | 标为不变，不做空负责人更新，不发分配通知 |
| 全部负责人均不变 | 明确提示无需变更，预览不可采用 |
| 不变任务是本批变化任务的后续 | 仍可被原依赖规则失效，最终版本／状态可能变化 |

例如选中A及其后续B，A需要换负责人、B已经属于目标人员：B不发生负责人写入，却仍可能随A的变化失去验收资格。回执必须表达依赖处理后的真实最终状态，不能把“负责人不变”显示成“完全没有影响”。

已验收后续任务可能失效，已完成迭代／里程碑可能重新打开。预览显示真实逐项变化和通用影响，不承诺完整下游计数或固定依赖图。原运行、代码、测试和Review历史保留；后续独立测试与正式验收仍按原门禁进行，不自动派发。

## 原子性与恢复

采用前重新核验当前权限、全部所选任务版本、规范目标及其资源版本、预览摘要。任何任务冲突、目标失效或通知失败都整批回滚，不产生部分负责人变更。

结果未知时保留原用户／组织／项目、JSON、原版本、摘要和操作标识，核对同一原操作。原回执恢复仍需当前授权；相同标识改正文拒绝，不能换标识或自动采用新版本重试。

恢复入口独立于当前选择，实际接线为Records(tasks)→TaskRecordsScope→TaskViews.selectionActions，TaskCollection仅作embedded内容且controls=null。零选择仍保留原操作／持久化故障入口；409保留选择和目标，重新预览是明确的新决定。

父层401／403／404同步遮蔽受保护内容，取消读取并隔离迟到写结果。blocked时可明确GET task-owner-targets（limit=1）核对当前原视角写资格；成功才通知父层清除denial并刷新读取，随后仍须用户明确恢复原操作，不自动重放，也不授予角色。

## CLI 三步

```text
suma --project PROJECT task-owners targets --query "姓名"
suma --project PROJECT task-owners preview --file preview.json
suma --project PROJECT task-owners apply --file original-apply.json
```

POST项目仅在正文中传递，全局project用于核对／补齐一致的project_id。预览保留原tasks数组顺序及精确版本；采用再提供准确preview_sha256、acknowledge_invalidation:true与原idempotency_key。结果未知时原文件、版本和操作标识不变，不能换ID重试。

## 界面与范围

加载、无选择、无合格人员、目录错误、403、版本冲突与未知结果分别提示。切换身份／项目或失权清除受保护预览和目标，迟到响应不能恢复。中英文、键盘、至少44px操作目标及390px布局是本片交互要求，实际观察另记。
