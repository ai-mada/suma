# 关键用户旅程

状态：产品验收合同。每一步核对可见结果、持久事实和恢复方式。

| 旅程 | 关键步骤 | 完成事实 | 失败恢复 |
|---|---|---|---|
| 需求到派发 | 项目→新需求→设计/验收条目→拆解草稿→选中编辑→依赖检查→负责人→执行流程 | 选中内容原子创建，绑定需求修订和执行版本 | 冲突保留草稿；依赖错误定位；不重复生成或创建 |
| 并行开发到验收 | 发布流程→固定输入→独立工作树→并行开发/测试→汇合→审查 | 原件、代码、节点尝试、测试和审核人完整关联 | 失败节点定位；旧测试失效；要求修改保留审查意见 |
| 条件与人工交接 | 条件依据→分支→待审批收件箱→批准/退回→后继 | 一次有效决定释放一次后继 | 过期或依据变化要求重新审查；拒绝仍可用于收尾 |
| 断线恢复 | 失联→最后观测→检查原执行→恢复回传或核对→新尝试 | 没有重复副作用，原输出可查 | 未确认停止/结果保持未知；禁用直接重跑 |
| 发布与问题回流 | 已验收范围→版本候选→部署审批→观察→问题→修复需求 | 版本产物和实际部署证据关联；问题来源保留 | 回退独立执行；入池去重；转需求不自动解决原问题 |

## 通用交互验收

刷新、返回和分享直链保留项目、筛选、当前对象、流程版本、节点与尝试；运行事件不抢焦点；每项拖拽有非拖拽入口。桌面保留图与详情，390px 默认节点/任务列表并可全屏查看图。

首次使用从创建所有者开始，填写组织和项目后进入空工作台。项目中没有需求、执行器或模型时使用引导操作，状态与统计保持真实。
