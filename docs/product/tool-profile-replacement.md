# 工具配置换新 PRD

状态：T-TOOL-REPLACEMENT-200限定验证完成；suma1.0.0；负责人：平台集成；关联[合同](../../contracts/tool-profile-replacement.md)、[架构与AI SOP](../architecture/tool-profile-replacement.md)、[交互](../design/tool-profile-replacement.md)。完整31项／P0–P7目标继续。

用户调整工具时，需要清楚旧配置与新配置的关系，避免分别登记和暂停造成部分成功、断线后重复创建或无法知道交接结果。一次明确操作完成准备，新配置启用、实际执行、停止和验收保持各自流程。

| 编号 | 场景 | 验收结果 |
| --- | --- | --- |
| R200-1 | 新建目标 | 核原版本及目标fresh完整可用库存，新建paused/v1并保存正式关联 |
| R200-2 | 采用已有目标 | 明确选择完整匹配ID／版本，保留其enabled／paused状态；发现已有匹配不能静默选择 |
| R200-3 | 选择是否暂停原项 | 默认不暂停；明确暂停才更改原enabled版本，已paused不空涨；旧Profile／任务依据不改 |
| R200-4 | 调整至另一节点 | 保留准确原source，只有明确的同项目合资格目标迁移；不被最近配对节点替代 |
| R200-5 | 断线与部分故障 | 原身份／路径／body／key恢复同一回执；原子回滚新目标、旧项暂停、关联及操作记录 |
| R200-6 | 刷新与协作追溯 | 原项出向、新项入向历史可分页读，显示提交人和交接时两快照，不冒当前资格 |
| R200-7 | 简洁双语交互 | 原Quick和全局写恢复继续复用，旧→新一次确认；失败保草稿、未知优先原操作 |

首次初始化允许新关系表正常创建；未知既有布局拒写，不清用户数据。合法大观察导致关系超过读取上限时，必须提交前拒绝并全部回滚，不能返回无法再次读取的成功。权限、CAS、完整Profile比较、幂等、当前节点资格及匹配竞争沿原领域，不能由界面草稿或历史快照代替。
