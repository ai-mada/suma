# 执行工作区编辑与保存：产品和交互规格

状态：1.0.0／T-P4-038，有界功能与本机真实界面已验证，2026-10-27。负责人：平台集成、Control、Runner。关联需求：多工具与多人协作、完整IDE、异常恢复、中英文及资源效率。[合同](../../contracts/workspace-write.md)、[架构](../architecture/remote-workspace-write.md)、[AI SOP](../operations/remote-workspace-write.md)、[英文](../en/remote-workspace-write.md)；[限定证据](../quality/workspace-write-verification.md)。完整平台仍按P0–P7和需求1–22实施。

## 用户目标

用户从项目开发工作空间选择当前原生执行尝试，预览真实文件，取得完整字节后编辑，并按原文件摘要保存。浏览器不接收Runner路径或MCP凭据。目标的can_write表示当前项目写权限及任务资格，不表示连接或模型健康。

已有文件和新正文均限48KiB有效UTF-8；不提供创建、删除、强制覆盖、远程Git写、PTY／LSP／DAP。分页片段不能保存成整文件；full_file模式一次返回完整小文件，包含3000行短文本等情况。完整远程IDE和大文件策略属于后续总体范围。

## 正常操作

1. 打开“开发协作→工作空间→执行工作区”，明确选择运行、节点及attempt。
2. 预览文件；有当前写资格时使用“编辑文件”。若是分页，先读取完整文件并核对实际字节SHA。
3. 在Monaco输入草稿，使用保存或Ctrl／Cmd+S。按钮同时处理新保存与原保存核对，避免用户记忆多个恢复入口。
4. 只有相同原命令、scope、策略、原SHA、新SHA和准确native回执匹配，才显示“原保存已确认”。之后输入的新草稿不能被旧ACK覆盖。
5. 保存递增工作区generation；仍需当前源码检查、独立测试及原人工验收。保存不改变需求、计划、任务和历史Review的业务含义。

## 交互状态

| 情况 | 用户反馈和操作 |
|---|---|
| 草稿未改 | 保存禁用；可关闭 |
| 草稿修改 | 可保存，离开页面前保护未保存内容；切换本地／执行来源保留各自草稿 |
| 原POST响应不确定 | 保留同一正文、摘要、操作key及原调用上下文；“核对原保存”恢复原请求 |
| 首次明确拒绝 | 保留草稿，但释放确定没有提交的新请求；用户可关闭或修正权限／依据 |
| requested／leased | 展示等待／一次许可已授予；轮询原元数据，不自动提交第二个写命令 |
| reconciling | 只有用户明确点击才请求inspect；核对超时重试仍使用原inspection key与预期版本 |
| CAS冲突 | 未覆盖文件，保留草稿；读取当前完整文件，左侧显示快照、右侧编辑合并结果；明确勾选后采用新比较基线 |
| 预先比较 | 未保存前也可读取当前文件并比较；比较期间保存禁用，需明确采用基线或放弃草稿 |
| 关闭已知原命令的草稿 | 不撤销已提交效果；可在“最近保存”继续核对，不把关闭当成取消写入 |
| 来源观察过期 | 用户草稿保留为原基线，不伪装成最新代码；真正保存重新核验当前权限与文件CAS |
| 原读取身份失效 | 立即隐藏原身份代码与草稿；不将旧回执混到新身份 |

“最近保存”默认折叠，打开时才加载当前原调用凭据最近50份元数据，准确显示已加载／总数。详情可刷新和显式核对；不读取正文，不轮询整个历史列表。刷新后保留来源／当前目标，草稿不进入持久浏览器缓存，保存命令由服务端记录。

## 组件、国际化和资源生命周期

沿用现有Radix／Monaco、共享提示及设计令牌，新增远程编辑器、写请求校验和折叠历史组件；不创建第二套IDE框架。平台文案、状态、数字、时间和错误支持中英；代码、路径、摘要和用户内容保持原事实。Monaco内置菜单仍英文。

左右差异区分别具有当前快照／合并草稿名称，随语言更新。修复React Monaco4.7的退出顺序：独立URI模型由组件明确所有，先从DiffEditor分离，再释放；SDK0.52的无关选项更新会重置内层ARIA，使用公共配置事件及相等性检查保留当前语言名称，监听与模型一起释放，不拦截或忽略异常。

实际桌面界面验证见报告。窄屏沿用响应式布局，但本阶段未执行移动视口、全部主题、跨平台或大图性能验收。
