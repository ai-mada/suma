# 本机工具凭据续期

T-DESKTOP-CREDENTIAL-178；suma 1.0.0；2026-11-01。状态：源码、定向、真实私有CLI与代表合成组件验证通过，完整桌面与生产待验。负责人：主集成代理；领域协作：Desktop、控制面与 Runner。关联[实施合同](../../contracts/desktop-runner-renewal.md)、[架构与 SOP](../architecture/desktop-runner-renewal.md)、[交互设计](../design/desktop-runner-renewal.md)及[英文说明](../en/desktop-runner-renewal.md)。实际验证与交付结论由本阶段质量报告记录。

本功能解决已排空的本机 Worker 凭据到期后无法沿原配置重新连接的问题。用户在原工具连接卡明确续期，保留 Worker、项目、工作区、工具配置和执行日志，取得新的凭据登记期限；续期不代表执行任务或完成质量验收。

## 用户流程

1. 查看原工具连接卡的凭据登记期限和库存观察期限。两者分别来自 Worker 回执和库存观察，不能互相替代。
2. 正常停止原本机 Worker，等待确认关闭。若原登记结果未知，先核对原登记；若已有续期结果未知，继续核对该次续期。
3. 点击“续期凭据”。主进程检查本机原日志与服务端未结执行，使用当前管理员身份和原来源证明提交续期。
4. 收到准确原操作回执后，连接回到 `prepared`。用户再明确连接，由原 Worker 恢复合法已知回执并发布新库存。
5. 工具档案仍沿原登记和启用流程：新增档案先暂停登记，再明确启用。凭据续期与工具启用各有独立回执。

续期入口只接受原身份、项目、工具和语言，不提供新路径、配置或密钥输入。同一次操作的响应丢失时，界面显示“核对原续期”，继续使用原正文、key 和已保存的新 secret。

## 对外事实

| 字段 | 含义 |
| --- | --- |
| `credential_expires_at` | 当前凭据登记有效期，来自 Worker 登记／续期回执或当前读取 |
| `credential_version` | 当前 Worker 凭据登记版本，与工具版本分开显示 |
| `expires_at` | 库存观察期限；失效后需获取新库存 |
| `phase=renewal_unknown` | 原续期尚未取得确定结果，只允许核对原操作 |
| `renewal_reason` | 安全、闭合的原因提示，不携带路径或 secret |

`renewal_reason` 仅有六值：`execution_pending`、`local_state_pending`、`credential_changed`、`access_changed`、`context_changed`、`result_unknown`。已知服务端拒绝与未知传输分别表达；重启后缺少原瞬时原因时只能显示 `result_unknown`，不能据此放宽恢复条件。

## 准入与验收口径

续期要求原进程已确认关闭、当前管理员有权、原登记持有人及来源一致、旧授权未撤销、Worker 版本与旧摘要相符，并且本机与服务端均无待核对执行或副作用。租约过期、主日志 pending=0、停止请求已发出，都不足以证明排空。

验收应分别确认：新 secret 先加密持久化；原 body/key 可恢复；CAS 冲突和撤权拒绝；旧 token 原子失效；原 Worker 与配置不变；本机待回执和服务端未结执行阻止续期；成功只到 `prepared`，明确连接后才核验新库存。源码与定向检查不能替代真实集成、厂商或生产证据。

当前目标为**空闲且已排空的凭据续期**。“旧授权已过期且仍有旧 token 绑定的未结副作用”需要专用恢复票据，本阶段尚未实现，必须保留原操作供核对。完整 31 项、P0–P7 及 58 limited／34 pending／92 total 的平台范围继续保留，不能用本片完成度替代全平台交付。
