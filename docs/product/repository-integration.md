# 已测试候选到受控目标分支的集成 PRD

状态：T-P4-028 限定本地已验证；产品版本：1.0.0。本文定义本阶段产品行为，不代表真实 Git、浏览器、远端或生产验收已经通过。
依据：[冻结合同](../../contracts/repository-integration.md)；关联：[架构与 AI SOP](../architecture/repository-integration.md)、[交互设计](../design/repository-integration.md)。

## 用户问题与目标

任务完成开发、独立测试和人工验收后，平台已有固定代码候选及其证据，但这些事实不能证明目标分支已更新。
负责人需要看清“把哪份已验收代码，按哪次批准，写入哪个实际分支”，并在断线后核对同一次操作。

本阶段提供一条完整受控路径：选择已验收候选和预置目标，准备真实差异，明确批准固定计划，再明确执行。
目标为管理员管理的 bare Git 仓库及固定分支。只支持快进集成，结果提交就是原来已独立测试的候选提交。
分支分歧时需要重新开发和测试候选；本阶段不生成未测的合并提交或 squash 提交。

入口位于原任务详情“集成已测试候选”，不增加顶层管理页面，不改变当前 IDE 的本机工作区。
任务状态、测试结果、人工验收、仓库集成、版本发布和部署分别记录；成功集成不自动宣布后续事项完成。

## 主体与权限

| 主体 | 可执行操作 | 权限依据 |
|---|---|---|
| 当前项目读取者 | 查看选项、原计划、差异、批准及回执 | 当前项目读取权限；历史内容不产生写权限 |
| 当前项目写入者 | 明确准备集成计划及其异步运行 | 浏览器或当前范围 API 权限，且固定候选仍合格 |
| 浏览器项目批准者 | 绑定预置目标、调整名称与状态、批准或拒绝计划 | 当前浏览器项目批准权限 |
| 当前项目批准者 | 执行已批准计划、核对原操作 | 浏览器或当前范围 API 权限；执行仍需有效的浏览器批准 |
| Runner／资源池 | 领取托管运行、持当前租约调用提供方、回写证据 | 原机器身份、路由、槽位、grant、attempt 与 fence |
| 仓库提供方管理员 | 配置固定 Git、bare 仓库、分支与提供方秘密 | 本机启动配置，不通过模型或普通项目表单填写 |

Agent 和 Runner 凭据不能作出治理决定。把工具或机器加入团队，也不会获得仓库审批权。
前端以服务端 `can_*` 和阻断原因展示当前操作；不能从用户角色名称自行推导授权。

## 用户旅程

1. 打开任务详情并展开面板。普通默认折叠时不请求本域数据；原计划深链或待恢复请求可直接打开相应事实。
2. 选择服务端返回的已验收候选，核对任务版本、来源运行、候选提交及固定测试依据。
3. 选择项目已绑定的受控目标。没有目标时，由浏览器批准者展开“管理目标绑定”，从管理员预置的提供方和别名中选择。
   提供方为空时说明先完成管理员配置，不显示可任意输入的仓库地址、路径或命令。
4. 明确点击“准备真实差异”。服务端固定任务、来源和目标版本，并原子创建一次托管准备运行；准备不更新目标分支。
5. 等待提供方返回实际文件清单和完整、有界的 diff。核对预期目标提交与结果提交，必要时打开原运行和固定依据。
6. 填写审阅理由并勾选对本次固定差异的确认，再批准。批准和执行是两个独立动作；批准本身不写 Git 目标。
7. 当前有权执行者重新明确确认后执行。页面显示实际执行运行，收到经过核验的本操作 Git 回执后才显示“已集成”。
8. 刷新或分享原计划链接继续查看。来源、目标或权限变化时不套用旧批准；冲突需处理后重新准备。
9. 网络结果不确定时恢复原请求；外部效果不确定时核对原操作，不能通过重新创建计划或人工选择结果来消除未知。

## 关键规则

- 每个计划固定任务验收依据、来源 run/node/attempt/fence、封存 bundle、目标绑定与配置摘要。
  `ReleaseTaskBasis` 在此仅复用代码验收快照结构，不代表产生了发布制品或发布候选。
- 目标的 provider、alias、ref 与配置摘要在绑定后不可改写；名称与 active／paused／retired 状态按版本更新。
- 准备及实际副作用前分别检查当前权限和固定依据。审批者撤权、候选／测试／验收变化、目标漂移或过期均不能靠旧批准放行。
- 封存 bundle 上限 64 MiB，文件变更上限 1000，diff 上限 512 KiB。超限或不能完整审阅的二进制变更明确阻断，不截断后冒充完整差异。
- 执行通过一次 Git 引用事务比较预期目标，写目标、原操作回执及目标级 fence。只看到目标等于候选，不足以证明本次操作成功。
- 未知结果保留目标独占屏障。核对只依据同一请求的真实提供方证据；缺少回执本身不能证明“未生效”。
- 必要的负向核对须经当前授权，以原子负向回执和 fence 阻止旧请求继续写入，并与可能残留的原 Git 事务安全竞争。
  当前仍有有效运行租约时，不能绕过既有托管恢复门禁。
- 重试不自动批准、执行或改写结果；同一操作标识只恢复原请求。409 读取当前版本并保留理由，但清除原确认勾选。

## 状态与异常

| 计划状态 | 用户含义与下一步 |
|---|---|
| preparing | 已创建真实准备运行，尚无可批准的差异 |
| ready | 差异已回写，可按当前权限审阅；不表示已批准 |
| approved | 固定计划已有批准，仍需明确执行与副作用前检查 |
| rejected | 本计划被明确拒绝，不更新目标 |
| applying | 已创建真实执行运行，尚未由回执确认目标效果 |
| integrated | 本操作完整 Git 回执已核验；不代表已部署 |
| blocked | 已知条件不满足或已知未生效，保留理由与原件 |
| reconciling | 结果待核对，保持原操作及独占屏障 |

准备、执行或待核对期间，界面不能用“重新准备”绕开原操作。历史仍按需读取，原内容和后续当前资格分别展示。
后续分支前进不会抹去已经存在的真实原操作回执；当前分支位置也不能替代历史证据。

## 验证边界

本阶段需证明当前权限、固定来源、SQL 原子提交、准确差异、Git CAS／回执／fence 竞争、撤权与未知恢复，
以及代表性中英文完整界面流程。必要验证复用已关闭的已验收候选及隔离 bare 目标，不重新调用模型。
已落界面和定向交互检查不能替代提供方真实事务、整合浏览器或生产验收；实际结果由集成质量记录单独确认。

远端托管平台、任意 merge／squash、AI 自动审阅、跨物理主机生产运行及完整 P0–P7 仍保留在平台后续范围。

阶段实现、实际 Git／中英文旅程及未验收边界见[限定验证](../quality/repository-integration-verification.md)。
