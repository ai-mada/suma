# 工具重新检查：准确节点与真实报告

状态：限定实现与验证完成；版本：suma 1.0.0；需求：T-TOOL-REINSPECTION-194；负责人：主集成代理。接口以[领域合同](../../contracts/tool-reinspection.md)为准，实现及覆盖见[限定验证](../quality/tool-reinspection-verification.md)。完整31项需求、P0–P7继续推进。

## 用户问题与目标

管理员需要在工具版本、配置或连接发生变化后，直接检查原工具所在的执行节点。重新读取历史库存不能证明节点重新探测；本机连接成功也不能替代用户选定的远程节点。

本阶段贯通“创建准确目标请求 → 原节点消费 → 本次真实探测 → 关联库存持久化 → 查看当前诊断”。常用操作保持一个入口，高级来源与恢复依据按需展开。已有安装、配置、模型登录、任务执行和验收仍分别表达。

## 旅程与验收标准

| 编号 | 用户行为 | 可观察验收结果 |
|---|---|---|
| R194-1 | 从已登记工具发起重新检查 | 使用原项目、工具版本、完整配置摘要及准确节点；当前管理权限由后端核验。只读用户不会获得写权限 |
| R194-2 | 请求进入等待 | 显示已保存请求及等待原因；旧的fresh库存、另一个节点的上报及普通状态刷新不能把本请求标记完成 |
| R194-3 | 节点领取请求 | 原Worker通过经过认证的出站请求领取，同一库存处理者串行执行；不启动第二个进程抢占Journal，也不领取业务任务来冒充检查 |
| R194-4 | 节点完成检查 | 新库存操作绑定本次请求与领取凭据；服务端在同一事务保存库存及请求结果。探测完成不等于配置匹配、模型可用或任务可派发 |
| R194-5 | 创建或上报回执丢失 | 恢复原请求、原领取或原库存操作；保持原始身份，不另建请求或重新执行未知动作 |
| R194-6 | 失联、超时、撤权或依据变化 | 明确等待、结果未知或依据失效，不显示成功，不静默换节点、配置、凭据或权限；保留可追溯记录 |
| R194-7 | 筛选当前工具列表 | 空结果只说明当前筛选没有匹配；可清除工具筛选，保留任务筛选和项目位置，不误称从未接入 |
| R194-8 | 进入准确节点的连接向导 | 本机自动状态回调不能覆盖原工具、草稿或用户明确选择的节点；切换节点必须有明确用户操作 |

## 自动化范围

执行节点只检查自身已登记的配置与既有工作区，沿原探测、身份、库存和回执协议执行。请求不能携带任意命令、程序路径、脚本、环境变量值或安装参数。共享资源池继续核验准确项目授权和当前grant，不扩大可访问范围。

系统可以自动推进已明确发起的检查、持久化报告、解释当前阻塞，并引导用户进行下一步。安装工具、修改模型或密钥、提升权限、启用配置、停止外部进程、执行代码与正式验收分别保留原流程，不能由一次检查代为完成。

## 简洁交互与国际化

工具详情提供一次明确的“重新检查”操作及当前请求摘要。创建、等待、运行、完成和异常状态均有中英文说明。等待或结果未知期间不反复显示可创建新请求的主按钮；提供读取原请求或恢复原操作的动作。

列表、详情和快速接入共用正式数据，不增加第二个工具管理页面或新的派发器。窄屏、键盘操作、加载、空态、失权和断线均使用原组件规范；技术标识、版本和回执默认折叠，需要排查时可查看。

## 交付判定

源码、合同检查、真实HTTP／SQLite／Worker／Journal验证和产品界面验证分别记录。至少验证一次新请求对应真正新探测，以及一次回执丢失恢复不重复探测。真实厂商账号、物理多机、其他数据库运行及规模验收不由本地受控验证替代。减少未变模块的重复测试，阶段验证后正常提交并推送dev。
