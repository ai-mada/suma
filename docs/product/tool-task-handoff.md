# 工具到任务的准确交接

版本：1.0.0。阶段：T-TOOL-TASK-HANDOFF-213。状态：实现已落，实际集成验收以[最终质量报告](../quality/tool-task-handoff-verification.md)为准。负责人：工作台／任务派发／主集成。关联：[唯一合同](../../contracts/tool-task-handoff.md)、[架构与 AI SOP](../architecture/tool-task-handoff.md)、[交互设计](../design/tool-task-handoff.md)。完整31项／P0–P7继续。

## 用户目标

在工具连接和配置核对完成后，直接把准确档案交给当前项目的任务，继续使用原有流程、模型、预算和质量门禁。减少在工具目录与任务列表之间重新寻找目标的操作。

## 完整操作

1. 在原工具详情核对准确配置。当前档案已启用、有真实可用观察、可写且支持任务协议时，显示“用于任务”。
2. 按需打开任务选择，复用原项目任务分页、检索和当前权限。列表仅说明已加载范围；选择任务后重新读取准确任务及原工具。
3. 进入原任务派发弹窗，选择已发布流程及接收任务的 Agent 节点。界面显示带入工具的名称、版本和执行节点。
4. 明确点击“核对并采用此工具”。重新读取原工具并核对项目、ID、版本、Worker、完整配置摘要及当前观察，通过后填入原工具选择器。目录首屏没有此工具也可准确采用。
5. 使用原组件配置模型、参数、预算和知识引用。生成正式计划预览后，再单独确认启动。正式服务端继续核验当前权限、项目路由及执行依据。
6. 沿原执行进度、同提交独立测试、人工验收、问题回流与基线交接推进交付。

任务选择与派发表单依次使用一个 Modal。关闭交接回到原准确工具，并恢复到入口焦点；形成正式计划后进入可刷新的原任务／计划地址。

## 配置变化与异常

| 情况 | 用户可见结果 |
|---|---|
| 工具暂停、撤销、版本或摘要变化 | 显示原配置已变化，不替换为其他版本或同名档案 |
| 任务、流程或 Agent 节点变化 | 清除已采用选择及对应模型绑定，保留带入意图供明确重核 |
| 已采用工具 A 后重新核对 | 先撤下仅由交接采用的 A 及模型绑定，读取失败后不能继续用该旧响应预览 |
| 用户手动选择 B | B 保留；A 的采用提示失效，旧异步回调不能覆盖 B |
| 权限失败或网络结果未知 | 提示准确状态，重新核对由用户明确发起 |
| 原预览写入回执未知 | 优先恢复原 path／body／key，交接动作保持锁定 |

带入 pin 只含公开定位依据，保存在当前界面内存。模型、预算、凭据与完整配置不进入 pin 或地址栏。工具可用观察不等于具体任务已获准执行。

## 交付与验收边界

本阶段复用原接口及执行内核，新增工具选择到任务派发的界面交接。中文／英文、44像素操作目标、窄屏单列、键盘选择及焦点恢复纳入代表界面验收。

定向检查覆盖准确工具、目录页外采用、来源变化、选择归属及未知预览恢复。真实集成采用当前 HTTP／SQLite、任务选择和正式预览，预期不启动运行、Worker或模型；执行、独立测试及验收链的未变证据复用。实际结果和剩余范围统一见最终质量报告，不将预览通过视作完整研发平台验收。
