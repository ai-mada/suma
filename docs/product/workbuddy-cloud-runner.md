# 正式云任务执行与恢复需求

版本1.0.0；阶段T-WORKBUDDY-RUNNER-155；负责人：主集成代理；状态：Windows／SQLite限定验收通过。依据：[执行合同](../../contracts/workbuddy-cloud-runner.md)、[架构](../architecture/workbuddy-cloud-runner.md)、[交互与操作规程](../design/workbuddy-cloud-runner.md)、[验收证据与边界](../quality/workbuddy-cloud-runner-verification.md)。

用户在原节点授权一次云任务创建，速码分配给有资格的执行节点。用户始终看到原运行、原尝试和原云任务；失联、撤权、取消和未知回执不生成替代任务，也不能把供应方完成当成代码验收通过。

## 角色与操作

项目写成员可以在本人连接上明确委派、撤回及查询原任务。项目可读成员查看安全事实，不能借用委派人的凭据。正式Runner使用自己的机器身份领取；共享资源池还须匹配当前双边项目授权和凭据版本。浏览器不发送机器创建请求，不持有OAuth或ACP凭据。

节点详情默认只显示主状态、下一步和原执行入口。请求正文、摘要、执行者、attempt、fence、连接、用量和最后观察放入可展开详情。中英文、窄屏和键盘沿统一设计系统实现。显示语言不参与身份、摘要或操作键。

## 验收标准

| 场景 | 必须满足的行为 |
| --- | --- |
| 无委派、委派过期或owner失权 | 不取得可执行派发，不创建供应方任务 |
| 云硬预算enforce | 明确拒绝；未知用量和费用不能用零代替 |
| 正式领取 | 一次锁定机器、全部候选owner、组织及Pool；同事务固定binding和dispatch |
| 首次创建 | 原请求和operation ID先持久化，再经中央唯一入口外发 |
| 创建ACK丢失／Runner重开 | 读取原提交；prepared/unknown不重复创建；已知任务只观察原ID |
| 心跳更新 | lease/state观测可变，原请求、摘要及key不变 |
| 供应方completed | 等待交付证据，下游不开启，业务任务不自动验收 |
| Runner失联 | 保留attempt，释放process资源；外部效果及未知费用记录保留 |
| 用户取消 | 明确远端停止未确认；本机停止观察不能代替远端停止回执 |
| 中央确认未创建 | 原提交缺失且委派未消费才允许无效果失败；明确重试仍受幂等、次数、退避、期限和当前权限约束 |
| 晚到或篡改回执 | 替代attempt/fence、委派、key、凭据或任务均拒绝 |

本阶段交付保护性领取、中央创建、持久恢复、当前授权观察和无本机槽位等待。机器ACP授权、云代码候选导入、独立测试、人工验收、生产发布和真实供应方验收继续沿完整计划实现，不通过额外成功开关跳过。P0–P7及58 limited／34 pending／92总项保留。
