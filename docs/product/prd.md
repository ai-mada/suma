# 产品需求与成功标准

状态：目标合同；实现进度见交付状态。负责人：产品与平台。

平台身份／SSO、可复用权限、插件／技能、MCP／A2A、配置与诊断的细化需求见[平台基础PRD](platform-foundation-prd.md)，分层及成熟SDK策略见[工程架构](../architecture/platform-engineering.md)。这些需求继续属于完整平台范围，实现与真实验收分别跟踪。

## 产品目标

让人、智能体、开发工具和执行节点在同一项目上下文中交付可验收的软件。一次交付可以关联需求、设计、代码、执行、测试、审查、发布和问题，用户能够从任何结果回溯依据及责任人。

## 参与者

| 角色 | 责任 |
|---|---|
| 组织所有者/管理员 | 身份、项目授权、模型、节点、存储、预算和账单 |
| 产品/设计成员 | 需求、验收条目、设计资产、基线与范围变更 |
| 开发成员 | 拆解、代码、执行、提交审查和缺陷修复 |
| 审核成员 | 核对固定代码与测试证据，批准或退回 |
| 运维成员 | 环境授权、部署、观察、故障与回退 |
| 智能体/工具 | 在冻结权限、输入和预算内执行；无权自行批准结果 |

组织身份与项目资源目录分开：登记一个同名工具或人员不会授予登录或执行权限。

## 功能合同

1. 多组织、多团队、多项目、项目组合、迭代、里程碑、容量、依赖和风险。
2. 需求采集、去重、评审、PRD、UED、架构、可编辑拆解和验收覆盖。
3. 完整开发工作台、原生智能体、本地模型、外部工具、任务派发和检查点。
4. 持久 DAG 的并行、条件、汇合、动态展开、审批、等待、恢复、预算与补偿。
5. 测试计划、自动执行、缺陷、人工验收、版本、部署和运维回流。
6. 文档、表格、演示、会议、语音、渠道与授权电脑/浏览器操作。
7. 桌面独立工作、所有项目离线同步、单机部署、私有团队和分布式 SaaS。
8. 本地文件、SQLite、LanceDB、OceanBase 和对象存储；可恢复备份与迁移。
9. SaaS 套餐、席位、用量、配额、支付宝、微信及企业结算。

## 产品规则

- 任务交付成功需要有效执行、测试和人工审查；运行完成不能直接修改成验收完成。
- 需求或任务内容变化使旧验收依据失效；保留旧记录供查阅。
- 每个图表可回到真实对象；未知数据明确为未知。
- 生成建议先成为可编辑草稿，再由已授权动作采用。
- 操作失败保留输入；回执未知恢复同一操作；版本冲突展示最新内容与差异。
- 默认本机安装不要求用户维护数据库服务。模型、工具、商户和服务器的实际可用性分别探测。

## 成功标准

五条用户旅程全程从产品界面完成，能跨重启恢复；核心数据隔离与错误恢复通过；分布式容量、跨平台安装和外部服务实机验证具有独立证据。
