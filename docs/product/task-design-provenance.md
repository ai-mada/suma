# 任务设计依据与项目 CLI

状态：T-P4-017 实现，最终证据见[阶段验收](../quality/task-design-context-verification.md)。负责人：平台集成；关联需求：项目需求设计、可追溯任务、外部开发工具、FND-I18N-001。

## 用户问题与交付目标

开发者打开任务时，需要直接回答“这项任务采用了哪份需求和设计、当时批准的验收条件是什么、现在还能否按此派发”。此前依据藏在派发工作区，查看需要先选择流程及工具；任务移出设计范围后，最新采用指针也不能直接代替原开发依据。

任务详情增加一个紧凑的只读依据卡片，不增加顶层导航。默认显示当前资格、原需求及设计版本、批准采用时间；正文、任务验收条件、覆盖项和依赖按需展开。查看不要求配置工具或创建运行。正式任务、受保护绑定、不可变采用和批准修订共同证明来源，用户可编辑字段不能伪造批准事实。

## 行为与验收条件

| 场景 | 用户应看到的结果 |
|---|---|
| 未采用设计的任务 | 明确说明尚无正式设计依据，不生成示例内容 |
| 已采用且依据仍有效 | 原需求快照、批准设计、原任务提案及当前可用状态 |
| 新发布、需求变化或任务独立修改 | 明确失配原因；保留可验证的历史正文，不能自动换成新正文 |
| 设计范围移出任务 | 显示已排除，保留该任务最后实际 create/update 的依据；keep 记录不冒充新采用 |
| 原采用或修订损坏、丢失 | 显示来源不可验证，禁止拼装看似完整的批准材料 |
| 当前需求缺失或归档 | 来源不可用；独立可验证的历史依据仍可审阅 |
| 切换账户、组织、项目或任务 | 立即隐藏旧作用域内容；晚到回复不能覆盖新选择 |
| 暂时失败或撤权 | 有明确失败／重试状态；403 后不保留此前调用者的事实 |
| 中文／英文切换 | 产品文字跟随语言，正文、SHA、版本及展开位置保持 |

批准修订全文摘要标注为设计 SHA256。链接仅定位同项目的正式需求与设计面板。当前任务版本随读取返回；卡片是只读视图，能否真正派发仍由正式命令在事务内重新核验。

## CLI 与第三方开发工具

知识入口支持列表、单项、历史、创建、草稿编辑、来源提取与命令；需求设计入口支持读取、保存、预览、修订、采用历史和明确采用。JSON-only 通用 API 支持 PUT，文件参数可有界读取标准输入；大整数和稳定操作标识不应被客户端改写。完整示例见[CLI 合同](../api/cli-project-context.md)。

所有入口使用同一服务端授权，保留原用户／组织视图。API 身份可以编辑允许的草稿，但不能通过 CLI 绕过浏览器人工批准规则。仅已实现的设计预览 POST 被视为只读，未知路由继续保守处理。CLI 支持中英文帮助和受控错误，不翻译用户正文和原始证据。

## 后续范围

此阶段不自动生成模型设计、不宣称完整 UED 编辑器，不新增厂商执行协议。完整 IDE／厂商工具、SSO、MCP／A2A、插件执行、跨数据库与分布式验收仍按[总计划](../delivery/implementation-plan.md)实施；已有文本技能和项目记忆不等于完整插件或外部记忆平台。
