# 快捷接入与工具档案复用

T-TOOL-PROFILE-REUSE-180；suma 1.0.0。依据[冻结合同](../../contracts/tool-profile-reuse.md)，配套[架构与 AI SOP](../architecture/tool-profile-reuse.md)、[交互设计](../design/tool-profile-reuse.md)和[英文说明](../en/tool-profile-reuse.md)。当前限定实现及验证见[阶段报告](../quality/tool-profile-reuse-verification.md)，完整生产验收继续待办。

用户重新打开快捷接入或恢复原节点连接时，可以明确采用已登记的相同工具配置，避免重复登记。名称只用于展示；相同配置由当前租户、项目、准确节点及完整不可变 Profile 决定。

## 用户流程

1. 选择工具与执行节点，取得该节点准确、新鲜的工具库存。
2. 界面自动只读查找当前完整配置对应的全部已有档案。
3. 明确选择已有档案，或在没有可复用档案时明确新建。
4. 暂停档案进入原启用确认；已启用档案打开原详情并显示当前可用性。

匹配查询不会登记或启用工具。正在恢复原写入时，先核对原操作；不能用新的匹配结果替代其未知回执。

## 四个独立事实

| 事实 | 能说明什么 |
| --- | --- |
| 配置匹配 | 原节点及完整 Profile 相同，不代表权限或运行健康 |
| 当前可用性 | 原 `Available`／`Reason` 描述当前授权、库存与节点条件 |
| 明确复用 | 用户采用原档案身份，不复制、不改名、不修改配置 |
| 明确启用 | 沿原版本确认派发授权，不由匹配或连接自动发生 |

暂停档案可复用，但仍须单独启用。已启用档案可能因库存过期、节点离线或授权变化而不可用。撤销档案仅保留历史，不能复活；用户可在没有暂停或已启用匹配时明确新建。

多个可复用匹配必须明确选择，不自动采用第一项。只返回前 200 项、查询失败或响应不完整，都不能证明“没有已有配置”。

## 创建竞争与原操作恢复

普通创建仍产生暂停档案。创建事务在恢复本次原回执之后、插入之前，再检查完整匹配；发现暂停或已启用档案时返回 `409 tool_profile_match_exists`。

界面随后重查匹配，并保留名称草稿。这个冲突不返回其他创建操作的成功回执，也不自动采用其档案。两个窗口同时新建时，沿原组织与项目授权锁防止重复插入。

创建或启用响应未知时，只能使用原 body 和稳定 key 核对。新查询不清除 pending，不更换 key；启用继续使用原 `expected_version` CAS。状态、权限或配置变化后重新读取当前事实，不自动重新启用。

## 命令行与交付范围

`suma --project PROJECT tools matches --file REQUEST_JSON` 查询同一完整匹配集合；`--file -` 从标准输入读取。它没有操作 key 或确认参数，不创建档案、不启用工具。查询超时按只读失败处理。

本片复用原连接、Worker、库存和执行链，不新增执行器或授权票据。匹配成功不证明真实模型执行、代码候选、测试或人工验收；完整 31 项／P0–P7 目标继续保留。
