# Cursor ACP 开发执行

T-CURSOR-ACP-189；suma 1.0.0。依据[合同](../../contracts/cursor-acp-execution.md)，原31项／P0–P7继续。Cursor 从被动发现推进到现有 ACP 开发链；本轮真实厂商模型执行尚未验收。各层证据见[限定验证报告](../quality/cursor-acp-execution-verification.md)。

## 简单接入

1. 在工具快捷接入中选择 Cursor，检测本机安装。编辑器、脚本入口或未核实的 `agent` 文件只显示对应观察；受审包需要通过完整文件闭包和版本检查。
2. 在实际运行机器配置独立密钥环境变量，在页面只填写变量名。速码不接收密钥值，不借用其他工具凭据或原登录目录。
3. 明确读取模型目录，选择返回的准确模型，再确认连接。目录读取可能创建供应方会话或要求认证；未发送开发 Prompt 不等于供应方零内部动作。认证失败时显示原因，不生成可采用目录。
4. 核对新 Runner 库存和准确配置，登记工具后另行明确启用。发现安装、连接成功和派发资格是不同事实。
5. 从任务、讨论计划或专家团队预览开发。固定工具模型、原任务与流程、知识及技能依据后，明确 Start；普通与 Pool 均复用原派发权限。

无桌面桥时使用原 Runner 配置入口，在目标机器配置并报告库存。另一台机器的事实不能由当前电脑的检测代替。

## 开发过程

| 看到的事实 | 准确含义 |
| --- | --- |
| 检测到包／需要配置 | 文件与版本观察，不表示已登录或可执行 |
| 模型配置已确认 | ACP 确认准确模型选项，不证明底层提供方身份或账单 |
| 等待一次权限 | 当前原生请求需要有资格的真人决定，仅允许本次／拒绝本次 |
| 候选已产出 | 代码已按原工作树规则封存，仍需同提交独立测试 |
| 测试通过／已验收 | 原质量事实与另一次明确 Review；工具不能自认证质量 |

Cursor 使用观察型用量，组织或项目要求 enforce 预算时，原开发准入拒绝执行。用量缺失与部分观察如实呈现，不显示虚构硬上限或费用。

本机包、模型、库存或任务依据变化时重新预览。未知写入保留原操作和来源，只恢复原 HTTP／Journal 事实，不自动再发 Prompt 或加载旧会话。运行中的计划、模型、审批和验收不会因工具通知而改变。

## 本轮状态

Windows 厂商包已实际检查版本、帮助和 ACP 初始化；未认证的会话创建返回需要认证，未登录、未提供用户凭据、未发送厂商 Prompt。该探测的 ACP 进程经有界停止收口，不能记为正常退出。
