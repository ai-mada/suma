# 原生工具确认需求

T-CODEX-HUMAN-REQUESTS-174；suma 1.0.0；2026-10-31。负责人：产品、权限领域及工作台。关联[合同](../../contracts/codex-human-requests.md)、[架构与SOP](../architecture/codex-human-requests.md)、[交互](../design/codex-human-requests.md)和[验证](../quality/codex-human-requests-verification.md)。

## 用户问题与目标

团队统一管理本机及远程智能体时，工具可能在开发中途请求执行命令或修改文件。用户应能在原任务上下文中看懂影响、明确作出一次决定，并在断线后核对原决定，不必理解RPC或复制配置。执行节点应继续原回合，而非重新创建任务。

管理员维护工具、模型和执行节点范围；当前有权用户作出一次决定；机器只能上报原执行观察。不同角色不能相互冒充。可接受动作由当前权限、准确原生请求及范围完整性共同决定。

## 本片交付

| 需求 | 验收条件 |
| --- | --- |
| 统一入口 | ACP／Codex当前请求在原节点同一确认区可查看，不要求新增管理页 |
| 准确一次决定 | 原请求正文、协议、当前版本及Actor固定；重复同body/key只返回原回执 |
| 明确范围 | 命令／文件影响默认可读；未知、不完整或永久授权范围无允许按钮 |
| 恢复 | 响应丢失仍可核对原提交；不能换key重复批准或重发原生turn |
| 异步 | 等待人类时stdout、取消和其它请求继续处理，不占协议互斥锁等待 |
| 可追溯进度 | 人决定、Runner观察、实际写出、供应方清理与item结果分别可见 |
| 当前权限 | 历史只读、撤权清理；普通／Pool沿原机器、租约及fence授权 |
| 易用与多语言 | 中文／英文完整，390px单栏、44px操作、键盘焦点及后台刷新不打断操作 |

工具确认只处理本次原生操作。代码基线、独立测试、业务验收、生产操作、硬预算及OS隔离仍由原领域和各自证据裁定。其它供应方审批类型、会话级策略、真实模型及完整团队平台继续按原范围交付，不将本片当作参考项目全部能力完成。
