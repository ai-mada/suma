# 任务审核责任请求

T-REVIEW-142，产品1.0.0的限定协作切片。本文说明已冻结的业务范围；实际检查和最终界面观察由阶段质量报告分别记录，不能据此宣布完整平台验收完成。

使用者在原任务详情的交付门禁处，选择一名真实人员，请其审核准确的一次交付。请求固定任务及运行版本、任务内容依据、发起人与审核人当时的姓名和说明。它补齐“谁负责看这次交付”的事实；正式接受或退回仍由原任务Review执行。

只有规范活跃人员且当前为组织owner/admin或项目admin/reviewer，才出现在审核人目录。创建请求需要项目业务写权。允许请求自己审核；指定责任人不会授予权限，也不会阻止其他合法审核者通过原Review决定。负责人分配、交接接收、Agent完成、DAG审批、测试成功和正式人工验收继续分别展示。

每个任务最多一个pending请求。新建要求当前准确运行已成功，这只证明交付定位，不证明完整质量门禁通过。任务或运行绑定变化时显示依据已变，审核人撤权或资源失效时显示当前不可审核；读取保留历史，不自动取消或改写。发起人或当前组织／项目管理员可在仍有业务写权时明确取消，再建立新请求。

指定审核人的私有Inbox收到`task_review_requested`。通知只在原请求、固定接收人与反向通知关系完整时提供准确入口；打开、已读、归档与正式决定各自独立。取消或完成请求保留原私人事件。正式Review成功记录时，在同一事务关闭准确匹配的pending请求，展示实际决定者；拒绝继续走原问题回流。

范围变化清除旧受保护内容；未知写入保留原正文、身份、版本、路径和操作标识。恢复时重发原请求，不能凭当前新版本或新审核人替换未确认的旧请求。

原计划P3／P5与Multica矩阵M27继续保留通知偏好、订阅、通道及可靠outbox等后续范围。本切片不新增执行授权或第二套验收流程。Multica当前源码受其附加限制许可证约束，此处仅参考人工交回与准确通知的行为语义，没有复制源码或资产、没有增加依赖。
