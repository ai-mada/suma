# OpenCode SDK 快捷配置准备

状态：本阶段限定验证；版本1.0.0；需求T-OPENCODE-PREPARATION-207；负责人：主集成／Runner／Web／共享指南。合同见[唯一准备合同](../../contracts/opencode-tool-preparation.md)。

## 用户问题

现有OpenCode支持正式SDK运行与桌面托管连接，但远程管理员需要填写独立bundle路径、手工复制完整commands，并另行对接原Runner指南。容易出现入口与manifest不一致、同一节点的工具选择丢失及检查命令引用悬空。

本需求把原执行能力接回一致的配置准备体验：常用设置突出固定模型、供应方、服务地址和凭据变量名称；机器文件设置按需填写。由平台生成私有stdin命令，目标Runner静态核对原审核运行包后创建新文件，之后沿原准确库存、登记和启用链路继续。管理员保有明确执行和启用权。

## 可观察验收

1. 原Quick选择OpenCode SDK后准确进入本配置页，保持当前项目和执行节点；中文／英文均无未翻译键，窄屏可操作。
2. 未补齐机器信息或不合法地址／变量时，准备与继续动作明确不可用；不靠占位符假定实际路径，也不回显密钥值。
3. 单一命令明确创建一个新commands文件；不安装、不覆盖已有文件、不调用模型或启动Runner。固定bundle由审核manifest推导，检查集合为空，不携带不存在的检查ID。
4. 文件／资产变化、非法输入或取消时拒绝，原用户文件保持不变；输出仅说明文件已准备，不显示已连接／已验证模型／已启用。
5. 明确采用后准确传递shell、commands路径及OpenCode SDK协议到原远程指南，保持其原来源与nonce防护；检查／限时等待准确库存后可回原Quick，登记和启用仍各自明确。
6. Go、TypeScript和真实CLI使用同一九字段输入，定向验证不重复原供应方与模型执行。真实账号、多机和正式开发交付另行记录。

此项推进完整平台的工具自动化与团队分布式接入；Pool免令牌配对、WorkBuddy可信代码及独立质量、其他部署与完整平台仍保留原待办。
