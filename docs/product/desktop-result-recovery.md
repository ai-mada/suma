# 原结果回执核对与到期恢复

T-DESKTOP-RESULT-RECOVERY-179；suma 1.0.0。依据[冻结合同](../../contracts/desktop-result-recovery.md)，参见[架构](../architecture/desktop-result-recovery.md)、[交互设计](../design/desktop-result-recovery.md)和[英文说明](../en/desktop-result-recovery.md)。平台已完成定向 SQLite／HTTP 验证；桌面、私有 CLI 和界面整链的交付状态以最终集成证据为准。

本功能处理一种明确情况：Runner 的原结果已被服务端提交，本机却未收到确认回执（ACK），随后机器凭据到期。用户可核对原提交事实，并补齐本地 ACK。旧凭据仍然失效，核对过程不会重新执行任务、调用模型或再次提交结果。

## 操作流程

1. 使用当前有权限的浏览器管理员会话，在原项目、工作区和本机连接中明确选择恢复。
2. 确认原 Runner 进程已经关闭。桌面保存原恢复计划和操作标识，再核对服务端已有回执。
3. 对准确匹配的结果，一次原子保存本地 ACK；没有回执或正文、来源不符的结果保持原样。
4. 查看仍待核对项和只读检查结果。只有原续期门禁满足后，才可独立选择续期；连接也须另行明确操作。

恢复不会自动登记、启用、续期或连接。续期结果未知时，须先核对原续期，不能另建恢复操作绕过可能已更换的凭据。

## 结果与下一步

| 核对事实 | 含义与操作 |
| --- | --- |
| 匹配 `matched` | 原结果确已提交，可补齐该项本地 ACK；不表示任务成功或副作用已排空 |
| 缺失 `missing` | 服务端没有准确的原回执；保留本地结果，不能据此重发或重执行 |
| 不符 `mismatch` | 原操作回执与结果摘要不一致；保持阻塞并核查原结果 |
| 来源变化 `source_changed` | 原 Worker、凭据摘要、登记、工作区或历史执行来源不符；回到原连接核对 |
| 部分完成 | 仅准确匹配项已确认，其余原件仍在；按具体原因继续处理 |
| 凭证到期／授权变化 | 在当前有效授权下重新核对原计划；不能延长旧机器凭据权限 |

界面只显示数量、阶段和原因。原结果正文、恢复计划、路径、签名凭证和密钥保留在私有主进程边界。

主日志之外的 sidecar（旁路日志）不会被清除；云操作、工作区写入、发布、权限等未结事实继续阻止续期。原结果为 `unknown` 时，即使 ACK 已补齐，结果仍是 `unknown`。本片不恢复尚未提交的副作用，也不代表原 31 项／P0–P7 或完整平台目标已经完成。
