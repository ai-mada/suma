# 自动检查与工具登记

T-TOOL-ONBOARDING-176；速码 1.0.0。状态：本阶段源码、定向检查、真实 CLI 观察与合成组件视觉已验证。负责人：工具接入领域。关联[合同](../../contracts/tool-onboarding-scan.md)、[架构与 AI SOP](../architecture/tool-onboarding.md)、[交互](../design/tool-onboarding.md)、[验证](../quality/tool-onboarding-verification.md)。

工具接入的第一步应回答三个问题：这台电脑有哪些接入项、还缺什么、下一步做什么。用户无需逐一选择工具来重复检查，也无需理解探测 JSON。现有原生模型配置、托管节点、暂停登记、明确启用和任务派发仍使用同一条链路。

| 场景 | 用户操作和结果 |
| --- | --- |
| 桌面首次打开当前项目 | 自动进行一次被动检查，显示安装事实和协议；近期同范围观察可复用 |
| 安装工具后返回 | 点击重新检查，绕过完成缓存；正在运行的同范围检查合并 |
| 找到所需工具 | 选择接入项进入现有配置；不自动连接、不覆盖其他草稿 |
| 只有浏览器 | 展示桌面或执行节点接入指引；不把服务端电脑当作用户电脑 |
| 采用执行节点探测清单 | 显示当前来源及有效性，保留修改过的名称；过期引导重新读取 |
| 手工填写配置 | 继续允许暂停登记，明确区分未验证配置与当前安装观察 |
| 上次登记结果未知 | 恢复原操作，保留原请求、操作 ID 和当前权限核对 |

两个 Codex 接入项分别表示 JSONL 和原生 app-server 协议，不能作为两种已安装产品计数。Cursor 的编辑器／Agent 候选、Qoder 的安装／配置、其他 CLI 的运行环境缺失均按实际理由表达；不能把已安装改称已健康或可派发。

本阶段不引入新的数据库、执行服务或依赖，不自动安装软件、获取登录、创建开发目标或授予执行权限。跨平台、其他 CLI／Harness 的真实接入及完整研发闭环继续按原 31 项需求、P0–P7 计划交付。
