# 原生智能体编码 PRD

状态：T-P4-020 限定本地纵向已验证，完整平台继续实施。Owner：原生运行时／执行节点／工作台，集成由Root负责。关联P2/P4/P5、FND-I18N-001。接口基线：[实现合同](../../contracts/native-coding.md)。

## 用户工作与边界

项目负责人把已明确的需求和验收条目分配为开发任务，选择管理员已经安装并声明的原生编码档案。智能体在独立attempt工作树中修改真实文件、运行固定开发检查并形成候选提交。另一个执行者测试同一候选，再由有权限人员明确评审。使用者应能区分“能力声明”“正在编码”“开发检查”“候选封存”“正式独立测试”和“人工验收”。

平台原生Agent原先仅有四项项目读取工具，不能以回答中的代码块表示文件已写入。本阶段补齐attempt-local文件、开发检查和宿主封存；不授予主工作区、任意shell、生产部署、目标分支合并或自主验收权限。

## 角色及完整旅程

| 角色 | 操作与责任 |
| --- | --- |
| 执行节点管理员 | 安装固定SDK bundle，配置可信仓库、基准、允许检查命令和隔离目录，明确允许执行；发布实际库存 |
| 项目开发负责人 | 选择固定profile与任务依据、检查预算和执行计划，派发原生编码任务 |
| 原生智能体 | 从授权目录读取上下文，在当前工作树列举／读取／创建／替换／精确编辑／删除文件，调用固定检查 |
| 测试执行者 | 取得封存后的不可变SHA，在独立工作树执行管理员指定的正式测试 |
| 评审人员 | 核对需求／设计／任务版本、候选来源和独立测试，明确批准或退回 |

1. 管理员生成单文件原生运行时及manifest，配置非只读Suma profile与固定check IDs；版本／帮助探测只确认安装及协议。
2. 负责人在原任务派发流程选择该profile。源需求、任务、知识、工具摘要、仓库基准和预算固定，运行后按原版本推进。
3. Runner为完整attempt/fence创建独立detached工作树；创建只在本机存活、带短期秘密的工具服务，原生子进程通过官方MCP客户端访问。
4. 智能体读取文件SHA，再以CAS编辑。大文件可使用唯一匹配的精确替换，避免重复全文和上下文浪费；需要新文件时明确要求原来不存在。路径或版本错误可重读纠正，未知效果立即阻断。
5. 固定检查可失败后继续修复；修改使旧检查过期。配置的检查必须在最终源码上已知成功，才允许宿主封存。
6. 子进程唯一成功终态、退出及进程树已知静止之后，宿主关闭工具服务并形成真实Git候选；不能由模型自行写Git元数据或冒用人类作者。
7. 复用现有bundle／ACK／候选导入和独立test节点。工作台展示真实摘要、原始依据及检查输出，评审仍使用原正式门禁。

## 验收与诚实状态

| 项目 | 必须成立的事实 |
| --- | --- |
| 受控编码 | 原件在独立Source，文件操作有原SHA／不存在条件、稳定操作ID和持久回执；不会写控制面主目录 |
| 目录与配置 | 当前profile固定Node、bundle、manifest、Git及引用检查闭包；未知工具或工作流自带endpoint／argv不能扩大权限 |
| 恢复 | 同ID同输入恢复原结果；异输入冲突；第三种内容、未知进程或未知seal保留原操作并要求核对 |
| 开发检查 | 固定检查命令和源码快照绑定，原始输出按需查看；不等于正式独立测试 |
| 候选提交 | 原HEAD CAS、操作receipt ref、真实tree与干净index；无净变更明确no_change，不伪造提交 |
| 正式验收 | 原生证据必须闭合、工具策略匹配、seal与候选SHA一致，且仍需本次运行独立测试同一SHA |
| 产品体验 | 无新密集导航；沿用工作树证据区域，摘要清楚、详情折叠、原文不翻译，中英及键盘保持状态 |

源码和定向检查不替代实际部署。当前证据统一进入[阶段验证](../quality/native-coding-verification.md)。本地协议fixture只代表模型边界受控；真实厂商模型、容器／低权限沙箱、跨平台安装、外部会话恢复、目标分支合并和完整P0–P7仍单独实施。
