# 从已准备配置连接Pool机器

版本1.0.0；阶段T-POOL-CONNECTION-212限定实现与验证通过。负责人：控制面／Runtime／工作台。关联：[唯一合同](../../contracts/pool-connection.md)、[架构与AI SOP](../architecture/pool-connection.md)、[交互](../design/pool-connection.md)、[验证](../quality/pool-connection-verification.md)。完整31项／P0–P7继续。

## 目标与用户步骤

将原Pool机器配对、多项目本机配置准备、实际身份核对、持续维护及项目工具入口贯通。操作者能看到准确机器和项目的当前报告依据，再决定使用哪个工具；不用把“文件已生成”当作“机器已连接”。

1. 在原Pool节点下完成配对和本机配置准备，保留公开身份文件、原配置文件及状态目录。
2. 展开“连接这台机器”，核对控制地址、身份文件和派生的`.runner-state`目录。复制单次检查命令，在目标机器明确执行；检查只认证当前身份及配置范围。
3. 选择启动用途。默认维护模式须明确允许固定目录工具检测；任务模式明确允许执行任务，安装检测另行选择。复制前台启动命令后由操作者执行，网页不自动启动机器进程。
4. 选择准确已授权项目并刷新报告，查看登记、凭据、历史联系及库存来源，读取结果沿当前授权和路由核对；无报告、过期、来源不符和受限分别说明。
5. 仅在当前项目读取权限允许时进入该项目的原工具管理，准确定位Pool／Runner／Worker，继续原Quick、Guide及Doctor流程。进入页面不会自动检测、登记、启用或派发。

## 用户可以依赖的事实

| 事实 | 含义与边界 |
|---|---|
| 配置已准备 | 原允许命令及目录引用通过静态检查，并形成新配置文件；不调用模型或启动Worker |
| 单次检查通过 | 原系统凭据与准确Pool／Runner相符，服务器返回当前身份、容量及本地配置范围的授权交集；不证明在线或工具资格 |
| 历史联系时间 | 原库存上报留下的历史记录；凭据轮换后仍可保留，不能代替当前凭据证明 |
| 当前库存来源相符 | 截至服务器检查时间，当前路由、Grant、机器凭据及维护身份一致，新鲜维护声明与库存属于同一观察时间 |
| 库存条目数 | 只在当前来源相符时给出；0表示真实空清单。条目可能不可执行，数量不等于可派发工具数 |
| 正式工具资格 | 仍由原档案、当前启用、模型预算、任务权限和Doctor等领域门禁判断 |

Pool拥有者只获得已共享的Grant元数据，不因此读取其他租户项目的库存。界面按服务器检查时间显示事实并在期限结束后撤销当前标记，不能长期保持“当前有效”。

## 受控交付范围

一次真实HTTP／SQLite旅程完成原系统凭据配对和配置准备，执行编译CLI单次检查1次；原库PoolWorker按明确维护／任务用途启动2次并排空2次，发送真实库存。准确项目入口打开原Quick，没有自动登记或启用。

随后通过原Engine及Pool路由完成1个DAG运行、1个节点、1次attempt的自有只读Node检查，结果经原HTTP回写成功。它证明限定的允许命令执行链，**不是业务任务完成、代码候选、独立质量验收或人工验收**。复制的前台CLI启动命令未执行；持续Worker使用相同配置与身份的原库入口。真实厂商、模型、多机器、其他数据库及生产验收仍按完整计划推进。
