# 已验收任务候选交给后续开发

速码1.0.0 · T-ACCEPTED-TASK-BASELINE-222。负责人：主集成；[统一合同](../../contracts/accepted-task-baseline.md)／[架构](../architecture/accepted-task-baseline.md)／[交互](../design/accepted-task-baseline.md)／[限定证据](../quality/accepted-task-baseline-verification.md)。完整31项／P0–P7继续。

## 解决的问题

普通智能体任务已经产出代码、由另一Worker测试同一提交并正式验收，但原基线仅允许多分支合成或终端候选。现在可直接采用该任务的准确产出步骤，后续任务仍沿原派发、受保护bundle传输及独立工作树开发，不再人为制造合成计划或搬运Git对象。

## 用户步骤

1. 打开未开始任务的开发基线，选择“已验收任务候选”，明确选择来源任务和产出步骤。同一任务可能有多个producer，不自动选择第一条。
2. 查看准确任务版本、产出步骤、完整提交SHA及原运行尝试；填写采用原因并明确确认。
3. 原服务端重新校验当前权限、目标／绑定双版本、正式Review、来源尝试和另一Worker的同SHA测试，保存当前任务基线。该操作不会启动任务或继承旧验收。
4. 在原派发中审阅新计划、模型／预算、开发和独立测试工具，再明确开始；新Worker导入准确来源bundle，基于已验收提交继续开发，新候选重新测试和验收。

原合成结果仍可明确选择；终端候选保持自己的正式入口。只显示原接口最近200条来源，空列表只表示已加载范围；来源过期、无权限、变化、未确认读取和真正无基线分别表达。

## 自动化和异常处理

浏览器只传来源任务ID、预期版本和步骤ID，不能用提交字符串、ReviewID或“测试成功”字段自行授权。版本、候选、资格或账号变化取消旧确认；刷新不自动重试写入。结果未知时核对原路径、正文和操作标识，即使来源已经退回或不再列出也保留原操作。绑定之后来源失效会阻止新的派发、传输或验收，已经发生的完成／停止事实保持。

AI SOP：读取当前目标与原待核对操作→选择准确已验收producer→说明B/M/N提交关系与成本→请求具体采用确认→沿原计划和代码broker执行→独立测试新提交→人工Review。禁止把绑定或旧测试当新开发验收，不自动启用工具、替换模型或向生产推送。
