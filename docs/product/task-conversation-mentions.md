# 任务讨论精准提及需求

状态：T-MENTIONS-140，实施中；负责人：协作领域／主集成。关联需求：人员协作、项目任务、Multica M09／M24／M27。产品初始版本1.0.0。

## 用户价值与范围

讨论者可以把一条确定的任务消息交给指定人员关注；接收者能从自己的收件箱回到原讨论。交付责任仍由任务分配与交接管理，代码开发仍经过正式调度、独立测试和验收。提及不产生新的执行权、业务状态或已读事实。

发送路径为：打开任务工作台→展开讨论→输入正文→选择当前可见的项目人员→检查接收人→发送。接收路径为：开发→收件箱→查看“在任务讨论中提及你”→打开讨论→准确原消息→决定回复或另外启动正式开发流程。

| 场景 | 用户可观察的验收结果 |
|---|---|
| 明确提及 | 可搜索人员，选中后以可移除标签显示，最多20人；正文的@文字保持原文，不自动广播 |
| 当前可用人员 | 只出现活跃且具备当前项目读取权的规范人员账号；不会把工具、智能体或未绑定账号当成人 |
| 可靠发送 | 消息与全部接收通知一起成功；单个接收人失效则全部失败，保留草稿供调整 |
| 结果未知 | 保留原正文、接收人、版本和操作标识，只核对原发送，不能悄悄发送第二条 |
| 原消息定位 | 通知能定位超过最近20条的原消息，无需逐页加载全部历史；可刷新并保留地址 |
| 历史稳定 | 发帖时的接收名称作为会话事实保留，后续改名不改变已经用于智能体规划的消息来源 |
| 权限变化 | 当前读取或发送撤权后清理受保护内容；原个人事件不扩大权限，不提供失效来源链接 |
| 个人收件状态 | 打开消息与已读分开；归档不删除消息，也不表示业务验收完成 |
| 简洁与可访问 | 选择器按需展开；列表、键盘和窄屏均可操作；中英文使用相同能力与状态 |

## 数据与配置边界

最多20名接收人是当前固定业务约束，目录读取默认20、最多50条。没有新增隐藏的全员广播或自动智能体触发开关。草稿按当前用户、组织、项目和任务隔离，只持久化本人的正文及选中资源ID；目录名称按当前权限重新读取。讨论历史中的固定接收快照与当前目录资料有明确区别。

源消息、当前读取权限、当前目录、通知私人状态、任务交付和模型执行分别建模。对外合同见[精准提及合同](../../contracts/task-conversation-mentions.md)，实现位置在`internal/platform/task_conversation_mentions*`及Web讨论／收件箱模块，验收证据在阶段交付时登记。

完整后续目标仍包括团队／全员策略、审核请求、偏好降噪、跨项目收件、邮件／IM可靠投递及智能预警。当前功能不得表述为上述能力全部完成。
