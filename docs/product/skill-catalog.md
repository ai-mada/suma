# 组织共享技能：需求与交互规范

版本：1.0.0；阶段：T-P4-025；状态：实现与限定验收中；负责人：平台集成。

## 用户目标

项目中验证过的开发方法，可以经审核沉淀为组织共用技能，再由其他项目选择合适的固定版本。使用者能知道技能适用什么领域、什么场景、谁审核、从何处来，以及采用后是否已在本项目发布。

此能力承接完整需求第 10／11／12／16／17 项。统一目录的组织共享权限与项目采用权限分别审核；技能文字不授予文件、终端、网络、模型或部署权限。CLI、MCP 和智能体继续使用原有受控执行入口。

## 角色与操作

| 操作者 | 当前权限与行为 |
|---|---|
| 组织成员 | 在有访问权的项目中搜索目录，阅读组织批准正文、元数据、历史 |
| 组织管理员 | 同时具有源项目批准权限时，明确确认组织共享；修改领域／场景／标签，选择当前源发布；退役 |
| 目标项目批准者 | 明确选择目录版本和摘要，采用为本项目草稿，再单独审核发布 |
| 项目 API／MCP 客户端 | 按凭据的当前项目范围搜索及读取，不能共享、采用或批准 |
| 原生 Agent | 不扩大既有四项工具权限；读取目标项目已发布、明确引用的知识上下文 |

## 用户旅程与验收条件

1. 在“资料 → 项目知识”编辑或从真实来源提取 skill，审核后发布。草稿编辑与发布原件分开。
2. 在“资料 → 共享技能”选择本项目的有效已发布 skill，填写领域、应用场景、标签与审核原因，确认将正文共享给当前组织。
3. 在另一项目按关键词、领域、场景或状态筛选，选择技能。详情先显示正文、适用范围和当前资格；来源 ID／SHA、历史按需展开。
4. 目标批准者确认采用为项目草稿。成功后明确提供草稿入口；不显示已启用、已安装或执行成功。
5. 目标项目审核草稿并发布；派发任务时选择其发布修订。任务上下文保留当前固定正文与原目录、源修订、首次采用的不可变关系。

刷新恢复项目、选择项及筛选。切换账号、组织或项目立即隔离读取与恢复请求，取消旧请求。写入结果未知时保留原 key／body，重试恢复同一操作；禁止换 key 再建一次。版本冲突保留编辑内容，先读取当前版本，重新核对后明确确认。新版源发布不能沿用对旧正文的共享确认。

## 页面与状态

沿用资料模块的双栏列表／详情。操作表单仅在请求时展开，不增加顶层导航或复杂配置面板。窄屏转为列表／详情单栏；键盘可操作筛选、列表、披露和表单，焦点沿用现有对话框规范。

| 状态 | 呈现与允许操作 |
|---|---|
| 无目录 | 清楚说明需要源项目先发布技能；有权限时提供共享入口 |
| 当前有效 | 展示当前可采用；目标批准者可采用为草稿 |
| 源已变化／隐藏 | 旧批准正文与历史可查；新采用禁用并说明原因 |
| 目录已退役 | 历史保留，新采用禁用；不删除其他项目已采用的副本 |
| 新草稿 | 继续使用旧发布依据；不把草稿内容当作共享正文 |
| 正在加载／失败 | 保留同一路径的已知数据；明确重试入口，不用占位数字表示成功 |
| 无权限／撤权 | 服务端判定，只读或拒绝；旧列表和回执不能代替当前权限 |

中文、英文使用成对领域目录。领域、场景、标签、正文、作者 ID 和 SHA 为用户／审计数据，切换语言保持原值。使用简洁文字区分“组织共享”“项目草稿”“项目发布”和“运行使用”。

## 限定交付与后续

当前交付审核元数据、版本化共享、关键词检索、独立项目采用、CLI／MCP 消费及固定上下文。向量检索、模型萃取质量评估、团队／专家组策略、签名执行包和自动升级建议继续实施；现有 extractive 只表示有来源的文本提取。

接口与实际证据见[合同](../../contracts/skill-catalog.md)、[架构与 AI SOP](../architecture/skill-catalog.md)、[阶段验证](../quality/skill-catalog-verification.md)。完整平台目标保持。
