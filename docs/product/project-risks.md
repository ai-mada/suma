# 项目风险登记与处置 PRD

状态：T-PROJECT-121实施中，1.0.0当前设计。负责人：项目治理／工作台／质量集成。关联需求7、10、12、13；P3／P5。完整平台范围继续见[实施计划](../delivery/implementation-plan.md)。

## 目标与业务事实

项目负责人需要知道风险是什么、由谁处置、何时复查、关联哪些交付以及为什么可以关闭。排期模型的建议只提供线索，建议被确认或标记已处理，不代表正式风险已缓解。

本领域提供人工登记或明确采用既有模型建议、可编辑评估、责任分配、处置计划、任务／需求／问题关联、提交复核、人员决策和保留历史的重开。开发仍沿现有任务派发、固定候选、独立测试及当前正式Review，不新增执行器或绕过质量门禁。

## 用户旅程

1. 从项目概览的真实风险摘要或项目计划进入风险列表；空态可直接登记，已有模型建议可预填为待确认登记内容。
2. 填写描述、负责人、复查日期、处置策略和计划，选择真实的同项目任务／需求／问题。概率和影响可以未知；均已评估时才显示服务端计算的相对评分。
3. 负责人启动处置，通过关联任务打开现有任务详情并安排工具执行。风险不会因为模型声称已解决或运行变绿自动关闭。
4. 完成处置后提交明确的复核依据。代码缓解需要关联任务的当前正式验收及其真实测试证据；接受、避免、转移或不适用是人员风险决定，界面分别表达，不称为代码修复通过。
5. 有审核权限的人核对固定评估、关联依据、剩余风险和理由，批准关闭或退回。依据已变化时保留原复核，要求重新提交。
6. 风险重现可重新打开为新周期；历史关闭人、时间、处置依据及结论仍可查看。

## 评估与显示

概率和影响采用1–5的顺序等级；乘积用于本项目风险矩阵和相对排序，不表示统计概率、货币损失或预测模型。任一项未知时评分未知，不显示零。原始模型文本、用户说明及证据保持原文。

默认显示标题、状态、责任人、复查日期和简短评估。详细依据、来源、关联版本和历史折叠展示。概览统计来自当前授权下的完整服务端统计；当前页数量单独显示，不把前三条或单页合计当作全项目数量。

## 验收要求

| 场景 | 可观察结果 |
| --- | --- |
| 采用建议 | 保留真实建议、分析与运行来源；同一来源只建立一条正式关系，无新模型调用 |
| 并发编辑 | 原版本冲突，保留本地草稿；恢复原请求不会创建第二条风险或重复决策 |
| 负责人或关联无效 | 服务端拒绝跨项目、撤权或不适用资源，不由界面过滤代替权限 |
| 未知评估 | 缺少概率／影响明确显示未知；不补零或编造风险等级 |
| 代码缓解 | 当前正式任务Review及独立测试证据满足原门禁后才可提交适用的缓解复核 |
| 依据变化 | 旧复核不能批准新任务版本、被撤销的验收或新风险评估 |
| 人员决策 | 有权人员明确关闭／退回，接受风险和代码修复结论分别展示 |
| 重开 | 新周期保留旧关闭快照，不自动继承旧关闭资格 |
| 简洁双语界面 | 中英文、加载／空态／失败／无权限／冲突、窄屏和键盘可操作 |

本阶段不宣称完整跨项目portfolio、量化预测、外部监控、自动风险批准或生产处置验收完成。它们继续保留在原平台待办。
