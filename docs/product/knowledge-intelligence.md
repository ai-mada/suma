# 模型辅助知识、规范与技能提炼

阶段：T-P4-026；产品版本：1.0.0；状态：本地实现与限定验证，实际界面及单次模型协议联调由阶段质量报告记录。
接口依据：[领域合同](../../contracts/knowledge-intelligence.md)。关联：[项目知识](project-knowledge.md)、[组织技能目录](skill-catalog.md)、[架构与运维](../architecture/knowledge-intelligence.md)。

## 问题与目标

团队已在资料、需求、任务和问题中积累经验，但把它整理成可复用说明仍需要人工归纳。
本功能让项目写入者选择明确来源，交给固定模型形成提案，核对和编辑后保存为项目草稿。
用户能够区分原资料、模型原件、人工修订、正式发布及组织共享，并追溯各自依据。

产物类型沿用 memory、spec、skill，分别用于项目记忆、规范和技能说明。
skill 仍是文本工作说明，不安装插件，不执行代码，也不增加模型或执行节点的权限。
现有“原文提取”继续提供确定性摘录；“智能提炼”明确表示发生模型调用和用量。

## 角色与权限

| 角色／凭据 | 可执行的操作 |
|---|---|
| 当前浏览器项目写入者 | 创建提炼、修订提案、明确采用为草稿、关闭已形成或失败的提案 |
| 当前项目读取者 | 查看本项目分析、固定来源、原件与提案 |
| 固定项目 API 凭据 | 在其当前项目读取范围内查询分析，不能发起模型调用或采用 |
| 当前浏览器项目批准者 | 按原有知识流程审核发布草稿 |
| 当前组织管理员及源项目批准者 | 按组织目录流程另行审核共享已发布 skill |
| 当前授权执行节点 | 领取固定任务，报告原执行结果与真实用量 |

权限在服务端重新核验，旧页面、旧回执或凭据外观不能代替当前授权。
创建和采用的确认分别记录，不把“同意调用模型”解释为“批准发布”。

## 用户旅程

1. 在项目知识页展开“智能提炼”，选择 memory、spec 或 skill，填写本次整理目标。
2. 从当前项目真实资料、需求、任务或问题中选择 1–8 个来源；可指定原文连续片段。
3. 核对来源版本和内容，选择可用的专用提炼工具、输出预算，并确认将内容交给该固定模型。
4. 提交后查看实际运行链接与事件，等待提案；重试丢失的响应时恢复原操作，不再调用一次模型。
5. 对照模型原件、固定来源和当前提案，修改标题、说明、正文、使用的来源索引及理由。
6. 明确采用，打开生成的项目草稿；再由有批准权限的人审核发布。组织共享需要另一次操作。

模型只使用已封存的输入，不在执行中搜索其他项目或调用工作区工具。
单次提炼最多一次模型请求；增加输出预算不增加工具权限或自动执行步骤。

## 页面与反馈

入口默认折叠，表单集中呈现目标、类型、来源、工具、预算与确认，不增加独立的复杂配置流程。
没有专用工具时给出工具设置入口；已配置工具不等于节点在线、凭据有效或额度充足。
来源、模型原件、摘要及采用溯源按需展开，提案编辑区保留用户尚未保存的内容。

| 分析状态 | 用户理解与下一步 |
|---|---|
| running | 原运行正在排队或执行，通过运行链接查看实际进度 |
| ready | 模型返回有效提案；依据仍有效时可以明确采用 |
| failed | 运行、结构校验或原件大小等条件失败，保留可追溯事实 |
| reconciling | 结果未知，需要核对原运行，不提供盲目重新调用入口 |
| adopted | 已创建独立项目草稿，提供草稿入口，尚未自动发布 |
| dismissed | 已明确关闭提案，历史及原件仍保留 |

`ready` 与“当前可采用”是两个事实：来源变化后提案仍可查看，但 `basis_current=false`，采用操作不可用。
版本冲突时保留编辑内容，提示重新核对最新版本；未知写入保留原请求和操作身份。

## 输入与输出限制

- 目标 1–4000 UTF-8 字节；来源类型仅 documents、requirements、tasks、issues。
- 单个引用片段最多 16000 字节；空片段选择当前完整可见正文，超限要求缩小选择。
- 包含目标、元数据和全部来源的完整输入最多 32000 字节，服务端拒绝超限，不静默截断。
- `max_steps` 省略时为 1，且只支持 1；输出 token 预算省略时为 4096，合法范围 1–8192。
- 提案标题 1–200 字节、说明最多 1000、正文 1–16000、理由 1–8000。
- `source_indices` 为固定来源数组中的 0-based、唯一非空子集；模型不能自造来源、版本或摘要。
- 模型原件公开上限 64 KiB；超限失败并保留完整摘要及执行事实，不将截断文本冒充完整原件。

输出是提案，不是事实正确性、可执行性或发布资格的自动证明。
人工修订保留模型原件；采用时重新核验完整固定来源，而不只核验模型选择的子集。

## 费用与中英体验

执行沿用组织／项目月度额度和固定模型费率版本；领取预留与最终真实用量结算进入原账本。
配置费率产生的是费用估算，预留是准入控制，不是厂商硬消费上限或厂商账单。
缺失、部分上报和未知用量不能显示为已知零；失败或来源过时也不抹掉已经发生的使用量。

宿主状态、错误、按钮和说明提供中文／英文；用户目标、来源、模型原件及人工理由保持原值。
切换语言或刷新不得重写提案、自动采用、自动调用模型或丢失仍待核对的操作身份。

## 验收边界

必要验收包括：真实来源与单次运行、严格提案解析、原件与人工修订分离、草稿采用及溯源。
同时核对撤权、固定项目 API、来源漂移、结果重放、未知恢复、事务回滚及原有正式发布门禁。
共享资源池切面使用独立项目所属组织核验费用归属，重复完成不能重复记账或生成草稿。
本地协议夹具只替代模型边界，不代表厂商模型效果、账号健康、生产批准或厂商计费验收。
真实单次本地协议运行与代表性界面结果以阶段质量报告为准，文档不提前宣告通过。
自动模型萃取评估、长期自主治理、向量检索、技能安装、外部平台及完整 P0–P7 继续实施。

阶段证据：[限定本地验证](../quality/knowledge-intelligence-verification.md)。源码完成、本地协议及代表性界面验证分别记录；厂商、生产及完整平台继续实施。
