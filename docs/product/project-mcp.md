# 项目 MCP 接入与受控应用工具 PRD

状态：T-P4-019 限定本地已验证；实际SDK客户端和代表性浏览器证据见阶段报告。更新：2026-10-26。Owner：平台主集成；协作：应用工具、官方 SDK、工作台与国际化。关联需求：外部 CLI／IDE 协作、统一当前权限、可追溯草稿、FND-I18N-001。

## 问题与目标

开发者需要在惯用客户端读取项目真实上下文、形成可追溯草稿，同时知道自己接入哪个项目、哪些工具可用、哪类凭证适用。工具发现、配置成功、真实调用和业务验收必须分别表达，不能把复制配置或签发令牌显示成“已连接”。

本阶段提供官方 SDK 的入站 MCP，以及既有项目令牌页中的紧凑接入说明。原生 Agent 和 MCP 复用同一应用工具实现、当前权限与正式领域回执；不建立第二份业务状态，不增加顶层菜单。

## 角色与用户旅程

| 角色 | 需要完成的工作 | 边界 |
|---|---|---|
| 项目开发者／Agent 使用者 | 查看绑定项目、可信端点与目录，读取项目上下文 | Agent 凭证只提供原四项读取；目录声明不等于当前凭证已验证 |
| 当前有权的项目 API 使用者 | 读取正式资料，创建需求／任务草稿或保存设计草稿 | 服务端逐次核验写权限、原账户／组织、版本和幂等身份 |
| 组织所有者／管理员与部署管理员 | 明确签发独立凭证，维护客户端可达的公开地址 | 签发仍受现有浏览器门禁；无公开地址时先配置部署，不由页面猜测 |

1. 在当前项目进入“设置 → 项目令牌”，按需要明确签发 Agent 或 API 令牌；原一次性展示和未知回执规则保持。
2. 阅读“客户端连接未验证”，核对服务端提供的端点及地址来源；无地址时联系部署管理员配置 `SUMA_PUBLIC_URL`。
3. 复制不含秘密的 Codex 配置，将当前令牌放入客户端进程环境 `SUMA_MCP_TOKEN`，再打开新的客户端会话。固定账户／组织头只约束原上下文，不授予权限。
4. 按需展开工具目录，在客户端发现工具并读取同项目资料；草稿写入携带原版本和稳定 `idempotency_key`，结果未知时恢复原操作。
5. 回到速码核对正式记录与版本，继续既有评审、采用或派发流程；MCP 草稿结果不代表这些后续动作已完成。

## 本轮 13 项工具范围

下表是产品声明范围。MCP 名称为 `suma_` 加 canonical 名称中点号替换为下划线；实际发现和调用仍按当前身份过滤／核验。

| canonical name | 凭证范围 | 用户得到的结果 |
|---|---|---|
| `project.overview` | Agent／API | 当前项目概览与真实活动 |
| `project.tasks` | Agent／API | 有界分页任务 |
| `project.search` | Agent／API | 有界关键词检索与来源 |
| `project.knowledge` | Agent／API | 明确 ID／修订／SHA 的已批准固定知识 |
| `project.requirements` | API | 有界分页需求 |
| `project.requirement` | API | 单个正式需求 |
| `project.task` | API | 单个正式任务 |
| `project.requirement_design` | API | 需求设计读取 |
| `project.task_design` | API | 原任务设计依据及当前资格 |
| `project.knowledge_list` | API | 当前权限内的分页知识元数据 |
| `project.requirement_draft_create` | API 且当前可写 | 创建 draft 需求，返回正式标识／版本摘要 |
| `project.task_draft_create` | API 且当前可写 | 创建 todo 任务，返回正式标识／版本摘要 |
| `project.requirement_design_save` | API 且当前可写 | 严格版本化保存设计草稿 |

本入口不注册评审、验收、派发、运行、发布、采用、生产、文件或进程工具。原生 `/agent/tools` 与 `/agent/tools/invoke` 保持原四项只读合同。平台其他 REST 接口继续遵守各自合同，不能把 MCP 的目录边界扩大为所有 REST 接口的新限制。

## 验收矩阵与当前事实

| 验收项 | 可核对结果 | 当前记录 |
|---|---|---|
| 单一入口与可信地址 | 既有令牌表单保留；端点仅来自可信服务配置或明确回环监听；未配置时无可复制连接 URL | 定向与实际本地部署通过；生产部署待验收 |
| 安全配置 | 模板只引用进程环境，无令牌值；固定项目、账户、组织与语言头；页面不改客户端配置文件 | 真实复制回贴通过；厂商模型客户端未验收 |
| 工具与权限 | 13 项声明、Agent 原四读取、API 受控读取／草稿；Runner／浏览器凭证不能接入 MCP | 官方SDK客户端及受控权限验证通过 |
| 当前授权与恢复 | 过期／撤权／跨项目拒绝；设计保存严格版本；未知写结果按原工具／正文／key 恢复 | 领域与协议定向、实际同key回放及撤销后401通过 |
| 页面异步状态 | 加载、空目录、失败重读、401／403 清旧事实；切项目／身份不接受晚到响应 | UI 定向通过 |
| 一次性秘密 | 改用途范围／身份清旧结果；身份变化后晚到令牌不显示；旧未知签发继续阻断重复提交 | UI 定向通过 |
| 双语与紧凑目录 | 中英文即时切换；默认折叠目录显示格式化数量；URL／ID／工具名保持原值 | 实际中英、Enter、390英文通过；完整主题矩阵另行验收 |
| 协议与资源边界 | 官方 SDK Initialize → ListTools → CallTool；严格参数、有界输出／取消、Host／Origin、维护模式保持 | 由 Root 在阶段证据中登记真实运行范围，不由界面检查替代 |

本次界面切面为28项／3文件，通过类型与3165键双语目录检查；另有真实SDK客户端124项和代表性浏览器验证。具体厂商客户端、业务人工验收和生产部署分别记录，不合并为“平台已完成”。最终证据见[阶段验收](../quality/project-mcp-verification.md)。
