# 工具准备与恢复 PRD

T-TOOL-PREPARATION-203；suma 1.0.0；负责人：主集成代理。状态：本阶段限定实现与验证完成，见[验证报告](../quality/tool-preparation-recovery-verification.md)。关联[合同](../../contracts/tool-preparation-recovery.md)、[架构与AI SOP](../architecture/tool-preparation-recovery.md)、[交互](../design/tool-preparation-recovery.md)、[English](../en/tool-preparation-recovery.md)。完整31项／P0–P7继续。

用户选择工具并准备一个执行节点后，应继续处理同一工具、同一节点。当前缺口是准备入口丢失适配选择，以及SDK资源或凭据引用不可用时只显示笼统失败，用户无法判断下一步。

| 需求 | 可观察行为 |
| --- | --- |
| R203-1 准确交接 | 当前适配协议及批准节点进入原指南，未知协议不落到默认Codex／全部工具 |
| R203-2 准确原因 | Claude SDK与OpenCode SDK的可信检查边界返回闭集原因，不回显路径、密钥或原始异常 |
| R203-3 直接处理 | 资源与版本问题进入对应指南；凭据引用问题定位名称字段；未决原操作继续核对 |
| R203-4 草稿保留 | 只消费当前目标的新明确请求；普通渲染和旧请求不覆盖人工编辑，旧工具配置不覆盖新工具 |
| R203-5 简洁交互 | 中英文显示短原因和适用的原动作，详细依据按需查看；键盘和窄屏可操作 |
| R203-6 原生Codex配置 | 专门表单与真实Runner七字段模式生成全新commands文件，不落回JSONL或全部工具 |

本地准备观察、配置文件生成、节点库存、正式登记、启用、模型认证及测试验收分别记录。凭据名称不可用只表示本机引用不成立，不等于厂商账号认证失败。OpenCode未指定凭据引用时仍按原规则处理。

远程指南输出目标机器的公开命令草稿，壳类型和路径来自明确输入，不从浏览器操作系统推断。已有配对、身份、报告及启动合同继续适用；本阶段不增加安装器、执行模式、业务接口或派发器。

验收覆盖真实资产校验的失败边界、私有响应解析、原操作优先、准确工具／节点交接、草稿隔离和中英文代表组件。精确证据由主集成代理收口；完整平台、真实厂商模型、物理多机和跨平台安装分别推进。
