# OpenCode SDK 快捷接入

T-OPENCODE-QUICK-CONNECT-177；suma 1.0.0。状态：源码、定向检查、真实SDK资源及代表组件验证完成，实际原生模型旅程待验。依据[冻结合同](../../contracts/opencode-quick-connect.md)、[原SDK执行合同](../../contracts/opencode-sdk.md)、[架构与SOP](../architecture/opencode-quick-connect.md)、[交互设计](../design/opencode-quick-connect.md)和[限定验证](../quality/opencode-quick-connect-verification.md)。

本片把已有OpenCode SDK执行接到原工具快速连接入口，减少手写配置。执行仍使用 `opencode-sdk` / `opencode-sdk-v1`，SDK和原生server固定1.19.4，不增加调度器或模型服务。

## 使用流程

1. 在桌面工具页选择OpenCode，检查本机安装。只有精确支持的原生1.19.4可继续；存在文件不等于已连接。
2. 填写提供方ID、固定模型ID、模型服务地址，以及可选的凭据环境变量名称。凭据原值须已在桌面主进程环境中，不在表单输入或导入用户登录文件。
3. 明确连接。桌面重新核对原生文件、版本及宿主SDK／Node资源，然后复用当前项目、工作区和原Worker登记。
4. 等待本次启动后的准确新库存。匹配成功后，按原流程把工具配置登记为暂停，再明确启用。
5. 任务继续采用该工具的固定提供方和模型；原独立工作树、候选、同提交独立测试及人工验收不变。

OpenCode这里没有模型目录发现或自动选模。更换固定模型或提供方，应先确认原节点停止且没有未结操作，再明确提交新配置；普通重连保持原配置和原登记标识。

## 结果与下一步

| 当前事实 | 用户操作 |
| --- | --- |
| 未安装／版本不支持 | 按现有安装说明准备精确版本，再检查；不降级通用CLI |
| 已安装、尚未配置 | 填写必要提供方信息；此时不显示可派发 |
| 缺可信SDK载荷或目标Node | 修复桌面资源后重新连接；不先发行新Worker身份 |
| 登记结果未知 | 核对原操作，保留原请求和key，不新建身份掩盖未知 |
| 正在连接 | 等待启动后新库存；旧库存不能证明本次连接成功 |
| 已连接 | 查看持久配置的提供方、模型和安全origin，继续暂停登记／明确启用 |
| 停止未确认 | 保留原配置与核对入口，不能当成已安全停止 |

已连接回执必须包含 `model`、`tool_version`、`executable_sha256`、`configuration_sha256`、`provider_id`、`endpoint_origin`。原生版本／SHA、Node版本／SHA及包装器版本分别核验；详情来自原持久配置，不随当前草稿变化，也不返回完整服务地址或密钥。

普通浏览器提供桌面或服务端Runner指引，不声称能扫描浏览器所在机器。配置、连接、登记、启用和模型执行是不同事实；使用量仍为observe-only，不承诺硬预算、价格或供应方身份。当前真实原生／厂商执行及完整安装包交付尚需各自证据，不能由源码或离线资源核验推定。原31项／P0–P7及58／34／92范围保持。
