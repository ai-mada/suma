# 手动执行节点凭证轮换

本合同适用于工具管理中通过手动登记建立的项目执行节点。负责人持当前浏览器项目管理员权限时，可以从原节点行发起轮换。界面显示的轮换入口表示当前操作者具备该节点的管理资格。凭证到期、节点是否在线和执行是否排空分别判断。

`POST /api/v1/release-workers/{id}/rotate-credential` 接收 `project_id`、`expected_version`、`acknowledge_stopped:true` 和 `idempotency_key`。用户先停止节点并保留工作目录和执行日志，再确认。服务端以现有凭证签发、Grant、槽位和签发操作证明手动登记来源，并复核当前管理员、持有人、来源及节点版本。过期的原凭证仍可轮换，撤销或其他登记方式由各自的凭证流程处理。

轮换与原调度、授权锁同事务。存在未决运行、制品、工作区操作或外部效果时，返回 409 `worker_rotation_pending`，等待原操作核对完成。过期凭证对应的未封存制品仍保持待核对，当前缺少独立的安全处置入口。成功后旧凭证即时失效，原节点标识、发布配置、工具配置和历史运行保留。服务端作废旧工具库存观察，新进程需使用新凭证重新上报。

首次完成返回原操作、当前节点登记和一次性新凭证。原请求恢复仍校验当前管理权限。已提交的原操作只返回同一回执和节点登记；此前未到达服务端的原请求可能在恢复时首次签发。浏览器恢复记录只保存请求依据，不保存凭证。若首次响应丢失，先核对原操作。确实无法取回凭证时，用户可基于刷新后的版本另行确认一次新轮换。重新连接使用原节点标识和原工作目录。

手动节点的停止由操作者确认，服务端凭据变更回执记录轮换事实。桌面托管和远程配对各自保存的机器凭证及恢复过程按[桌面续期](desktop-runner-renewal.md)和远程配对合同处理。
