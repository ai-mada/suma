# 任务驱动开发工作台读取合同

状态：1.0.0，T-WORKBENCH-126；负责人：项目交付／工作台领域；关联需求9、10、12、23、25。完整Octop、WorkBuddy、Multica对齐目标和未实现能力保持在产品能力台账。本文冻结当前工作台读取语义，不授予派发、编辑或验收权限。

## 当前上下文

`GET /api/v1/workspace/task-context?project_id=...&task_id=...`在一次当前项目读授权事务内组合正式任务、需求、负责人、设计采用、交付和计划用例摘要。浏览器与有当前项目读取资格的项目API可使用；Runner凭据、历史运行和MCP读取身份不自动获得该接口。

`WorkspaceTaskContext`固定`project_id`、`observed_at`、`task`、`requirement`、`owner`、`design`、`delivery`和`quality`。缺少可选对象使用明确`null`；集合使用空数组；正文来自正式字段，不附可编辑任意`Data`、完整运行输出、环境或凭据。

`task`包含准确ID／版本、标题、说明、验收条目、业务状态、优先级、负责人、需求及原运行ID。`delivery`复用原`TaskDelivery`的相同任务版本与确切运行，不能按最新运行或相似标题猜测。原需求和受保护设计采用关系沿原版本检查；过期显示`stale`，缺失或不能确认分别表达，权限拒绝及底层读取失败不能伪装为空。已验收任务仍可读取，不能复用只允许派发状态的任务上下文方法阻止历史查看。

`owner`只含正式项目成员ID／版本、姓名、种类及状态。不读取凭据或联系资料。任务当前没有正式团队字段，团队事实沿交付摘要中的受保护专家计划／原关系展示，不能从任意JSON猜测。

`quality`保留原测试计划及执行的ID、修订、摘要、运行、当前依据和逐例汇总。测试节点成功数不证明不同Worker或同代码独立测试；用例通过也不替代正式人工验收。独立来源必须打开原执行及证据核对，`formal_acceptance`只来自原交付判定。无计划、未运行、过期、失败和未知分别表达。

## 任务查找

`GET /api/v1/workspace/task-context/tasks`接受`project_id`、可选`search`、`limit`和`cursor`。默认20、最多50项。标题关键字是服务端字面匹配，转义SQL LIKE通配符；搜索最多200字符。按`updated_at DESC,id ASC`稳定分页，游标绑定租户、项目及搜索条件；重复／未知参数、非法游标和跨范围游标拒绝。响应`WorkspaceTaskPage`含正式选项、当前查询总数、上限及下一游标，不将当前页客户端筛选标成全项目搜索。

已选任务不在本页时仍通过准确ID读取上下文。切换账号／组织／项目要取消在途读取、清除受保护结果及输出，迟到响应不能进入新视图；手动刷新必须沿同一已选ID重新授权。

## 交互边界

工作台位于原开发／工作区入口。`panel=workbench-task:<taskID>`只恢复查看的任务，不能放入会改变页面含义的通用`run`参数。选中、清除及跳转使用原导航保护；不能丢弃编辑器草稿、未知保存请求或原文件基线。

选择任务不证明当前文件目录就是该任务的实际工作树，不更改项目绑定、代码提交、原attempt、模型、工具或预算。编辑仍走原文件读取、CAS保存、冲突和原操作恢复。任务、运行、测试及验收状态分别显示；详细依据默认折叠，并链接原任务、确切运行与测试计划。界面不创建快捷批准、第二派发器或虚构执行进度。

当前读取合同不实现交互PTY、LSP／DAP、完整Git写入、办公文件编辑或远程桌面；这些完整目标继续交付，不能将链接、配置或文件观察称为已经具备相关能力。未来终端须经单独Shell／工作区权限、进程树／停止、隔离、输入回执及原Runner执行合同，不得将只读broker升级为任意命令执行。
