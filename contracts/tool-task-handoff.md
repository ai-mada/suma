# 准确工具到项目任务交接

版本1.0.0；阶段T-TOOL-TASK-HANDOFF-213。完整31项／P0–P7继续。依据：[工具管理](tool-management.md)、[当前派发选项](task-dispatch-options.md)、[Pool连接](pool-connection.md)。

## 可观察行为

当前工具详情增加一个“用于任务”动作，仅当前准确、已启用、有真实可用观察、可写且支持原任务协议的档案开放。按需打开当前项目任务选择，复用原任务分页／检索与权限；明确选择后先重新读取准确任务及准确工具，保留工具ID、版本、Worker和完整配置摘要，不因为目录分页、同名或更新而替换目标。无资格、当前依据变化或权限失败明确返回原配置，不自动启用、建任务或派发。

选择完成后在原ToolWorkspace中打开原TaskDispatchDialog；只存在一个Modal，关闭返回原准确工具及焦点。原派发支持可选内存交接pin，包含project_id、id、version、worker_id、profile_sha256和name。pin不是权限或健康证明，不能进入URL、存储或执行合同，也不绑定模型／预算／秘密。

任务派发中显示带入工具的准确名称／版本及简短依据。选择发布流程及Agent节点后，由明确动作调用派发选项的准确工具模式，在同一次授权读取核对任务版本、发布流程、Agent 节点、工具观察和当前执行路径。浏览器只采用符合条件且与 pin 的版本、节点和摘要一致的档案；工具不在首目录页也能采用。当前工具已变化时不悄然使用新版本，不自动搜索同名配置。任务、流程或节点变化清除已采用选择和模型预算绑定，保留交接意图供重新核对；选择其他工具是原显式手工操作。工具暂不可用、流程不兼容和执行路径不匹配在采用前分别反馈。正式预览和启动重新核对各自条件。

## 权威与异常

复用原任务列表和准确单项读取、ToolProfile读取、TaskDispatchPlan预览／Start、ModelExecutionPanel、候选、同提交独测、Review及问题回流。准确预检扩展原派发选项读取和生成合同，复用原档案、事务、依赖与调度器。公开交接仅是UI内存，不创建第二配置权威。

当前actor／组织／project／API caller及每次操作意图绑定所有回调；A→B→A不能接收旧结果。选择任务、刷新、关闭或重新打开不复活旧请求，失败不保留可采用的旧响应。原未确认写入优先：交接不能覆盖或绕过原body／path／key／caller恢复，关闭沿原阻止离开规则。

原预览固定任务／需求／设计／代码基线／知识、准确工具和流程版本，模型及预算仍由原组件明确配置；生成计划后单独确认Start，后端再次核当前权限、路由与依据。后续独立测试、人工验收、问题回流及基线交接保持原领域门禁，不由“用于任务”按钮隐式触发。

## 交互与验收

入口一个动作，任务选择用现有有界列表和检索，不设计常驻复杂向导。原Modal／Field／错误、加载、空态、键盘焦点、44像素触达及中英文词条复用；窄屏单列。明确区分“已带入”“已核对采用”“已形成计划”“已启动”。

主集成负责ToolWorkspace接线、共享pin模块、实际集成和交付；任务选择代理负责ToolTaskHandoffDialog及专属词条／检查；派发代理负责TaskDispatchDialog薄接线、专属交接核对区和检查；Runtime代理独立审查原权威及受影响后端证据。

必要验证：首目录页外准确工具、暂停／撤销／版本或摘要变化、任务重新读取版本、来源ABA／关闭／失败、原pending优先、原预览固定准确ID／版本／配置；一次生产组件真实HTTP／SQLite选择与预览的代表中英旅程。原执行、同提交独测及Review源码未改时复用证据，不为新选择入口重复供应方或模型执行。真实前台CLI、多机、数据库矩阵、完整App／跨平台／规模／生产和原31项全部目标继续。
