# WorkBuddy云任务状态与暂停呈现

T-WORKBUDDY-CLOUD-UI-163；产品1.0.0。扩展[云任务执行合同](workbuddy-cloud-execution.md)的呈现，不新增后端动作、轮询、执行状态机或权限。完整平台目标和原验收边界保留。

## 两类正式事实

平台运行／节点状态与WorkBuddy任务观察是不同事实。原运行暂停，不代表供应方任务已暂停、已停止或已取消；供应方完成也不代表代码交付、独立测试或人员验收通过。页面同时表达平台暂停与已有供应方观察，不让`task_known`吞掉平台暂停信息。

停止未确认、执行节点失联、创建未知、授权变化和观察未确认等原关键原因保留准确的优先级，不为显示暂停而覆盖它们。暂停期间不得显示可执行的伪恢复／停止按钮，不自动刷新或重复创建；已有操作的当前权限、版本、原body／key、未知恢复和锁定规则保持。

## 默认可见的事实摘要

存在已知供应方任务时，原上报状态和最近核实时间不依赖展开技术详情即可看到。最近读取失败时，明确说明正在展示保留的旧观察；不把旧时间改为当前时间、不清空原任务或渲染任意服务错误正文。

只移动影响决策的事实，技术ID、尝试／fence、摘要、固定请求及委派边界继续默认收起。保留现有“查询原云任务”等准确动作及权限，不添加第二套重复操作。未上报的状态／时间使用原未知文案，不填0、成功或进度百分比。

```text
WorkBuddy云任务                    当前平台阶段
平台暂停提示（适用时；远端停止另需回执）
供应方上报状态                     最近核实时间
最近查询失败时：已保留上次观察
查询原云任务／读取当前记录（沿原权限与锁定）
执行详情 ▸   固定请求、技术ID、委派与尝试
```

沿用原设计令牌、正文及状态字级和字体；实际全局浅色基准为text `#293145`、surface `#ffffff`、border `#e7eaf0`、muted `#6e778b`、accent `#645ac8`，深色继续由原主题令牌提供，不新增硬编码主题。左对齐、紧凑事实行，窄屏单列，长值换行。状态不用装饰性指标或新的大卡片堆叠；现有44px动作、可见焦点和减少动效规则保持。

## 团队读取与本人操作

准确节点通过项目授权后，可直接呈现已保存的运行阶段、供应方观察与时间。只有校验后的节点返回本人委派或明确允许委派时，页面才读取该节点固定的本人连接。团队视图缺少委派字段表示该视角无法查看私人委派，使用“共享记录”。已保存的供应方状态与关键阻塞仍按原依据显示。

原授权人的账号读取可与已授权进度呈现并行。读取期间保留同一连接及授权代次的草稿上下文，并锁定委派、撤销、查询供应方和原操作核对。私人连接 404 仅撤下账号。当前访问被拒时清除节点、账号与私有会话呈现。原会话、历史和回合入口只对节点返回本人委派的用户打开。主动共享的内容仍通过原任务讨论提供。

## 项目进度列表

`GET /api/v1/workbuddy-cloud-progress` 复用当前项目读权限及单节点安全进度投影。`project_id` 必须出现一次。`limit` 默认 10、最大 20，`before` 使用原页的 `next_cursor`。当前浏览器会话和同项目 API 凭据可读，每页重新核对权限。返回 `project_id, items, next_cursor?, filter?, task_links?`，条目只来自已保存的提交，并在同一授权事务核对其准确运行和节点。游标绑定租户、项目和当前读者。分页按稳定的提交键读取，刷新重新读取第一页。记录不一致时返回核对错误。

可选 `filter=attention` 查询整个项目已保存的待处理提交，响应回显 `filter: "attention"`。匹配依据为平台标记的处理原因、提交结果未知、最近观察失败，或供应方记录为等待输入、失败、未知。每次最多核对 40 条。到达匹配上限或核对上限后，从最后一条已核对记录续查。筛选页可以少于 `limit`，也可以为空且仍有 `next_cursor`。仅游标耗尽表示已查完此次遍历范围。筛选游标绑定当前项目、读者和筛选，未筛选的原游标保持原范围。

列表计数表示已加载项。未产生提交记录的执行通过调度队列和原运行查看。读取不调用供应方或读取个人授权账号。供应方完成、平台待交付、独立测试及人工验收分别呈现。

`task_links` 只附在项目分页响应中。每个链接按 `run_id` 和 `node_id` 对应本页唯一条目，包含原任务 `task_id`、当前 `task_version`、`run_relation` 及可选纯文本 `task_title`。服务端只为具有下文所述正式派发来源且仍存在的任务返回链接。标题缺失时显示任务编号。单节点安全进度结构保持原样。

## 从云运行打开原任务交付

T-WORKBUDDY-DELIVERY-RETURN 在既有准确节点 GET 中增加可选的 `task_delivery`。在同一授权事务中，正式已启动的派发计划必须匹配当前项目、原运行、节点、节点规格摘要及固定请求摘要。服务端只投影原任务 ID、当前版本，以及任务与该运行的关系。关系为 `current`（仍关联）、`changed`（已改绑）或 `unbound`（已解绑）。未找到正式来源或该项目已无原任务时省略该字段。正式来源存在而固定依据冲突时返回冲突。替代运行和他人的委派详情不随此定位返回。

页面只从最近一次核实且仍匹配当前运行版本的节点视图提供入口。读取中、读失败和拒绝时隐藏定位。原任务深链使用 `development / tasks` 下的准确 `record` 和 `panel=task-delivery`。正式任务与交付详情各自复核当前访问权限。打开交付只读取平台事实，沿原规则处理测试、人工验收及候选。

## 多语言与验证

中文／英文自有标签、暂停边界、旧观察提示准确配对，日期经原格式化函数呈现；原任务正文、供应方状态原文和标识作为字面内容，不自动翻译或当HTML解释。

回归必须证明`details`关闭时内容实际可见，不能只检查祖先`textContent`。定向检查组合`task_known + paused`及优先级更高的未知／失联／观察异常，确保展示调整不增加调用。只做受影响检查、一次类型／语言检查，以及三个代表状态的真实组件浏览器可见性；中文桌面和英文窄屏代表图独立复核。

组件合成数据、真实账号HTTP、供应方执行和生产验收分别记账。此阶段不修改供应方协议、正式调度或计费，不据截图宣称WorkBuddy完整产品能力已实现。
