# 当前人员任务关注合同

阶段：T-MULTICA-FOLLOW-154；速码1.0.0；状态：限定实现已完成，Windows／SQLite真实HTTP与界面16项检查通过；其他数据库、多机、规模与生产仍待验。继续Multica M09／M27及现有完整研发协作范围；不替换既有通知、讨论、执行或验收权威。

## 个人关注

用户在原任务内明确关注或取消关注，只管理当前账号自己的偏好。浏览器／当前用户API可用，Runner、Agent、Pool及代表其他人的请求拒绝。每次读取、写入和原操作恢复均重验当前组织／项目读取权限及准确任务。项目viewer可以管理自己的关注，不取得任务业务写权；不按任务负责人、团队或历史提及自动创建关注。

`GET /api/v1/tasks/{task}/subscription?project_id=...` 返回 `TaskSubscription {project_id,task_id,user_id,version,following,updated_at}`。首次读取纯观察：没有行时version=0、following=false、updated_at为空，不创建偏好、消息、通知或审计。已有关注／取消关注记录保留单调版本与更新时间；不公开其他关注者或账号目录。

`POST /api/v1/tasks/{task}/subscription/commands?project_id=...` 接收闭合 `TaskSubscriptionCommand {project_id,task_id,expected_version,action,idempotency_key}`。action仅follow／unfollow，version为0或有效正整数，正文与URL的项目／任务须一致。当前用户从凭据推导，禁止额外recipient／user／tenant覆盖。未知字段、重复字段、null、非规范ID／操作标识拒绝，沿当前公开API的浏览器视图及API身份规则。

返回 `TaskSubscriptionReceipt {idempotency_key,subscription}`。CAS检查当前个人行；真正改变才递增版本，已为目标状态时不空更新。取消首次未关注的对象可以得到version0的无副作用回执。原操作ID和正文绑定；相同请求恢复原回执，另一正文不得复用。旧回执只证明原提交，当前状态另读；冲突不自动换版本重发。取消保留个人偏好行，不回删历史通知。

## 同源讨论通知

原讨论消息事务向提交时已关注且当前有项目访问权的账号产生 `task_followed` 通知，包括正式保存的人／用户API消息和有完整原回复绑定的最终assistant消息。自发的人／API消息不再通知作者；同一原消息的精准提及接收人只收到既有task_mentioned，不增加关注通知。最终assistant回复仍可通知已关注的请求人。取消只影响随后提交的消息，不改变已发生事实。

沿现有通知序号和唯一插入权威，同一原消息／关注／账号只投影一次。投影与消息或最终回复、原回执同事务提交，投影失败使原事务回滚；不是另建可任意发送系统通知的API。处理全部有效关注者，不静默截断，不在读取／打开页面时补发历史消息。按现有索引／集合读取核对，不能逐接收人获取新的身份锁造成锁顺序反转。

通知只保存来源引用和私有反向绑定，不复制讨论正文、标题或模型输出。新kind的source_resource_id为私有关注行ID；准确消息、关注ID、接收人、租户／项目／任务、原任务版本、通知反向ID和确定事件摘要必须一致，才返回message_id和当前任务。之后取消关注不隐藏既有来源；当前项目撤权仍按原收件箱拒绝。损坏或缺失来源不水合正文或任务链接。

人工发帖与最终assistant持久化应共用领域投影核心；执行进度、模型流式片段、工具日志、任务验收与部署不是讨论通知来源。不能以关注通知声称任务开发、测试、验收或发布成功。

## 交互与恢复

任务讨论入口旁显示一个可键盘操作的关注按钮，中文／英文与当前主题一致；状态文字、aria-pressed和可见焦点表达是否关注，不以颜色单独表达。默认不展开额外配置，不在挂载时自动订阅。

未知写入沿现有useWriteAction保存原body／key，阻止重复变更并提供明确核对。刷新、重读或当前状态已符合不能替代原操作核对；存储不可用不外发。用户／组织／项目／任务或API caller变化立即退休旧响应，401／403／404清除受保护内容。现有个人收件箱为新kind显示准确新讨论，打开原消息与标为已读分开。
