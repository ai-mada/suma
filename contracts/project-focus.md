# 项目交付焦点读取合同

状态：T-EXPERIENCE-133，产品1.0.0；负责人：控制面／工作台；关联完整P0–P7、项目进度及统一工具接入。正式范围与58／34／92总账不变。

`GET /api/v1/project-focus?project_id=…`复用当前项目读取权限，只接受一次准确项目参数。浏览器与具备相应项目读取权的API身份可读取；Runner／Agent不因新增页面获得业务读取权。请求不触发工具探测、模型、派发、审批或数据写入。

## 当前事实与范围

同一授权事务内按租户／项目、任务当前`run_id`及同范围运行连接，统计每一分类的准确总数，每类最多读取6条紧凑记录。按实际任务／运行更新时间倒序、任务ID稳定排序。只读当前已知可操作状态；其他状态通过“全部任务”查看。四类互斥，不作为全项目交付百分比或质量分母。

| 分类 | 事实依据 | 展示约束 |
| --- | --- | --- |
| planning | todo／draft且没有绑定运行 | 待计划，不推断资源或派发资格 |
| execution | 当前绑定运行处于已知活动／等待／暂停状态 | 展示运行状态，不虚构执行进度 |
| review | in_progress、当前运行成功、原受保护任务绑定版本仍匹配 | “运行完成，待检查验收”，不代表测试覆盖或可批准 |
| attention | 任务blocked，运行失败／取消／核对中、原运行缺失或成功运行的任务依据变化／不可证明 | 固定原因码，真实详情另行下钻，不泄漏原日志 |

节点核对中也属于当前运行的attention事实；运行存在独立分支时，不把父运行running误读为没有未知效果。原绑定版本匹配只证明任务修订未变；需求、依赖、独立测试、正式Review仍由既有领域逐项判断。

响应为`ProjectFocus`、`ProjectFocusSection`和`ProjectFocusItem`；字段及原因码从Go类型和公共合同生成。`observed_at`是本次授权读取时间，不是工具在线证明。`truncated`必须与总数／6项上限一致。错误、失权、切换项目及读取未完成时不显示零队列或保留其他项目内容。

## 交互及扩展

首页保留同库全量交付事实与分页关注队列；“任务计划与执行依据”默认收起，展开才独立读取本合同，关闭即卸载。不依赖首批任务列表，不增加默认请求。暂时服务失败时可独立重试；已知失权后清除主视图和诊断，不能保留旧私有快照。分类是筛选，不派发任务；打开任务详情继续既有计划、模型预算、独立测试与验收流程。中英文、键盘按钮、窄屏和减少动效沿现有设计令牌。

后续新增分类须同步当前事实、授权、SQL方言、字段／原因码、UI语言及证据。不能仅通过添加菜单、配置或客户端适配器建立新的状态／审批权威。SQLite当前实测与OceanBase／PostgreSQL真实矩阵分别记录。
