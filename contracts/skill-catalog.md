# 组织共享技能目录合同

状态：T-P4-025 实施中。版本：1.0.0。负责人：平台集成。关联：产品基线第 10、11、12、16、17 项；项目知识合同、当前权限合同。

## 一条正文链路

目录复用项目 `kind=skill` 的不可变发布修订，只保存组织审核元数据与原项目、知识、修订和 SHA 指针。它不是另一套正文仓库，也不安装插件、执行脚本或增加任何工具权限。领域、应用场景、标签为显式可配置元数据；本阶段使用有界关键词检索，不把它宣传为已接通向量检索。

源项目先提取或编辑技能草稿、人工发布；组织管理员在当前源项目批准权限下明确同意向组织共享，生成目录版本。更新仍固定同一个源知识，只能明确选择其当前发布修订。修改源草稿不会改变目录；源重新发布、退役、原来源变化或隐藏后，旧目录原文与历史保留，但阻止新采用。目录正文不带源资料的 quote、标题或外部来源正文，避免组织共享正文时附带未授权原件。

## 采用与当前授权

组织成员通过有当前访问权的项目读取目录批准的文本。项目 API 凭据还需满足其固定项目范围。原生 Agent 现有四项只读工具不扩大；工具在目标项目批准并发布后，通过既有 `project.knowledge` 读取固定修订。

组织共享与项目采用为两个明确审批：源批准者／组织管理员共享；目标项目批准者按目录版本与 SHA 采用，创建 `catalog_adoption` 项目草稿和不可变采用关系，再经过目标项目的正常审核发布。目标成员无须加入源项目，也不因此取得源资料访问权。采用是经目标人审的独立项目副本；后续目录更新不会覆盖旧采用、旧任务或运行。更新需要另一次明确采用与审核。

目录写入、采用、不可变修订、审计和回执在同一事务提交。操作使用稳定 key 与预期版本；当前权限在回执前检查。采用校验目录版本、摘要、当前源资格与目标批准权限。重复请求恢复原结果，不创建重复草稿。退役禁止新采用，保留历史读取。

## 接口与界面

- `GET/POST /skill-catalog`：当前组织列表／明确共享。
- `GET/PATCH /skill-catalog/{id}`：详情／CAS 更新元数据和源发布。
- `POST /skill-catalog/{id}/commands`：明确退役。
- `POST /skill-catalog/{id}/adoptions`：明确采用为目标项目草稿。
- `GET /skill-catalog/{id}/revisions`：分页读取不可变历史。

资料导航新增“共享技能”，延续列表与详情布局。关键词、领域、场景、状态与选中项可从 URL 恢复；来源、摘要和历史按需展开。只显示服务端当前可用操作；冲突保留草稿并读取新版本，结果未知保持原请求重试。所有新增界面、诊断与 CLI 帮助提供中文和英文；用户正文和摘要不自动翻译。

CLI 与 MCP 复用相同服务和权限。MCP 仅新增目录列表与固定版本读取，不开放共享、批准、采用或执行。采用后的固定项目上下文继续通过现有派发合同进入真实工具，不绕过其权限、预算和测试验收。

## 本阶段必要证据

检查同组织跨项目读取／采用、不同组织拒绝、撤权后 fresh/replay 拒绝、草稿／发布分离、源变化／隐藏、退役、版本冲突、重复采用幂等和固定派发上下文。界面验证代表性中英共享→采用→草稿→发布→固定上下文，必要类型／合同与受影响测试；不重复未变化的全平台或规模验收。
