# 核对并结束未完成的候选代码传递

在「工具管理 → 执行节点身份 → 轮换凭证」展开核对区，选择候选代码。可核对原运行、节点、尝试、围栏、Git 基线和候选提交、包摘要及声明大小。用户可切回发布制品独立查看。浏览器读取只给出安全摘要。

`GET /api/v1/release-workers/{id}/candidate-transfers?project_id=P&cursor=TRANSFER_ID` 只覆盖当前项目、手动登记节点及其当前凭证绑定。每页最多检查 20 条。游标定位已检查的记录，已封存和已结束记录不显示，因此某页没有待核对项时仍可能有下一页。围栏用十进制字符串保留完整精度。

`POST /api/v1/release-workers/{id}/candidate-transfers/{transferID}/abandon` 要求当前节点版本、原包摘要、显式确认和原操作编号。服务端在同一授权和调度事务下重验。只有精确匹配的原尝试已明确失败或取消，且候选绑定仍在上传、没有成为封存证据时，才可结束传递。仍运行、待核对、成功但缺乏封存以及证据不一致的记录继续核对。

结束传递保留原包、Git 依据和历史，将传递标为 `abandoned`。结束状态不能作为封存候选使用。原回执可按当前授权核对。操作者另行确认凭证轮换，当前节点的其他未决效果继续由原规则判断。共享资源池、远程配对和桌面托管的管理动作由各自身份合同约束。
