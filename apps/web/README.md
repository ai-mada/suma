# Suma 浏览器工作台

在仓库根统一安装依赖。开发服务使用同源 `/api` 代理连接 `http://127.0.0.1:8080`；浏览器会话由 HttpOnly Cookie 管理。

## 构建与检查

工作目录为 `apps/web` 时，可使用已安装的本地入口运行：

```text
node node_modules/typescript/bin/tsc --noEmit
node node_modules/vitest/vitest.mjs run
node node_modules/vite/bin/vite.js build
```

默认构建输出 `dist/`，并设置 `emptyOutDir:false`，重复构建会保留旧摘要资源。工作流和本地 Monaco 编辑器按页面延迟加载，所有语言 Worker 均包含在本地构建产物中。

## 发布时保留旧版静态资源

不要在正在提供服务的 `dist` 目录中直接执行会清空输出的构建。已经打开的标签页可能仍需要旧版本的带摘要 JS/CSS 文件；只替换新包并删除旧资源会导致延迟加载出现 404。

建议在仓库忽略的 `.cache/web-releases/<release-id>/` 内构建独立版本，然后部署：先向服务中的 `assets/` 追加新版本带摘要资源，保留旧文件，再最后原子切换 `index.html`。回滚时恢复上一版 HTML，保留它引用的资源。独立目录本身不会让旧 URL 自动可达，静态服务或反向代理必须继续能返回旧的 `/assets/<hash>` 路径。

旧资源保留期至少覆盖约定的活跃标签页与回滚窗口；使用明确版本清单管理回收，不应在发布时盲目清空共享 `assets`。源码、截图和交付记录按照项目目录策略保留。

根错误边界与延迟页面错误边界会把资源加载失败显示为可恢复页面，保留当前项目与 URL，并提供显式重新加载入口。不会自动刷新、自动重新提交写请求或把失败伪装成空白成功页。已保存的业务内容仍在服务端；未保存内容应在发布前保存，不能依赖错误恢复页恢复内存中的草稿。
